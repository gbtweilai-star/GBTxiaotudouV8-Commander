## 一、两枚原生位做了什么

### 1) `hand_retarget` — 手部姿态 → 关节角

| 项 | 内容 |
|---|---|
| 输入 | 21×[x,y,z]（MediaPipe 风格；Vision Pro / Quest3 / 摄像头 / IMU 手套先转 21 点）· 或直接 `joints` 字典 |
| 输出 | 目标手关节角（rad 或 deg），带限位夹取、标定偏移、左右手符号 |
| 模型 | 内置 `generic_15dof`（5 指×3 屈曲）· `generic_20dof`（+5 外展）· 也接受自定义 chain/joints/limit dict |
| 算法 | 几何向量法：**MCP 用掌平面前向轴**（修掉"掌骨宽度被算成屈曲"的假读数）+ PIP/DIP 用相邻骨段夹角；外展用掌平面基底投影 |
| op | `status` / `models` / `retarget` / `where` |
| 诚实边界 | **不是 IK**；无接触/触觉建模；外展/对掌为掌平面近似；高精度需逆运动学（本仓暂无） |
| 吸收来源 | AnyDexRetarget · PCHands · BrainCo-Revo2 · hand-tracking-fusion-system（4 份胶囊） |

### 2) `hand_bridge` — 灵巧手 HAL

| 项 | 内容 |
|---|---|
| 统一接口 | `connect / read_state / move / stop / disconnect` |
| 传输 | `loopback`（仿真手，**真状态机**）· `modbus_tcp`（纯 stdlib 组 MBAP+PDU 真帧）· `serial` / `can`（缺 pyserial / python-can 时如实 `needs_dependency`） |
| 关节表 | `generic_6dof` / `generic_20dof`；自定义 profile dict |
| 安全 | 关节限位夹取；`move` 默认 `dry_run=true`；真机写必须 `confirm=true`；真机必须提供 `register_map`（否则 `needs_config`，**不猜寄存器**） |
| op | `status` / `transports` / `profiles` / `connect` / `read_state` / `move` / `stop` / `disconnect` / `where` |
| 诚实边界 | loopback 是仿真装置，**不驱动真手**；串口/CAN 适配未实现（只登记依赖状态）；厂商寄存器表未吸收 |
| 吸收来源 | rh56dfx_description · inspire-hand-rh56-py · rp_dexhand · dexterous_hand_ros2 · tesollo_ros2（5 份胶囊） |

## 四、实现口径（为什么这样写）

- **几何法而非 IK**：先要"能跑、可解释、零依赖"；IK 需要目标手 URDF + 优化器，属于下一层。
- **MCP 参考轴改为掌平面前向**：第一版用"腕→MCP 与 MCP→PIP"夹角，直手小指 MCP 假报 **33.7°**（掌骨宽度被当屈曲）；改成前向轴后直手非拇指屈曲 ≤5°。
- **loopback 不叫假成功**：它明写 `simulated=true`，状态机真更新、真回读；真机才谈"驱动"。
- **真机必须 `register_map`**：吞噬的硬件仓只给了 README/接口概念，**没有**寄存器表；写死任何一家寄存器名都是编造 ⇒ 缺映射就 `needs_config`。
- **写面默认 `dry_run` + `confirm`**：手部硬件误动代价高；真机写/停都要显式 `confirm=true`。
