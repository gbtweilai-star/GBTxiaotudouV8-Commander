# 演示脚本（v2 · 覆盖装置与投屏）

> 2026-10-27 更新 ｜ 配套：`gbt beam`（视觉装置）· `deck.mp4`（片子）· `docs/26–28`（投屏）
> 每页 40–60 秒，全程 5–6 分钟。铁律：**不吹能力，只报读数；做不成就说做不成。**

---

## 开场（30 秒，站定再说）

> 「这不是云端产品。她是一整套跑在手机里的私人框架——权重、数据、判据、片子，都在自己手里。
> 我先用五分钟讲她能干什么，讲完你可以随便问。**问到我答不上来，我就说答不上来。**」

**停顿两秒。** 后面所有可信度都建立在这句话上。

---

## 第 1 页 · 她跑在手机上，不接云

- 「7.6 B 的量化权重，安静时每秒七到九个字。慢，但东西不出这台机器。」
- 「探不到自己的权重时，她会**报错**，不会悄悄换成别人的模型糊弄你。」

**追问：「那能干什么？」**
→ 「写、改、判、拆流程够用；真需要大模型的活，她会说做不了。」

---

## 第 2 页 · 现场演示一：视觉装置（60 秒，最抓人）

```bash
gbt beam          # 起服务 + 交给 Safari
```

Safari 里：允许相机 → 镜头画面立刻变成万花筒。

要讲的三个点：

1. **四种效果**：万花筒 / 隧道 / 对称镜 / 色散（都是同一套着色器分支，切换不掉帧）
2. **双指捏合缩放、双指旋转**，点屏幕唤出预设（2/3/4/6/8 段）
3. **点 📷 截图** → 图落到本机 → `gbt grab --tags 现场` 直接进素材库

**这一段的杀伤力在于**：它是「摄像头 → 特效 → 可投屏」的全链路，而且**今天就能跑**。

---

## 第 3 页 · 现场演示二：判据与修复（60 秒）

```bash
gbt gate 某张图.png                     # 7 轴判定，几秒出读数
gbt fix 某张图.png --declutter --reframe  # 五轴里能修的两轴
gbt batch '<目录>/*.jpg' --reframe --declutter  # 批量 + 报告
```

- 「五条能修：边缘密度、留白、焦点、对比、色调。三条互相冲突时会**回退**，不硬改。」
- 「六张实测：四张从不过改到通过，两张改不动——那两张我留着当失败样本。」

**这段话的作用**：主动交出失败的两张，比讲十张成功的可信。

---

## 第 4 页 · 现场演示三：出片与投屏（60 秒）

```bash
gbt deck --spec deck.json --images assets/ --script \
        --mp4 --narration-audio --burn-subs --review
gbt deckcheck <目录> --expect-audio --expect-subs   # 八项验收
gbt cinema <目录>/deck.mp4                          # 原生播放器起片
```

- 「片子 1080p、有旁白、有硬字幕、有审片图。八项验收不过，我不放。」
- 「投出去三条路，**都不花钱**：AirPlay 到已有电脑/电视、屏幕+凸透镜、闪光灯+透明胶片。」

**追问：「能投多大？」**
→ 「透镜 20cm、投 1 米，39×84 cm，亮度剩 25%，必须全黑。要更大更亮，得有一台真投影仪——我没买，也不建议为这场演示买。」

## 五句不要说

1. 不说「AI 会思考」——说她按判据判断。
2. 不说「完全自主」——说卡住会停下来报错。
3. 不说「本地能出照片级图像」——现在出不了，只有 512 级量化模型在编译中，成了我再说。
4. 不说「摄像头能投影」——**摄像头是进光口，不是出光口**，说了当场会被懂行的人打脸。
5. 不说「下次一定」——这三句一出口，前面五分钟全白讲。

## 被问到答不上来的时候

不要说「应该可以」「理论上支持」。**这两个词是演示现场最贵的两个词。**
