# 108 · 真进程回收：150 帧稳定 21fps / p95 39ms

> 上一步：60 帧内 25fps，150 帧在单进程里退化。
> 这一步：**每个 chunk 起独立子进程**，真进程回收。

## 一、实测（150 帧 / 10s 长视频，chunk=60）
| chunk | frames | load_ms | mean_ms | p95_ms | seconds |
|---|---|---|---|---|---|
| 1 | 60 | 75.01 | 34.59 | 38.25 | 2.22 |
| 2 | 60 | 73.24 | 33.90 | 39.60 | 2.18 |
| 3 | 30 | 67.14 | 33.30 | 39.36 | 1.10 |
| **总计** | **150** | — | **~34** | **~39** | **7.14s / 21.0fps** |

- 150/150 帧处理；
- 每个 chunk 稳定 ~34ms，没有长跑退化；
- 模型加载 67–75ms/chunk，可接受；
- 结论：**长跑退化由单进程长期占用引起；真进程回收有效。**

## 二、架构
```
hand_onnx_chunked_proc.py
  → 每 60 帧 spawn 一个 hand_onnx_chunk_worker.py
  → 子进程加载模型 → 处理 chunk → 退出
  → 父进程汇总 chunk 指标
```

## 三、边界
- 仍是视频批处理，摄像头未接；
- 进程启动成本 67–75ms/chunk（60 帧摊薄 ~1.2ms/帧）；
- loopback 仿真，不驱动真手；
- 实时流需要 chunk/看门狗策略，不是无限长跑。

## 四、下一步
1. 把 chunked_proc 接进 `hand_realtime` 作为长视频模式；
2. 摄像头流按时间/帧数切 chunk，超时回收；
3. 维持 p95 ≤100ms + coverage ≥0.8；
4. 真机标定后再谈力控。
