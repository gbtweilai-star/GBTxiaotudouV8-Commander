# 107 · 长跑 chunk / 进程回收（当前结论）

## 一、60 帧稳态（已确认）
| 指标 | 读数 |
|---|---|
| frames | 60 |
| fps | **25.3** |
| mean / p95 | 34.53 / **37.51 ms** |
| RSS | 116.8 → 121.1 MB |
| 线程数 | 66 → 66 |
| 第一帧 | 243.75 ms（冷启动） |

## 二、150 帧仍异常
- in-process 150 帧：674.99s，infer mean 4416ms、p95 10371ms；
- **模型 reload 分 chunk 也没救**：
  - chunk1（60帧）：mean 31.17ms；
  - chunk2（60帧）：mean 2704.07ms；
  - chunk3（30帧）：mean 1465.24ms；
  - 说明不是模型对象状态，而是更底层（OpenCV DNN/系统调度/热节流）。

## 三、真进程回收测试
- 已写 `hand_onnx_chunked_proc.py`（每 chunk 起独立子进程）；
- 本机 harness 的 Windows Job runner 在嵌套子进程时返回 `3221225794`，未能取得完整结果；
- **不把未跑完当成功**，该项标记为“待独立终端验证”。

## 四、当前可复现结论
- **60 帧内**：ONNX 可实时（25.3fps / p95 37.5ms）；
- **150 帧长跑**：不可信，不能宣称实时稳态；
- 下一步在独立终端跑进程回收；若仍退化，换 ONNX Runtime 或定时重启整个应用。
