# 本体 · 一体式设计（模型 + APP 是一件事）

指挥官模型不是 APP 的「外挂服务」，APP 也不是模型的「客户端」。
**一条生命周期、一本内存账、一个健康面。**

## 一、本体由四段组成

| 段 | 进程 | 角色 | 冷态占用 |
|---|---|---|---|
| 壳 | electron.exe | 界面、IPC、生命周期主人 | 未跑时 0 |
| 桥 | python server.py :8791 | 唯一出口（钥只在桥里） | **21 MB** |
| 权重 | python local_llm_server.py :8792 | 自有权重 Q5_0 | 冷态 0（按需加载） |
| GPU | llama-server.exe :8793 | Vulkan 车道（实验，严判闸门） | 关闭时 0 |

## 二、生命周期（一条线，不是一个服务一个服务地起）

```
壳启动
  └─ 拉起桥（21 MB，秒级）
       └─ 启动预热：能力目录 + GPU 车道自检（失败也不影响用）

用户发第一条消息
  └─ 桥发现 :8792 没监听 → 现拉权重服务（加载 2.07s）
       └─ 回答；记下 lane 与 weights_ours

闲置 GBT_SELFHOST_IDLE（默认 900s）
  └─ 权重服务自退，4.88 GB 文件从工作集里退出

壳退出
  └─ 按端口收掉 8792 与 8793，不留后台进程
```

## 四、内存账：RAM 和 VRAM 是两本账

| | 容量 | 谁在用 | 能不能「按需」 |
|---|---|---|---|
| RAM | 7.39 GB | 桥 21 MB + 权重 0（冷）/ ~400 MB（热） | ✅ 能：闲置即退 |
| VRAM | **4 GB（物理固定）** | GPU 车道关闭时 0 | ❌ 不能：显存是焊死的，不会因为「按需」变大 |

所以「ngl≥16 显存不足」说的是**显卡那 4 GB**，不是内存。
内存这边其实很宽裕：冷态整机剩 3.5 GB，模型热起来也只占 400 MB 左右（mmap 换页）。

## 五、想让更多层进显卡，只有三条路

1. **降精度**：Q5_0（4.88 GB）→ Q4_K_M（约 4.4 GB）→ 每层小 10%，能多塞 1–2 层；
2. **压 KV cache**：`-ctk q8_0 -ctv q8_0`（实测 b6000 上不支持，起不来）；
3. **换驱动**：现在的 AMD 驱动 2022-05，Vulkan 推理输出会漂（见 GPU-车道实测与判决.md）。

前两条只改「能塞多少层」，第三条才决定「塞进去的层算得对不对」。
**在第三条没解决前，塞得越多错得越多** —— 所以闸门是严判，宁可跑 CPU。

## 六、一句话

一体式 = 一条生命周期 + 一本账 + 一个健康面（`/v1/unit`）。
「按需」解决的是**内存**浪费，解决不了**显存**容量，也解决不了驱动错误。
