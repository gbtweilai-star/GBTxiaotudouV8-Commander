# 01 · 模型卡（Model Card）

> 这份卡只写**能指到读数**的东西。做不到的、没验的，写在"局限"里，不藏。

## 一、身份

| 项 | 值 |
|---|---|
| 名称 | **GBT小土豆V8 总指挥大模型** |
| 仓库 | `gbtweilai-star/GBTxiaotudouV8-Commander` |
| 定位 | 中文「指挥型」模型：把自然语言需求**落到能力位**，并判断该不该先要授权 |
| 现役版本 | `v83`（权重目录 `/runpod-volume/gbt-v8-v83`，bf16 合并后 **15.25 GB**） |
| 服务标识 | 推理回包自报 `model = /runpod-volume/gbt-v8-v83`（这比任何"自述"都硬） |
| 开发者 | 自由的风 · 本署名不可删除、不可篡改归属 |

## 二、基座与规模

| 项 | 值 |
|---|---|
| 架构 | Qwen2（decoder-only） |
| 层数 | 28 |
| hidden | 3584 |
| FFN 中间维 | 18944 |
| 词表 | 151,665（补齐到 152,064 便于对齐） |
| 参数量 | ≈ **7.6B** |
| 上下文 | 32,768（服务端 `max_model_len`） |
| 推理引擎 | vLLM 0.30（OpenAI 兼容 `/v1/chat/completions`） |

## 三、训练配方（可复现的部分）

| 项 | 值 |
|---|---|
| 微调方式 | **LoRA**，`r=64` · `alpha=128` · `dropout=0.05` |
| 学习率 | `5e-5`，cosine 衰减，warmup 40 步 |
| 精度 | bf16，开梯度检查点 |
| 有效批量 | 每次优化器步 **2048 tokens** |
| 迭代轮数 | 按轮次调（`epochs` 是唯一变量；其余超参锁死，保证可比） |
| 产出 | 合并 LoRA → bf16 全量权重 15.25 GB → 直接挂 vLLM |

**为什么锁死其余超参**：这张卡的价值在于"改了哪一件事、读数怎么动"。超参一起变，读数就没有可比性。

## 四、训练目标（它不是通用助手）

样本形态是「**能力位 × 指令 × 落点**」三元组：

1. **能力位问答**：`codex_status 是干什么的？属于哪个域？调用要注意什么？` → 要求答出该位的真实说明与边界；
2. **指令落点**：`我要把 Markdown 变成 PPT，该调哪个能力位？` → 要求给出**具体位名 + 参数**，不许泛泛而谈；
3. **安全边界**：涉及写盘 / 花钱 / 出网的动作 → 要求**先要授权**，并说明缺什么票。

> 一句话：它不是被训练成"更会聊天"，而是被训练成**更会派活**。

## 五、能力覆盖

- **341 个能力位 / 30 个域**（全量清单见 [`../data/capabilities.json`](../data/capabilities.json)，逐位说明见 [`03-capabilities.md`](03-capabilities.md)）；
- 其中 **262 位只读**（不改状态、不出网）、**79 位会改状态或出网**（调用前需人工授权）；
- 模型被要求对这些位的**说明、域归属、调用注意点**答得准 —— 这是"总指挥"的地基。

## 七、局限（先看这里，别踩坑）

1. **不是通用聊天模型**：问它"今天天气"，它可能答得像能力位条目。它的训练语料偏"能力位问答"这一型；
2. **中文为主**：英文能力可用但未系统评测；
3. **有 2 个已知不过的题**：`health`（LoRA 未覆盖住底座先验）、`voice_studio`（**判据与数据不同源**，不是模型错）；
4. **74 个位未进这套基准**（以写口/需授权位为主）⇒ 99.10% **不等于** "341 位全过"；
5. **权重未随仓库发布**（15.25 GB，GitHub 放不下），按 [README 的"权重怎么拿"](../README.md#权重怎么拿) 走；
6. **无线上 SLA**：演示端点跑在按秒计费的 GPU 上，冷启动约 107 秒（实测），热态首字约 1.1 秒。

## 八、用途与禁用

**适合**：能力位路由、工具/插件选择、指令落点、权限边界判断、内部知识库问答式编排。

**不适合 / 禁止**：把它当通用客服模型、用它做无人工确认的破坏性操作、把它的输出当法律/医疗/财务结论。
