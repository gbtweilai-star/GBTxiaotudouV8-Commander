# 身体 · 设备即本体

她不该只在某台机器上「有手有眼」。装到哪台设备，就把那台的感官与动作**现读**成身体；
缺的如实报缺 —— 不假装有，也不因为换机器就残废。

## 接口（桥 :8791）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/v1/body` | 这台设备的身体清单（感官 + 动作 + 每项的实读证据） |
| POST | `/v1/body/act` | 真动一下：`{limb, args}` |

页面：`holo_pet_w3/body/index.html`（打开即读身体，点按钮就动）。

## 七根感官（本机实测 7/7）

| 肢体 | 读什么 | 本机读数 |
|---|---|---|
| `see_screen` | 屏幕数量/分辨率 | 1 块 · 1920×1080 |
| `see_camera` | 摄像头枚举 | 1 个 · 640×480 |
| `hear_mic` | 输入设备 | 4 个（Realtek 麦 + 蓝牙耳机 + 立体声混音） |
| `speak_out` | 输出设备 | 10 个（Realtek 扬声器为主） |
| `feel_power` | 电量/CPU/内存 | 96% 充电中 · CPU 16.7% · 内存 5.2 GB 已用 |
| `net_reach` | 网卡/IP/主机名 | DESKTOP-VPVP0BP · 169.254.x（APIPA，未连网） |
| `bt_nearby` | 蓝牙适配器 | 20 个 PnP 设备 |

## 六个动作（本机实测可用）

| 动作 | 说明 | 实测 |

## 为什么走独立进程

身体要的库（mss / cv2 / sounddevice / pycaw）装在 **3.12**；桥跑在 **3.14**。
所以桥用 `GBT_BODY_PY`（默认 `C:\Python312\python.exe`）起一个子进程读身体 —— 
桥自己不背这些依赖，换台机器也不用为了读电量去装一堆包。

## 换设备会怎样

同一个 `/v1/body`，在别的机器上会返回那台机器的清单：
没有摄像头的服务器 ⇒ `see_camera` 报 `missing`；台式机无电池 ⇒ `feel_power.percent` 为 null。
**不会因为缺件就整页崩** —— 每项独立 try，缺什么写什么。

## 复跑

    py -3.14 tools/model-bridge/body.py            # 打印身体清单
    py -3.14 tools/model-bridge/body.py --act volume '{"level":0.4}'

## 已知短板

- `net_reach` 只列 IPv4，且本机现在全是 APIPA（没连网）⇒ 显示的是真实状态，不是 bug；
- `hear_mic` 会把「立体声混音」算成麦克风（那是内录，不是收音）；
- `type` / `click` 需要前台窗口配合，非交互会话里没法验证，**如实标「已接未验」**。
