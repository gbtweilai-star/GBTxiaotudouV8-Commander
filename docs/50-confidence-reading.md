# 50 · 置信度读数：它拦得住"没把握"，拦不住"自信地选错"（2026-11-01）

> 承接 docs/49（文法实验）。那边结论是「文法消灭造名字，却换来自信的错答案」，
> 于是这一步把**信心本身**量出来：接 llama-server 的 `logprobs`，算被选名字那一段的联合概率。

---

## 一、怎么做

1. `commander.ask(..., logprobs=True)`：请求体带 `logprobs: true, top_logprobs: 1`；
2. `_confidence(name, content)`：只累计「拼起来还是 name 前缀」的 token，
   联合概率 = `exp(Σ logprob)`；读不到就返回 `None`（不编）；
3. `route()` 回传 `confidence`；另有 `min_conf` 可选门（默认关）。

## 二、实测（k=12，本机 Q5_0）

| 意图 | 选出 | 置信度 | 对不对 |
|---|---|---|---|
| 帮我把这段文字塞进剪贴板 | `clipboard_copy` | **0.967** | ✓ |
| 资产索引 查资产台账 | `asset_index` | **1.000** | ✓ |
| 回车确认键 | （无效输出） | None | ✓ 诚实失败 |
| 撤销上一步 | （无效输出） | None | ✓ 诚实失败 |
| 量化回测入口… | `quant_backtest` | **0.993** | ✗ 孪生位 |
| 吞天闭环…蒸馏 | `devour_scan` | **0.999** | ✗ 近义位 |
| 读取量化项目结构… | `quant_params` | **0.458** | ✗（会被 0.5 的门拦住） |

## 三、判读（这是这轮最值钱的一句）

**置信度区分的是"有没有把握"，不是"对不对"。**

- 对的：0.967 / 1.000 —— 高置信；
- **错成孪生位的：0.993 / 0.999 —— 同样高置信**；
- 没把握的：`None`（模型给不出候选内名字）。

⇒ 置信度门（`min_conf`）只能拦住"本来就没把握"的少数（如 0.458 那条），
**拦不住"选错兄弟"**，而那才是剩下的主要 miss 类型。默认 **不开启**，只把 `confidence` 作为读数回传，
让上层（`pulse_core route` / 调用方）自己决定要不要用。

## 四、代价

`logprobs=true` 会略微增加响应体；实测单次耗时 **15–124 s**（区间大），但同期后台还在跑 481 项判决，
**引擎是共享的**，所以这组耗时**不能**当成"开 logprobs 变慢了"的证据 —— 要测代价，得等判决跑完再单测。

## 五、结论与下一步

| 问题 | 现状 |
|---|---|
| 造名字（无效输出） | 已定位，成因是格式；文法能消，但会换来错答案 ⇒ 不用 |
| 选错孪生位 | **置信度高**，任何阈值门都拦不住 ⇒ 只能靠更强模型 / 更好的候选区分度 |
| 候选区分度 | **可改**：给孪生位加"区分词"（如 quant 讲"策略入口"、quant_backtest 讲"回测接口"）比换模型便宜 |

下一步（有具体动作、可量）：**给 5 组孪生位补区分性描述（registry desc），重跑这几条**，
看是否把 0.99 的错答案拉回正确项 —— 改的是**数据**，不是模型，符合"能改数据就不改模型"的取舍。
