# 102 · 同进程 ONNX + 三线程：fps 上去了，e2e 延迟没达标（如实）

> 上一步：ONNX 串行 23.69fps / frame p95 91.7ms / realtime_ok=true。
> 这一步：按“同进程 + 三线程”验证，是否还能更好。

## 一、实测
| 路径 | fps | e2e p95 | detect p95 | realtime_ok |
|---|---|---|---|---|
| ONNX 串行 `onnx_video` | **23.69** | **91.7 ms** | 42.86 ms | **true** |
| 同进程三线程 qsize=8 | 26.21 | **402.81 ms** | 70.84 ms | false |
| 同进程三线程 qsize=1 | 27.40 | **255.20 ms** | 32.20 ms | false |
| ONNX 常驻子进程 | 1.30 | — | 576.89 ms | false |

## 二、结论
- 三线程把 **fps 提到 26–27**，但 **e2e p95 仍 255–403ms**；
- 原因是启动/队列 backlog：帧一进队就排队，端到端被“排队时间”拉长；
- 串行 `onnx_video` 反而是当前最佳：23.69fps、p95 91.7ms，**达到实时判据**；
- 常驻子进程最差（1.3fps），IPC/进程调度在这台 CPU 上不划算；
- 不把“fps 高”冒充“延迟低”。

## 三、下一步（按数据）
1. 三线程改成 **latest-frame 队列**（只保留最新帧，旧帧丢），压 e2e；
2. 预热后再计时（冷启动单列）；
3. 摄像头通后重测真实输入；
4. 实时走串行 ONNX；IK 异步离线，不拖闭环。
