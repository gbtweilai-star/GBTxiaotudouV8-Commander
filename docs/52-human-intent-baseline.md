## 一、尺子怎么造

新工具 `tools/codex-scripts/commander-bench-lexicon.py`：

```
查询 = 词条的 say[0]（人写的，如 "ppt" / "字数" / "审计" / "回滚"）
期望 = caps 里权重最高的那一项（人标的）
同时记两个数：recall@k（期望项在不在候选里）与 hit@1（模型选没选中）
```

分两个数报，是为了**分清"召回没兜住"和"模型选错"**——这是 docs/46 定下的口径。

## 三、怎么读这个数（别急着下结论）

1. **样本太小**：n=6。`发布` 一条就能把 16.7% 变成 33%，不能当结论。
2. **查询是"一个词"**：`审计` 本身就有歧义（`audit_query` 还是 `caps_called_audit`）；
   `镜像` 也歧义（`mirror_scan` / `mirror_status` / `mirror_rehearse`）。
   词条里的"期望"是人按**自己意图**标的，对模型是**苛刻的唯一答案**。
3. **耗时被污染**：同一时刻后台还在跑 481 项判决，引擎共享 ⇒ 95.6 s/次不代表常态。
4. **召回 100%**：说明候选池覆盖没问题——这与方法学结论一致（docs/46 的 478 项也是 recall 满、错在判决）。

## 四、两把尺子的定位（以后别再混）

| 尺子 | 量什么 | 当前读数 |
|---|---|---|
| 478 项合成（desc 回环） | **可达性上限**（每一项都进得了候选） | 进行中（255/481，约 226 命中） |
| 24 条人写词（say） | **短意图下的真实可用性**（词少、歧义多） | 首轮 1/6（n=6，样本不足） |

**结论**：短意图是当前最弱的一环，而它恰好是主人最常用的形态（"审计"、"回滚"、"镜像"）。
但要得出结论，得先跑满 24 条、且不与别的负载抢引擎。
