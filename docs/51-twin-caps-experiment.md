# 51 · 孪生位实验：加了区分词，2/5 命中 —— 结论是**尺子本身有歧义**（2026-11-01）

> 承接 docs/50：置信度拦不住"选错兄弟"，于是改**数据**——给 10 个孪生位在 desc 最前面加区分词，
> 重跑那几条失败用例。结果不如预期，但它揭示了一件更重要的事。

## 一、做了什么

给 10 个"长得很像"的能力位在 `caps_registry.py` 的 desc **最前面**加区分词
（路由菜单只截 desc 前 30 字，所以区分词必须在最前）：

| 能力位 | 加了什么 |
|---|---|
| `quant` | 【量化·总入口】 |
| `quant_backtest` | 【量化·回测接口】 |
| `quant_strategy` | 【量化·策略信号】 |
| `quant_params` | 【量化·数值参数】 |
| `platform_profile` | 【量化·项目结构】 |
| `absorb_loop` | 【吞天·闭环】 |
| `devour_scan` | 【吞天·缺口扫描】 |

## 三、为什么没用 —— 问题出在"尺子"

看第一条就明白了：

> 意图 = **"量化回测入口外部业务模块tech"**（这是从 `quant` 自己的 desc 生成的）
> 模型选 `quant_backtest`，因为**这句话里"回测"两个字最响**，而 `quant_backtest` 名字里就有 backtest。

这不是模型笨，是**题库本身有歧义**：孪生位的 desc 互相包含对方的词（`quant` 的 desc 里
就写着"量化/**回测**入口"）。用 desc 生成意图、再让模型选回原 desc —— 对孪生位而言，
这条基准**构不出唯一正确答案**。

⇒ 结论：这两类（`quant*`、`*_distill`）的 miss，**不能算路由失败**，要算**基准缺陷**。
按本仓"不假绿也不假红"的口径，应该在报告里单列，而不是拿去调模型。

## 四、保留还是回退？

**保留**区分词。理由不是"它提升了命中"，而是：

1. 它们**语义准确**（总入口 / 回测接口 / 策略信号 / 数值参数 确实是四件事）；
2. `cap_self ask` / 能力总表 / 域页里，人读起来也更清楚；
3. 对**真人意图**（"帮我看看回测接口有哪些参数"）有帮助，只是对"desc 回环"式合成意图无感。

## 五、下一步该换尺子，不是换模型

要做真正可信的命中率，必须用**人写的意图**（不是 desc 回环）。仓里有现成的：

- `data/intent-lexicon.json`（人工词表：`what` / `say` / `caps` 权重）；
- `semantic_route` 的留出集（`holdout3` 冻结读数 10/24 = 41.7%）。

**下一步**：从 `intent-lexicon.json` 的 `say` 里抽人话（它们是人写的、且不回环），
对 `caps` 字段点名的能力位跑一轮命中率 —— 与 478 项合成基准并列报出，两个数分开写，**不混成一个**。
