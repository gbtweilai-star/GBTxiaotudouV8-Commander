# 73 · 一句话入口：说一句就走完整链（2026-11-01）

> 主链（蓝图→过目→思维导图→派遣→研究→落地）已经通了，但每次都要我手敲 `make/approve/land`。
> 这一轮把它收成**一句话**。

---

## 一、`blueprint op=go`

```python
run_task("blueprint", {"op": "go", "text": "按这个架构推进到落地：触手主干 + 无限制上下文 + 脉冲提速"})
# 没写"已确认" ⇒ stage=blueprint，pending_approval=true，把 id 与过目命令还给你
```

```python
run_task("blueprint", {"op": "go", "text": "…，已确认：触手主干 + 脉冲提速", "approve": True})
# 已确认 ⇒ approve → land → stage=landed
```

解析规则（`parse_intent`）：

- 剥掉口语前缀（按这个架构/推进到落地/开始执行/落地吧/干吧…）；
- 出现「已确认 / 确认过 / 直接跑 / 直接落地 / 不用问 / 我已看过 / 我看了」⇒ 视为已过目；
- **没写就只到蓝图**——入口不替你确认（这是唯一保留的交互）。

## 二、实测

```
不确认："按这个架构推进到落地：触手主干 + 无限制上下文 + 脉冲提速"
  → stage=blueprint · pending_approval=true · tasks=26（复用了已验证模板）

已确认："…，已确认：触手主干 + 脉冲提速 + 自主吞噬"
  → from_template=上下文-不打扰-主干-吞-93816
  → stage=landed · 29 任务 1 轮全通过 · 自动沉淀新模板
```

## 三、纪律没变

1. **没确认不过目**：入口把 `pending_approval` 留着，等你一句话；
2. **过目后不再问**：approve 里自动 `autonomy.declare`；
3. **失败/卡点照旧**：查资料 → 深推理 → 质量门 → 兜底 → 两轮 stuck 剔除。

## 四、判据（`test_blueprint` 第 [14] 组 5 条）

- 解析出架构
- 未写已确认 ⇒ approved=False
- 不确认时停在蓝图
- 已确认时走到落地
- land 有读数

测试会在结束时**删掉自己造的蓝图**（不制造垃圾）。

## 五、顺手修的一个测试坑：**并行跑会互相踩**

固化时我同时跑了两份 `test_blueprint`（一个在前台、一个在后台），结果 `[13] 落地后自动沉淀模板` 偶发失败。

原因：测试里用了**固定 id**（`blocker-test-0001` / `stuck-test-0001`），两份进程共享同一份
`state/blueprints/<id>*.json` 与 `runs.jsonl` —— 一份清了另一份正在写。

修法：固定 id 改成 **进程号后缀**（`blocker-test-<pid>`）。

**教训写进纪律**：涉及共享 `state/` 的判据**不许并发跑**；要么顺序跑，要么 id 带 pid。

## 六、固化收尾：测试**全局自清**（不留垃圾）

主人提醒「每一步做完都要固化，别又乱丢」。这轮清点发现两个真问题：

1. **蓝图残留**：`test_blueprint` 里 [6]/[7]/[13] 造的蓝图每次留一堆（实测清了 78 个、又清 282 个）；
2. **签名缺口**：`docs/capabilities` 曾重新生成过，30 页署名丢了（属"历史残留"，不是新文档没签）。

处理：

| 问题 | 做法 |
|---|---|
| 测试残蓝图 | 测试开头记 `blueprints/`+`blueprint-templates/` 快照，结束**删掉所有新增文件** |
| 重复模板 | 按关键词签名去重（清 6 个，留 4 个） |
| 签名缺口 | `signature.audit(restore=True, scope="all")` 补 30 页，套件前后均 `missing=0` |
| 验证 | 跑一遍测试：蓝图文件数 **6 → 6**（不再增长） |

**纪律**：判据测试**只许看，不许留**；凡写 `state/` 的测试必须在退出前恢复原状。
