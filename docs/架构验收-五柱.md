## 柱 1 · 双向绑定

| 检查 | 结果 |
|---|---|
| 名册可取 | 348 条 |
| 每条能力位有页 | 缺 0 页 |
| 页面 data-kind 对得上 | 错 0 |
| 页面允许连本地桥（CSP） | 缺 0 页 |
| 页面挂了渲染器 cap.js | 缺 0 页 |

原生病根：每页 CSP 是 `connect-src 'none'` —— 页面**物理上无法调用任何东西**。
改成 `connect-src http://127.0.0.1:8791` 并重生成 348 页，才谈得上双向。

## 柱 5 · 算力（GPU）—— 失败，有证据

硬件与环境：

```
Vulkan0: AMD Radeon(TM) Graphics  4037 MiB (3835 free)
Vulkan1: AMD Radeon RX 6500M     4080 MiB (3420 free)
Vulkan Instance 1.3.301 · vulkan-1.dll 1.3.300 · 驱动 30.0.14064.4 (2022-05)
llama.cpp b11840 vulkan 构建
```

实测：

| 配置 | tok/s | 输出 |
|---|---|---|
| CPU（现用） | 1.7 | 中国的首都是北京。 ✅ |
| Vulkan ngl=12 | **5.45** | GGGGGGGGGGGG ❌ |
| Vulkan ngl=12 + --no-kv-offload | 3.60 | GGGGGGGGGGGG ❌ |
| Vulkan ngl=12 + fp16 KV | 5.56 | GGGGGGGGGGGG ❌ |
| Vulkan ngl=6 | 0.52 | GGGGGGGGGGGG ❌ |
| Vulkan ngl=16/20/24 | — | 显存不足，起不来 |

**速度快 3.2 倍，但结果全错 —— 不能用。**三种规避（关 KV 卸载 / 强制 fp16 KV / 降到 6 层）都复现同样的乱码，
所以不是配置问题，是**驱动与 Vulkan 后端的兼容问题**（驱动是 2022 年的）。

可行的解：升级 AMD 驱动后重测；升级不了就继续用 CPU（1.7 tok/s，结果正确）。
