# 53 · 短意图修复：用人工词表收窄候选，1/6 → 5/5（2026-11-01）

> 承接 docs/52：人写短意图（"审计"/"镜像"/"字数"）命中只有 1/6，但**召回 100%**。
> 这轮不再调模型，改**候选集**——用仓里人写的 `data/intent-lexicon.json` 收窄。

## 一、诊断回顾（为什么收窄是对的）

docs/52 的 6 条里，模型选错的都是**兄弟位**：

| 查询 | 模型原来选 | 人标的期望 |
|---|---|---|
| 字数 | `action_gate` | `count_words` |
| 审计 | `truth_scan` | `audit_query` |
| 镜像 | `mirror_rehearse` | `mirror_scan` |

而 `intent-lexicon.json` 里 **人早就写死**了：`"审计" → audit_query(10) / caps_called_audit(4)`。
**人的判断比 7.6B 在 12 个候选里瞎挑可靠** —— 那就别让它瞎挑。

## 二、改法（只收窄，不替它拍板）

```python
_lex = _lexicon_boost(查询)             # 人写词表命中 → {cap: 权重}
cands = _shortlist(..., restrict=set(_lex))   # 候选池收窄到人点名的那几位
r = ask(...)                            # 仍由权重在 2–3 个里选
```

三条纪律：

1. **只减少候选，不改判断**：最终仍是模型在候选里选，不是我硬写答案；
2. **不命中就不收窄**：词表没写着的话，走原来的 12 候选（行为不变）；
3. **可关**：`route(..., use_lexicon=False)` 回到旧行为，便于对照。

## 三、实测（同 5 条此前失败/通过的短意图）

| 查询 | 收窄后 | 置信度 | 收窄 | 结果 |
|---|---|---|---|---|

| 字数 | `count_words` | 0.982 | ✓ | **HIT** |

| 回滚 | `pipeline_rollback` | 0.994 | ✓ | **HIT** |

**1/6 → 5/5**（同一批短意图；`发布` 那条本来就对，未列入）。

注意 `ppt` 置信度只有 0.444 —— 收窄让它在两个候选中选对了，但**模型自己并不确定**；
这正好说明"确定度 ≠ 正确"（docs/50 的结论）依然成立。

## 四、边界（这条很重要）

1. **覆盖面有限**：词表只有 24 条，覆盖约 30 个能力位；词表没写到的短意图**不受益**。
2. **词表质量决定上限**：人写错，它就跟着错。词表的 `caps` 权重是唯一的"人判断入口"。
3. **不是"训好了"**：这是**用数据绕过模型弱点**，不是模型变强。

要扩覆盖面，正确的做法是**扩词表**（人写），而不是让模型猜——这符合本仓一贯取舍。
