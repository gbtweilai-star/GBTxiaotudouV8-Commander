两档分开报，**不把提及混进绑定**冒充 100%。

## 四、四机制：读数与执行点

### ① 触手脉冲（提速）
`bridge.pulse()` 实测：`ok / skill=pulse / capabilities_total=351 / pack` 一次成包
（含能力全集 + 本次激活子集 + 任务边界）。脉冲是"一次广播拿全身状态"的快路，
不必逐页探活 —— 页级核对走 `page_scan` 并发，状态口径走 pulse，两条腿分工。

### ② 量化压缩
| 档位 | 大小 | 说明 |
|---|---|---|
| fp16 | 14.19 GB | 逐 token 与 Q8 相同 |
| Q8_0 | 7.54 GB | |
| **Q5_0（主道）** | **5.24 GB** | 已下载、合并、**sha256 与公布值逐字相同** |
| Q4_0 | 4.00 GB | **不可用**：`PROOF-weights.md` 实测激活放大 2600×、输出退化成 `vana` |

压缩比：**14.19 / 5.24 = 2.71×**；Q4_0 再小 24% 但会坏，**不采用**（不拿质量换体积）。

### ③ 按需激活
`tentacle/commander.py` 的 `start/stop`：幂等（已在服务就复用）、只停自己 pid 文件那个、
起停收 `process_execute` 门。实测冷启动 **2.6 s** 到 `/health` 可用；
权重按 `state/weights/ACTIVE.json` 现读，换版只改指针。
**睡着了会自己醒**：`start(idle_s=600)` 给 llama-server 传 `--sleep-idle-seconds 600` ——
10 分钟没人用就卸权重、让出内存，下一次请求来了再加载（这就是「按需激活」的落地，不是常驻烧内存）。

### ④ 精准直达
- 召回层：`_shortlist` 的 **recall@20 = 478/478 = 100%**（95+ 触手方法 + 351 能力位全进候选）；
  同表生成口径，是**可达性上限**，已在 `commander-coverage.py` 里写明。
- 判决层：`commander-coverage.py` 真跑（478 项逐项过权重、每项落 JSONL）。
  截至本文件落笔：前 16 项 **15 HIT / 1 MISS**（`audio_voices`），平均 ~40 s/项；
  全程约 5 小时，**后台续跑，可断点续跑**（`state/commander/coverage-rows.jsonl`）。
- 一步命中：仓里 `pulse_direct` 的 audit 读数为 `observed=2 / 一步命中 0 / 没命中 2`
  （样本太小，只记录，不据此下结论）。

## 六、诚实边界

1. **强绑 42.4%**：983 页按"神经系统"口径兜底挂主干 `tentacle` —— 它们**有绑定、能互通**，
   但没点到具体能力位。要提到 100% 强绑，得逐页写 `state/page-caps.json` 申报，是**人工活**，不是脚本能猜的。
2. **互通口径是图连通**（页与页的引用/邻接图），不是"每页都能直接调每个能力位"；
   后者是权限与语义问题（比如 `credential_steal` 要票），不该也不允许打通。
3. **判决层 478 项** 只跑完前 16 项（约 5 小时全量），本文件写的是**进行中读数**；
   全量结果落 `state/commander/coverage.json`，行级明细 `coverage-rows.jsonl`。
4. 页图扫描于 2026-10-24，之后新增的文件不在 1706 页里；重扫需跑 `tools/page_bind` 的扫描器。
