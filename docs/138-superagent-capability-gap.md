# 138 · 吸收 DeepSeek Super-agent：能力缺口对照（不吸收限制）

日期：2026-11-02 · 主人令：只吸收缺失能力；不吸收阉割/限制；按我们自己的规矩——
**架构蓝图用户确认后，AI 锁定任务、不再要求用户帮忙，直到项目落地。**

## 一、对照表

| DeepSeek superagent 能力 | 我们现状 | 判定 | 吸收方式（去掉限制） |
|---|---|---|---|
| 主动监听 GitHub / 飞书 / CI | 只有手动对话、看板 | **缺** | 增加 Sources：GitHub 通知 + 直接 Issue 轮询 + 本地任务；不要求专用账号 |
| Policy/准入（allowed、explicit/inferred） | trusted owner 全开，外部无准入 | 部分 | 外部来源只需一次主人确认；主人/蓝图内任务永远直通，不设 observe |
| Ticket 生命周期（去重/队列/重试/状态） | 蓝图任务有状态，无主动工单 | **缺** | 新增主动工单队列（持久化、去重、重试、事件台账） |
| 独立执行器 / 每工单一 Session / 工作目录 | 数字人/触手有执行器，无按工单隔离 | **缺** | 每工单独立沙盒目录 + git worktree；执行器不询问用户 |
| 交付（commit / PR / 验收） | 有构建/测试/推送能力，无自动交付链 | **缺** | 执行完成自动 commit → 分支 → PR → 回写 Issue；失败自动修到落地 |
| 面板（Triggers/Tickets/Workers） | 有多域监控/看板 | 部分 | 并入多域监控：来源、工单、执行器、变化同屏 |
| Prompt/团队配置 | 有蓝图/角色/技能 | 已有 | 不重复造 |
| accept=observe / 专用 agent 账号 / 人审闸门 | — | **不吸收** | 与“确认蓝图后锁定任务”冲突，全部去掉 |

## 二、我们已有、不能丢的优势
- 蓝图确认后锁定任务、不要求用户帮忙、直到落地；
- 万能插 7 类插座默认全开、可信主人会话直通；
- 触手骨位/眼手脑闭环/关联线路监控/多域监控；
- 记忆链、能力域、桌面 APP、数字人。

## 三、本轮已落地的吸收
- 新增 `gbt_allinone/proactive.py`：
  - Sources：本地任务 + GitHub 通知/Issue；
  - Policy：外部需在允许名单；主人来源直通（无 observe 降级）；
  - Tickets：持久化队列、去重、状态、步骤、结果、事件台账；
  - Executor：本机 8792 引擎 + 受限沙盒读写/执行；
- 已停止外部 3082 的 superagent 服务（只吸收能力，不再“用她”）。

## 四、尚未完成（继续自动做，不向用户要帮忙）

3. git worktree + commit/PR 交付；
4. 控制台“主动智能体”面板并入多域监控；
