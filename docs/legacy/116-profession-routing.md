# 116 · 职业路由（任务 → 职业 → 能力位）

> 主人 2026-11-01：「下一步」——21 种职业配齐后，任务要能自动找对口的触手。

## 一、路由怎么算（可解释，不黑箱）

`gbt_allinone/profession_router.py`：

| 加分项 | 权重 | 说明 |
|---|---|---|
| 中文关键词（每职业一张表） | +5/词 | 「短视频/编曲/修 bug/渗透/直播…」 |
| 职业标题分词命中 | +4 | 标题里的词出现在任务里 |
| 职业 headline / KPI 分词命中 | +2 | |
| 域命中 | +2 | 任务里出现域英文名 |
| 能力位名命中 | +3 | 任务里直接点名能力位 |
| **代码类动词优先** | **+20** | `(修/改/实现/开发/补/重写)+（bug/代码/模块/功能/逻辑/接口）` → 编程工程师优先（避免被 QA 抢走） |

同分按能力位数量排序；没有任何命中 → 走「协同 / 指挥」兜底。
候选能力位分成 **safe / gated** 两栏：需授权位标出来（要票），不混在可执行候选里。

## 二、接口与界面

- `POST /api/route`，body `{"task": "剪一条30秒短视频"}` → `{profession, matched, safe_candidates, gated_candidates, tools, kpi, alternatives}`
- 职业视图（`#prof`）顶部有输入框 +「职业路由」按钮；结果直接显示：
  **职业（命中词）→ 候选能力位（另有 N 个需授权位要票）→ 工具 → KPI**
- 巡检标记：`data-route = ok:<职业id>:<候选数>`、`data-route-prof`
- **只读规划**：路由不派单；真派单仍走 `run_task`，危险/转账永远要票。

## 三、实测（5 条样例全过）

```
剪一条30秒短视频，要爆点开头   → 短视频编导
给这段歌词编曲混音             → 音乐制作
修一个 bug 并跑测试            → 编程工程师        ← 代码动词优先生效
做一个数字人口播直播           → 数字人 / 直播
拍一部三分钟的电影短片         → 影视 / 电影

POST /api/route {"task":"剪一条30秒短视频"}
  → ok=True profession=短视频编导 候选 8 / 需授权 8
页面 #prof：路由条在（route-input/route-btn），data-prof=ok:21职业+编程首席
```

## 四、边界（如实）

- 关键词表是显式维护的（不接语义模型），新任务类型要补关键词；
- 路由给的是**候选**，不自动执行；派单要人/协同触手确认（危险能力必须票）；
- 还没做「按职业派单后自动回填账本」的闭环（下一步：route → dispatch → ledger 一条链）。
