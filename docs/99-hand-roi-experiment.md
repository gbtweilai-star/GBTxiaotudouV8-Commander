# 99 · ROI/降分辨率实验：没有换来实时（如实记录）

目标：把视频视觉链的 176ms 处理延迟压下去。做法：`roi=True` 只裁上一帧手框 + `proc_width=256` 降分辨率 + MediaPipe complexity=0。

## 一、实测（30 帧本地视频，ComfyUI 已停）
| 配置 | detected/moved | latency mean | p95 | frame_age |
|---|---|---|---|---|
| 全图 512 / complexity 1 | 30/30 | 694.23 ms | 966.72 ms | 18.392 s |
| ROI 256 / complexity 1 | 30/30 | 880.71 ms | 1016.42 ms | 13.181 s |
| 全图 256 / complexity 1 | 30/30 | 829.89 ms | 998.06 ms | 12.197 s |
| ROI 256 / complexity 0 | 30/30 | **654.44 ms** | 803.99 ms | 14.347 s |

## 二、结论（不粉饰）
- ROI + 降分辨率**没有把延迟压到实时**；最好也只有 654ms，帧年龄 14s；
- 降 complexity 有一点收益，但杯水车薪；
- 主瓶颈是 MediaPipe 图/模型在 CPU 上的推理与重复初始化，不是输入分辨率；
- 继续裁 ROI 不是正确方向。

## 三、下一步正确方向
1. **常驻推理进程**：模型只初始化一次，视频帧走 IPC；测首帧 vs 稳态；
2. **复用 tracker**：不要每次 run 新建 `Hands`；
3. **线程/帧池**：采集、推理、IK、手 HAL 分线程，避免串行；
4. 如果仍 >100ms，就诚实标“本机 CPU 不适合实时手势”，不拿 2fps 冒充 15fps。
