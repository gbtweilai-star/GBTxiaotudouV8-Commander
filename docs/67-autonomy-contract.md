# 67 · 自主契约：架构给完之后不许打扰主人（2026-11-01）

> 主人严令（逐字）：「除了终端危险能力和转账拿票，其他东西必须在用户给完架构之后就不能打扰用户，
> 和要求用户帮助这是严令禁止的」。

这一条比前面所有能力都重要：前面解决「能不能做」，这条解决**「该不该问」**。
一个通用智能体如果每件事都回头问，那不是智能体，是带语音的对话框。

---

## 一、落成可判定契约（第 364 位能力 `autonomy`）

`state/autonomy.json`：

```json
{"architecture_accepted": true, "since": "...", "exceptions": ["danger", "transfer"]}
```

| op | 作用 |
|---|---|
| `status` | 契约状态（架构是否已给、例外清单、历史打扰次数） |
| `declare` | 声明架构已给（从此进入自主模式） |
| `check` | `{"kind": "danger|transfer|other"}` → allow / deny（deny 必记账） |
| `guard` | 给一段模型输出，把「需要你确认/要不要我/请提供…」**改写成自主推进**并记账 |
| `ledger` | 打扰账本 |

## 二、判据三条（少一条不算）

1. **架构已给才生效**：没给架构前允许提问（否则没法干活）；
2. **例外只有两个**：`danger`（终端危险能力）与 `transfer`（转账/花钱）—— 这两个必须拿票；
3. **打扰必留痕**：真有人（或模型）试图问，记进 `state/autonomy-bothers.jsonl`，可审计。

## 三、实测

```
status   → architecture_accepted: false（初始）
declare  → true
check danger    → allow: true    （例外：危险能力必须拿票）
check other     → allow: false   （架构已给 ⇒ 禁止打扰，已记账）
guard  "需要你确认一下用哪个参数；要不要我继续？"
       → "（按架构契约自主推进；除非危险能力或转账，不打扰主人）" · rewritten: true
```

## 四、接到哪

1. **`trunk_reason`（触手推理环）**：LLM 给的"下一步"若是在回头问主人 ⇒ 按契约改写为自主推进；
2. **记忆条**（`cap_self brief`）：新增一条铁律 ——
   「架构给完后除 danger 与 transfer 外，**禁止打扰主人**，不确定就自主决策并如实标注」；
3. **判据**：`tests/test_autonomy.py`（4 组 10 条）—— 未声明允许问 / 两个例外放行 / 其余拒绝 /
   问句被改写 / 改写后不含问句 / 打扰留痕。

## 五、边界（如实）

- 契约**不代替**危险能力与转账的门：它们仍然要票（这是仅有的两个例外）；
- `guard` 是**文本级改写**，不是"阻止模型思考"——模型仍可能自己想到要问，但输出会被改写并记账；
- 账本只追加，不自动清理（审计资产）。
