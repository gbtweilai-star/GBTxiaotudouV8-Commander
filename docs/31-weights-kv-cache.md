# 31 · 我们权重的架构参数与 KV Cache 账（现读，不是抄的）

> 2026-10-28 立。主人给了一组讲 **MQA / GQA / MLA 省显存** 的截图，
> 问「我们的权重你有没有把这些整理清楚」。
> 本文所有数字都从 `weights5/gbt-v8-v82-q5_0.gguf` 的**元数据现读** + 公式现算，
> 不引用任何"大概""应该"。

---

## 一、我们权重的真实架构（GGUF 元数据现读）

```
general.architecture              qwen2
qwen2.block_count                 28        层数 L
qwen2.embedding_length            3584      隐藏维度
qwen2.attention.head_count        28        Q 头数
qwen2.attention.head_count_kv     4         KV 头数   ← 关键
qwen2.feed_forward_length         18944     FFN
qwen2.context_length              32768     原生上下文
qwen2.attention.layer_norm_rms_epsilon  1e-06
```

推导：

```
头维度 d_head = embedding / head_count = 3584 / 28 = 128
Q:KV 分组比   = 28 / 4 = 7          ⇒ 每 7 个 Q 头共用 1 份 K、V
注意力变体    = **GQA（Grouped Query Attention）**，不是 MHA，也不是 MLA
```

`Q4_0` 与 `Q5_0` 的架构参数**逐项相同** —— 量化只动数值精度，不动形状。

---

## 二、按截图那条公式算 KV Cache

公式（截图原样）：

```
Bytes = 2 × 2 × L × n_kv × d_head        （再 × 上下文长度）
         │   │   │    │      │
         │   │   │    │      └ 头维度 128
         │   │   │    └ KV 头数（GQA=4，MHA=28）
         │   │   └ 层数 28
         │   └ 每元素 2 字节（BF16/FP16）
         └ K 和 V 各一份
```

**每 token：**

```
MHA（n_kv=28）  2×2×28×28×128 = 401,408 B = 392.0 KB
GQA（n_kv= 4）  2×2×28× 4×128 =  57,344 B =  56.0 KB
                                        ⇒ GQA 省 7.0×
```

**按上下文长度：**

| 上下文 | MHA(28KV) | **GQA(4KV)** | GQA-FP8 | GQA 省 |
|---:|---:|---:|---:|---:|
| 4,096 | 1,568 MB | **224 MB** | 112 MB | 7.0× |
| 8,192 | 3,136 MB | **448 MB** | 224 MB | 7.0× |
| 32,768 | 12,544 MB | **1,792 MB** | 896 MB | 7.0× |

> 注：截图里的例子是 80 层 / 64 KV 头 / 128 维（那是更大的模型）；
> 我们是 28 层 / 4 KV 头 / 128 维 —— 同样一条公式，代入我们的数。

## 四、为什么手机只跑 ctx=4096（把账算到一起）

```
Q5_0 权重            4.88 GB
GQA KV @ 4096         0.22 GB
运行时/图/临时         约 0.3 GB
─────────────────────────────
合计                 约 5.40 GB
```

**iOS 单 App 拿不到 11.42 GB 整机的额度**（实测 `app_memory` 只有 0.58 GB 级别，
iSH 容器另算），LM Pocket 实跑就落在 **ctx=4096** —— 这不是参数没调，是装不下。

**原生上下文是 32768**，但那个上下文光 KV 就要 **1,792 MB**，加上权重 4.88 GB = 6.67 GB，
**手机侧没有这条路径。**

---

## 五、这条账指向的三件事

**① 我们的权重已经是省显存的架构（GQA 7:1）**
如果它是 MHA，光 ctx=4096 的 KV 就要 1,568 MB —— 根本跑不起来。
**能上手机，靠的就是 head_count_kv=4 这一个数。**

**② 再想省，只剩三条路（按代价）**

| 做法 | 省多少 | 代价 |
|---|---|---|
| KV 用 FP8 | ÷2 | 要引擎支持；LM Pocket 未必给 |
| 降上下文（4096→2048） | ÷2 | 记不住更长的对话 —— **用环形上下文补**（见 docs/17） |
| 换 MLA | 更狠 | **要改模型结构，我们的权重不是 MLA，做不到** |

**③ 无限上下文的正确答案在我们这边，不在模型那边**
模型的 KV 是有限的（ctx 卡在 4096），所以**长对话不能靠模型记**：
`ring_context` 把窗口钉死在预算内、溢出的逐条落库、要查秒回（docs/17 §四十八）。
**这是用工程补硬件的账，而不是假装 ctx 是无限的。**

## 七、主人提的「把头换成触手」—— 逐条定论（2026-10-28）

主人原话：

> 「如果把这些头换成触手不就可以实现极限压缩显存精准直达了吗」

### 7.1 这个思路框架里已经蒸馏过了（不是新想法，是对的方向）

`offload_distill` 的 `op=map` 原文（蒸自 Edge0-AI/Edge0）：

| 上游机制 | 我们的触手语言 |
|---|---|
| mmap 懒读 | 触手**按需伸手**，不预占 |
| 固定 slot + LRU | 触手手上的**停车位**与**肌肉记忆** |
| prerouter 预判 | 触手的**预判神经** |
| IO 与前向重叠 | 一根触手取、另一根算，**不等** |
| Recover-LoRA | 一套底座 + **多套岗位技能** |

**「按需伸手 + 预判 + 并行」就是主人说的「极限压缩 + 精准直达」。方向一致。**

### 7.2 但有两条边界，是框架自己写死的

`offload_distill.where` 的 `hard_rules` 原文：

```
· 边界不许说反：本机 = Windows/AMD + torch CPU；上游 Python 路线绑 MLX ⇒ 跑不了那条
· **我们是 7B dense，不是 MoE**：它的 prerouter 预测的是「专家路由」，
  搬到我们身上要退化成「按层顺序预取」，收益远小于 MoE —— 这条必须说清
```

**⇒ 预判这一条在我们身上打折。** 不装作没这回事。

### 7.3 三段拆开看：哪一段真能触手化

| 段 | 现状 | 能不能触手化 |
|---|---|---|
| **权重** | **已经是 mmap 懒读**（llama.cpp 默认）—— 5.24 GB 的 GGUF 能上手机，靠的就是它 | **已经在做，无需再改** |
| **KV 张量** | 在 LM Pocket 引擎内部；`:1234` 只暴露 OpenAI 兼容的 chat 面，**没有 /props /slots / KV 控制** | 🔴 **插不进去**（黑盒） |
| **头数（n_kv=4）** | 权重里**固定**，改它等于改模型结构 = 重训 | 🔴 做不到 |

**关键区分：**

- **「把 K/V 存到哪儿」可以按触手组织** —— 但那要引擎配合（llama.cpp 的
  `--cache-type-k/v` 量化、`--no-kv-offload` 搬回 CPU，LM Pocket 没给开关）
- **「把 K/V 头换成触手」改不了** —— `head_count_kv=4` 写在张量形状里，
  不是运行时能换的东西

### 7.4 我们真能做的等价物（而且已经做了）

既然 KV 插不进，就在**引擎外面做同构的事** —— 文本级分页：

```
ring_context   窗口钉死在预算内（等价于「固定停车位」）
              溢出逐条落 SQLite FTS5（等价于「离芯落盘」）
              recall 秒查（等价于「精准直达」）
context_vault  索引 + 检索层（正文不复制）
pulse_direct   resolve/audit —— 量「一步命中率」，越直越好
```

**这是我们能拿出的「触手化 KV」：分页、离芯、直达，一个不少 ——
只不过分页的单位是「消息」而不是「KV 张量」。**

### 7.5 要真做 KV 级触手，得付什么

```
① 自己写推理引擎（llama.cpp 那层）
   ⇒ 本机做不到：iSH 缺 FP16 指令（fcvt s22,h22 非法指令），早已实测
② 换能改 KV 的运行时（MLX / vLLM / MLC）
   ⇒ 本机装不了；而且 LM Pocket 是封闭 App
③ 重训一个 n_kv=1（MQA）的小模型
   ⇒ 那是训练，train_recipe 的 readiness 已经如实报：无 torch / 无 CUDA
```

**三条都堵死。所以「KV 头 → 触手」这一步，在我们的执行面上做不到 ——
但每一步的收益，我们已经在「消息级」拿到了。**
