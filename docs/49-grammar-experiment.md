# 49 · 约束解码实验：消灭"造名字"却换来"自信的错答案"（2026-11-01）

> 起因：判决层 204 项实测里 18 个 miss，**13 个是"模型自己造名字"**（如 `operate_on_thing`，不在候选里），
> 只有 5 个是近义误选。⇒ 主要矛盾是**格式**，不是判断。于是试了 llama.cpp 的原生 GBNF 约束解码。

---

## 一、怎么做

给 `commander.ask()` 加 `grammar` 参数（直接透传给 llama-server 的 `grammar` 字段），
`route()` 用候选名 + `none` 拼出文法：

```
root ::= "none" | "enter" | "press" | "tab" | …（本轮 12 个候选）
```

server 侧实测支持（单测：4 个候选 + 文法 → 返回 `press`，是候选内的名字）。

## 二、实测（同 4 条此前的失败用例，k=12）

| 意图 | 开文法后 | 期望 | 判读 |
|---|---|---|---|
| 回车确认键 | `action_gate` | `enter` | ✗ 错但合法 |
| 在输入框打字 | `type_to_field` | `type` | ≈ 近义 |
| 撤销上一步 | `pulse_direct` | `undo` | ✗ 错但合法 |
| 资产索引 查资产台账 | `asset_index` | `asset_index` | ✓ |

**代价**：单次耗时 **70–95 s**（关文法时 25–40 s）。

## 三、结论：**默认关闭**（`use_grammar=False`）

| 维度 | 开文法 | 关文法 |
|---|---|---|
| 无效输出（造名字） | **0** | 13/18 |
| 正确答案 | 1/4 | 0/4（都是无效输出） |
| 错但合法 | **3/4** | 0 |
| 单次耗时 | 70–95 s | 25–40 s |

开文法把"诚实失败"换成了"自信的错答案"——对路由是**更坏**的结果：
错名字会被真的执行，而失败至少还能落到词表辅路。按本仓铁律「宁可如实报错，绝不静默造假」：

> **默认走裸判决；文法能力保留在 `route(..., use_grammar=True)`，等配上信度门再谈默认。**

## 四、下一步该做什么（用读数决定，不拍脑袋）

要真正解决"造名字"，缺的不是文法而是**信度**：

1. `logprobs: true` + 取首 token 概率；
2. 候选概率 `< 阈值`（如 0.5）⇒ **判 none**（诚实拒绝），别硬选；
3. 只有在模型**真确定**时才走"直达"，否则退回词表辅路。

这条路能同时保住"格式合法"与"不装懂"。没做，是因为要先把 logprobs 的返回形状摸清
（llama-server 的 `top_logprobs` 与 OpenAI 形状有差异）——**下一步就做这个**。

## 五、代码落点

- `commander.ask(..., grammar=None)`：GBNF 透传（已在，默认不传）；
- `commander.route(..., use_grammar=False)`：默认关，理由与实测数字写在函数注释里；
- `none` 出口：即使开了文法，模型仍可输出 `none` 表示"候选里没有合适的"——不逼它硬选。
