# 权重操作纪律（2026-10-24 事故后立）

> 一次 `--allow-requantize` 直接跑在唯一一份 Q5_0 上，把源文件写坏了（sha256 不符），
> 之后模型输出 `能力西侧 autoFocus 3 pérdida dint`，全线停摆约两小时。

## 三条铁律

### 1. 动之前先记基线

```powershell
Get-FileHash state/weights/<file>.gguf -Algorithm SHA256
```

把哈希写进当天记录。任何「转换 / 量化 / 合并 / 重命名」之后**再算一次**，不一致就停。

### 2. 转换只对副本做

```powershell
Copy-Item <src>.gguf <src>.working.gguf
# 只对 working 副本跑 quantize
```

**唯一副本永不参与写操作。** 磁盘再紧，也不能省这一步 —— 4.9 GB 的复制比两小时的重下便宜得多。

### 3. 分片必须验完再删

| 步骤 | 要求 |
|---|---|
| 下载 | 逐片比对字节数（`part1..3 = 1,700,000,000`，`part4 = 143,397,568`） |
| 合并 | 顺序拼接，记录总字节 |
| 校验 | `sha256 == 983f19a6…cd262f` |
| 清理 | **只有校验通过才删分片** |

这次就是因为「先删后校验」，导致重下两轮。

## 附：两次误报的教训

- 第一次报「已恢复」，实际只合了 1.7 GB（分片被提前删）；
- 更早报「内存只占 423 MB」，那是刚加载未生成时的读数，真实热态是 4,663 MB。

**结论类的话，必须站在刚跑出来的读数上说，不能站在期待上说。**
