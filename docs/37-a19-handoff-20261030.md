# A19 与本机权重：今晚的实测结论与交接（2026-10-30）

## 一句话
**A19（她的 7.6B 权重）我起不来 —— 那个开关在 LM Pocket 的私有界面里。**
其余闭环全部打通并有铁证。

## 一、A19 为什么起不来（每条都是实测，不是推断）
```
:1234  127.0.0.1 / 192.168.1.148 / ::1  全 ConnectionRefused
拉起后 MemFree 1373 → 1113 MB（只少 260MB ⇒ 只是 UI 起来，5.24GB 权重没进内存）
apple-open lmpocket:// → opened=false（间歇；成功时也只把 App 拉到前台）
深链 11 变体、全端口扫、.gguf 关联、body_click(pyautogui,iOS无)、minis-debug(Release 被编译掉)、MCP(0 服务)
```

## 二、我做了什么让它"一通就全线接管"
```
Minis 模型组 GBT小土豆V8  →  A19 · gbt-v8-v82-q5_0（原来是死掉的云端）
桥 selfhost              →  base=127.0.0.1:1234/v1 · model=gbt-v8-v82-q5_0 · key=raw:gbt
model-chat               →  A19 不在时自动改走本机权重（900ms 探活），?local=0 可关
哨兵                     →  三地址每秒探；抓住即验 models → 拉身份 → drain 队列 → 落凭据
minis-scheduled          →  每 15 分钟自检 8 次，A19 一通就自动跑完
```

## 三、本机权重这条路：能跑，但当前 WebView 里不适合当聊天后端
```
worker.html（极简工人 · 长轮询 · 整机 GPU）
  实测：state=ready backend=gpu；单人任务 1s 内回包 77.02 tok/s
  但：忙轮询会把标签拖到 navigate 300s 无响应；后台又被 iOS 节流到不可用
  ⇒ ownweights 默认**不挂**降级链；要试：export GBT_LOCAL_WORKER=1
```
RPC 侧复验：A19 不通时 **0.74s 如实报错**（不再 180s 静默）。

## 四、需要主人做的一件事（唯一）
LM Pocket 里点 **Load & Start Server**，并把 API 密钥填**小写 `gbt`**。
之后 3 秒内：哨兵抓到 → 桥切 selfhost → 页面标「自有权重 · selfhost · 7.6B」。

## 五、环境现状（内存吃紧）
iSH 容器 MemFree 常年 150–250MB；`panel_server` 起来后被 OOM 杀过多次，
`:8765` / `:8792` 偶发掉线。守护 `svc_guard watch` 常驻，但验收跑动本身也会挤内存。
