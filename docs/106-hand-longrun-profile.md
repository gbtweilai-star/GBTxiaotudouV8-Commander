# 106 · 长跑定位：60 帧稳态正常，150 帧仍异常

> 目标：把“冷启动”和“稳态”分开，定位长跑退化。

## 一、60 帧 profile（10s 长视频前 60 帧）
| 指标 | 读数 |
|---|---|
| frames | 60 |
| 总耗时 | 2.37 s |
| fps | **25.3** |
| mean / median | 34.53 / 31.86 ms |
| p95 | **37.51 ms** |
| 第一帧 | 243.75 ms（冷启动） |
| RSS | 116.8 → **121.1 MB** |
| 线程数 | 66 → 66 |
| 分段 | first 38.17ms / middle 32.65ms / last 32.77ms |

结论：**前 60 帧没有明显退化**；首帧冷启动 244ms，之后稳定 ~32ms。

## 二、150 帧仍异常
- 之前 150 帧跑了 **674.99s**，infer mean 4416ms、p95 10371ms；
- 本次 150 帧 profile 超过 5 分钟仍未完成，已终止；
- 60 帧与 150 帧行为不一致，不是普通 warmup，是**长跑/资源问题**；
- 可能：OpenCV DNN 长跑内存/图缓存、系统调度、视频文件 loop 解码边界。

## 三、当前结论
- **短/60 帧稳态可用**：25.3fps、p95 37.5ms；
- **150 帧长跑不可信**：不能声称“长时间实时稳定”；
- 需要**分段/进程回收**，而不是继续无限长跑。

## 四、下一步
1. 每 60 帧重启一次推理（进程/模型回收），把长视频切成 chunk；
2. 记录每个 chunk 的 RSS/耗时，确认是否在 60 帧后恶化；
3. 若 chunk 稳定，长视频按 chunk 流水；
4. 摄像头真实流也按 chunk/看门狗回收。
