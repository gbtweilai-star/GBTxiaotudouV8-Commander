# 十二类心跳触手 · 运行手册

> 主人令 2026-10-30：「把所有原生能力以及操控部位分类好**必须严格分类好**，然后**每一个分类
> 部署一根心跳触手**来对分类内的一切进行**定点自检**和**状态返回给大脑执行层分析**，
> 再**返回执行指令**。」
> 追加令：「分类触手在自检的时候要懂得**清理垃圾**和**整理自身文件整洁不被其他东西混入**。」

---

## 一、五个闭环，各在哪里

| 环 | 从 | 到 | 落点 |
|---|---|---|---|
| ① 分类 | 349 条能力 / 30 domain | 12 大类 | `gbt_allinone/cap_taxonomy.py` |
| ② 自检 | 12 根触手 | 六层状态 | `gbt_allinone/heartbeat_tentacle.py` |
| ③ 上报 | 状态 | 落盘 | `state/heartbeat/tentacle-<类>.json` · `latest.json` |
| ④ 分析 | 状态 | 执行指令 | `brain_exec.advise()` |
| ⑤ 执行 | 指令 | 真动作 + 重新定级 | `brain_exec.act()`（CLI `--act` **与常驻循环每拍**都会调） |
| ⑥ 定时 | 时间 | 自动打一跳 | `tools/codex-scripts/monitor-loop.py`（每拍） |

## 三、六层定点自检

| 层 | 查什么 | 判红条件 |
|---|---|---|
| ① 登记 | 成员是否都在真源、条数与分类表现算一致 | 缺一条 |
| ② 分派 | 每条 handler 是否真在 `api.py` 分派表内（静态解析，三种写法都认：`kind ==` / `kind in (...)`） | 有漏 |
| ③ 策略 | 每条过 `policy.evaluate` | 抛异常 |
| ④ 探针 | 该类专属器官 | 探针报红 |
| ⑤ 漂移 | 与上一跳比成员进出与状态翻转 | 只报不判红 |
| ⑥ 卫生 | 垃圾 / 超额 / 外来混入 / 状态被写脏 | 混入与错位 |

### 分频深检（浅检每拍、深检每 N 拍）—— 不许"看着绿其实没测"

实测踩到的洞：自动链路（monitor-loop）原来**永远 light**，而「身」的器官探针是 full 档的
`body_map`（七感官六动作逐根回读）⇒ **全身扫描从来没在自动监控里跑过**，
而报告照样 12/12 绿（`probe.ok=None` 不参与判定）。**那就是"没测"的绿。**

现在：

| 项 | 值 |
|---|---|
| 浅检（`light`） | 每拍，约 0.7 秒（`_dispatch_kinds` 已缓存） |
| 深检（`full`） | 每 `DEEP_EVERY` 拍一次（默认 10 拍 ≈ 50 分钟），约 3.3~6.5 秒；**模块探针在这一档做真 import**（`find_spec` 只证在位、不证能起来） |
| 过期阈值 | `DEEP_MAX_AGE_S = 24h` —— 一天至少一次全身扫描 |
| 记账 | 报告里的 `deep: {last_full_at, age_s, ever, stale}`，CLI 直接带出来 |
| 从未/过期 | `never_deep_checked` / `deep_check_stale`（P2）→ 且**能自动补齐**（`act` 跑 full） |

⇒ 12/12 绿从此要配合 `deep.ever` 一起读：**没深检过的绿是"只有静态检查在绿"。**

### 两个必须记住的边界

1. **闭环⑤ 必须在常驻循环里真调 `act()`**
   踩过：monitor-loop 原来只 `advise()`，全仓没有一处自动调 `act()` ⇒
   "深检过期自动补""垃圾自动清"在真实运行里**根本不会发生**，只有人手跑 `heartbeat --act` 才生效。
   闭环⑤ 当时只是对着一个假的门关上了。现在每拍都 `act()`，并把 `acted=[做了什么]` 记进读数。

2. **缺字段 ≠ 从未深检**
   踩过：`heartbeat()` 的简报没带 `deep`，常驻循环把它递给 `act()` ⇒ `advise` 判"从未深检"
   ⇒ **每拍**补跑一次 full（实测每拍多 4~8 秒的 churn，而且看起来还挺勤快）。
   现在 `advise()` 只在 `deep` **确实给了** 时才判定；没给就如实说不知道，不替它编一个"从未"。

## 四、卫生层三条纪律（写死在常量里）

1. **只动自己的抽屉** —— 仅 `state/heartbeat/`，绝不伸到 `outputs/` `projects/` 或用户内容；
2. **外来物只报不删** —— 判定为"不是我们的东西"时一律不动；
3. **默认 dry-run** —— 加 `--clean` 才真删**垃圾**。删除是写面，得有人明确要。

⚠️ **一个例外，必须说清**：`scan-*.json` 的**环形保留是无条件的**（`_prune_scans`，`KEEP_SCANS=20`）。
它不是"清理"，是**缓冲区上限**——踩过：prune 原来只在 `--clean` 时跑，而定时链路从不传 clean
⇒ 扫描件无限增长（实测连跑 6 次 23→28 份；按 5 分钟一拍是 288 份/天）。

12 根共用一个抽屉 ⇒ **值日制**：都查都清（幂等），抽屉层面的问题只由值日那根（身）上报，
否则同一个外来文件会被报 12 遍、12 根全红。

**值日根是常量 `KEEPER = "身"`**，不靠字典顺序（原来写的是 `next(iter(CATEGORIES))`，
谁重排分类表就悄悄换人）。若它被改名/删掉：自动降级给第一个分类继续值日
（**监控不留空白**），同时报 `keeper_lost`（P0）——"谁在值日"这种变化不许悄悄发生。

**清单常驻**：`MANIFEST.json` 每跳都写（不是只有 `--clean` 才写），写明允许的文件、
豁免后缀、保留份数、当前值日根 —— "什么才算属于这个抽屉"要有书面依据。

**原子写**：所有状态件先落 `.swapping` 再 `os.replace`。并发（monitor-loop 一拍 + 人手一条
CLI）时读到的要么是旧完整版、要么是新完整版，**不会读到半截 JSON**（原来 `write_text` 是
截断再写，半截会让漂移层误判"首跳"且不报错）。`.swapping` 在卫生层**豁免**，
否则另一根触手会把正在写的那份当垃圾扫掉。

## 五、怎么用

```bash
# 打一跳并出执行指令（约 0.3 秒）
py -3.14 -X utf8 -m gbt_allinone heartbeat

# 全身扫描（七感官六动作逐根回读，约 6.5 秒）
py -3.14 -X utf8 -m gbt_allinone heartbeat --full

# 清自己抽屉里的垃圾与超额扫描
py -3.14 -X utf8 -m gbt_allinone heartbeat --clean

# 把可自动的指令真的执行掉（表外一律跳过并写明原因）
py -3.14 -X utf8 -m gbt_allinone heartbeat --act
py -3.14 -X utf8 -m gbt_allinone heartbeat --act --dry   # 只演练

# 读上次心跳 / 看分类总览
py -3.14 -X utf8 -m gbt_allinone heartbeat status
py -3.14 -X utf8 -m gbt_allinone heartbeat taxonomy

# 只打某一类
py -3.14 -X utf8 -m gbt_allinone.heartbeat_tentacle pulse 守

# 常驻（每拍含心跳，红了返回非零但循环不死）
py -3.14 -X utf8 tools/codex-scripts/monitor-loop.py --once
```

## 六、哪些能自动执行（`_AUTO_ACTIONS` 表，表外一律留给人）

唯一判据：**出错时只伤自己的抽屉**才配自动。

| 信号 | 自动动作 | 为什么可以 |
|---|---|---|
| `garbage_found` | 清心跳抽屉的垃圾与超额扫描 | 只删自己的 tmp/pyc/超额 |
| `state_flip` | 重打一跳复检 | 只读，无副作用 |
| `never_deep_checked` | 跑一次 full（全身扫描） | 只读，约 3.3~6.5 秒 |
| `deep_check_stale` | 同上 | 同上 |

**不自动**（要改代码或改分类表，自动改等于系统自己给自己签字）：
`registry_gap` · `dispatch_gap` · `policy_break` · `members_removed` · `taxonomy_broken` · `persist_failed`。

**全局根因只开一张单**：`persist_failed` / `dispatch_unreadable` / `taxonomy_broken` /
`keeper_lost` 的病根在共享那一层，12 根会各报一次。这几类按 `code` 去重，合成一条并带
`affected=[分类…]`，免得"一个磁盘写不进"被念成 12 个问题。

## 六半、与 `health()` 的分工（不许混成两个答案）
| 件 | 看什么 | 覆盖 |
|---|---|---|
| `brain_exec.health()` | 执行链五个面（路由/执行/触手/眼/审计） | **一条能力位都没看** |
| `brain_exec.heartbeat()` | 12 根分类触手 | **全部 349 条能力位** |

两者**不能互相替代**。现在 `health()` 的返回里带 `heartbeat` 摘要 + `stale_s`（多久前打的）
+ `scope_note`（分工说明），所以问"系统好不好"只有一个入口，不会得到两个答案。

**INFO 不进指令**：探针被档位跳过这类纯信息走 `notes`，`instructions` 里只有**能做的动作**。
（踩过：INFO 曾被塞成 P2 指令且不带 `signal_code`，每跳多一条不可追溯的噪音。）

## 八、这个系统**没有**做什么（说清楚，别当它有）

1. **没有注册成能力位** —— `heartbeat_tentacle` 不在 `caps_registry.BENIGN_CAPS` 里，
   所以 `run_task("heartbeat_tentacle", {})` 会报 unknown capability，前端页面也列不出它。
   原因：`caps_registry.py` 是 3139 行静态大表、无追加机制，改它要通读全文（G7 规则锁），
   且会把已对齐的 349 打乱、牵动 `data/capabilities.json` / `docs/capabilities-full.json`
   与公开仓。**这是唯一还开着的环**，要注册得单独排一次。
2. **不会自己改代码** —— `act()` 只做表内的两个安全动作，P0 类一律留给人。
3. **不监控别人的东西** —— 卫生层只在 `state/heartbeat/` 里动，别处一概不碰。

## 九、「域」有四种粒度 —— 一个词、四个数，别再混（2026-10-30 深度对齐）

**起因**：主人令「继续深度对齐推进」。一查发现**同一句"我有几个域"，仓里四个数，而且同一份文件里前后矛盾**。

| 说法 | 真源 | 现读数 | 它到底指什么 |
|---|---|---|---|
| **域段** | `omni_tentacle.py::TENTACLE_MANIFEST` 的 `### 名字(N):` 小节 | **10**（9 小节 + 听觉段） | 她自己的能力总纲分段；`tentacle_manifest` 吐的就是它 |
| **邻域** | `tentacle/bridge.py::TENTACLE_NEIGHBORHOOD_MAP` | **13** | 意图路由图（哪个词打到哪根手指） |
| **能力大类** | `cap_taxonomy.py::CATEGORIES` | **12** | 349 个能力位归类（身/感/知/言/造/工/察/守/调/数/群/进） |
| **绑定台账** | `state/cap-bindings.json::tentacle_domains` | **10** | 三边绑定里的域段列（解析自域段，所以跟域段同数） |

### 修掉的四处自相矛盾（都是"写的时候对、后来忘了改"）

1. **`TENTACLE_MANIFEST` 标题写 `(8域)`，正文实有 10 域** —— 她给自己写的说明书，第一行就数错了自己。
   连带 `AGENTS.md`（开工必读）与 `welcome.py`（自我介绍）都抄了这个「十域」。
2. **`### 点击(15)` 后面实列 16 条**、**`### 窗口等待监控(19)` 后面实列 20 条**。
3. **缺口清单写「听觉：没有」，而正文上方明明写着「`audio_loopback` 已实测通」** ——
   一行假缺口足够让她**拒绝做本来会做的事**，比不写更坏。
4. **`welcome.py` 写死「十域触手」** —— 挑了四个数里的一个当真、另三个当不存在。

### 怎么修的（不手改数字，改成现算）

- `_sync_manifest_counts()`：每个 `### 名字(N):` 的 N 按**实列条目**重算（`task_guide_*(6)` 这类聚合缩写按 6 计）。
- `_sync_manifest_title()`：标题 `(N域)` = `###` 小节数，与正文「第 N 域」的最大 N **取大者**（听觉不占小节，靠它补）。
- `AGENTS.md` / `welcome.py`：**去掉数字**，写「数见真源」。
- 新铁律 **H11 · 自我描述自洽**（`iron-rules-check.py` rule13）：源码字面量**独立重算** ↔ 运行时读数**必须相等**。
  ⚠️ 关键在"独立"：如果调被测函数算出期望值，那是自己判自己，**永远绿 = 没写**。
- 负控：`tools/codex-scripts/iron-rules-negctl.py` 三路喂故障（停掉现算回填 / 自我介绍写死 / 启动页漂移）必须判红，跑完自动还原。

> 负控当场咬出一个假判据：rule13 最初用 `from gbt_allinone.welcome import WELCOME` 读自我介绍，
> **喂进"十域触手"它照样绿** —— 因为模块缓存里还是老值，改磁盘不影响它。改成直接解析源文件
