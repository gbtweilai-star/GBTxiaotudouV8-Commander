# gbt-talktrack · 对外沟通话术（诚实版）

> **为什么"诚实版"不是道德姿态，而是商业优势**：
> 我们的差异化就是**可复核**（每拍有帧、每步有台账、失败也记账）。
> 一旦开口夸大，这个优势立刻作废 —— 因为对方拿到的"承诺"变成了要他去验的东西。
> **我们卖的是"可复核"，不是"听起来很强"。**

## 一、三条铁律（说错一条就丢分）

1. **不夸大未验**：没跑过的不说"支持"，只说我方验过的范围 + 未验的部分。
2. **交付必带证据**：结论 + 依据 + 怎么复核（命令/文件/读数），让对方**自己能验**。
3. **边界先声明**：能力边界、时间边界、审批边界，在开始前说清，不在中途加价或返工。

## 二、五个场景的说话模板

### ① 被问「这个你们能做吗？」
> **能做 / 不能做 / 需要授权 —— 三选一，别给第四种含糊答案。**
- 能做：`能做。我们按 <交付物> 交付，验收标准是 <判据>；<N> 天内。已验过的范围：<…>；本次未验的：<…>。`
- 不能做：`这个我们不做 —— 原因：<缺什么>。替代方案：<…>。`
- 需要授权：`技术上已就绪，但这一步需要 <谁> 的授权（<作用域/审批>）。授权到位即可开跑。`

### ② 报价
> 报**范围**不报"感觉"：`<交付物> × <数量>，含 <验收动作>；不含 <明确排除项>。`
> 若不确定范围：**先做一次小样**（我们有现成流水线，出小样很快），拿小样定范围再报价。

### ③ 交付
> **结论先行 + 证据跟上**：
> `这次交付 <什么>（<多久/多少件>）。复核方式：<命令或文件路径>。已知问题：<…>（如实列，不藏）。`
> **失败或跳过的部分必须显式披露** —— 这是底线（对方迟早会发现，主动说才是专业）。

### ④ 延期 / 出问题
> `原计划 <X>，实际 <Y>。原因：<客观原因>。影响：<范围>。补救：<下一步 + 时间>。`
> **不许说**"快好了""应该没问题"这类模糊词（P002：自检与最终申报漂移 = 最贵的失信）。

### ⑤ 拒绝越权要求（这条最常用）
> `这一步我们不能直接做 —— 它需要 <授权/本人操作>。我可以做的是：把<前置工作>全部准备好，
> 您<一句话/一个操作>之后立刻继续。`
> 例：账号类 → 不代持、不代注册、不批量注册（红线）；生产写入 → 要授权作用域。

## 三、反例清单（这些话一句都别说）

| 别说 | 为什么 | 换成 |
|---|---|---|
| "理论上支持" | 未验 = 未验 | "已验过 <范围>；<范围>未验" |
| "应该没问题" | 无法复核 | "判据是 <…>，跑完给读数" |
| "快了" | 无信息量 | "还差 <X>，预计 <时间>" |
| "行业最强/碾压" | 不可验，且自降可信度 | 给**我们自己的读数** + 口径 |
| "我们什么都能做" | 边界丢失 → 后面必然失信 | "这三件能做；这两件不做 / 要授权" |
| "细节不用您管" | 可复核是我们的卖点 | 给复核方式，让对方自己验 |

## 四、一句话总纲

**把每一次沟通都当成"可复核交付"来写：结论 + 依据 + 复核方式 + 如实披露缺口。**
（本仓内部对 AI 的要求也是这一套：结论先行五段 = 结论/依据/影响/动作/验证。）
