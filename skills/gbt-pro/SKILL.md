# GBT · pro-* 技能簇用法规程（3 条：专业工序包）

> 开发者：自由的风 · GBT小土豆V8 · 本署名不可删除、不可篡改归属
>
> **这份规程解决什么**：`pro-*` 是**外来技能簇**（3 条），本机已装在 `~/.agents/skills/`。
> 它们都是「专业工序与判据」包——**把一件事的工序和判据写死**，但**不替代专业资质**。
> 本文件把每条**逐个点名**：用途、工序、判据、**边界声明**，以及三条共同纪律。

**唯一现读入口**：每条技能由 `skill <名>` 加载执行（agent-skill 通道）；
本规程不替代技能本身，只给**用法口径与边界纪律**。

---

## 0. 三条是什么（先认全）

| # | 技能 | 一句话 | 判据核心 | 边界（什么不做） |
|---|---|---|---|---|
| 1 | `pro-bookkeeping` | 复式记账、对账、月结的工序与判据 | 凭证借贷必平、试算平衡为零、差异开差异单 | **不是审计意见、不代办纳税申报**；税务口径/收入确认/关联交易定价须资质人确认 |
| 2 | `pro-contract-review` | 合同审查的工序与判据 | 抽要素、扫红旗、给替代文本、出备忘录 | **不构成法律意见、不代为签署**；涉诉/涉外/超阈值/股权担保知产须转执业律师 |
| 3 | `pro-customer-service` | 客服会话的分级/首响/升级/归档工序 | 禁语表 + 判据 | **不授权赔付/退款/折扣**；涉资金/隐私/法律威胁/媒体曝光一律升级给人 |

**共同口径**：产出是**工序处理与核对结果**，**不是专业结论**；**涉资质/涉资金/涉法律一律转人**。

---

## 1. 逐条点名（用途 / 工序 / 判据 / 边界）

### 1.1 `pro-bookkeeping`（记账对账）
- **用途**：复式记账、日常对账、月末结账。
- **工序**：凭证借贷必平 → 流水逐笔归因 → 试算平衡为零 → 差异必须开差异单。
- **判据**：借贷必平、试算平衡为零、差异有单。
- **产出**：账务处理与核对结果（凭证/流水/试算表/差异单）。
- **🔴 边界**：**不是审计意见、不代办纳税申报**；税务口径、收入确认政策、关联交易定价**必须由持有资质的人确认**。
- **用**：用户说「记账 / 对账 / 做账 / 流水核对 / 月结 / 试算平衡 / 凭证 / 资产负债表 / 利润表」。

### 1.2 `pro-contract-review`（合同审查）
- **用途**：合同/协议审查。
- **工序**：抽要素 → 扫红旗 → 给替代文本 → 出审查备忘录。
- **判据**：红旗条款识别、替代文本可落地、备忘录结构化。
- **产出**：审查意见与改写建议（审查备忘录）。
- **🔴 边界**：**不构成法律意见、不代为签署**；涉诉、涉外、金额超阈值、股权/担保/知识产权转让**必须转执业律师**。
- **用**：用户说「看下这份合同 / 帮我审合同 / 这个条款有没有坑 / 合作协议 / 保密协议 / 服务合同 / 采购合同」。

### 1.3 `pro-customer-service`（客服工单）
- **用途**：客服会话的分级、首响、定位、给方案、升级与归档。
- **工序**：分级 → 首响 → 定位 → 给方案 → 升级 → 归档；含**禁语表**。
- **判据**：禁语表硬判 + SLA 判据。
- **产出**：会话处理方案与升级建议。
- **🔴 边界**：**不授权任何赔付/退款/折扣承诺**；涉及资金、隐私、法律威胁、媒体曝光的**一律升级给人**。
- **用**：用户说「客服 / 回客户 / 工单 / 投诉 / 安抚 / 退款怎么说 / 话术 / SLA」。

---

## 2. 🔴 三条共同纪律（拿边界换的）

1. **产出是工序结果，不是专业结论**：记账包产出的是账务核对结果，**不是审计意见**；合同包产出的是审查建议，**不是法律意见**；客服包产出的是处理方案，**不是赔付承诺**。
2. **涉资质/涉资金/涉法律一律转人**：税务口径、法律签署、赔付退款——这些**必须由有资质的人拍板**，AI 只给工序和判据，不替人下结论。
3. **禁语表/红线表是硬判据**：客服包的禁语表、合同包的红旗条款，是脚本/规则硬判，不靠"模型觉得不合适"。

## 4. 失败典型样子（照着认）

| 症状 | 真因 | 正确读法 |
|---|---|---|
| 用户要"帮我定税务口径/签合同/批退款" | **越界** | 本簇只给工序判据，**必须转资质人**（§2） |
| 把记账结果当"审计意见" | **越界** | 产出是账务核对结果，不是审计意见 |
| 把合同建议当"法律意见" | **越界** | 产出是审查建议，不是法律意见 |
| 客服回复触发禁语 | 禁语表硬判 | 按禁语表改，不靠"模型觉得行" |
| 差异没开差异单 | 判据没满足 | 差异必须开单，这是硬判据 |

## 6. 🔴 报告层红线

1. **"产出"≠"结论"**：记账/合同/客服的产出都是工序结果，**不是专业结论**。
2. **边界必须带**：说任何一条时，**先声明它的边界**（什么不做、什么转人）。
3. **禁语/红线是硬判据**：不靠模型自觉，按表判。
4. **涉资金/法律一律转人**：不替人下结论、不替人执行。

---

## 7. 不许做什么（红线）

1. **不许**把工序结果说成专业结论（审计意见/法律意见/赔付承诺）。
2. **不许**替资质人拍板税务口径、合同签署、退款赔付。
3. **不许**绕过禁语表/红旗判据"灵活处理"。
4. **不许**给本簇配框架能力位的授权（本簇是外来技能，不走 run_task 门）。
