# gbt-selfgrowth · 自生长知识库（我们自己的落位）

> **来源与口径（先说清，本仓规矩：凡抓取必写口径）**
> · 来源：主人 2026-09-27 现场拍摄的演示稿 8 张（26–32 页 + 封面），标题
>   「基于 Codex + Google WikiSkill 搭建个人自生长知识库 4.0 · CODEX 管理 · AGENT EXPERIENCE COMPILATION」。
> · 口径：**二手资料（演示稿图片）**，不是一手论文/产品文档。演示稿自己也写了这句：
>   「WikiSkill 架构与论文数据来自本地二手资料整理；**公开发布前，论文细节和产品现状仍应回到一手来源复核**」。
>   ⇒ 本技能**只承接方法论骨架**，不复述具体论文结论、不引用未亲验的数字。
> · 该稿的实验边界也一并承接下来（见 §5）：**它证明"门控能发现退化"，不证明"所有 Skill 都会变好"**。

## 1. 一句话内核

**不是让 Agent 自动记住一切，而是让知识与能力都拥有「来源 · 验证 · 版本 · 回滚」。**

三条复利循环（缺一条就退化成"自动记一堆没出处的东西"）：

| 循环 | 路径 | 复利什么 |
|---|---|---|
| 知识复利 | `Raw → Wiki` | 外部真实来源 → 可链接、可修订、可追溯的概念知识 |
| 能力复利 | `Trace → Pattern → Skill` | 执行迹 → 成功要素/失败模式 → 约束下一次行动的 Skill |
| 可信进化 | `Validate → Accept / Rollback` | 候选能力经**门控**才准入；退化可**回滚** |

一句话记住：**让成功经验可以复用，让失败经验不会白费，也让错误经验没有资格被永久记住。**

## 2. 三个必须分清的边界（这是整套方法的地基）

| 判据 | 含义 | 反例（混淆了就全塌） |
|---|---|---|
| **Raw ≠ Trace** | Raw 是**外部真实来源**（不改写）；Trace 是 **agent 的执行迹** | 把"我做过"当成"世界上是这样" |
| **Wiki ≠ Skill** | Wiki **解释世界**；Skill **约束下一次行动** | 把百科条目当操作手册用 |
| **PURPOSE 必须存在** | 每条 Skill 的说明都要能**密封回它自己的 Pattern** | 没有出处的能力 = 无法验证、无法回滚 |

## 3. 最小可用目录（生命周期先分开，再谈自动化编排）

```
raw/                 # 外部来源，不改写
sources/wiki/        # 概念知识（可链接可修订）+ index.md
trace/logs/          # 完整任务轨迹 + trace.md
patterns/            # success.md（成功要素）· failure.md（失败模式）
skills/              # 候选 Skill：提案 → 门控 → 候选（SKILL.md, skill-1.md…）
knowledge-index/     # index.md（结论都能回到来源）
governance/          # purpose.md + protocol.md（Accept / Reject）
outputs/  runtime/   # 产物 与 运行时
```

> 目的不是好看：**让任何结论都能回到来源，让任何能力变更都能找到提案、分数与回滚记录。**

## 4. 本仓没有的机器吗？没有 —— 一一对位（这是本技能真正的价值）

| 4.0 组件 | 本仓已有的对应物（可直接用，不必新建） |
|---|---|
| `Raw`（外部来源，不改写） | `_upstream/`（第三方参考，永不入史）· 探针工作区 `04-调研/` + 抓取台账（源/时间/口径） |
| `sources/wiki` | `docs/` · `memory/*.md` · `store/devoured/`（知识胶囊）· 大脑 vault |
| `trace`（执行迹） | **`state/*.jsonl` 全是执行迹**：`asset_bindings` · `cross_scan_trace` · `dag_runs` · `fleet` · `work_log` · `store/audit.jsonl` |
| `patterns/success.md` | 判据库（23 条常设判据）· `state/full_scan.json` 的分诊表（哪些类命中是预期的） |
| `patterns/failure.md` | **`store/pit_log.json` 坑册**（root_cause + lesson + 防复发锁）· `memory/2026-09-22-假绿与自伤清单.md` |
| `skills/`（提案→门控→候选） | `skills/gbt-*`（79 个）· **源↔装唯一真相 + 哈希锁**（`tools/skills_sync.py`，覆盖前先备份） |

| `知识索引` | `state/skill_atlas.json` + `caps_registry.BENIGN_CAPS`（185 位 × 30 域） |
| **验证门控 Validate** | 三板块总监令 · 交付前主检查清单 · `test_*` 常设判据 · **反向自检**（故意造缺陷看它红不红） |
| **回滚 Rollback** | `.backups/`（skills-hub 覆盖前留档）· `.trash/`（只移不删）· DAG 检查点 · `git worktree reap` |
| **生产/实验隔离** | **镜像多维度是唯一试验场**（生产零修改、一次性晋升）· 舰队 `git worktree` 每根一份隔离工作区 |

**结论**：4.0 的方法论我们**七成已经在跑**，缺的是把它**显式成一条闭环判据**（见 §6 的三步落地）。

## 5. 适用边界（照抄它的诚实，也照抄我们自己的）

**适合先做**：高频重复、**结果可检查**的知识工作；已有可鉴定的基线（baseline）与历史轨迹；
错误成本可由隔离环境承受；能明确划分"训练/测试"。

**不要直接自动化**：样本极小、目标持续变化的任务；评价标准是**价值判断**或需偏好；涉及
**账务 · 资金 · 客户 · 不可逆操作**；**没有沙箱、没有回滚能力**的系统。
（最后两条本仓是硬红线：动生产面要授权、破坏性操作要主人点头。）

**它不能证明什么（原样承接）**：它证明"门控能发现退化"，**不证明**"所有 Skill 都会变好"；
一个模型、两项验证任务、小样本 ⇒ 结论**不许外推**到所有工作流/模型/数据规模。

## 6. 我们怎么落地（三步，每步都有可机检产物）

1. **先立基线**：给要进化的那条线定"做完的样子"+ 评分表（我们的说法：**判据先行**）。
   · 产物：一条常设判据（`gbt_allinone/tests/test_*.py`）——**能红才算数**。
2. **再开轨迹**：让每次执行都往 `state/*.jsonl` 留执行迹（**无痕即未发生**已在跑），
   并把"成功要素/失败模式"提炼进坑册与判据。
3. **后开门控**：候选 Skill 只能走 **提案 → 门控 → 候选 → 人工实施**；
   门控 = 判据全绿 + 反向自检过 + 覆盖矩阵无死角；回滚 = `.backups/` + `git`。
   · 命令：`python tools/skills_sync.py check`（源↔装不许分叉）·
     `python tools/coverage_matrix.py sweep`（无死角）·
     `python tools/selfgrowth.py check <候选技能目录>`（四判据机检，见 §7）。

## 7. 四判据的机检（`tools/selfgrowth.py`）

```
python tools/selfgrowth.py init <目录>          # 建最小可用目录 + 四判据模板（只建不删）
python tools/selfgrowth.py check <候选技能目录>   # 机检：Raw≠Trace · Wiki≠Skill · PURPOSE 在 · 隔离在
python tools/selfgrowth.py promote <候选> <目标>  # 门控通过才准入；准入前**先备份**（=可回滚）
```

**四判据怎么机检（不靠感觉）**：
1. **Raw≠Trace**：`raw/` 里不许出现带执行迹特征的文件（时间戳流水、exit code、"本次"字样）；
   执行迹只许在 `trace/`。
2. **Wiki≠Skill**：`sources/wiki/**` 不许被 `skills/` 直接引用为操作步骤（反向也要查）——
   两类文件的引用关系必须显式（`PURPOSE.md` 里写清"我这套动作来自哪条 Pattern"）。
3. **PURPOSE 密封**：每个候选 `SKILL.md` 必须含 `PURPOSE:` 段，且段内指到 **同名 Pattern 文件**。
4. **隔离**：候选不许直接落在生产目录（`skills/` 真身）；必须从 `skills/_candidates/` 走门控。

## 8. 实验骨架（演示稿 19–25 页 · 这段是"为什么不能让 Skill 凭感觉上线"的证据）

**① 可归因原则（19 页）**：初始知识库 · 任务 · 模型 · 权限全相同，**Baseline 与 Candidate 的唯一
设计差异**只能是那个 Skill —— 否则差异归因不到 Skill 头上。它还做了一件我们该学的：
把**测试任务封存**（`filetrash`），**Candidate 过验证才解锁**；任务矩阵 `task-matrix.csv` 记分组来源与 sealed 状态。

**② 训练阶段不许直接改 Skill（21 页）**：五次任务反复暴露的**真正值得沉淀**的问题，必须是
"**能回到具体 Run 和实际文件**"的 Pattern，**不是"模型应该更仔细"这种泛泛建议**。两条真实 Pattern：
- **P001 输入到证据链未兑现**：新 Raw 已建，但 Wiki 的 Sources / 规范 Raw 字段 / 索引 / 日志**没有全部同步**；
  → 可操作修复：`Published → Raw → Wiki → Sources → Raw link → index → log` 一条链逐环对账。
- **P002 自检与最终申报漂移**：检查失败或只验了部分字段，**最终回复仍写成"全部通过"**。
  → 可操作修复：**最终报告只能引用"真实返回通过"的检查；失败 · 跳过 · 未知必须显式披露**。

> **P002 就是我们的"假绿"**（本仓原话：假绿比错更贵）—— 两边独立收敛到同一条戒律。
> 这条对我们**直接可用**：任何"自检通过"的结论，只许引用真跑过且返回通过的那几项。

**③ 一次只加一个原子门（22 页）**：候选人只新增**一个**完成门（"每个输入都必须完成来源链对账"），
不改主题路由；候选状态**先放实验目录，不装进正式 Skills**。

**④ 它是怎么被否决的（23–25 页）—— 这一段最值得记**：
Candidate **更快更收敛**（平均耗时 176.38s → 139.95s = **−20.7%**，命令数 10.0 → 7.0 = **−30%**），
但**平均质量分 −8.0**（87.5 → 79.5）⇒ **REJECT**。原因：它**伤害了最不能伤害的**——
- **压缩掉了 Raw 证据**（输入约 24,002 规范字符 → Candidate Raw 只剩约 594 字符；"大意还在，原始证据不可回复"）；
- **把命令回显写进了 Raw**（Agent 已看见污染并尝试修复，最终文件仍残留工具输出，**而最终报告没有披露**）。

⇒ **局部规则变好，不代表系统质量变好**；"看起来成功"必须让位给"来源完整"。

**⑤ 失败了怎么算不浪费（25 页）**：候选 Skill **回滚**（不进正式 Skills、不改原版生产任务、
测试保持封存），但**保留**完整轨迹 · 两条 Pattern · 验证分数 · 失败证据 · 下一版改进方向，
全部写进 `skill-impact` 作为下一轮提案的输入。原话：**"Skill 可以回滚，经验记录不能回滚。
这一规，系统才真正开始『从失败中进化』。"**

## 9. 我们的常设规矩（主人令 2026-09-27 · 已落成判据，不靠记性）

> **新增能力必须与触手双向绑定；触手随时可用不断连；没实现也必须有名有姓有记录；
> 全框架状态必须随时可感知。**

落在四处（缺一处就是没落地）：
| 落点 | 是什么 |
|---|---|
| `tools/framework_state.py` | **全状态一屏**：能力位 / 双向绑定 / 技能源装 / 覆盖矩阵 / 视觉面 / 舰队 —— 全读盘现算，坏文件不许静默当空 |
| `state/unimplemented.json` | **未实现登记处**：任何"有名字没东西"的必须记 where/missing/reason/**who_can_fix**/evidence |
| `gbt_allinone/tests/test_cap_bind_bidirectional.py` | 判据（已挂开机自检）：三处齐 · 双向通 · 缺口必须登记 · 六面可读 |
| `boot-selfcheck` 「新增能力双向绑定」 | 开机就红 —— **口号不会自己红，判据会** |

反向自检（不咬人的判据等于没有，两路都验过）：登记表损坏 ⇒ 红；塞一个没接线也没登记的
假能力位 ⇒ 立刻报「未登记缺口: ['zz_fake_cap']」。

## 10. 三段隔离与三层责任（演示稿 08–12 页 · 这一节补上"谁负责什么"）

**① 三层不是三个文件夹，是三种证据责任（09 页）**：`Raw 记录发生了什么 · Wiki 解释为什么 ·
Skill 规定下次怎么做`。把事实、解释和执行规则混在一起，**失败就无法追溯**；分开才能知道
"某条规则来自哪次经验、经过了什么验证"。

| 层 | 性质（原文） | 我们的对应物 |
|---|---|---|
| Raw | **IMMUTABLE TRACE**：一次写入，**不事后见之明改写** | `state/*.jsonl` 追加式台账 · `store/audit.jsonl` |
| Wiki | **PERSISTENT KNOWLEDGE**：Pattern / logs / skill-impact | `docs/` · 坑册 `store/pit_log.json` · 本技能 |
| Skills | **EXECUTABLE + REVERSIBLE**：候选必须过验证，**可以回滚** | `skills/gbt-*` + `skills_sync`（覆盖前备份 = 可回滚） |

> **最关键的非对称性（原文）**：**Wiki 永不因提案失败而回滚；Skill 必须能够回滚。**
> ⇒ 我们的落法：坑册与 `docs/` **只增不删**（失败也留），`skills/` 必须**能回滚**（`.backups/` + git）。

**② 三段隔离（11 页）—— 这条我们此前**不合规**，已立封存集**：

| 阶段 | 可以做什么 | **不能做什么** | 产物 |
|---|---|---|---|
| Train | 分析轨迹、形成 Pattern、提出**一个原子**改动 | **不能把训练样本答案写进 Skill** | 候选 Skill |
| Validation | Baseline / Candidate **成对比较** | 不能根据验证任务继续改候选 | 接受或拒绝 |
| Test | 评估通过版本的**未见任务** | **验证未通过时不得解锁** | 最终泛化证据 |

> 原文："训练任务负责提出假设，验证任务负责反驳假设，**最终测试只对通过门控的版本开放**。
> 三者混用，Agent 就可能**记住答案**，而不是学会方法。"
>
> **我们的诚实自查**：本仓判据（`gbt_allinone/tests/test_*`）此前**既当训练反馈又当验收** ——
> 正是"三者混用"。已立 `state/holdout.json`（**封存集**，只增不删）：封存项**只在晋升/发布时跑**，
> 日常迭代不许拿它们的结果当"再调一版"的反馈；`tools/selfgrowth.py check` 现在把"封存集存在且非空"
> 作为**判据 5**（缺了或空了一律红）。

**③ 六个角色分工（08 页）**：**执行者 / 知识编译器 / Skill 提案者 / 质量门卫**分工协作 ——
一版进化**不是**一次改 Prompt；关键是让每次改动**都有来源、有验证、有撤销路径**。
循环：`① 执行者产出轨迹 → ② Raw 一次写入（保留真实步骤/工具输出/错误）→ ③ 知识编译器提炼
成功策略与失败模式并留证 → ④ 提案者读 Pattern，只提一个原子改动 → ⑤ 质量门卫在**未训练任务**上
与 Baseline 成对比较 → ⑥ Accept / Rollback`。中心四个字：**持续进化但不失控**。

**④ 执行挂具的位置（12 页）**：`Codex 提供本地文件、工具调用、任务执行与验证环境；
WikiSkill 给出经验进化机制；**人仍然负责方向、红线与最终放行**。`
⇒ 我们的落法完全同形：**`run_task` 是执行挂具**（本地文件/工具/验证），**本技能是进化机制**，
**主人管方向、红线与放行**。

**⑤ 失败要产生复利，必须过四道（10 页）**：它原话 ——
**"失败不是自动有价值。只有被定位、复现、验证并写入审计链的失败，才会产生复利。"**
另两条可直接用的判据：**"模型是否看到了失败却仍宣称成功"**（= 我们的假绿）、
**"规则修好了旧问题，是否制造了新问题"**（= 改完必须重跑全判据，不许只看目标那一项）。
