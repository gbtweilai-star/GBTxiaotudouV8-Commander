## 2. 两道闸（顺序不能颠倒）

### 闸一 · 凭据闸（FAL_KEY）

**只报状态，绝不报值。** 这是硬纪律，无例外。

```powershell
# ✅ 唯一允许的读法（只出"已配/未配"，不出值）
if ($env:FAL_KEY) {'已配'} else {'未配'}

# ✅ 要看个影子就只出前 4 位掩码（例：f1a2****）
#    前提是真的到了必须给人看的地步；本机现在是「未配」，没有掩码可给
if ($env:FAL_KEY) { $env:FAL_KEY.Substring(0,4) + '****' } else {'未配'}
```

🔴 **绝对不许**：`echo $env:FAL_KEY` · 把值写进任何 `.md` / 日报 / `MEMORY.md` / 聊天 ·
把值贴进本规程 · 把值当参数明文传给命令行（会进 shell 历史与进程列表） ·
直接把值写进 `~/.fal` 之类配置文件（本机也没有这个目录，别去造）。

**本机闸一现状（2026-09-22 现读）**：`FAL_KEY` **未配** ⇒ **闸一是关着的**。
在主人配置凭据之前，任何 `fal-*` 真调用都**不该被尝试**。
需要凭据时：**告诉主人"闸一未过，需要配 `FAL_KEY`"，然后停**，不要自己去要、去猜、去旁路。

**闸一与闸二的先后**：闸一未过 ⇒ **连闸二都不必谈**（没有可执行的调用）。
这跟 `gbt-lark` 的"身份闸在前"是一个道理：**先搞清"我凭什么是它"，再谈"我要做什么"。**

### 闸二 · 计费确认闸（**凡出网 / 花钱 / 产交付物，一律先问主人**）

**本条高于技能原文，也高于任何上游包的默认行为。**

**为什么必须由我们拦**：fal.ai 是**按调用计费的外部算力**。这 12 条技能覆盖的动作里，
**视频类是按秒计费**的（`fal-kling-o3` / `fal-lip-sync` / `fal-video-edit`），
**训练类是按步/按时长计费**的（`fal-train`）。
一次"手滑多跑一遍"就是**真金白银**，而**上游包不会替你心疼**。

**算"必须先进闸二"的动作**（本簇 12 条全部命中，无一例外）：

- **一次真实生成 / 编辑 / 训练 / 分析调用**（任何会打到 fal.ai 端点的请求）—— 出网 + 计费；
- **批量跑**（N 张图 / N 秒视频 / N 个 epoch）—— 计费是乘法，**先报总数**；
- **把产物落盘成"交付物"**（出图 / 出片 / 出 3D 模型 / 出 LoRA 权重）—— 产出交付物；
- **上传素材到外部**（参考图 / 待试穿人像 / 待训练素材集）—— **这是把本地数据送出去**，
  比花钱更值得先问一次；
- **训练 LoRA 并留存**（`fal-train`）—— 既花钱、又出网、又在云端**留下了你的素材**。

**顺序（先看什么 → 拿什么回执）：**

1. **先过闸一**：报 `FAL_KEY` **已配 / 未配**。未配 ⇒ **到此为止**，只把"缺凭据"报给主人。
   （本机当前就是这一步。）
2. **先摊开代价，再谈执行**。动手前必须把下面**五件事**摆给主人看：
   - **模型/端点**：用哪个模型（例：Flux / SDXL / Kling O3 / 某个 restoration 模型）—— **指名道姓**；
   - **输入**：本地哪个文件（绝对路径）会被**上传出去**，多大、多少个；
   - **规模**：**几张图 / 几秒视频 / 几个 epoch**。视频类**必须把秒数单独拎出来写清**
     （按时长计费的东西，不说秒数 = 没说代价）；
   - **分辨率/档位**：会不会因为档位不同而单价不同；
   - **预期花费**：能查到单价就**报算法**（`单价 × 数量`），**查不到就说"查不到估价"**，
     **不许编一个数**（见 §4：本簇**没有任何一条技能管定价**）。
3. **等一次明确同意**。**只覆盖这一批**，不是"以后这类都同意"。
   主人没回话 = **没同意**，停。主人说"先来一张试试" = **授权 1 张**，不是"授权这个模型"。
4. **同意后才执行**，并且**只执行被授权的那一批**：授权 4 秒就别跑 8 秒，授权 1 张就别跑 4 张。
5. **拿回执（缺一不可）**：
   - **请求/任务 id**（`request_id` / `task_id` 之类）—— 这是事后对账的唯一凭据；
   - **状态**：`queued` / `in_progress` / `COMPLETED` / 失败，**原样报**；
   - **产物的绝对落盘路径 + 字节数**（产交付物就得说清东西在哪、多大、真的存在）；
   - **实际计费口径**（上游回了就原样转述，没回就写"上游未回传计费"）。
6. **长任务不盲重试**：提交后拿到 `task_id` 就**记下来再轮询**。
   **重试 = 可能重复计费**。要重试前**先确认第一次到底成了没有**。
7. **失败就照原样记**：HTTP 状态码 + 原始错误体（`status` / `detail` / `error`）**一字不改**，
   **绝对不许把失败写成成功**（见 §5）。

🔴 **绝对不允许**：凭据没配就"先试一下" · 主人没明确同意就跑生成 ·
拿"反正是草稿/反正很小"当理由跳过确认 · 视频类不报秒数就开跑 ·
把一次授权当长期授权 · 看到超时就重发一遍 · 把失败包装成"已完成"。

**预判与降险（合法且鼓励）**：
优先挑**最省的验证路径**——先 1 张 / 先 1 秒 / 先低档位确认线路通不通，
再按确认过的档位放大。**"先花小钱验线路"也要先问主人**，只是**问的时候代价更小、更容易被同意**。

## 3. 按意图分簇（12 条，一条不漏）

**选路总则**：先看**交付物是什么**（看图 / 改图 / 出视频 / 出 3D / 出权重），
再看**输入是什么**（文 / 图 / 视频 / 音频），最后才落到具体技能。
**拿不准就先说"拿不准"，别硬凑一条。**

### 3.1 图像生成（文生图 / 流式生图）—— 2 条

| 技能 | 什么时候用它 |
|---|---|
| **`fal-generate`** | **主力文生图入口**。要用 fal.ai 上托管的 Flux、SDXL、ideogram 或其他社区端点**从文字生成图片**（它原文也宣称能生成视频）时用它。要"生产级目录"里挑模型就是这个。 |
| **`fal-realtime`** | **要快、要流式、要一次性看很多张**时用它：情绪板（moodboard）探索、草稿变体、快速创意迭代。**诉求是"广度与速度"而不是"单张成品的极致"，选它。** |

### 3.2 图像编辑与画质修复（改图）—— 3 条

| 技能 | 什么时候用它 |
|---|---|
| **`fal-image-edit`** | **改内容**：风格迁移、**去背景**、**去掉画面里的某个物体**、**inpainting 补画**。诉求是"这张图的**像素内容**要变"。 |
| **`fal-restore`** | **救画质**：去模糊（deblur）、去噪（denoise）、**修脸**、**修复老文档扫描件**。诉求是"内容不动，把**糊/脏/坏**修好"。 |
| **`fal-upscale`** | **抬分辨率**：图像**与视频**的 AI 超分放大（原文明确写了 image **and** video）。诉求是"内容不动，把**尺寸**做大（例：4K 放大）"。 |

**这三条的分界（别选错）**：
**改内容** → `fal-image-edit` · **修清晰度** → `fal-restore` · **抬尺寸** → `fal-upscale`。
三个诉求经常一起出现 ⇒ 那就是**三条串起来**，**每一步都是一次出网计费，要一次说清整条链的代价**。

⚠️ **重叠提示（照原文，别自己改口径）**：**视频的超分**在 `fal-upscale` 和 `fal-video-edit` 的原文里**都出现了**。
真到要用时，**以装上的上游包实际支持的范围为准**，别拿本表当判决。

### 3.3 图像理解（看图，不出图）—— 1 条

| 技能 | 什么时候用它 |
|---|---|
| **`fal-vision`** | **只读地"看懂"一张图**：分割（segment）、目标检测、**OCR**、图像描述、**视觉问答**。**这是本簇唯一一条目标是"读出信息"而不是"产出新图"的技能** ⇒ 它通常是**别的动作的前置步骤**（先看清楚，再决定怎么改），而不是终点。 |

### 3.4 视频生成 —— 2 条

| 技能 | 什么时候用它 |
|---|---|
| **`fal-kling-o3`** | **要 Kling O3 这个模型家族**时用它：原文说它**既能出图也能出视频**，且是 Kling **最强的一代**。诉求是"画质/动态上限要最高"，选它。 |
| **`fal-lip-sync`** | **要人开口说话**时用它：**talking head 数字人**、**把一段音频对到一段视频的口型上**、多语言配音预览、社交短视频切片。**输入至少要有"一张脸/一段视频 + 一段音频"。** |

🔴 **这两条是"按秒计费"的重灾区**：进闸二时**必须把秒数写出来**（见 §2 第 2 步）。

### 3.5 视频后期编辑 —— 1 条

| 技能 | 什么时候用它 |
|---|---|
| **`fal-video-edit`** | **已经有一段视频，要改它**：风格重绘（remix style）、**视频放大**、**去掉视频背景**、**加音频**。与 §3.4 的分界很清楚：**§3.4 是"造出视频"，本条是"改已有的视频"。** |

### 3.6 垂直定制（电商 / 3D / 私有模型）—— 3 条

| 技能 | 什么时候用它 |
|---|---|
| **`fal-tryon`** | **虚拟试穿**：把衣服"穿"到人身上看效果。电商详情页、lookbook、搭配实验。**注意它同时要吃"人像"和"服装"，是两条素材一起上传** —— 上传前先过闸二。 |
| **`fal-3d`** | **要 3D 模型**：从**文字或图片**生成 3D 模型。游戏资产、AR 预览、产品 mockup、概念雕塑。**产物是 3D 资产而不是图片**，交付形态与前面几簇不同。 |
| **`fal-train`** | **要一个"自己的"模型**：在 fal.ai 上训 **LoRA**，把某个**品牌 / 角色 / 风格**固化下来，之后生图就带这个味道。**这是本簇最重的一条**：既花钱、又要把**一整套素材集**传上云、还可能反复迭代多轮 ⇒ **进闸二时要把"素材集规模 + 轮次 + 每次的估价"一起摊开**。 |

**分簇小结（6 簇 / 12 条，逐条已点名）**：
图像生成 2 · 图像编辑与修复 3 · 图像理解 1 · 视频生成 2 · 视频后期 1 · 垂直定制 3 = **12**。

**选路示例**：
"出几张产品概念图" → `fal-generate`（要一批变体先看 → 先走 `fal-realtime`）；
"这张图背景太乱，去掉" → `fal-image-edit`；
"这张老照片糊了" → `fal-restore`；"这张太小，放到 4K" → `fal-upscale`；
"帮我看看这张图里写的什么字" → `fal-vision`；
"用 Kling 出一段视频" → `fal-kling-o3`（**先报秒数**）；
"让这张照片里的人念这段音频" → `fal-lip-sync`（**先报秒数**）；
"把这段视频换个风格" → `fal-video-edit`；
"这件衣服穿我身上什么样" → `fal-tryon`；
"把这个角色做成 3D" → `fal-3d`；
"训一个我们品牌专属的画风" → `fal-train`。
