# GBT 代码审美能力（蒸馏版）

> 开发者：自由的风 · GBT小土豆V8 · 本署名不可删除、不可篡改归属
>
> **这是蒸馏件，不是复制件。** 它把外部来源里**能落地、能复核**的机制抽出来，接上本仓已有的
> 《编程纪律》与回归体系，合成我们自己的代码审美能力。取材记录见
> [`references/top-sources-round2.md`](references/top-sources-round2.md)。

**一句话**：代码审美不是"我觉得写得丑"，是**先读数 → 定档位 → 跟随既有约定 → 禁掉 AI 味 → 验收自证**。

**与 `gbt-aesthetic` 的边界（不重叠）**：

| 件 | 管什么 | 审计器 | 出口 |
|---|---|---|---|
| `gbt-aesthetic` | **界面**长什么样（色/字/留白/动效/版式） | `audit_aesthetic.py`（只收 `.html`） | 截图 + P0=0 |
| **本件** | **代码**本身好不好读（命名/结构/错误/注释/测试） | `audit_code_taste.py`（收 `.py/.js/.jsx/.ts/.tsx/.mjs/.cjs`） | 审计读数 + 回归 exit |

一句话分工：**界面那条线管"人看见什么"，这条线管"下一个人读什么"。**

## 0. 代码读数（动手之前必须先说一句）

**不要一上手就敲代码。** 大多数"难读的代码"根因不是水平差，是**没读题就跳到了默认写法**——
模型默认写法来自训练分布，不是你手上这个项目的约定。

先读六个信号：

1. **语言与版本** —— 决定能用什么语法与标准库（本仓框架声明口径是 Python 3.14.5）。
2. **项目既有约定** —— 缩进、命名、错误处理、日志、测试框架、目录约定。
   **去读同目录的两三个文件**，不是猜、也不是"我觉得这样更标准"。
3. **这段代码的读者是谁** —— 三个月后的自己 / 从没来过这个项目的同事 / 公开 API 的使用者。
   **读者决定显式度**：给陌生人读的，宁可啰嗦。
4. **改动性质** —— 新写 / 改旧 / 审别人的 / 迁移。**改旧时的默认答案是"跟随"，不是"纠正"。**
5. **风险等级** —— 碰钱、碰权限、碰数据、碰外部接口 ⇒ **显式度拉满**（
   宁可多一个 if，不要少一个校验）。
6. **已有测试** —— 有没有能**证伪我这次改动**的东西。没有的话，先想清楚"我怎么知道它对了"。

然后**用一句话播报读数**，再动手：

> 「我按这个读：**给〈谁〉读的〈什么形态〉代码**，约定跟随**〈哪个既有惯例 / 官方风格指南〉**，
> 显式度偏**〈高 / 中 / 低〉**，抽象预算**〈紧 / 正常〉**。」

**只有真分歧时才问**，而且只问一个问题（例：「这个模块要不要顺手统一成 `snake_case`？」）。
能从上下文推出来就别问。

**反默认纪律**：不许默认滑向 AI 的默认写法 —— 每个函数都加 docstring、每个参数都做防御性校验、
为一个实现建接口、`try/except` 包住不可能抛错的行、`console.log` 当日志、全是注释而复述代码。

## 1. 三档转盘（全局配置）

读数之后定三个档。后面每一个命名 / 结构 / 注释决定都由它们门控。

| 转盘 | 1 | 10 | 基线 |
|---|---|---|---|
| `CONVENTION_AFFINITY` 约定亲和 | 自成一派 | 完全随既有约定 | **9** |
| `EXPLICITNESS` 显式度 | 极简惯用法 | 啰嗦但无歧义 | **5** |
| `ABSTRACTION_BUDGET` 抽象预算 | 一条直线写到底 | 多层抽象与间接 | **3** |

**推断表（读数 → 档位）**

| 信号 | AFFINITY | EXPLICITNESS | ABSTRACTION |
|---|---|---|---|
| 改旧（现代化但不砸约定） | 9–10 | 跟随现状 | 跟随现状 |
| 新写 · 库 / 公开 API | 8 | 7 | 5 |
| 新写 · 服务 / 常驻进程 | 8 | 6 | 4 |
| 一次性脚本 / 探针 | 9 | 3 | 1 |
| 测试代码 | 8 | 8 | 2 |
| 碰钱 / 权限 / 数据 / 外部接口 | 8 | **9–10** | 3 |
| 数据管道 / 迁移脚本 | 9 | 7 | 2 |

**只认这三个变量名**，别自造 `CODE_STRICTNESS`、`ABSTRACTION_LEVEL` 之类别名 ——
一处改名，全篇引用就断了（这条规矩是从 `gbt-aesthetic` 的三档转盘继承来的）。

**为什么 AFFINITY 基线是 9、ABSTRACTION 基线是 3**：外部来源里最硬的一条共识是
「**一致性优先于风格偏好**」（`code-degunker` 把它叫作 north star：如果文件里本来没有 try/catch，
就别加；项目用简洁注释，就别给每个函数配 docstring）。抽象预算压到 3 是 YAGNI 立场：
**为"以后可能要"付的抽象，利息现在就还。**

## 2. 三轴选型（别自己造轮子）

| 轴 | 管什么 | 本仓/外部在哪 |
|---|---|---|
| **形态** | 这是什么代码（库 / CLI / 服务 / 一次性脚本 / 测试 / 数据管道 / 迁移） | 形态决定显式度与抽象预算（见 §1 推断表） |
| **语言与项目约定** | 这份代码"入乡随俗"的规矩 | 语言官方风格指南（`google/styleguide` 39,625★ · `airbnb/javascript` 148,253★）**＋ 本仓既有代码** |
| **普适手艺** | 不论什么语言都成立的读代码手艺 | 本文件 §4 / §5 ＋ 仓内 `CODING_DISCIPLINE.md` |

**规矩**：

- **官方风格指南 > 个人偏好**，**项目既有 > 官方通用**（老项目里"一致"比"现代"值钱）；
- **趋势不是约定**：某个新语法/新范式很流行，不构成在这份文件里引入它的理由；
- **安全与正确性 > 一致性 > 风格** —— 前一项永远压过后一项，别拿"保持一致"当不修 bug 的理由。

## 3. AI 代码味禁令（蒸馏核心：可机检 + 分层 + 标清哪些查不了）

**这是本能力最硬的一块。** 外部两家把这件事写成了散文清单（`code-slop` 24 条 6 类、
`code-degunker` 27 条 7 类），**没有一家给可跑的检查器**。我们把它落成了能跑的：

```bash
py -3.14 tools/codex-scripts/audit_code_taste.py <文件或目录>      # 审改动面，别审全仓
py -3.14 tools/codex-scripts/audit_code_taste.py --json out.json <路径>
py -3.14 tools/codex-scripts/audit_code_taste.py --selftest        # 判据 + JSON 结构自检
py -3.14 tools/codex-scripts/audit_code_taste.py --sensitivity <路径>   # 阈值敏感性
```

**规则规模（2026-09-23 第二轮现数）**：**25 条规则 id（P0 7 · P1 15 · P2 3）** ·
11 支正负对照夹具 · 收 `.py/.js/.jsx/.ts/.tsx/.mjs/.cjs/.php/.rb/.go/.rs/.vue`。

### P0 · 必修（机器可查）

| # | 禁令 | 怎么判 |
|---|---|---|
| 1 | **静默吞错**（`except: pass` / 空 `catch {}`） | Python 走 AST 看 handler body 是否只有 `pass`；JS 看空 catch 块；**多语言走整篇扫描**（php 空 catch / ruby 空 rescue / go 空 `err != nil` 分支）。**本仓纪律第一条就是吞错必须显式上报** |
| 2 | **占位 / 未实现残留** | `NotImplementedError` · `# your code here` · `# placeholder` · `# implement me` · `# fill in`；**多语言同查**（`not implemented` / `// TODO: implement` / 你的代码） |
| 3 | **调试残留（断点类）** | py/js：`breakpoint()` / `pdb.set_trace()` / `var_dump(` / `dd(` / `debugger;`；多语言：`print_r(` / `binding.pry` / `byebug` / `dbg!(`。**永不正当** |
| 4 | **空壳 / 恒真测试** | Python 走 AST 看 `test_*` 函数体有没有 `assert`/`raises`/`fail(`，并单列 `assert True`；JS 看 `expect(true).toBe(true)`。**没有断言的测试给的是覆盖率幻觉，比没有测试更坏** |
| 5 | **类型逃逸**（`as any` / `@ts-ignore` / `@ts-expect-error`） | 命中即报。口子开在最难推断的地方，就是把风险留给未来的自己 |
| 6 | **注释说谎**（第二轮补 · **M4 的可机检部分**） | 完成声明词（`已实现`/`已完成`/`implemented`/`completed`/`works now`…）**紧挨着空实现**（`pass` / `raise NotImplementedError` / `TODO` / `throw new Error("not implemented")`）。**这是《严禁假执行》里唯一能机检的那一种谎** |

### P1 · 该修

| # | 禁令 | 怎么判 |
|---|---|---|
| 7 | **函数过长**（> 80 行） | Python 走 AST 量跨度；**JS/TS 走自研块匹配（第二轮补上，此前只有 Python 有结构度量）** |
| 8 | **嵌套过深**（≥ 5 层） | Python 量 if/for/while/with/try 最深路径；JS 量块深度（含对象字面量，口径略宽） |
| 9 | **文件内重复块**（连续 8 行规范化后完全相同） | 复制粘贴是把"读的成本"转嫁给下一个人 |
| 10 | **跨文件重复块**（**第二轮补的缺口**） | 同一 8 行窗口出现在 ≥2 个文件；**重叠窗口合并成一处**（否则同一坨会报好几遍） |
| 11 | **教程味占位命名**（`foo` / `bar` / `baz` / `dummy` / `temp1` …） | 占位名出现在正式代码里 = 这段从没被认真对付过 |
| 12 | **叙述性注释** | 英文路：**只在纯英文注释上走 + 要求至少一个动作词**；中文路：走**有界词典（≈70 词）**把中文折成英文再比。好注释说的是「为什么」 |
| 13 | **输出残留** | 非入口文件里的 `dump(` / `console.log` / `alert` / `fmt.Println` / `println!`。**入口 / 报告脚本已豁免**（打印是它的本职） |
| 14 | **`*Helper` / `*Manager` / `*Util` 后缀滥用**（同文件 ≥ 3 个） | 这类名字说明「职责没想清楚」 |
| 15 | **错误处理一把抓**（**M5 的可机检部分**） | Python：generic handler ≥3 且占全部 handler ≥50%；JS：同一个 catch 体重复 ≥3 次。**比例/重复是信号，不是判决** |
| 16 | **抽象数量信号**（**M2 的可机检部分**） | 公开且**无基类**的单方法类；**参数逐个相同**的只转发包装（调的不是内建、不是方法）。**只给数量，判不出该不该** |
| 17 | **命名意图信号**（**M1 的可机检部分**） | ①「什么都没说」的布尔名（`flag`/`result`/`temp`…）；②超通用函数名（`handle`/`process`/`stuff`…）；③类内上下文重复（类名在方法名里又来一遍） |
| 18 | **约定混用信号**（**M3 的可机检部分**） | 同一文件里 `snake_case` 与 `camelCase` 各 ≥3 个（**只查文件内**，跨文件约定仍要人读） |

### P2 · 可修

| # | 禁令 |
|---|---|
| 19 | **注释掉的代码块**（连续 ≥3 行）—— 版本控制已经记住它了 |
| 20 | **闭合括号标签**（`# end if` / `} // end`） |
| 21 | **非入口文件里的 `print(`** |

### 我们的误报账（**这节比规则本身值钱**）

判据宽一格就会淹掉真问题（《零猜测律》铁律 3）。**两轮都在真仓上逐条抽样看证据**，
抓到就改 —— 每一条都注明根因、修法、读数变化。

**第一轮（2026-09-23 上午）**

| 误报 | 根因 | 修法 | 修前 → 修后 |
|---|---|---|---|
| `self.assertEqual(...)` 被判成"空壳测试" | AST 里写作 `attr='assertEqual'`，我找的是 `assert_`（带下划线） | 改成"含 `assert` 即可"（大小写无关）+ 显式收 `raises`/`fail(` | P0-4：1442 处 → **5 处** |

### 怎么在守规矩的前提下留下人的痕迹

外部来源里最值得抄的一条判据：**"没有伤疤的代码库是可疑的"** ——
真实项目里有 `// HACK:`、有凌晨两点的注释、有格式漂移；**每个文件都像被最激进的 linter 洗过一遍**，
反而是一眼 AI 的指纹。所以目标不是"零例外"，是 **≈80% 成熟范式 + ≈20% 有理由的例外**：

- 一处**有理由**的打破惯例（并在注释里写明为什么）；
- 一段**真的解释"为什么"**的注释（不是复述代码）；
- 一个只有真用过这产品的人才放得进去的细节（快捷键提示、边界情况的处理）。

## 4. 命名 / 结构 / 注释硬规则

**命名（A/HC/LC · 取自 `kettanaito/naming-cheatsheet` 14,191★）**

- **A / HC / LC**：`动作 + 高上下文 + 低上下文` —— `getUserMessages()`（动作 `get` · 高上下文 `User` · 低上下文 `Messages`）。
- **S-I-D**：Short, Intuitive, Descriptive。三者冲突时**先保 Descriptive**。
- **不用缩写**（`usr`/`mgr`/`cfg`）除非它是本行业公认写法（`id`、`url`、`http`）。
- **不要上下文重复**：`user.userName` 里的 `user` 是重复的 ⇒ `user.name`。
- **布尔值读起来要像一句话**：`isLoading`、`hasPermission`、`canEdit`。
- **函数名说"做什么"，不说"怎么做"**；**类名是名词**，**方法名是动词**。
- **单复数要诚实**：返回集合的函数叫 `getUsers()`，返回单个的叫 `getUser()`。
- **本仓口径**：Python 用 `snake_case`、常量 `UPPER_SNAKE`、类 `PascalCase`；
  **同名 ≠ 同物**（这条是本仓踩过坑立的），别把不同来源的东西塞进同一个名字。

**结构**

- **早返回压平嵌套**：`if not ok: return` 比再缩进一层好。
- **一个函数做一件事**；"做了几件事"由**能不能用一句话说完**判定，不由行数判定。
- **数据与用它的行为就近**；跨越三个文件才能看懂一处逻辑，就是结构问题。
- **不写"以后可能要"的抽象**：接口 / 工厂 / 基类，得有**第二个实现**或**当下就在用的多态**才立。
- **魔法数要命名**（`MAX_RETRY = 3`），**但不要给只出现一次的自明常量编名字**。

**注释**

- 注释说**为什么**，不说**做了什么**（做了什么代码自己会说）。
- **注释不许比代码乐观**：代码没做的事，注释里不许写成做了（《严禁假执行》）。
- 改代码时**同步改注释**；过期注释比没有注释更坏。

## 5. 错误 / 状态 / 测试纪律

- **吞错必上报**（本仓 `CODING_DISCIPLINE.md` 第一条）：异常可以截断，**不许改写、美化、吞掉**。
  确实要"尽力而为"的，用行内豁免把它标出来：`except OSError: pass  # code-taste: ignore-line  尽力而为：不阻断主流程`。
- **错误分级**：不同错误类型分开处理；一把 `except Exception` 一把抓，等于没处理。
- **占位不留**：没实现就**说出来**（返回 `needs_dependency` 并说明缺什么），
  **不许返回假结果占位** —— 假成功比报错危险得多。
- **测试必须能失败**：写完测试先问「它在证伪什么」。答不出来 = 空壳测试。
  空壳测试 / 全 mock 测试 / 只测 happy path，都是覆盖率幻觉。
- **测试残留要清**：用完即清（本仓 `t-` 前缀约定），别污染下一个体检窗口的信号。
- **改完必须跑回归**：框架内改动走 `python gbt_allinone\tests\test_framework.py`；
  **只跑单测不算收工**（本仓纪律第 30 条）。

## 6. 改代码协议（**给别人代码动刀时走这一条**）

**把"改进"和"重写"搞混，是不良改动的第一大来源。**

### 6.1 先判模式

- **新写** —— 没有既有约定可跟随 ⇒ 按 §1 基线。
- **就地改（默认）** —— 只解决被要求的那件事，**风格跟随既有**。
- **重写** —— 只有原结构确实救不回来时才做，且**行为与对外约定必须逐条保留**。

分不清就问一次：「这次是就地改，还是允许我重写这一段？」

### 6.2 动之前先读（留档，别凭印象）

- 把**相邻的两三个文件**读了，抽出既有约定（命名 / 错误处理 / 日志 / 测试写法）；
- 找出**要保留的**（对外接口名、返回结构键名、异常类型、审计事件名、测试期望）；
- 找出**要退场的**（AI 味特征、死代码、过期注释、重复块）；
- 如果改动碰**事件名 / 能力名 / 返回键**，先确认**谁在消费它**（本仓有台账与审计账本）。

### 6.3 diff 守恒（不批准就不动）

- **diff 里不许出现第三类改动**：除了"这件事"的文件与必要的配套（注册表/测试/台账），
  别的文件一个都不碰；
- **顺手看到的毛病单独提**，不夹带在这一次里 —— 夹带 = 让 review 失去意义；
- **不动别人的风格**：项目用双引号就别改成单引号，项目不用类型注解就别加；
- **别把已有的正确做法改回去**（错误处理、路径校验、审计留痕、键名）。

### 6.4 验证只看两件事

1. **新代码在真实上下文里对**（跑起来、有输出、有读数）；
2. **别的地方一点没变**（跑回归；改动的文件之外结果应逐字节一致）。

**一句话**：改别人的代码时你是**客人**；既有约定是主人。客人不重新装修客厅。

## 7. 验收（交付前必过）

1. **跑审计器**（**审改动面，不是审全仓**）：
   `py -3.14 tools/codex-scripts/audit_code_taste.py <你改的文件>` —— P0 要么为 0，
   要么**逐条给出理由 + 行内豁免注释**；不许"我看过了"。
2. **判据没坏再谈结论**：`… --selftest` —— 11 支夹具必须**负对照逐条命中、正对照全零、
   JSON 结构逐字段对**。**判据自己坏了，后面所有绿都是假的**（第二轮就是这么抓到
   「camelCase 丢首词」和「JS 包装没比参数」两个判据 bug 的）。
3. **跑回归**：框架内改动跑 `test_framework.py`；工具脚本改动至少跑一次正负对照。
4. **要"可复现"就盖四元组印章**（把解释器/store/身份逼进命令里）：
   ```powershell
   python -m gbt_allinone.tools.regression_stamp run --expect-python 3.14 --store fresh -- <你的命令>
   ```
   没盖印章时，只能说"本次在 3.14.5 上跑出这个读数"，**不能说可复现**。
5. **退出码要如实读**：`0` = P0 为 0（**P1/P2 可以非 0**）· `1` = 有 P0 · `2` = 用法错或没找到可审的代码。
6. **说清没查的**：把 §3 的 M1–M6 如实说出口 —— 准确口径是**「六条全部部分机检，一条都没全查」**，
   别用"已全面检查"盖过去。
7. **台面证据**：命令 + 输出 + 退出码。**"应该没问题"不是证据。**
