## 0. 先记住三个词（不然后面全看不懂）

| 词 | 人话 | 你要知道的一件事 |
|---|---|---|
| **触手** | 一个**能力位**（框架里能干活的最小单位，如 `one_shot`、`filmkit`） | 触手只能从**唯一门** `run_task` 进；绕过门 = 事故 |
| **工具/脚本** | `tools/` 下的一条命令（如 `beatgrid.py`、`filmgrade.py`） | 它们**不是触手**，在终端里直接跑；手册里两类会**分开标** |
| **判据** | 一句**能红能绿**的机器判定（如"断连必须为 0"） | 判据红了 = 有问题；**它是你的护栏**，不是障碍 |

**你的主要动作只有两个**：
1. 说人话 → `python tools/codex-scripts/omni.py ask "<一句话>"`（它告诉你落哪条触手）；
2. 看面板 → [工作台](holo_pet/assets/workbench/index.html) / [3D 全景](holo_pet/assets/tentacle3d/index.html) / 每条产线一页（`wf-film` 等）。

## 一、核心创作流程：从构思到成品

### 1.1 六个环节（每一环都有"你看什么"）

| # | 环节 | 目标 | 输入 | 输出 | 依赖 | **可执行要点（你照抄）** | 你看什么 |
|---|---|---|---|---|---|---|---|
| 1 | **构思收敛** | 一句话 → 可执行产线输入 | 你的想法（人话） | 全链计划（节奏 BPM / 帧率 / 时长 / 调色意图 / 8 拍模板 / 缺什么） | 无（只读） | `run_task('one_shot', {'op':'plan','prompt':'来一条 60 秒暗黑科技感的短视频'})` | 计划里**明列缺什么**（缺授权会写出来） |
| 2 | **拍子表** | 定"节奏骨架" | 音/曲或 BPM | 拍子表（每拍时长，帧率由 BPM 反推） | ① 的 BPM | 工具：`python tools/beatgrid.py derive` / `plan` | 每拍时长、总拍数 |
| 3 | **分镜与镜头** | 把拍子表变成"镜头单" | 拍子表 + 题材 | `manifest.json`（场=音频+3 镜 prompt；每镜含运镜与机位） | ② | 触手 `filmkit`（`op=plan` 出镜头单 / `op=gen` 生成；另有 `seg/build/add/rm`）· 触手 `actioncam`（10 运镜 × 4 机位） | 镜头单里每拍一镜、都写了运镜 |
| 4 | **出图/出片** | 把镜头变成画面 | 镜头单 | 图片帧序列 | ③ | 触手 `comfyui`（本机生图，966 节点）· 洗图触手 `zimage_rewash` | 抽帧看**画面对不对**（不是"跑完了"） |
| 5 | **装配** | 帧 + 音 → 成片 | 帧序列 + 音轨 | 成片 mp4（画布统一、音轨连续） | ④ | 工具：`python tools/filmkit.py gen`（或装配脚本） | 时长 / 分辨率 / 有没有黑边 |
| 6 | **交付验收** | 过闸才算成品 | 成片 | 交付判据读数 + 交付物 | ⑤ | `filmgrade.deliver_check(成片)` → **交付三必查**；`deliver_ladder(...)` → **SSIM 阶梯定码率档** | 三必查全过；阶梯给出每档损失 |

**编排加速（可选）**：一次跑多条线 → 工具 `python tools/dagrun.py`（有命令行入口；同 Spec 同 hash、断点续跑）。
**唯一交付通道**：进生产/镜像必须走触手 `pipeline_submit`（**要授权**，AI 不会自批）。

### 1.2 关键节点（卡住你的就是这三个）

- **节点 A：镜头单（③）** —— 这里定错了，后面全白干。判据：每拍都有镜、都有运镜与机位。
- **节点 B：出图（④）** —— **必须看抽帧图**再往下（"跑完了"不等于"画面对"）。
- **节点 C：交付（⑥）** —— 没过交付判据就不叫成品；缺授权会如实报，**不会偷偷放行**。

## 二、修饰与打磨：怎么提升质量与表现力

> 打磨不是"再多做一点"，是**按顺序拧三个旋钮**：先规格 → 再画质 → 后观感。

| 阶段 | 目标 | 输入 | 输出 | 依赖 | **可执行要点** | 你看什么 |
|---|---|---|---|---|---|---|
| **规格守卫** | 别让规格漂（尺寸/时长/命名不一致） | 产物 + 规格表 | 一致或报错 | 无 | **函数库**（无命令行）：`specguard.py` 的规格校验函数 —— **由我代跑** | 它**当场拒**不一致的产物 |
| **画质** | 清晰度/细节 | 原始帧 | 更清晰帧 | 出图完成 | 触手 `zimage_rewash`（**放大环已可用**：ffmpeg lanczos+unsharp） | 放大前后对比图 |
| **色彩与质感** | 统一的"片子长相" | 成片 | 调色后成片 | 装配完成 | **函数库**（无命令行）：`filmgrade.pick('暗黑科技感')` 选调色 · `preview(...)` 出样 · `deliver_check/qc` —— **由我代跑** | 调色前后各一帧 |
| **真交付档位** | 用最小体积换可接受损失 | 成片 | 各档 mp4 + SSIM | 上面都过 | **函数**：`filmgrade.deliver_ladder(成片, 输出目录)` → 抽段做无损参考 → 各档重编 → **SSIM 量化**（**由我代跑**） | 每档 SSIM，选"够看且最小"的那档 |
| **页面/界面观感** | 别一眼假、别像模板 | HTML/页面 | 过审页面 | 见第四条 | 审计器：`python tools/codex-scripts/audit_aesthetic.py <文件>` → **P0 必须 0** + `UI-check.md` 五步 | 审计器读数 + 截图亲眼看 |

**打磨的诚实边界（现在就告诉你，免得白等）**：
- `zimage_rewash` 的**反推提示词 / 重绘**两条环**还没接线**（如实标在它的说明里）；能用的只有**放大**。
- **`filmgrade.py` 与 `specguard.py` 都只有函数、没有命令行**（实测：0 处参数解析、无 `__main__`）⇒
  你**不用**去敲 `python tools/filmgrade.py`（那命令不存在）；**直接说"帮我跑交付三必查/SSIM 阶梯"**，我代跑。
  有命令行的工具是 `beatgrid.py` / `actioncam.py` / `filmkit.py` / `dagrun.py`（用法以 `--help` 现读为准）。

## 三、调试：怎么定位问题、怎么迭代

> 调试的核心不是"更用力看"，是**先固定住"我看的是什么"**，再谈对错。

### 3.1 五步定位法（从便宜到贵，别跳步）

| 步 | 做什么 | 工具/触手 | 输出 |
|---|---|---|---|
| 1 | **先看（不许盲猜）** | 触手 `action_gate`（`op=observe` → `preflight`） | 证据捆（路径 + sha + 龄）+ 闸号 |
| 2 | **判断"是坏了还是读数坏了"** | 触手 `brain_verify`（肉眼验证：视觉指纹 + 穿透读回） | 真实画面/文本读数 |
| 3 | **扫一遍找病根** | 三件套：触手 `penetrating_cross_scan` · 工具 `coverage_matrix.py` · 触手 `sec_sweeper` | 分诊清单（真问题 / 需人核） |
| 4 | **代码面专项** | 触手 `code_audit`（findings + **独立验证** + 复现命令） | 每条带证据与复现命令 |
| 5 | **记账 + 探针** | `state/排查台账.json`（F 编号）+ 复跑 | 逐条结项或改账 |

### 3.2 三条防"自己骗自己"的规矩（本仓用血换的）

1. **未验 = 未验**：没跑过就说没跑过；`exit 0` **不算完成**。
2. **同一概念不许两套口径**：比如"文件 sha"和"规范化短哈希"不是一回事 —— 报数必须带**口径**。
3. **判据要能红**：任何"看着在判"的东西，都要能喂它一个坏样本把它弄红（否则它只是装饰）。

### 3.3 迭代怎么闭环

**发现问题 → 写进台账（带证据）→ 修 → 复跑同一条判据 → 结项**。
要复现"上次到底怎么红的"，用四元组印章：
`python -m gbt_allinone.tools.regression_stamp run --expect-python 3.14 --store fresh -- <命令>`（解释器/存储/身份/命令一起记）。

### 4.3 皮肤改动的最小流程（不会代码也能参与）

1. **你选**：要哪种感觉（更冷/更暖、更密/更疏、动效更强/更静）——说人话；
2. **我改令牌**：只动**令牌表**（颜色/圆角/间距），**不散改**每个元素（这是"客人不重新装修客厅"那条纪律）；
3. **数据不变**：页面数字仍来自 `console_hub`（**页面不许自己编数**）；
4. **过闸**：审计器 P0=0 + 截图给你看；
5. **留档**：改了什么写进 `DESIGN.md` 的增补（**旧 `DESIGN.md` 不许静默覆盖**，那是你的设计合同）。

## 七、唱歌这条路（主人令 2026-09-28：「把插件连接好部署语音…装 3 个轮询避免卡壳」）

### 本地事实（不改口径）
本机**零算力**（无 CUDA、内存紧）⇒ 2B/8B 级歌声合成模型**本地跑不动**（`语音中枢v2.0` 一手实测）。
**本地能做的是"念白"**（Windows SAPI，零依赖）；**真"唱"必须走云**。

### 云这条走廊：`hf_voice`（Hugging Face · **3 臂轮询**）
```python
run_task('hf_voice', {'op':'status'})     # 三臂在位/健康/冷却（只回掩码）
run_task('hf_voice', {'op':'arms'})       # 轮询策略：hf-1 → hf-2 → hf-3，冷却自动跳过
run_task('hf_voice', {'op':'models'})     # 候选模型（**全部未验**，人工听感才是判据）
run_task('hf_voice', {'op':'sing','text':'主歌四句…','model':'facebook/mms-tts-zho'})
run_task('hf_voice', {'op':'rotate','arm':'hf-2','action':'disable'})   # 手动换道
```

**"3 臂轮询避免卡壳"的机制**（与 `key_gateway` 同一纪律，不另立一套）：
单臂连续失败 3 次 ⇒ **冷却 300s** ⇒ 下次自动投下一臂；三臂全失败 ⇒ **如实报"三臂全失败"**，
**不重试刷额度**（台账 `state/hf_voice.jsonl` 每条 fail 都记原因：401=token 无效 / 429=限流 / 5xx=对方抖动）。

**出网硬钉**（写死在代码里）：只 https · 主机白名单（`api-inference.huggingface.co` /
`router.huggingface.co` / `huggingface.co`）· **显式拒绝**环回/私有/保留地址 · 拒重定向 ·
**只回掩码**（密钥只走 `env:` / `vault:` 引用，永不写文件）。

### 三把 token 怎么装（**只有主人能装，我不代持**）
二选一（都不进任何文件、不进版本库）：
1. **环境变量**（最简）：设 `HF_TOKEN_1` / `HF_TOKEN_2` / `HF_TOKEN_3`（HF 免费账号可开多个）；
   第 1 臂也认 `HUGGINGFACE_API_KEY` / `HF_TOKEN` 作回退。
2. **保险箱引用**：用 `key_gateway` 铸条目，再在 `hf_voice.ARMS` 里用 `vault:<名>` 指过去。

装完复跑 `run_task('hf_voice', {'op':'status'})` ⇒ `arms_ready` 应从 0 变 1~3；再 `sing` 真出 wav。

### 诚实边界
- 四个候选模型**全部未验**（本机没 token）—— **不许当"已支持"**；其中 `musicgen-small` 是**器乐**不是人声。
- 真"唱"（歌声）在 HF 上要靠 singing 专用模型；本表还没纳入验证过的项 —— **要真唱，先让 token 到位，我再拿它逐个试**。
- `sing` 过 **`external_llm`** 门（把文本发到外部服务）；`out=` 指**仓外**路径时另过 `filesystem_write`。
- **听感是人的判据**：wav 出来了要**你自己听一遍**才算成品 —— 判据器只能证明"发出了、落盘了"。
