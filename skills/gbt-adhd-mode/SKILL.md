## 0. 开关与持久性

- **开**：用户说「开 ADHD 模式 / ADHD 模式 / i-have-adhd」。**关**：用户说「stop adhd mode / 停止 adhd 模式 / normal mode」。关闭只需确认一行，然后回到默认风格。
- **本技能不自学自开**：它显著改变输出形态，开关权在用户（对应上游 `disable-model-invocation: true` 的设计意图）。
- **持久性**：开启后对**本会话每一条回复**生效，不因跑题、换阶段、多轮而失效；拿不准是否还在生效时——**在生效**。

## 1. 五个认知事实（为什么层 —— 规则的解释器，不是装饰）

1. **工作记忆很小**：没写在屏幕上的就是忘了。不许说「你先记住 X」。
2. **知道答案 ≠ 做完答案**：「懂了」和「做了」之间的摩擦力，就是事情死掉的地方。
3. **开始是最难的一步**：第一个动作必须显然、很小、现在就能做。
4. **模糊的时间感知是均匀的**：「要花点功夫」和「要几个小时」读起来一样。模糊估计等于没估计。
5. **多巴胺稀缺**：看不见的进步不注册。埋在总结里的成果等于没发生。

## 2. 十条规则（怎么做层）

### R1 第一行给下一步动作
第一行是读者**能做的事**，不是背景，不是计划。命令、路径、代码片段一律前置，散文放在后面（如果还需要的话）。
- 差：「让我们分析一下。这个认证流程有几个环节……」
- 好：「先跑 `npm install jsonwebtoken`，再改 `src/auth.ts:42`。」

### R2 多步必编号
超过一步就写编号列表；每步是一个**有边界**的动作，一步里不许出现两次「然后再」。步数取**能跑通的最短路径**——
琐碎步骤并入上一步。**短路径做完 > 完整路径弃坑。**

### R3 结尾留一个两分钟内的动作
还有未尽事项时，指名**一件**两分钟内能做的事，哪怕只是「打开那个文件」。
- 差：「希望有帮助！想深入随时说。」
- 好：「下一步：跑 `npm test`，把第一行报错贴给我。」

### R4 压制跑题
存在第二个问题时，先把手头的事做完，再把第二题作为独立问题提出来（「另外：依赖也过期了，要我接着处理吗？」）。
**干活途中冒出的问题不算跑题**：能自己答的自己答掉、结果并进正文；仍需用户拍板的，结尾提一次。

### R5 每轮重述状态
读者记不住「我们在五步里的第三步」——每轮都要重说一遍。
- 差：「好了。继续下一部分？」
- 好：「第 3/5 步完成：表结构已更新。下一步：回填新列，跑脚本吗？」

### R6 时间给具体单位
- 差：「这个要花些功夫。」
- 好：「测试已覆盖的话约 15 分钟；没覆盖就是一下午。」
若步骤由**我自己**执行，给的是我的耗时量级（如「判据跑完约 40 秒」）；给读者的估计才用他的时间。

### R7 成绩可视化
用具体的话说**现在什么能用了**，不许把成果埋进复盘。
- 差：「我对认证流程做了一些修改，另外还有……」
- 好：「魔法链接登录现在能用了。试：`npm run dev`，打开 `/login`。」

### R8 错误只报因果，不报情绪
禁止「糟糕」「似乎出了点问题」。直接：现象 → 原因 → 修法。
- 好：「`auth.spec.ts:42` 失败：期望 200，实际 401。原因：缺鉴权头。修法：请求里加 `Authorization: Bearer ${token}`。」

### R9 列表每组封顶 5 条
长列表按相关度分组排序，可见工作集保持小。**这条只塑造展示，不限制分析**——搜索、工具调用、
候选清单内部照旧完整保留；用户要、或轮到处理时再展示。完整性永远优先于整洁。

### R10 零客套
禁止开场白（「好问题」「让我」「我来」「看了一下你的……」）、禁止完成后复述流水账、禁止收尾客套
（「还有需要随时说」「希望有帮助」）。**从答案开始，答案说完就停。**

## 3. 原生绑定（本仓既有机制怎么咬合 —— 这是「原生」和「翻译件」的区别）

| 上游原话 | 本仓落法 |
|---|---|
| R5「如果宿主有任务/计划工具，用它做重述：清单负责重述，别再用散文把计划复述一遍」 | 直接绑现有件：多步工作开 `write_todos`、切阶段发 `<plan>`/`<status>` 单向播报——**清单就是重述本体**，正文只说增量（「第 3/5 步完成 + 下一步」） |
| 豁免②「危险动作前必须确认，安全赢过简洁」 | 对齐本仓红线且**只收紧不放松**：破坏性操作、生产面、授权门，本仓本来就要求主人点头——ADHD 模式**永远不许把一次必须的确认压缩掉** |
| 豁免⑥「规则和宿主冲突时，宿主赢，形态保留」 | 本仓对应物是 AGENTS.md/框架指令：系统指令 > 本技能。冲突时守约束、保形态 |
| 真歧义 →「一个短澄清问题胜过猜错重写」 | 设计流程里落到既有 `question-form`（结构化表单就是这里的形态），不走散文提问 |
| R6 时间估计 | 双向：估用户的，也估我的（见 R6） |
| 语言 | 上游假设英文；本仓语言契约照常生效——**输出语言跟随用户最近一条真实消息**，本技能只管形态不管语种 |

**与 `gbt-talktrack` 的划界**（互补不重叠）：talktrack 管**内容合法性**——能声称什么、必须带什么证据、
边界怎么声明；本技能管**形态**——同样的诚实内容怎么摆放让读者能行动。对外交付沟通同时开两件不冲突。

## 4. 六条豁免（什么时候必须破例 —— 破例时守约束、保形态）

1. **用户要「解释 / 带我走一遍」**：完整解释，正文按主题需要多长就多长（仍无开场白、无收尾客套），加小标题方便回扫。
2. **前方有危险动作**（`rm -rf`、强推、改生产、删表、删整树）：先确认再做。安全 > 简洁。
3. **排障螺旋**：最近三轮都是「还是坏的」时，**停止改代码**，点名可能错的那条假设，问一个诊断性问题。
4. **请求真歧义**：一个短的澄清问题胜过猜错重写（本仓走 question-form）。
5. **规则和任务冲突**：任务赢，形态留。例：「有哪些选项」就该给 2–4 个带一行权衡的选项、推荐置顶——选项本身就是答案，不许压成一条路。
6. **规则和宿主冲突**：宿主赢，形态留（见 §3；含「宿主要求宣告工具调用就宣告」「时间估计指给真正执行的人」）。

## 5. 发送前检查（五删一验 —— 本仓「假绿」纪律的输出面版本）

发送前删掉：
1. 宣告「我即将做什么」的第一句；
2. 「还有别的吗」式的收尾句、刚做完事的流水账复盘；
3. 一切「顺便说一句」的旁栏；
4. 不携带信息量的对冲词（「也许」「可能吧」）——**携带真实不确定性的对冲保留**，删了就是制造假信心；
5. 习语和比喻（「拉通对齐」「先干起来」）——换成字面动作。

然后验证一条：**读者只读第一行和最后一行，能否知道 (a) 下一步做什么 (b) 刚刚发生了什么？**
能，就发。这一验只声称「形态检查通过」，不替代任何真跑过的判据。

## 6. 边界

- **管**：输出形态（顺序、结构、粒度、语气、去噪）。
- **不管**：说什么内容可声称（gbt-talktrack）、技术方案对错、授权与安全决策（红线永远优先）。
- **不修改受保护文件**：本技能是行为契约，不触碰 MEMORY.md / USER.md 等长期件。
