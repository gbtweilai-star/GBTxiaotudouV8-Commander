## 1. 这条线是什么 / 边界

### 1.1 一句话

> **L7 管"从真实素材到一份能交出去的成片文件"这条链**：
> **取**（下载/转录）→ **剪**（账本/时间线）→ **字幕** → **画面层** → **导出烧片**。
> 它的出口判据从来不是"看上去对"，而是**一个落盘的成片文件（路径 + 字节数）**。

**L7 的三个专属动作**（别线不做这三件）：

| 动作 | 说什么 | 反面（不属 L7） |
|---|---|---|
| **剪**（cut / trim / 删词） | 在**已有素材**上做时间维度的删改 | 从零"画"出一段动画 |
| **字幕**（transcribe / burn subtitle） | 把**已经说出来的话**对齐到时间轴 | 给页面配标题 |
| **导出成片**（export / render to file） | **画像素 + 编码成容器**，产物是 mp4/mkv | 输出一段 HTML/React 组件 |

### 1.2 与 L4（动效与合成）怎么分 —— **只看一句：素材从哪来**

总规程里 L4 的出口是「动效与视频合成（HTML 合成 / React / GSAP 三层）」，
L7 的出口是「成片：剪辑/字幕/配音/导出」。**两边都能产出 mp4，所以这条线最容易被念混。**

| 判据 | **L4 动效与合成** | **L7 视频与成片** |
|---|---|---|
| **素材从哪来** | **没有外部素材** —— 画面由代码/时间轴**从零画出来** | **有真实素材** —— 一段录制、一条网络视频、一批口播原片 |
| **主要工具** | `gsap-*`(4) · `hyperframes-*`(8) · `remotion-*`(11) | `chengfeng-*`(7) · `video-*`(4) · 能力域 `video`(4 位) |
| **手艺中心** | **编排**（时间轴、缓动、图层、组件） | **判断**（哪句是废话、哪屏该断句、这段该不该动） |
| **产物形态** | 一个**可渲染工程**（HTML 合成 / React 工程），mp4 只是它的一种输出 | 一个**成片文件**，工程只是过程 |
| **验收靠什么** | 跑起来看动作对不对（L4 规程） | **抽帧用眼睛看 + 成片文件路径/字节数**（§4 闸二） |

**三处灰区，逐条钉死**：

1. 🔴 **`chengfeng-visual` 做的是 HTML 层，但归属 L7。**
   它的手艺（GSAP/SVG 动效）确实是 L4 那一套，**但它绑的是 L7 的账本与字幕屏**（`--cues`）、
   由 `chengfeng-export` 烧进 mp4 ⇒ **它是 L7 流水线的一段，不是 L4 的一条工具**。
   反过来说：**"这层怎么做得好"回 L4/L1 判，"这层该不该存在于这一屏"归 L7 判。**
2. 🔴 **L4 的工具被 L7 借调，不等于搬家。**
   `video-use/install.md` 原文写着动画引擎（HyperFrames / Remotion / Manim）
   **"installed lazily the first time a project actually needs them"** ——
   那时是 **L7 的流水线调用 L4 的引擎**；引擎的归属仍在 L4，`manim` 没装这件事**仍记在 L4/L7 各自的账上**。
3. 🔴 **`fal-video-edit` / `venice-video` / `sora` / `fal-lip-sync` 不属 L7** ——
   它们的线是 **L6 出图与素材**（生成/编辑/超分/换脸）。**L7 管"剪真实素材"，不管"生成素材"。**
   要生成素材 → 走 L6；素材到手要剪 → 回 L7。

## 6. 报告层红线

> 出口前先问一句：**「这是事实，还是我读错了地方？」**

### 6.1 🔴 `status:"ok"` ≠ 本体 `ok:true`（**本件现场复现**）

`five-dim.py cap` 的输出是**三层信封**，**真判据在 `result.result` 里**：

| 现场那一发（§3.5） | 外层 | 本体（`result`） | 退出码 |
|---|---|---|---|
| `cap h3_video_gen '{"op":"gate_hw","mode":"local"}'` | `status:"ok"` · `denied:false` · `stamp:true` | **`ok:false` · `denied:true` · `rule:"hardware_unverified"`** | **0** |

**原因（源码级）**：`run_task` 的 `status` 说的是**"这一发调用跑没跑通"**，
本体 `ok` 说的是**"这件事能不能做/做对没有"** —— 两件事。
⇒ **读本线任何一位，都要下钻到 `result`**；只看外层会得到**"看着全绿、实际被拒"**的假象。
`five-dim.py` 的退出码取的是**外层** `status` ⇒ **exit 0 也不能当"判据通过了"**。

### 6.2 🔴 **"能调" ≠ "能用"**

- 能力域 4 位**都能调**（`cap` 全绿、零作用域、`omni` 里三位 AUTO）——
  但**四位全是只读契约面，真出片的生成端一条都没接线**（`media_pipeline` 自报
  `external_generators_connected: false`；`libtv_skill` 自报技能包与密钥均未接）。
- `video-pipeline` **能读、能被引用** —— 但它**没有任何可执行体**，**永远给不出成品**。
⇒ **"命令跑通了"和"东西做出来了"之间隔着一整条链，别用前者证明后者。**

### 6.3 🔴 **"缺件" ≠ "工具坏了"**

本线现读的每一处"跑不动"，病因都是**缺件**，不是**坏件**：

| 现象 | ❌ 错误念法 | ✅ 正确念法 |
|---|---|---|
| `vtd.js` 报 `ERR_MODULE_NOT_FOUND` | "脚本坏了 / 命令敲错了" | **依赖没装**（`node_modules` 不存在 ⇒ `npm ci` 没跑过） |
| `chengfeng-*` 的 `<插件根>/scripts/*.cjs` 全解析不到 | "技能写错了" | **落盘方式与文档约定不一致**（7 条被**平铺**安装，没带插件外壳） |
| `~/.chengfeng-videocut` 不存在、5190 无人听 | "chengfeng 有 bug" | **Runtime 与 Studio 没装**（技能自己写的：*"安装 Skill 文件不等于功能可用"*） |
| `video-downloader` 无脚本 | "这世上没有这个能力" | **它是目录桩，上游真存在**，本机没装 ⇒ **"要用得先装"** |
| `h3_video_gen` 显存读数是 `null` | "它坏了" | **读数拿不到**（`nvidia-smi` 不在 PATH + 沙箱身份下 WMI 被拒）⇒ **门槛读数都没有，不许说能跑** |

### 6.4 其它四条（L7 现场版）

1. 🔴 **`yt-dlp` 不在 PATH** 是一条**真事实**，但**不能推成"本机不能下载视频"** ——
   缺的是一件外部二进制，装上就变（而装它要过闸二）。
2. 🔴 **PATH 里没有 `chengfeng` 命令 ≠ 没装**：它的入口是 `node <插件根>/scripts/*.cjs` + 5190 服务，

3. 🔴 **"发布端不启用"是纪律，不是能力读数**：它的意思是**"我们决定不发"**，
   **不是**"本机没有发布工具" ⇒ **别念成"系统里不存在发布这条路"**。
4. 🔴 **"盘上有 mp4" ≠ "这条链跑通了"**：`video-out/*.mp4` 是**工作区第三路**（`tools/video/cut.py`）的样本；
   `render/` 是**数字人项目的 PNG 渲染图**（**不是成片目录**）。
   ⇒ **先问"这个文件是谁产出的"，再谈"这条线能不能出片"。**
