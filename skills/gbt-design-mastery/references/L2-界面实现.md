## 1. 这条线是什么 / 边界

**一句话**：L2 管「**把已经定好调性的设计，落成真的能跑起来的界面**」——HTML/CSS/JS、React/Vue、App 页面、组件、可交互原型、浏览器里的 HTML 演示；产出物是**可执行代码文件**，不是审美结论、不是设计稿、不是 PPT。

**它管**：
- 界面代码的落地实现（结构、组件拆分、状态、样式实现、浏览器兼容、可跑）
- HTML 演示 / 幻灯片（`frontend-slides`，纯前端零依赖形态）
- 网页性能体检（`web-perf`，快不快）
- 多 provider 检索（`web-search-plus`，找资料/找参考时的取数工具）

**它不管**：
- **不管「好不好看」** → 归 L1 `gbt-aesthetic`。L2 不许自己发明审美标准；L2 也不许拿「能跑」冒充「好看」。
- **不管设计令牌 / DESIGN.md / 设计系统单源 / Figma 设计稿** → 归 L3。有 DESIGN.md 时，令牌与审美口径以 L3 件为真源。
- **不管 `.pptx` 文件本身** → 归 L5（`pptx` / `pptx-generator` / `pptx-swarm`）。L2 只做浏览器里的 HTML 演示。
- **不管动效/视频合成** → 归 L4（GSAP / HyperFrames / Remotion）。
- **不管出图与素材生产** → 归 L6。

**与相邻线的分界线一句话版**：L1 说「该长什么样」，L3 说「令牌与设计稿是什么」，**L2 说「代码怎么写出来并且跑得起来」**，L4/L5/L6 分别接走动效、成片与素材。

## 6. 报告层红线

1. **先问「这是事实，还是我读错了地方」。**
   atlas 一条成员只给**一个** `path`，但同名件可以有多份。本线现读就抓到 `frontend-design`、`frontend-slides` **各两份且质量不同**。所以：**报形态前必须先扫遍所有 root**（`.openclaw-autoclaw\skills`、`.claude\skills`、`.agents\skills`、`审美相关skill\skills`），说清「我读的是哪一份、另外几份是什么」。
2. **「能调」≠「能用」。**
   `search.py --help` **exit 0**、`--explain-routing` **exit 0 且 JSON 形状完整**（`scores`、`intent_breakdown`、`query_analysis` 全填好了）—— 但真搜 `-q` 是 **exit 1：`Missing API key for serper`**。
   `--explain-routing` 的 `confidence: 0.0 / confidence_level: "low" / reason: "no_available_providers"` 才是真相，**`scores.serper = 4.0` 是「本该给 serper 的意图分」，不是「serper 可用」**。
   → **形状对≠内容对**。看见结构完整的 JSON，先找 `error` / `reason` / `confidence` 这类字段。
3. **「目录桩」≠「能力不存在」。**
   `frontend-dev` 桩上写的是 MiniMax 的完整前端工作流、`web-design-guidelines` 桩上写的是 Vercel 的 UI 标准 —— **这些上游能力是真的**，只是**本机没 vendored**。正确说法是「**意图路由可用，正文与脚本不可用**」，而不是「这个能力不存在」；反过来也不能因为描述漂亮就说「本机能做」。
4. **桩的 `SKILL.md` 也是 `SKILL.md`。**
   42 行的桩有完整 frontmatter、有 `name`、有 `description`、有 `triggers`。**不能因为「文件在、格式对」就当成能执行的规程**。判桩的唯一依据是**现读正文**：有没有 `od.upstream`、正文是不是「What it does / Source / How to use」三段。
5. **目录名 ≠ 内容形态。**
   `design-assets-index/` 名字像素材库，**实际只有 3 个文件、`SKILL.md` 51 行全是外链**；反之 `审美相关skill/design-systems/` 名字像规则目录，**实际是 150 个品牌 `DESIGN.md`**。两边都别按名字下结论。
6. **读数必须带身份与时间口径。**
   本会话 `python --version` = `3.12.10`（`C:\Python312\python.exe` 能起）；但 AGENTS.md 记的沙箱身份下该解释器起不来。**同一台机器、不同身份，读数是两个数**。跨口径读数不许直接比。
7. **闸不过就报闸，不许绕过。**
   `web-perf` 说「不可用就 STOP」——那就 STOP；`web-search-plus` 没 key——那就报「缺 SERPER/TAVILY/EXA/YOU/SEARXNG 五个 key」。**不许自己装 MCP、不许自己配 key、不许找旁路**（本会话审批已关闭，本子代理也无权放宽权限）。

### 本次踩到的坑（照做，别自己重踩）

1. **同名两处、质量不同。** `frontend-slides` 在 managed 是 13 文件真工作流，在工作区是 1216 B 桩；`frontend-design` 两份正文一样但 frontmatter 不同。**只看文件名会读错地方。**

3. **管道会吃掉 exit code。** `python x.py ... | Select-Object -First 20` 之后 `$LASTEXITCODE` 是**空的**，得改写成 `python x.py ... > $null 2>&1; $LASTEXITCODE` 才拿到真值（实测 `search -q` = 1、`--help` = 0、`--explain-routing` = 0、`extract-pptx.py` = 1）。
4. **`atlas` 的 `path` 是单值。** 它只告诉你「一条成员指向哪」，**不告诉你「这条还散落在别处」**。形态判定必须自己扫 root，不能只信 `path`。
5. **控制台编码会污染读数。** `search.py --help` 的中文副标题在 PowerShell 里显示成 `Web Search Plus �� Intelligent…`，那是**编码差异不是脚本报错**；别把它记成「脚本坏了」。
6. **`files=1 且 ~1.1–1.3 KB`** 是这套 catalogue 桩的**稳定指纹**（7 条 figma-*、3 条 design-*、4 条 frontend-*/web-* 都是这个量级）。**看到这个量级先去正文找 `od.upstream`，别急着读内容。**
