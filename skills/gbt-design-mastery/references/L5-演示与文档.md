## 1. 这条线是什么 / 边界

**一句话**：L5 管**"讲清楚"** —— 把已有内容（PDF / PRD / 数据 / 大纲）变成一份**静态、可交付的演示件或文档件**。

**出口**（json L5 `outlet` 原话）：`幻灯片 / 报告 / PDF→网页或幻灯片`。
实物形态：`.pptx` · 多页 HTML 幻灯片集 · 单页 HTML 网页 · `outline.json` / `summary.md` 这类结构化伴生件。

### 与相邻线怎么分（给判据，不给感觉）

| 相邻线 | 它管什么 | **分界判据** | 落到谁 |
|---|---|---|---|
| **L4 动效与合成** | 动起来（GSAP 网页 / HyperFrames HTML 合成 / Remotion React 三层） | **产物靠不靠时间轴驱动。** 翻页/滚动就切的**静态页** = L5；有时间轴、要渲染帧 = L4 | "HTML 幻灯片" → **L5**（`glmv-*`）；"滚动动画 / 转场 / 合成" → **L4** |
| **L7 视频与成片** | 出成片 mp4（剪辑/字幕/配音/导出） | **产物是不是一条媒体流。** L5 只交**页**，不碰媒体流；L7 交 mp4 | deck → mp4 是**跨线两步**：L5 出页 → L7 出片。**L5 不做这一步** |
| **L1 定档与审美** | 好不好看（设计读数 → 三档转盘 → 三轴 → AI 味禁令） | **"做得好不好看"回 L1 判；"做得对不对、出不出得来"由 L5 判** | 同一份 deck **两把尺子都过**（`pptx` 的 Part 1 就是 L1 口径在 deck 上的落法） |
| **L2 界面实现** | 可跑界面（页面/组件/原型/改版） | **入口方向**："从设计/改版出界面" → L2；"从 PRD/PDF 出件" → L5 | `glmv-prd-to-app` 会**顺带**出全栈应用，但**产线登记在 L5**；纯做界面归 L2 |
| **L3 设计稿与设计系统** | 令牌 / 设计系统 / Figma 双向 | L5 **不碰令牌**、不做稿↔码对齐 | 要令牌层 → **L3** |

### 🔴 三件 gbt-glmv 明确划走的（别自己发明）

1. **不做** PDF→Word/Excel/图片/音频 —— 本簇只有三条路：PDF→幻灯片 · PDF→网站 · PRD→应用。
   `pdf_to_images.py` 是**流程内部的一步**，**不是"PDF 转图片工具"**。
2. **不做**"改已有 PPT / 已有网站" —— 两条 PDF 技能都是**从 PDF 生成新的 HTML**，
   没有"读回已有 HTML 再改"的阶段。**它是生成器，不是编辑器。**
3. **不导出真 `.pptx`** —— `glmv-*` 的产物是**多页 HTML** + `summary.md`。
   要 `.pptx` 走 L5 内的 **pptx 簇**（那是另一簇，`gbt-pptx` 管）。

| **覆盖/删除用户已有 `.pptx`** | 直接写同名文件 | 破坏用户的原件 |
| **上传 / 发布成品** | 把 deck 发到任何公开或他人可见的地方、发给真人 | **不可撤回的社会动作**；`glmv-*` 原文**没有部署步骤** ⇒ **别自己加** |
| **装上游技能包** | `npx skills add https://github.com/MiniMax-AI/skills` | 出网 + 改技能目录（这是 `pptx-generator` 唯一的落地路径） |
| **动 `pptd_dsl.pyz.larkcache`** | 改名/恢复成 `.pyz` | **改的是别人技能的盘上状态**；🔴 **要不要恢复由主人定，本件绝不擅自动手** |

**顺序（照 gbt-pptx §5 / gbt-glmv §2.3）**：
① 先过闸一（报解释器 + 各依赖已装/未装）→ ② **摊开四件事**（身份 · 目标 · 内容 · 影响面，含输入绝对路径、
会改什么、产物落点、预期花费）→ ③ 能先只读就先只读（`pptd_guard.py` 只读 JSON 不落盘；`--help` 零副作用）
→ ④ **等一次明确同意**（**只覆盖这一次**，不是"以后这类都同意"；主人没回话 = **没同意**，停）
→ ⑤ 只执行被授权的那一批 → ⑥ **拿回执**（成品**绝对路径 + 页数 + 文件字节数** + 退出码原文）
→ ⑦ 失败就照原样记，**不许静默重试写操作**。
🔴 **`glmv-prd-to-app` 额外加一道**：跑 `start.sh` 之前必须**先把那份脚本摊给主人看**，逐条点出
①装系统依赖 ②**drop DB / reset** ③起服务占端口 ④`wait` 长驻。**没对"重置数据库"单独点头，就不许跑那一段。**

**关于花费（诚实说法）**：本簇**不产生 API 调用费用**（全是本机脚本 + 本机算力）。
**但别把它说成"零成本"** —— 它花 **CPU / 磁盘 / 时间**，而且 `glmv-prd-to-app` 会 `npm install` 拉一堆依赖。
⇒ 正确表述是 **"没有 API 计费，但有本机资源与磁盘占用"**，**不要编一个"预计花费"数字**。

## 5. 出一份稿该走哪条

### 5.1 按意图选路

| 人想要… | 走哪条 | 为什么 | 本机现在 |
|---|---|---|---|
| **从 PDF 出一套幻灯片** | `glmv-pdf-to-ppt` | 唯一一条 PDF→多页 HTML 幻灯片的路 | 🔴 **跑不起来**（`pymupdf` 未装，第 1 阶段 exit 1） |
| **从 PDF 出一页网站** | `glmv-pdf-to-web` | 同上，前 4 阶段与上条**同一套** | 🔴 **跑不起来**（同源） |
| **从 PRD + 原型图出全栈应用** | `glmv-prd-to-app` | 唯一一条 PRD→应用的路 | ⚠️ **脚本依赖齐，但缺 `/workspace` 上下文**（本机不存在）⇒ 跑不了 |
| **从零造一份可编辑 `.pptx`（要工作流）** | `pptx-swarm` | PPTD 中间层 + 页 agent 编排；主路 | 🔴 **出不了 `.pptx`**（`pptd_dsl.pyz` 缺件） |
| **要直接写代码造 deck / 要设计铁律** | `pptx` | Part 1 设计原则 + Part 2 pptxgenjs API 深用 | 🔴 **跑不起来**（`pptxgenjs` 与 `python-pptx` 都没装） |
| **审/修一份 HTML 导出的 `.pptx`** | `pptx-html-fidelity-audit` | 页脚轨 + 游标流那套几何校验（不靠视觉 diff） | 🔴 **跑不起来**（两脚本要 `python-pptx`） |
| **用 MiniMax 那套做 PPT** | `pptx-generator` | ⚠️ **它是桩** | 🔴 **它不能被"执行"**；要真用得先出网装上游 |

### 5.2 簇内两条"看起来重叠"的路，怎么分

- **`pptx-swarm` vs `pptx`**：`pptx-swarm` 原文写死一句
  *"once this pptx-swarm skill is selected, **do not switch to the non-swarm `pptx` skill merely because the deck has fewer slides**"*
  ⇒ **页数少不是降级理由**。`pptx` 是**供料**（设计铁律 + API 深用），`pptx-swarm` 是**产线**。
- **`pptx-swarm` 内部还有一条硬纪律**：*"Directly operating on `.pptx` files is **strictly prohibited**.
  All your operations should apply to `.pptd` files, then use the CLI tools to convert"*
  ⇒ **不许直接操刀 `.pptx`**。
- **`glmv-pdf-to-ppt` vs `glmv-pdf-to-web`**：前 4 阶段同一套（建目录 → DPI 120 转图 → 按序读完 →
  写 `outline.json` → `crop.py` 裁图），**从 Phase 5/6 起分道**。
  ⚠️ **转图那一步是重复劳动**，但**"转一次两边都能用"是推断、未验** —— **不许宣称能省这一步**。
- **`glmv-*` vs `pptx-swarm`（常被混）**：前者交 **HTML**，后者交 **`.pptx`**。
  **`.pptx` 必须走 `gbt-pptx` 那一簇**；`gbt-glmv` 明确**不做跨簇保证**。

### 5.3 🔴 本机现在到底能不能真出稿

**不能 —— 一条真路径都没有。** 逐条证据（都来自 §3 的实跑或 §4 的现读）：

| 路 | 卡在哪 |
|---|---|
| `glmv-pdf-to-ppt` / `glmv-pdf-to-web` | `pymupdf` 未装 ⇒ 第 1 阶段 `exit 1`（**已实证**） |
| `glmv-prd-to-app` | 脚本能起来，但 **`C:\workspace` 不存在** ⇒ 没有可跑的真实任务 |
| `pptx` | `pptxgenjs`（npm）与 `python-pptx` **都没装** |
| `pptx-swarm` | **`pptd_dsl.pyz` 缺件** ⇒ `convert.sh` `exit 1`（**已实证**） |
| `pptx-html-fidelity-audit` | 两脚本都报 `python-pptx is required`、`exit 1`（**已实证**） |
| `pptx-generator` | 目录桩，上游未装 |

**唯一"能跑"的是脚本的 `--help`**（§3.3 的 8 条 + §3.1 的 3 条，全 exit 0）——
但那证明的是 **"脚本能加载"**，**不是"能出稿"**。
⇒ 最硬的一句：**"设计铁律与工作流我都读全了，工具链还没装。"**

### 5.4 需要配图时往哪走

L5 出 deck 常要插图/配图。**那一步归 L6，不归 L5。** 见 `references/L6-出图与素材.md` §5
（结论同样不乐观）。`pptx-swarm` 的 `page_manifest.json` 与 L6 的 `visual-asset-director.md`
是**两边各自的契约**，别互相顶替。

## 6. 报告层红线

> 这一节的四句话，**每一条都对应本簇一个真实踩过的误读**。

1. **读数先问"这是事实，还是我读错了地方"。**
   - 例：`pdf_to_images.py --help` 正常 ⇒ **不能**推出"这个脚本能用"。真因是 `import fitz`
     写在**函数体里的惰性导入**，`--help` 根本走不到它。**同一份文件里，`--help` 的结论和真跑的结论相反。**
   - 例：`convert.sh` 报 `not found` ⇒ 是**缺件**（判据 `[ -f ... pptd_dsl.pyz ]` 不成立），
     **不是"PPTD 工具坏了"**，也**不是"权限被挡"**。**"东西不在" ≠ "门不让你过"。**

2. **"能调" ≠ "能用"。** 本簇 6 位真业务件的 `SKILL.md` 都写得像随时能用（有的 626 行、有的 34 个文件），
   但实测 **`pymupdf` / `python-pptx` / `pptxgenjs` / `markitdown` / `defusedxml` / LibreOffice 一个都没有**，
   `pptx-swarm` 的 `pptd_dsl.pyz` **根本不在盘上**。
   ⇒ **"技能描述得很完整"和"这台机器上跑得起来"是两件事。**

3. **"凭据文件在" ≠ "凭据有效"**（本簇变体）：本簇**压根不要凭据**，
   所以这里最容易犯的错是**反向的** —— **把"不需要凭据"说成"没配好凭据"**。
   🔴 别写"`GLMV_API_KEY` 未配导致跑不了"。**诚实说法：本簇无凭据需求，卡点在依赖。**

4. **"checker 说 OK" ≠ "成品合格"。**
   - `pptx-swarm` 的 `0 errors, 0 warnings` 是**它自己的 checker 说的**，不等于 deck 好看/能用。
   - `pptd_guard.py` 返回 `errors: []` **只说明"该有的文件都在"**，不说明"内容对"。
   - 两把尺子都要过：**"做得对不对"用本线规程判，"做得好不好看"回 L1 判。**

5. **不许把目录桩念成能力。** `pptx-generator` 的 frontmatter 写着 `od.mode: deck`，**看着像业务件**；
   "这是桩"那句写在**正文第 30 行之后**。它的原文原话：
   *"This catalogue entry advertises the skill in Open Design so the agent discovers it during planning."*
   ⇒ **它只能被"发现"，不能被"执行"。** 说"本机有 MiniMax 的 PPT 流水线"是**假读数**。

6. **`--help` 过了 ≠ 流程过了。** §3.3 的 8 条 `--help` 全 exit 0，而**整条工作流一次都没跑通**。
   报的时候必须把这两层**分开写**。
