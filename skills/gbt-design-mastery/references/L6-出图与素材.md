## 1. 这条线是什么 / 边界

**一句话**：L6 管**"图从哪来"** —— 生成、改图、抠图、超分、修复、3D、识图、搜图、上传，以及现成素材从哪取。

**出口**（json L6 `outlet` 原话）：`图像/素材产出（含 3D、抠图、超分、修图）`。
实物形态：本地图片文件 / **公网 `image_url`** / **`oss_url`** / 3D 资产 / LoRA 权重。

### 与相邻线怎么分（给判据，不给感觉）

| 相邻线 | 它管什么 | **分界判据** | 落到谁 |
|---|---|---|---|
| **L1 定档与审美** | 好不好看（设计读数 → 三档转盘 → 三轴 → AI 味禁令） | **L6 只管"出得来"；"出得好不好看"回 L1 判** | **两把尺子都要过**：L6 出图 → L1 判审美 |
| **L4 动效与合成** | 动效与视频合成（GSAP / HyperFrames / Remotion） | **产物是静帧还是时间轴。** 静帧 = L6；有时间轴 = L4 | 合成件里的**静帧贴图**归 L6；**合成动作**归 L4 |
| **L5 演示与文档** | 幻灯片 / 报告 / PDF→网页或幻灯片 | **谁主诉。** deck 是主诉 = L5；deck **需要配图** = 图那一步归 L6 | L5 出 deck 时往本线要图（见 §5） |
| **L7 视频与成片** | 成片（剪辑/字幕/配音/导出） | **产物是不是一条媒体流。** L6 交**静帧/3D 资产**；媒体流归 L7 | ⚠️ `fal-*` 里 `fal-kling-o3` / `fal-lip-sync` / `fal-video-edit` / `venice-video` **名字带 video**，但它们是**外部云端生视频**，产线登记在 L6；**本机剪辑成片归 L7**。别把两者混成一件事 |

### 三条外发红线（**本线的特殊风险**）

L6 是七条线里**最容易把数据送出去**的一条：本线的动作会**把本地素材传到公网**。

1. **`autoglm-file-upload` 本身就是"数据离开本机"** —— 它把文件传到 `autoglm-agent.aminer.cn`，
   回来的是**公网可访问**的 `oss_url`。**上传 = 外发**，必须过闸二，而且要说清是哪个文件。
2. `fal-*` / `venice-*` 是**外部算力**：调用即出网、即计费。
3. **`autoglm-remove-bg` 的 URL 模式会下载远端图**（默认本地模式不出网）。

### 🔴 本线内部"谁管什么"的裁决顺序

- `gbt-autoglm`：**本规程管纪律 → `AGENTS.md` / `IMAGE_GENERATION.md` 管流程落点 → 每条 `autoglm-*` 的 `SKILL.md` 管命令细节**。
- `gbt-fal` / `gbt-venice`：**本文件管纪律 → 各技能原文管它自己宣称的能力边界**。
- ⚠️ **`gbt-fal` 与 `gbt-venice` 两份都写明"查模型 / 查定价"要路由给 `gbt-arkcli`**，
  并写死一句：**BytePlus ModelArk 与 fal.ai / Venice.ai 是两个产品，定价与目录都不通用，别互相顶替。**
- ⚠️ **`gbt-fal` / `gbt-venice` 两份里没有 fal↔venice↔autoglm 之间的分工声明**（`gbt-autoglm` 里也没有 fal/venice 字样）。
  ⇒ **本件 §5 的那张选路表是本次现读推出的，不是抄来的**；三份规程各自只管自己那一簇。

## 6. 报告层红线

> 这一节的每一条都对应本线一个**真实踩过的误读**。

1. **读数先问"这是事实，还是我读错了地方"。**
   - 例：`generate-image.py` 无参报 **token 错** ⇒ **不能**推出"这脚本参数有问题"。
     真因是它**先取 token 再查参数** ⇒ **本地服务没起，就永远看不到用法**。
     对照 `generate-image-seedream.py` **先查参数**，同样 exit 1 却是另一种原因。
     **同样"exit 1"，两回事。**
   - 例：端口探不到 ⇒ **不能**说成"技能坏了"。是**取不到凭据**，不是脚本错误。
     🔴 **"端口不通" ≠ "技能坏了"**；**"东西不在" ≠ "门不让你过"**。

2. **"能调" ≠ "能用"。**
   - `fal-*` / `venice-*` 的名字与描述都很像能力，**但它们是"广告位"**：
     *"真正的脚本、资产、参考资料都不在本机"*。原文自己说
     *"To run the full upstream workflow … install the upstream bundle"*。
   - `autoglm-*` 9 条的脚本**真的在**，凭据那条链**却断在端口上**。
     **"脚本在"和"能出图"是两件事。**

3. **"凭据文件在" ≠ "凭据有效"**（本线变体，三个方向都要防）：
   - **正向**：`arkcli` 的 key `status: "active"` 是**读到的事实**，但**真出图没验过**。
   - **反向**：`AUTOGLM_*` 全空 ⇒ **不能**说"凭据没配"。**真凭据是本机 token 服务**，
     **去找环境变量会一无所获** ⇒ **`AUTOGLM_*` 未配不代表没配好。**
   - **第三个方向**：`autoglm.exe` **在 PATH** 只说明"**入口在**"，
     **不构成"浏览器能力可用"**。
   - 🔴 **三份规程写的凭据名（`FAL_KEY` / `VENICE_API_KEY`）本身就是"按通行约定记的"，
     不是从技能原文读出来的，也没装上游包核实过** ⇒ **引用时要说清这是约定名，不是原文事实。**

4. **"零作用域 ≠ 只读"。** 本线最重的动作（**上传、生图、发帖**）
   **恰恰可能没有任何作用域声明**。**没有任何作用域声明 ≠ 只读。**

5. **不许把"桩"念成"能力"。** `fal-*` / `venice-*` 的 frontmatter 里
   `od.mode: image` / `od.category: image-generation` **看着像业务件**；
   "这是桩"那句写在**正文第 30 行之后**。
   🔴 **"上游有" ≠ "本机装了"；"桩也不能被执行"。**
   ⚠️ 而且 `state/skill_atlas.json` 是**现扫产物**：规程里记的
   "`fal-*` 的 `desc` 读出来是 `"|"`"**本次现读已不成立**（现读有 91–146 字符的真描述）
   ⇒ **图鉴被重建过，旧读数会过期。别拿过期读数当现读。**

6. **`--help` 过了 ≠ 流程过了。** `autoglm-*` 的脚本 `--help`/用法**全都能打印**，
   而**整条云端链路一次都没真跑通**（§7）。**报的时候必须把两层分开写。**

7. **"能出个 PNG" ≠ "可交付素材"。** `remove-bg` 出了透明确实是真事实，
   但规程的交付闸（`image-recognition` 质量评估）**要 token** ⇒ **整链没通**。
   **别把"某一步能跑"写成"这条线能用"。**

8. **不许编单价、不许编目录、不许编队列查询。**
   `fal-*` / `venice-*` **没有**模型目录、**没有**定价、**没有**队列/配额查询能力 ⇒
