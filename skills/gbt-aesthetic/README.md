# gbt-aesthetic · 发现层

> 这一份是**给"该不该用它、和谁一起用"看的**，不是规则正文。
> 规则正文在 [`SKILL.md`](SKILL.md)，逐字对照在 [`references/`](references/)。

## 一句话

**"好看"不是感觉，是四步**：先做设计读数 → 再定三档转盘 → 然后按三轴选型 → 最后过 AI 味禁令与验收。
配一个**能跑的审计器**（`tools/codex-scripts/audit_aesthetic.py`），把"AI 味"从嘴说变成能指行号、能让退出码非零的检查。

## 什么时候用它

| 你手上的活 | 说明 |
|---|---|
| 做/改**任何界面** | 落地页 · 仪表盘/看板 · 后台 · 移动端 · 组件 · HTML/CSS 版式 |
| **美化 / 打磨**已经存在的页 | 走 §6 重设计协议（先判模式：全新 / 保守改版 / 推倒重来） |
| 出**海报 / artifact / PPT 页面** | 触发面按上游口径放宽到这些（见 SKILL.md frontmatter） |
| 说"太模板了 / 有 AI 味 / 没设计感" | §3.0 三种默认长相 + §3.1 可机检禁令表 |
| 给**自己的设计**找茬 | §1.7 跨次不收敛自查 + §3.0.1 签名元素三种死法 |

## 🚫 什么时候别用它（同样重要）

> ⚠️ 这一节的字面写法别改：发现层 linter 按**字面串**判（`什么时候别用` / `不适用` / `When NOT`…）。
> 我第一版写成 `什么时候**别**用它`（加粗打断字面），被 linter 判成"缺" —— **内容对了、形状不对，照样过不了门。**

| 场景 | 该走哪 |
|---|---|
| **代码本身**好不好读、命名、技术债 | → `gbt-code-taste`（配 `audit_code_taste.py`） |
| 要**出图 / 生视频 / 剪片**这类素材产物 | → `gbt-design-mastery`（判是哪条设计线）· 出图走 `visual-asset-director` |
| **后端 / 算法 / 数据管道** | 本件只管"人看见什么"，别拿它审接口设计 |
| 给**受监管 / 公共部门 / 无障碍关键**的页面"加个性" | §1 分流表：这类隐性约束**压过审美偏好**，取保守档 |
| 只是**问一个颜色/字体的取值** | 直接答，不必启动四步流程 |
| 已经明确要求**照某个设计系统做** | 走 §2 三轴：用官方包，别自己发明 CSS 去模仿 |

## 和谁一起用（相邻技能导航）

| 什么时候 | 走哪 |
|---|---|
| **不知道该用哪条设计线**（设计/出图/动效/PPT/剪片） | 先 `gbt-design-mastery`（七条线的总决策流） |
| **要落地页/前端实现** | `gbt-frontend`（frontend-* 四条怎么用、哪些是桩） |
| **要看真页面**、截图对比、验收 | `tools/codex-scripts/render_page.py`（本仓的渲染取证器） |
| **要审代码**而不是界面 | `gbt-code-taste` |
| **要做成片/动效** | `gbt-hyperframes` / `gbt-remotion` / `gbt-gsap` |
| **要出素材图** | `visual-asset-director`（先立 Visual Style Contract 再出图） |
