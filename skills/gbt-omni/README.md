## 它解决什么问题

人只会说"**让框架去做某件事**"。而框架里有**上百个能力位 + 本机工具 + 装好的技能**，
落点、命令、要过的门**不该由人去背**。本件把这条链定死：

```
人一句话 → 落到哪个能力位/工具/技能 → 该跑哪条命令 → 要过哪道门
```

## 什么时候用它 ✅

- 想「**让框架去做某件事**」，但不知道该调哪个能力位 / 哪条命令
- 想知道**某个职业域有哪些能力可以调**（`omni list --domain <域>`）
- 想让框架**真跑**一件只读无参的事（`omni run`，默认拒绝，只自动跑能证明安全的）
- 看见"**报得出名字但点下去没反应**"这类症状，想知道到底卡在哪一层
- 需要**口径对账**（同一件事的多个数，哪个才是权威）

## 什么时候**别用**它 ❌

- **只是要跑一条已知的本地工具**（如 `quick_scan.py`）—— 直接跑，不必经过 `omni ask` 绕一圈
- **要过授权门的有后果动作**：本件**只给命令与门名**，**不代授权、不绕门**；缺授权就如实报缺
- **外部 CLI 的计费动作**（Ark / fal 等）：它们有**自己的门与账单**，走各自技能（`gbt-arkcli` / `gbt-fal`…）
- **想让它"自动把生产写好"**：本件**永不**因为"听起来是个好主意"就自动写生产；那条不改
- **要读某一门专业手艺的细节**：那是各 `gbt-*` 规程的活（如 `gbt-tentacle` / `gbt-security`），本件只负责**路由**

## 怎么用（一句话示例 + 预期结果）

```powershell
py -3.14 tools/codex-scripts/omni.py ask "扫一下这台电脑有没有病毒木马后门"
```

**预期结果**（这是判据，不是愿景）：
1. **本地工具面排在最前**，第一条是**真扫描器**（`quick_scan`），不是能力位；
2. 每条候选**带可达性**（`✅ 可达` / `🔴 加载不了`）；
3. 带后果的候选**逐条说明要过哪道门**（作用域名 + 怎么授权）；
4. `ask` **不写盘**（图鉴 mtime 不变，这一点可核对）。

跑真活（默认拒绝，五维默认路径）：

```powershell
py -3.14 tools/codex-scripts/omni.py run "看一眼框架健康不健康"
```

**预期结果**：打印「走的哪条路」（`sync_exec.run` 五维默认路径 / 退回 `five-dim.py cap`）·
信封状态 · 五维判决 · **嘴说漏了什么**（`missed`）—— 缺授权时**如实报缺**，不绕。
