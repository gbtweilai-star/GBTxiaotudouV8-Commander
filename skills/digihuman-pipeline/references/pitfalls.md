## 1. 判据类

### 1.1 判据没有自证找到了目标 ⇒ 整组读数作废
- **现象**：为了量"渲染清晰度"，我按"非背景像素的上 22%"自动取脸部 ROI。结果 ROI 取到了 **HUD 文字区**（HUD 也是非背景）—— 于是"清晰度提升 +5.3%"测的是 HUD，**结论作废**。
- **规则**：任何自动 ROI / 自动定位，必须附带**自证条件**：
  - 肤色占比检查（如 HSV 中 H 在 5–50、S 在 0.1–0.6）；
  - 排除已知叠加层（HUD 区域直接裁掉，或渲染时 `?hud=0`）；
  - 输出 ROI 裁图**供人眼复核**（这次就是靠裁图才发现取错了）。

### 1.2 判据对被测项不敏感 ⇒ 不能拿它下结论
- **现象**：用"梯度方差"衡量**超采样抗锯齿**，读数几乎不变（304.6→304.2）；用"轮廓锯齿度"衡量，两条都是 0.000（此取景下轮廓本就平滑）。
- **规则**：选判据前先问"这个指标对我要改的东西敏感吗"；不敏感就换（抗锯齿应量**边缘过渡宽度/频谱高频能量**），或者**承认该由人眼判**并给出对照图。

## 2. 几何/骨架类

### 2.1 子节点平移写成绝对坐标 ⇒ 绑定姿势错成 A-pose
- **实证**：`Shoulder→Hand` 夹角算成 **-38.8°（A-pose）**，改相对父节点后 **+2.1°（正确 T-pose）**。
- **原因**：glTF 子节点 `translation` 是**相对父节点**；写绝对坐标会被逐级累加。

### 2.2 复制 children 索引 ⇒ 自环 ⇒ 死循环
- **实证**：复制来的 children 索引整体偏 1，导致 **17 个骨骼节点把自己列为孩子**；求世界坐标的 `while` 永不终止（脚本卡死、还拖垮了一台机器的命令环境）。
- **规则**：层级**只由 `PARENT` 表重建**；重建后断言：无自环、父链可终止、根节点正确。

### 2.3 变量改名漏改引用 ⇒ 半路 NameError
- **实证**：`bone_nodes` 改名 `bone_ids` 后 119 行仍在用旧名 → `NameError`，且被我自己的 `Select-String` 过滤吞掉，误判为"内存问题"。
- **规则**：脚本失败时**先看完整输出**（别过滤），再谈原因。

## 3. GLB 读写类

### 3.1 块不对齐 ⇒ 加载器解析崩
- **实证**：姿态测试件报 `Cannot read properties of undefined (reading 'extensions')`；根因是 JSON 块未按 4 字节补空格（绑骨件当初是**碰巧**对齐才侥幸能加载）。
- **规则**：写出 GLB 必须补齐（JSON 补 `0x20`，BIN 补 `0x00`），并**自证**：`JSON 块长 % 4 == 0`。

### 3.2 深拷贝后共享状态 ⇒ accessor 指向越界
- **实证**：`J2 = deepcopy(J)` 之后仍用写 `J` 的 `add_view()`，结果 `accessor[7].bufferView = 10` 而只有 10 个 bufferView（0..9）。
- **规则**：往副本写就用副本的容器；写完用 `validate-glb.py` 过一遍引用完整性（它能一句话点破这类错）。

### 3.3 贴图语义别猜
- **实证**：按 `images[0]` 取 baseColor，结果取到**法线贴图**（紫底）—— 正确做法是按材质槽位解析：`materials[0].pbrMetallicRoughness.baseColorTexture.index → textures[i].source → image[i]`。
- **附带**：Tripo 下载的 `preview.png` **字节常是 JPEG**（扩展名骗人）—— 读取前用 `normalize-image.py` 按内容识别。

## 6. 材质类（2026-09-22 两次实证打回）

### 6.1 重建材质 + sheen ⇒ 黑衣被洗成褐色
- 现象：为做"皮肤次表面"把 GLB 材质重建为 `MeshPhysicalMaterial`，给 `sheen: 1.0`，结果**黑衬衫/黑裙渲染成褐色**。
- 判据：同一模型同一相机 A/B ⇒ **保留 GLB 原材质**时黑衣纯黑、重建时发褐。
- 口径：**不重建材质**；要加效果只加"环境反射强度"这类不改变基础色的项。

### 6.2 用肤色遮罩把 sheen 只上皮肤 ⇒ 满身雪花噪点
- 现象：运行时按肤色生成 `sheenColorMap` 遮罩 + `sheen 0.6` ⇒ 皮肤与衣服出现**砂纸状噪点**。
- 根因：这件资产的 **baseColor/normal 都是 1024²~2048² JPEG**，任何"细节增强/遮罩相乘"都会把**压缩噪点**放大。
- 口径：**先看贴图是不是有损压缩**；JPEG 贴图上不做细节增益。要提逼真度应换**无损或更高分辨率贴图**，而不是在噪声上做增强。

### 6.3 在 1024² JPEG 法线上再烘 detail-normal ⇒ 细节变噪点
- 现象：从 albedo 高通提细节混入法线（xy 能量 0.244→0.53）⇒ 表面呈砂纸状。
- 口径：detail-normal 只对**无损/高分辨率**法线有意义；对 JPEG 法线是**放大噪声**。


### 6.4 4K 重贴能治"脏"，治不了"不像"（A/B 实证 2026-09-22）
- 做法：对同一任务 `--then "texture:extreme, convert:gltf, texture_size=4096, texture_format=PNG"`（30+10 积分）⇒ 贴图从 2048² JPEG 变 4096² PNG。
- 读数：顶点/POSITION/TEXCOORD **逐一相同**（sha 一致）⇒ 骨架可直接搬；文件 44.43MB → 86.65MB。
- **A/B 结论（肉眼）**：4K 只让画面**更干净**（JPEG 斑块消失），**五官并没有更清楚**。
- ⇒ **逼真的瓶颈是几何与源信息，不是贴图分辨率。** 脸的形状来自"从 ~200px 源图猜出的通用头型"，把同一份信息放大到 4096² 变不出新细节。
- 附带判据教训：**JPEG 噪点会抬高"梯度方差"** ⇒ 用它对比有损/无损贴图会得出反向结论；且自动/固定裁切都必须先自证框到了目标。

### 6.5 派生：`texture` 步骤的参数口径（读 CLI 白名单得来）
- `texture:<quality>`，白名单 **standard / detailed / extreme**（detailed/extreme 价签更高）；
- 贴图**尺寸/格式**不在 texture 步骤，而在 **convert** 步骤：`texture_size` / `texture_format`；
- 贴图模型版本白名单：`v3.0-20250812`（默认）/ `v2.5-20250123`；
- 链写法：`texture:extreme, convert:gltf, texture_size=4096, texture_format=PNG`（`=` 段自动归属前一步）。


### 6.6 **脸部几何的真正杠杆：把生成预算全给脸**（head-only pass，2026-09-22 实证）
- 做法：拿**干净脸部特写**单独图生（`make ref-face-clean.png --then texture`，40 积分）。
- 结果：`raw/portrait-bust.glb`（755,556 顶点 / 1,451,528 三角形 / 2048² 贴图）—— 眼睛(眼睑+瞳孔)、眉、鼻梁鼻翼、唇形、下颌、耳环项链、发丝**全部清楚**，肉眼就能认出是她。
- **同取景对比**：身体模型（762k 顶点、4K 贴图）的脸明显更糊。
- ⇒ **口径：要脸像，就单独为脸开一次生成**（预算全给脸），再考虑并回身体；只在全身模型上堆分辨率没用（见 6.4）。
- ⇒ 下一步（已想清）：① 头肩胸像**可独立作为"头肩形象"交付**（说话型数字人最常用形态）；② 若要并回身体，走"颈部切面 + 缩放/位置对齐 + 焊缝 + 头部区域重权"。

## 8. 头身嫁接（head graft）· 核心技能（抓自行业做法 + 8 版实测）

**行业口径**（Blender 官方社区，版主/资深绑定师原话，链接见交接件）：
> 头网格与身体**分开、不焊接**，两者都只 **armature deform 到同一套骨架**；**"颈部尺寸不同"才是接缝的根因**；接完必须**检查颈部是否有可见问题**。

**八版实测得到的可复用结论**：
1. **缩放按"头高"定，不按"颈部半径"** —— 身体切口在**脖子**（半径 0.073）、胸像切口在**胸口**（半径 0.315），两者解剖位置不同 ⇒ 半径不可比。v7 按半径匹配把头缩到 0.232（错）。
2. **颈线用解剖比例，不用宽度启发式** —— T-pose 下"最宽"量到的是**双臂展幅**（实测 0.983）；胸像侧"最窄"会取到**头顶**（头发+衣领让颈部更宽）。⇒ 身体：头顶下 **0.125×身高**；胸像：头顶下 **0.40×自身高度**。
3. **对齐 = 头高比 × 0.93 + 颈截面水平居中 + 底部下沉 0.02**（沉进领口，接缝被衣领遮住）—— v8 实测接缝基本不可见。
4. **权重**：头部只用 HeadTop/Head/Neck（按到骨段距离），颈圈归 Neck ⇒ 与身体同骨同步形变，转头不裂。
5. **别用字符串补丁改脚本**（PS 锚点反复失配、正则半中）⇒ 用**索引定位**或直接重写整块。


### 8.1 头身嫁接 · 定稿参数（v10 · 审美合格）
- **身体颈线** = 头顶 − **0.125×身高**（8 头身标准；T-pose 下不能用宽度启发式）
- **胸像下巴线** = 头顶 − **0.40×自身高度**（头肩胸像的头部约占上方 40%）
- **缩放** = 头高比 × **0.965**（头高 ≈ 0.121×H，1/8.3 头身；×0.93 偏小、×1.0 偏大）
- **对齐** = 颈截面水平居中 + 底部**沉入 0.007**（核心口径：领口上方应露 **0.02–0.03×H** 的短颈；沉太多=没脖子，沉太少=露缝）
- **权重** = 头部只用 HeadTop/Head/Neck，颈圈归 Neck（同骨同步形变）
- 判定：**审美合格**（短颈自然 · 接缝藏在领口边缘下 · 比例标准）


### 9.1 面板静态路由的硬上限 = **12MB**（读源码得到，不是猜）
- `plugins/gbt-master/lib/host.js:29` `const MAX_BYTES = 12 * 1024 * 1024`；`:297` `fs.readBytes(..., MAX_BYTES)` 超限即抛 → **HTTP 500**。
- 实测：3.22MB ✓ 通过 · **26.88MB ✗ 500** · 61MB ✗ 500 ⇒ 与"大小阈值"无关的其他解释全部排除。
- **⇒ 面板档硬指标：< 12MB**（贴图 + 几何全部算在内）。
- 推论：分区 LOD 时**头不能留 354k 顶点**（独占 ~15MB）⇒ 头降到 **60–90k 三角形** 且贴图用 2K JPEG；Tripo 的 `decimate` 上限只有 20k ⇒ **需要本地减面**（顶点聚类/体素合并，保 UV 用代表点）。


## 10. 面板档减面（Round 6）· 顶点聚类不可用于带 UV 缝的脸

- **做成了**：`raw/rig/model-panel-tier.glb` **7.87MB**（身体 27,040 + 头 80,962 三角形）· **路由 HEAD 200**（12MB 上限内）· 引用合法。
- **但审美不合格**：聚类 + 拉普拉斯平滑把**脸打碎**（五官成碎片、破洞尖刺）。
- **根因**：顶点聚类会把**跨 UV 缝的顶点并到一起**（属性取格内均值）⇒ UV 撕裂、细碎面并成垃圾；平滑再放大破面。
- **口径**：带 UV 缝的脸部网格**不能用顶点聚类减面**；必须用**保 UV/边界**的方法（QEM 边坍缩，或 Blender Decimate Collapse 保 UV 与接缝）。
- **体积口径（实测）**：孤儿贴图会白占体积 —— 材质不再引用后图仍躺在 buffer 里（本例 metalRough 两张 **5MB**）⇒ 必须 `prune-glb.py` 修剪：**16.02MB → 7.87MB**。
- **面板档体积经验式**：几何 ≈ 顶点数×56B + 三角形×12B；**贴图是主项** ⇒ 只留 baseColor+normal 且 2K JPEG。


## 11. 次级动力学（弹簧骨）· 核心口径（Round 7 抓取）

**标准来源**：**VRMC_springBone-1.0**（VRM 规范）与 Unity/UniVRM SpringBone、DynamicBone。规范参数就四个：
`stiffness`（刚度/回正力）· `dragForce`（阻尼）· `gravityPower`（重力）· `hitRadius`（碰撞半径）。

**积分步（每一步照做，别自创）**：
```
next   = parentWorld · restLocal          # 静止位经父骨世界变换 = 本帧"目标位"
bias   = next − current
vel   += bias * stiffness * dt            # 回正
vel   *= (1 − dragForce * dt)             # 阻尼
vel   += gravity * gravityPower * dt      # 重力
current += vel * dt                       # 积分
current = head + normalize(current − head) * restLength   # 投影回骨长（长度硬约束）
bone.rotation = 由 (current − head) 构造的朝向
```
**规则**：① 弹簧骨**只允许旋转**、长度由投影硬约束；② `stiffness` 越大越"硬"、`dragForce` 越大回弹越快停；③ 根骨必须**平滑混权**到父骨（否则根部撕裂）；④ 每根骨的模拟是 O(1)，8 根骨在浏览器里开销可忽略。

**本项目区域读数（实测，低模全身件 `model-rigged-anim.glb`）**：
- 裙摆：y **−0.024（髋）→ −0.260（膝）**；半宽 x 0.092→0.031、z 0.137→0.073（**该带包含腿，须按半径剔除腿**：距腿轴 > 腿半径的才算裙）
- 头发：y **0.386（颈）→ 0.500（顶）**；半宽 x 0.068→0.052、z 0.074→0.043（后侧+两侧为主）
- 现有权重：裙摆已"**布料归髋**"（2031 顶点）；头发并入 Head/Neck

**实施计划（下轮直接做）**：
1. 加骨：裙 **4 根**（前/后/左/右，从髋环到裙摆）+ 发 **2–4 根**（后 1 + 两侧各 1）
2. 重权：区域内顶点 → 新骨（根部 30% 与父骨混权）
3. 页面侧：按上面积分步跑 JS 弹簧（每帧 O(骨数)）
4. 验收：帧条显示"髋动 → 裙/发滞后与回弹"；判据=滞后相位存在且不过冲发散


### 11.1 glTF 陷阱：`JOINTS_0` 是 **joints 数组下标**，不是节点号（Round 9 实证）
- 现象：给网格加 4 根弹簧骨后，three 报 `TypeError: Cannot read properties of undefined (reading 'matrixWorld')`。
- 二分定位：只加骨 ✓ 能加载 · 只改权 ✓ 能加载 · **两者同做 ✗ 必炸** ⇒ 说明是"权重引用的索引"与"joints 数组"错位。
- 根因：`skin.joints = [节点号…]`，而 `JOINTS_0` 里存的数字是**在 joints 数组里的下标**。我写成了**节点号**（24..27），而它在 joints 数组里的下标是 22..25 ⇒ 越界 ⇒ `bones[26/27]` undefined。
- 正确写法：`jid = len(旧 joints) + k`（新骨在 joints 数组中的位置），`hips` 也用 `joints.index(hips_node)`。
- 教训：**索引语义必须从规范确认**（glTF/VRM 这类格式里同名索引往往有两套语义）。


### 11.2 次级动力学的瓶颈常不在参数，而在**父骨有没有动**（Round 10 实证）
- 现象：裙摆弹簧只摆 **0.8°**（几乎看不见）。我先把 stiffness 0.45→0.18（更软）仍只有 0.8°。
- 根因：**激励不足** —— 我的 walk 里髋部动作太小（yaw ±4° / roll ±2° / 起伏 0.020），父骨不动，弹簧无从滞后。
- 处理：把走路本身做自然（髋 yaw **±9°** / roll **±4°** / 起伏 **0.028**）⇒ 弹簧偏角立刻到 **7.12°**（区间 0.4–7.1°，阻尼收敛不发散）。
- 口径：**先保证父骨有真实动作，再谈弹簧参数**；调参优先序 = 激励 → stiffness → dragForce → gravityPower。
- 附带收益：走路本身也更自然（一举两得），且 clip 循环闭合仍为 **0.00000**、步幅比 0.550 不变。


### 11.3 头发弹簧：区域必须**剔面部**（Round 12）
- 区域判据（实测可用）：`y > 颈线 + 0.03` 且 `(x < 0.02 或 |z| > 0.05)` —— 脸在 **+X**，所以"后半身 + 两侧"才是头发；不做这个剔除会连脸一起甩。
- 命中：**752 / 16,017 顶点**（低模头部占比合理）。
- 参数（比裙硬）：stiffness **0.25** / dragForce **0.45** / gravityPower **0.35**；父骨 = **Head**；根部与 Head 混权。
- 实测（7 骨同开，走路）：偏角 **1.7°–13.75°**（峰值 13.75°），阻尼收敛、无报错。
- 口径提醒：`jid = len(旧 joints) + k`（joints 下标 ≠ 节点号，见 §11.1）。


## 12. 保 UV 减面（Round 13）：正解与残余

- **库要按解释器查**：`trimesh`/`scipy` 在 **`python`(3.12)** 与 3.14 上有，**3.10 里没有** —— 我此前判定"trimesh 无"是查错了解释器。
- `trimesh.simplify_quadric_decimation` 只是包装，真正内核是 **`fast_simplification`**（`pip install fast-simplification` ~2MB）；
  `trimesh.proximity.closest_point` 需要 **`rtree`**（`pip install rtree`）。
- **UV/权重回传的三种做法与结果**（同一件头，QEM 到 7.5 万三角形）：
  1. **最近邻顶点**（cKDTree）⇒ 脸上**大片黑尖片**（跨 UV 缝取到黑衣区）✗
  2. **面上最近点 + 重心插值**（`closest_point` + barycentric）⇒ **黑片基本消退、五官可读** ✓（首选）
  3. 法线也要**插值**而非取面首顶点（我这版还没做，是残余碎片的一个来源）
- 残余：额头/发际线仍有少量碎片 ⇒ 下一步：法线插值 + UV 按岛钳制，或对该区域局部保留高密度。
- 面板档体积链：QEM 后 15.99MB →（`prune-glb.py` 剪孤儿贴图）→ **7.84MB** → 路由 **HEAD 200** ✓。


### 12.1 结论：只用"回传方法"救不回 QEM 后的脸（Round 13–14 三次实证）
- 已排除的三个嫌疑：① 贴图/光照 ② 法线（改重心插值后碎片仍在）③ UV 极值（按面钳制后仍在）。
- **真因**：原始头部网格的 **UV 岛边界存在近重合顶点**，QEM 边坍缩会**跨岛合并**它们 ⇒ 无论怎么回传属性都救不回。
- **正解**：**缝边锁定的 QEM**（collapse 时禁止跨 UV 缝/材质边界的边坍缩）—— 属 DCC（Blender/重拓扑工具）级能力；
  纯 trimesh 无此开关。⇒ 结论：**面板中景档的脸不在现有工具能力范围内**，别在它上面继续堆补丁。
- **交付定档（推荐且已按此执行）**：
  ① 面板实时档 = **现有 16k 低模**（干净、可服务、已带 7 根弹簧骨）
  ② 出图档 = **v10 高模 119MB**（审美合格的脸）
  ③ 中景档（7.84MB QEM）**不设为默认**，留作"缝锁定 QEM 到位后"的候选


## 13. pymeshlab 缝保护 QEM（Round 16）· 能力到位，卡在导出中转

- **正解能力**：`pymeshlab` 的 `meshing_decimation_quadric_edge_collapse_with_texture(targetfacenum, preserveboundary=True, preservenormal=True, planarquadric=True)` —— **保边界/保纹理**的 QEM；实测 354,306 → **75,000 面**，库内 `has_wedge_tex_coord()=True` ✓（自写近似做不到的就是这层）。

### 13.1 我自己的 bug：OBJ↔glTF 的 **V 轴相反**（下一轮一行修）
- pymeshlab 只能导 **`.ply` / `.obj`**（`.gltf/.glb` 均不认，已实测）。

### 16.2 三条"环境契约"（读源码/实测得到，别猜）
- **面板路由是三段白名单**：`TYPES[ext]`（扩展名 —— **没有 `.vrm`**）· `DENY[段名]`（目录 —— **`tools` 被禁**）· `MAX_BYTES = 12MB`。
  ⇒ 要被页面加载的任何东西必须同时满足三者；VRM 测试时以 `.glb` 名供路由（字节相同、容器相同）。
- **进程/解释器**：`shutil.which()` 返回的是**全路径**（`.CMD` 裸名 subprocess 不认 ⇒ FileNotFoundError）；
  库要**按解释器查**（trimesh/scipy 在 3.12/3.14 有、3.10 没有）；npm 全局命令走 shell。
- **CDN importmap 必须核验**：写死小版本号可能 404；用区间（`@3`）+ **导入失败自报**（否则门只会说"无读数"）。

- **"谁能读"比"我写对没写对"强**：最终验收交给**别人的官方实现**（three-vrm 读出 21 语义骨 / 3 表情 / 7 弹簧关节）。
