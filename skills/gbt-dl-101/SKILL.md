## 0. 开工读数（选型之前先问三件事）

**别一上来就问「用哪个模型」。** 指挥官的三问，顺序不能反：

1. **输入是什么形态？** —— 序列（文本/语音/时序）/ 图像视频 / 结构化表格 / 混合
   → 直接决定**架构族**（进 §1 的九叉表）
2. **有没有现成的？** —— 预训练模型、云 API、本仓已有能力位
   → **有就派，没有才训**（`gbt-ai-101` §5：先派 → 再买 → 最后才造）
3. **数据有多少？** —— 海量 / 中等 / 少量 / 没有
   → 海量可从零训；中等适合微调；少量只能提示词+检索；**没有 → 先收数据**

**读数出口**：三问答完，选型叉基本**只剩一个**候选。
如果还有三个候选在纠结，说明第一问（输入形态）没答干净，回去重答。

## 1. 九讲地图 = 九把选型叉（本件核心）

6.S191 的九讲，在工程师眼里是九章教材；在指挥官眼里是**九个叉路口**——
每一讲对应"一类输入 → 一族架构 → 一类任务"。

| # | 讲题 | 教什么（一句） | 指挥官要记的（一句） | 本仓落点 |
|---|---|---|---|---|
| L1 | Intro to Deep Learning | 神经网络的基础件：数据 · 模型 · 损失 · 优化 | **四件套缺一不可**；缺哪个补哪个，别急着换架构 | 一切产线的底座 |
| L2 | Deep Sequence Modeling | 序列建模：RNN/LSTM → 注意力 → **Transformer** | 一切"有先后顺序"的输入都归这叉：文本、语音、时序 | LLM 链 + 语音线（字幕/配音） |
| L3 | Deep Computer Vision | 视觉：卷积 / 池化 / 感受野 | 图像视频类任务归这叉；**画面质检也能用** | `vision` 域 + filmkit 素材验收 |
| L4 | Deep Generative Modeling | 生成：VAE / GAN / **扩散** | "从无到有造内容"归这叉；生成要**种子锁定**才可复现 | 生图线（pollinations/flux，扩散族） |
| L5 | Deep Reinforcement Learning | 强化：智能体 · 环境 · 奖励 · 策略 | "靠试错越做越好"的活归这叉；**奖励设错 = 学会钻空子** | 复刻 / 迭代优化循环 |
| L6 | New Frontiers | 前沿：LLM 智能体、多模态 | **我们就在这一讲里面**——触手 + 万能插就是智能体范式 | `run_task` + 178 能力位 |
| L7 | The Three Laws of AI | AI 的"三律"：伦理与安全 | 红线永远优先于效果（详见 §4） | `policy` + 生产面红线 |
| L8 | AI for Science | 科研应用：用 DL 解科学问题 | "数据找规律"的科研活归这叉 | `recon` / `data` 深蒸 |
| L9 | Massively Parallel Training | 大规模并行：数据/张量/流水线/序列并行、ZeRO、FSDP、MoE | **算力纪律**：并行不是快，是"不炸内存"（详见 §5） | 负载闸 `--batch` + 能源池 + 派云 |

**指挥官用表法**：拿到活 → 用 §0 三问定位 **1-2 行** → 按该行的"落点"直接派。
**跨叉的活**（如"给片子配音"= L2 序列 + L4 生成）就**串两条线**，别硬塞进一叉。

### 1.1 每个叉的一行补充读数

- **L1 四件套**：数据（燃料）/ 模型（引擎）/ 损失（考核标准）/ 优化（改进方式）。
  **指挥官最常犯的错**：考核标准（损失）定错了，却去怪模型不努力。
  → 对应我们的验收纪律：**先定验收线（三板块总监令），再动手**。
- **L2 序列**：现代序列建模的默认答案就是 **Transformer**（注意力机制）；
  RNN 家族是历史脉络，知道"为什么被取代"（长距离依赖）比会手写更重要。
  → 对应：我们的 LLM 链是"选供应商 + 定契约"，不是"自己训一个"。
- **L3 视觉**：卷积的本质是"局部看 + 权值共享"；**感受野**决定"一次能看多大"。
  → 对应：画面验收要**看整帧也要盯局部**（我们的六格/八格验收就是多感受野）。
- **L4 生成**：VAE 学潜空间、GAN 对抗互搏、扩散逐步去噪——
  **当下主力是扩散**（我们的生图线即此族）。
  **铁律**：生成必须**留种子**（seed 锁定），否则不可复现 = 不可审计。
- **L5 强化**：奖励函数是**指挥官写的工作说明书**——
  写歪了，智能体就会用你没想到的方式拿满分（钻空子）。
  → 对应：我们的迭代优化循环，先写清"什么算好"。
- **L6 前沿**：LLM 智能体 = 会调工具的模型。
  **我们没有在追前沿，我们就住在前沿**——触手模式就是这一讲的落地形态。
- **L8 科学**：这一讲给的是"用 AI 做发现"的范式：**数据 → 假设 → 验证**，
  与我们的 `devour` 蒸馏（读 → 提炼 → 固化三处）同构。

## 2. 三个 Lab = 三条手艺线（练手方法论）

6.S191 的三个实验不是"作业"，是**三条手艺线**——每条线练一种"能把架构变成产物"的本事：

| Lab | 书里的题目 | 练的手艺 | 本仓对应线 |
|---|---|---|---|
| Lab 1 | Python 深度学习 + **音乐生成** | 序列生成的最小闭环 | **音乐线**（板块三，待生成源落定） |
| Lab 2 | **人脸检测系统** | 视觉任务的检测闭环 | `vision` 域（画面验收/质检） |
| Lab 3 | **微调一个 LLM** | 把通用模型改成自己的 | **potato 链**（8111 位 → GPU 到位即真脑） |

### 2.1 书里的练手方法（照抄不要改）

6.S191 的实验设计强调：**task-based（任务驱动）· 自己填 `#TODO` · 自定进度 · 竞赛收尾**。
这四条与我们已有的纪律**逐条同构**，所以直接吸收为手艺线规程：

| 书里 | 我们的同构纪律 |
|---|---|
| task-based（每步有产出，不是读文档） | 幂等重跑：每步落盘可验收（`filmkit` list 状态表） |
| 自己填 `#TODO`（关键处亲手做） | **脑眼手三同步**：执行 → 看真实结果 → 再决定下一步 |
| self-paced（自定进度） | 长跑任务分批（`--batch`），不追一次性全量 |
| 竞赛收尾（拿真实标准评分） | **三板块总监令**：过标准才交付，缺一不交付 |

### 2.2 三条手艺线的当前状态（读数带日期）

- **音乐线**：装配位已就绪，**生成源待落定**（Suno / 网易天音 / Colab YuE 三选一）——未验。
- **视觉线**：`vision` 域已在册（1 能力位，门=privacy_read）；filmkit 六格/八格验收在用。

## 5. 大规模并行训练 → 我们的负载纪律（L9 的指挥官读法）

L9 讲的是**多 GPU 怎么把大模型训起来**：数据并行 / 张量并行 / 流水线并行 / 序列并行，
外加 **DeepSpeed ZeRO · FSDP · MoE** 这些省显存/扩容量的招。

指挥官的读法**不是"并行好快"**，而是：**并行的本质是"把装不下的东西拆开装"**——
拆的是什么（数据/张量/流水线/序列），省的就不是一回事。

本仓的同构纪律（已有实物，不是愿景）：

| L9 概念 | 我们的对应 | 状态 |
|---|---|---|
| 数据并行（一批拆多卡） | **负载闸按文件数缩放 + `--batch` 分批跑** | ✅ 已落地（commit e35867e7：内存紧也能拿全仓覆盖） |
| 显存不足 → 卸载/分片（ZeRO/FSDP） | **内存压强派单制**：本机可用 <1GB 即派云（渲染→Colab、挂机→牛马、部署→Codespaces） | ✅ 已定（剧组宪法第三律） |
| 资源调度层 | **能源池**（energy_pool，EnergySource 抽象；qwen-local 已接线态登记） | ✅ 在岗机制 |
| MoE（专家混合） | **触手按域分流**：178 能力位 30 域，各域各触手 | ✅ 在册 |
| 通信开销（并行的隐藏成本） | **网关/桥接的传输成本**（n8n ↔ 31717 网关） | ⚠️ 未量化 |

**指挥官铁律**：**"跑得动"永远优先于"跑得快"。**
先按文件数/内存把批量定对（不炸），再谈提速（可派云）。
