⚠️ 本节上一版列的 8 扇窗（含 `exec-deck` / `brain`）**已过期**：`exec-deck` 的页面在
2026-10-21 清壳时判定为空壳（盘上只剩空目录，已归档到 `_archive-20261021/shell-junk/`），

**一体式的三件事**（都由壳这一层注入/统一，**不改那 8 个页面**）：

### 3.1 对讲这条链的**两支专用验器**（2026-09-23 第 58 轮加）

上面六支器管的是"壳整体"。**语音对讲另有两处只有专门验器才答得了**，都在 `shell/` 下：

| 器 | 命令 | 它回答什么 | 现读 |
|---|---|---|---|
| 停得干净 | `node shell/intercom-kill-test.cjs` | **`child.kill()` 能不能连 `py.exe` 派生的真解释器一起停掉** | ✅ **起前 0 · 中 2 · 后 0**（父子一起消失） |
| 全程走门 | `py -3.14 .scratch\_verify_voice_ledger.py 3` | **每一次 `voice` 调用有没有 `run_task` 的信封**（有没有绕门） | ✅ **41 次调用 · 0 条无信封 · 0 条缺字段** |
| 收件箱机制 | `py -3.14 .scratch\_verify_inbox.py` | 听到的话**只追加**落盘：不改旧行、不污染真箱、长文本有界 | ✅ **1→2→3 行 · 顺序不变 · 截到 500 · 真箱未被测试污染** |
| 收件箱两态 | `py -3.14 .scratch\_verify_inbox_render.py` | 数据件里**有块** · 真实态**如实说没听到** · 注入夹具**能渲染条数** | ✅ **6/6**（`exists:false` 如实，不是拿 0 糊过去） |
| 快照真采纳 | `py -3.14 .scratch\_verify_live_snapshot.py` | **文件真变了会不会被采纳**（只验"没变就不 adopt"等于只验半条命） | ✅ **adopt 0→1 · lag 1082s→24s · polls 1→4** |

**三条纪律**（这一轮拿实测换的，与上面那三条并列）：

- **判据不许用正则在 JSON 结构里找东西**：`"voice_inbox":(\{.*?\}),"` 要求**尾随逗号**，
  而它是**最后一个字段**（后面直接 `}`）⇒ 永远匹配不上 ⇒ **假红**。改成剥前缀 `json.loads`。
- **判据自己坏掉时最危险**：它不报错，只安静地给出一个错数字（同轮还有一处 JS 里的
  `"…%.0f%%" % x` —— 那是 **Python 格式化**，在 JS 里 `%` 是取模 ⇒ 判据算出 `nan`）。
  ⇒ 每支探针的文件头要写清"**这条判据怎么才会假红**"。
- **验"没变"不等于验"变了会怎样"**：快照那条我先只验了"没变 ⇒ adopt 不涨"，
  而它的全部意义在"**变了 ⇒ 真采纳**"。**每条机制都要有它的两态**。

### 3.2 「一键无限生成视频」这条链（2026-09-23 第 22–24 轮加）

主人令原文是「一**定**要可以一键无限生成视频」。拆成三段做，**每段都有读数**：

| 段 | 件 | 它回答什么 | 现读 |
|---|---|---|---|
| ① 无限出帧 | `py -3.14 tools/codex-scripts/genrouter.py image --prompt "…" --n N` | 轮询池（云优先 / 本机兜底）· **每次调用硬截止 + 超时切腿 + 失败冷却** | ✅ 云腿真出图（秒级）· 实测切腿：`comfy_local` 未成 → 立刻切 `pollinations` 成 |
| ② 一键成片 | `py -3.14 tools/codex-scripts/make-video.py --frames … --out …` | Ken Burns（推拉交替）+ 交叉溶解 + 可选字幕/配乐 → mp4 → **ffprobe 回读校验** | ✅ 12.6s · 1280×720 · h264 · 378 帧（校验不过则退出码 5） |
| ③ 一条命令到底 | `pwsh -File tools/codex-scripts/gen-video.ps1 -Prompt "…" -Frames N` | 出帧 → 合成 → 校验 → 落盘；**出帧失败如实回落已有帧并写明原因** | ✅ 端到端 exit 0（出帧 2/2 → 5.4s 成片） |

🔴 **三条口径写死，不许含糊**：
- 「**无限**」是**额度上**的（零成本、零审核）；**时间上受限**：本机 CPU **586 秒/张** ⇒ 16 帧视频 ≈ 2.6 小时。
- **不是"逐帧生成式视频"**：帧是真生成的，**帧间运动是 ffmpeg 算的**（推移/溶解）。本机无 CUDA、内存 7.4GB ⇒ 逐帧生成式**不做**。
- 出帧失败（云腿挂住/冷却）⇒ **回落已有帧并写明原因**，不假装这一轮出了新帧。

**两条仪器纪律（都是这一轮拿实测换的）**：

- **"语法过了"不等于"函数还在"**：改文件时把 `def get_json(...)` 那一行当旧串替换掉，
  它的函数体缩进正好接在下一个函数后面 ⇒ `ast.parse` **全绿**，而 `get_json` **不存在**，
  调用方一跑就 `NameError`。⇒ 删/改函数头之后**必须按函数名复核调用方**
  （器：`.scratch\_fnchk.py`，且**它自己也要能被复核**——第 25 轮修了它的假阳性：
  把 import 与函数参数误报成"未定义"，那种"喊狼来了"会让真缺陷被忽略）。
- **同一命令不同 `status` 返回不同形状**：`genrouter` 的 `done` 才有 `images/轮询顺序/成功`，
  `no_backend` 没有 ⇒ 直接取会得到三个空值拼成「轮询顺序 · 成功 /」，**看不出真因**。
  （与 `five-dim` 摘要器那个错同类：**读者必须跟着 status 分形状**。）

**三条纪律**（都是这一轮拿实测换的）：

- **判红之前先看一条原始记录的真形状**：账本的信封在 **`meta.synced`**，不在顶层。
  我第一版读顶层 ⇒ **假红 83 条"绕过门"**。先跑形状探针（`.scratch\_ledger_shape.py`）才敢下结论。
- **一条调用会落多条记录**（`call` + `ok`/`denied`）⇒ **`call` 才计次**，别把记录数当调用数。
- **验器自己别被算进去**：过滤"命令行含 `intercom.py`"会命中**探针自己**（它的命令行里带这个字面量）
  ⇒ 我第一版因此把"杀干净"误判成"杀不干净"。必须同时按**进程名**过滤（只认 `py.exe`/`python*`）。
- **跑不通的验器不许留在册**：另有一支窗口生命周期验器（`intercom-lifecycle.cjs`）在 harness 下
  会被静默终止（exit 0、无异常），**已移入 `.trash/`**（回收站，不是硬删）。
  留在册会让人以为它可用 —— 那比没有更坏。

**两条纪律**（都是拿实测换的）：

- **量具不许有副作用**：`startup` / `interact` 会真挪窗、真点芯片 ⇒
  必须在 require `main.cjs` **之前**把 userData 指到临时目录，
  并各加一条**事后指纹断言**（`S:nopollute` / `I6`）—— 真布局文件被动过就判红。
  （事故：连跑几次探针之后，布局被写成"八扇窗全在屏幕外"。）
- **`show: false` 在 Windows 上不绘制** ⇒ 取证必须用 `show: true` + 屏幕外（`x = -20000`），
  否则 `capturePage()` 拿到空白帧，而**空白帧和"这窗本来就是空的"长得一模一样**。

## 6. 边界（写清，免得又混）

1. **渲染进程零写口**：`preload.cjs` 只暴露只读 IPC；页面里没有 `fetch`、没有 POST。
   SSE 订阅放在**主进程**（`panel_server` 不发 CORS 头，`file://` 直接被拦）；
   唯一的动作口是 `summon` / `connectDsh` / `showWindow` 三个，`non_readonly_capability` 那一行**同步登记**。
2. **节点大小 = 资源占用这一层今天拿不到**：按《反空壳律》画「未启用」（灰、无大小差异），**不拿默认值顶替**。
3. **打包是闸二**：`npm run pack` / `npm run dist` 要主人点头；装包（`npm install`）同理。
