## 一、这是什么（一句话）

**GBT小土豆V8 是她自己的原生桌面 APP**（Electron，`holo_pet_w3/` 这一棵树），
装在自己机器上、开机就能开、**打开就是她**；窗口之间在她自己的壳里切，**不出浏览器、不嵌别人家的站**。

**不是**：不是 DSH 的一个面板、不是网页收藏夹、不是别人 APP 的皮肤。
（DSH 是本 APP 的**对话引擎**，跑在她的一个窗里；宿主侧那套 gbt-master 面板已按主人令砍到 1 条。）

## 四、嘴对齐：两条路，写死界线，不许拿假口型冒充

1. **实时路线（就是现在这个 3D 她）**：动作、姿态、转速都能真调，**没有嘴**。
   - 要补：给头骨加 jaw + 下颚顶点权重 + 口型形态键（Blender 原生做，`Decimate` 同理要 DCC）。
   - 补齐之前，**页面不做假口型**：只出字幕 + 真声音。这条是**纪律**，不是能力不足的借口。
2. **出片路线（真嘴对齐）**：SadTalker 成片（`npc` 那套 `finish-clip.py`），
   已验过的成品是 `fullbody-tw-v5`（1472×2496 · 台湾腔 · r 0.5842@lag0）；
   它是**视频**（不实时、要 GPU 时间），在 APP 里当「她说话」的播放素材用。

## 五、工程口径（谁能改、怎么算完成）

- 权威树：`holo_pet_w3/`（不是镜像里七天的快照，理由见 README §0）。
- 窗表唯一真源：`shell/windows.json`；面板左栏唯一真源：`panel/index.html` 的 `PAGES`；
  宿主面板：`plugins/gbt-master/lib/host.js` 的 `PANELS`。**三处都由"墙上的数"现读，不许口头报数。**
- 验收顺序（每次改完都跑）：`node --check` → 重载窗 → CDP 读读数 → **看截图**（P7）。
- 完成判据（缺一条就不算完成）：
  1. 打开 APP 第一眼是她，**不是**工作台、不是空白；
  2. 她站得住、走得了、说得出声；
  3. 「嘴对齐」那条要么真做到（有 jaw 骨 + 口型驱动），要么页面上**明写做不到**；
  4. 全窗导航各一条（壳标题栏 + 面板左栏），不叠第三条。
