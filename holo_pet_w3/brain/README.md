## 一、数据从哪来（三段，别混）

| 段 | 来源 | 怎么到页面 |
|---|---|---|
| 能力/束长/依赖边/审计脉冲/技能雾 | `tools/codex-scripts/brain-feed.py` | 落成 `brain-data.js`（`globalThis.GBT_BRAIN = {…}`），**经典脚本**内嵌 |
| 生成后端轮询池 | `tools/codex-scripts/genrouter.py` → `state/genpool.json` | 由 brain-feed 读进同一个 `brain-data.js` 的 `genpool` 块 |
| 语音收件箱 | `tools/codex-scripts/intercom.py watch --inbox` → `state/voice_inbox.jsonl`（**只追加**） | 由 brain-feed 读**尾部 6 条**进 `voice_inbox` 块；页面「收件箱」行显示共 N 条 + 最近一条 |
| 语音对讲三条腿 | `tools/codex-scripts/intercom.py`（走唯一门） | 经**壳的桥**（`window.gbtW3.intercom`），**不走 HTTP** |

🔴 为什么全是"内嵌脚本"而不是 `fetch`：本页 CSP 是 `connect-src 'none'`（离线自包含的硬保证）。
要拿新数据只有两条合法路：**同源 `<script>` 重注入**（brain.js 每 15s 一次）或**宿主桥**。
**不放宽 CSP** —— 这条是主人定的口径。

## 二、读数全在 `window.__brainNet`（一个只读对象）

浏览器控制台敲 `__brainNet` 就能看到全部。字段与**怎么读**：

| 字段 | 含义 | 怎么读 |
|---|---|---|
| `bind.curves` / `bind.rebound` / `bind.map_size` | 纤维条数 / **端点引用被重新绑定的次数** / 节点数 | `rebound` = 修"两套引用"那个既有缺陷时改了多少个端点（实测 343） |
| `net.e0` → `net.e1` | 力导向**起始能量 → 收敛能量** | 两个数要**差一个数量级**才算真收敛（实测 36323 → 119.5） |
| `net.radius` | 排布半径（椭球三轴的实际占用） | 与 `BRAIN.R`（容积参数）比：实测量到 22.36 |
| **`net.mean_nn`** | **平均最近邻距离 = 密度的定义** | **越小越密**。改容积/斥力后比这个数，**不许用"看着更密了"** |
| **`net.nn_min`** / `net.nn_p10` / **`net.overlap_frac`** / `net.density_verdict` | **细粒度密度**：最近的那一对 / 第 10 百分位 / 比 **K/2** 还近的节点比例 / 判定 | 🔴 第 61 轮补 —— **平均值会掩盖重叠**（少数节点叠在一起、其余稀疏，`mean_nn` 照样好看）。判据：`overlap_frac` 必须 **0**。改前 `nn_min 1.39 < K/2 1.67`（**1% 重叠 = 图上是一团、拾取点不准**）⇒ 加**局部硬芯**后 `2.01 / 0` |
| `net.ideal_k` / `net.nn_vs_K` | 理想间距 `K = √(R²/n)·1.9` / 实测平均间距与它的倍比 | 现读 `3.34` / `1.14` ⇒ 间距比理想略宽 14% |
| **`net.radial_uniform_ref`** / `net.radial_max_dev` | **均匀填球**（体积 ∝ r³）时各桶**应有**的数 / 与它的最大偏离 | ⚠️ **参考值，不是门槛**。现读偏离 **0.47**，但这偏中心是"向心力 ∝ q"那条的**刻意设计**（中心密、边缘疏），**不是缺陷** —— 要不要改是**主人的选择**（见未验账第 2 条）。🔴 不许把它当红/绿判据用 |
| `net.centroid_offset` | 质心相对核的偏移（对齐前） | 取景是否歪的读数；对齐后应≈[0,0,0] |
| **`net.radial_hist`** | 归一化半径分 5 桶 + 出界桶 | **"是不是空壳"的判据**。实心应"小 q 多、边缘少"。改前 `[1,12,18,66,84,5]`（**90% 贴壳**）⇒ 改后 `[6,26,63,87,4,0]` |
| **`net.shell_frac`** / `net.hollow_verdict` | 边缘占比 / 空壳判定 | 现读 **0.02 / ✅ 实心**（改前 **0.48**）；`outer_void` 另报"中心两桶是否全空" |
| **`net.mean_nn_uniform`** / `net.density_vs_uniform` | **同容积均匀分布的基准** / 相对密度 | 基准 **3.24**；实测 3.71 ⇒ **比均匀疏 15%**（`-0.15`） |
| **`net.cluster_purity`** / `intra_mean` / `inter_mean` | **同域成簇是否成立**：离自家束长更近的比例 / 同域平均距离 / 最近外域平均距离 | **关联网络的命根**。现读 **0.87** / 4.85 / 7.33 ⇒ **比 0.66**（<1 即成簇）。🔴 **目标不是 1.0**：能力位之间有真实的**跨域依赖边**，本来就该把一部分节点拉到别的域旁 —— 硬推到 1.0 等于抹掉跨域耦合 |
| `net.gate_r` / `net.cam_dist` | 门禁环半径 / 相机距离 | 两者都跟着 `radius` 自动走（别写死） |
| **`net.screen`** | `{canvas, bbox, fill_x, fill_y, clipped, verdict}`：把节点**投影到屏幕**后的外接框填充率 / 跑出画外的节点数 | **取景的判据**。`fill_*` 是"画面填了几成"，`clipped` 必须 **0**。🔴 第 60 轮新加 —— 加之前这一段只有一个 `cam_dist`（**声明**），答不出"填了几成、切没切"（**读数**） |
| `net.cam_elev_deg` | **自选的俯角**（在 8°–56° 里挑"最小边填得最满"的那个） | 实测选中 **48°**。不写死 —— 这块脑容积宽而扁、画布近方，固定俯角天生填不满竖边 |
| `net.frame_center` | 拟合用的**真实外接框中心** | 实测 `[-0.1, 0, 0.5]`（≈原点，说明排布没偏） |
| `window.__brainView` | `{now, saved, restored, via, err}`：**视图页签的固化状态** | `saved=true` ⇒ 写出去了；重启后 `restored` = 上次那个视图。**双向绑定**：别的文档改同一个键会经 `storage` 事件把本页也切过去（`via="storage-event"`） |
| `fog.n` / `fog.roots` | 技能雾珠数 / 按 root 分的簇数 | 341 / 5（**真登记项**，不参与拾取） |
| `labels.core` / `labels.bundles` | 标签数 | 1 + 29 |
| `arcs` | **已打出的电弧条数**（累计） | 16 秒实测 22–25 条；**这是"脉冲真在跑"的判据**，不是看图上有没有光 |
| **`arc_audit`** | 最近 60 条**电弧出处**：`{ts, kind, leg:"main"\|"edge", to / edge, incident}` | 🔴 第 62 轮补 —— 改前只有 `arcs` 这个**计数** ⇒「打在对应依赖边上」是**声明**不是读数。现在验收器拿**盘上 `brain-data.js` 的 `edges` 独立对照**：现读 **60 条条条落在真边上、条条与事件 kind 相连**。⚠️ 它是**环形缓冲（上限 60）**⇒ **长度不是证据**：拿"长度差"当判据会**同时**造出假红（队列排空顶上来）与假绿（环形把旧的挤掉）—— 实测踩过，改成**唯一 ts 标记**才对 |
| `window.__brainProbe` | `{spawn(p), audit(), queue_left(), audit_cap}` | 只读自述之外的**验收注入口**：只调 `spawnPulse` 画一条弧，**不碰 `D`、不写盘**。**负对照**靠它：喂一个不存在的 kind，必须**一条都不画** |
| `hd` | `{dpr, pr, drawing, css, composer}` | 高清判据：`pr = min(dpr, 2)`；`drawing` 必须**逐像素等于** `css × pr`。🔴 第 65 轮补 `composer`：`{passes, rt_frames, bloom{strength,radius,threshold}}` —— **`rt_frames` 只增**，拿它证明「**合成器/辉光真在跑**」。改前 `hd` 只有四个数 ⇒ 谁把 `composer.render()` 改回 `renderer.render()`，**辉光会静默消失、而判据一条都抓不到** |
| `snap` | `{at, lag_s, polls, adopt, fresh, ok, poll_ms}` | 新鲜度：`lag_s` 现算；**`adopt` 只在快照真变了才 +1**（没变就 +0 = 没乱入队）。🔴 **`ok` 是"绝不假装在跑"的判据**：同源脚本取不到时 `onerror` 把它置假 —— 实测**失败态**：`ok false` · **`polls` 不涨**（取不到绝不算一次成功）· 状态点 `off` · 出现「快照更新失败…不假装在同步」 |

## 四、怎么自己复跑（探针都在 `.scratch/`，只读直连、不过门）

**最省事的一条**（一把跑完六项 + 汇总成一张表，约 4.5 分钟）：

```powershell
python tools/codex-scripts/verify-brain-objective.py
```

它**不自己判红绿**，只转发各验收器自己的 `verdict`；只有主人能开的几格会**单独印出来**。

单支复跑：

```powershell
# 渲染 + 上面所有读数 + 截图
python .scratch\_brain_shot.py brain_now.png 16

# 高清：1× 与 2× 对照（证明 pr 与绘制缓冲跟着设备像素走）
python .scratch\_verify_hd.py

# ④ 硬化：**2× 上限** + 合成器真在跑 + 辉光在位 + resize 不陈旧（9 条判据）
python .scratch\_verify_hd_hard.py

# 生成后端轮询池那一块（含"数据件里真有 genpool 块"+页面渲染+控制台错 三条判据）
python .scratch\_verify_genpool.py

# 中文排版第四层 A/B（判据含"对照组不溢出 ⇒ 夹具无效 ⇒ 判未验"）
python .scratch\_verify_cjk.py

# 前提探针：`file://` 的 localStorage **能不能跨重启持久** —— 先验这个才敢写"固化"
python .scratch\_persist_probe.py

# 视图固化：真重启（关掉整个 context 再同 user-data-dir 开）+ 反向绑定 + 清键/脏值回落，共 8 条
```

### 5.1 每支探针的**假红条件**（写清，免得下一个人被自己的判据骗）

| 探针 | 它怎么才会假红 |
|---|---|
| `_verify_inbox_render.py` | 用正则在 JSON 结构里找字段：`"x":(\{…\}),"` 要求尾随逗号，**末字段永远匹配不上**（已改成剥前缀 `json.loads`） |
| `_verify_cjk.py` | 夹具里的"长 token"**若带空格**就本来能断行 ⇒ 对照组不溢出 ⇒ 测了等于没测（判据里已写"对照组不溢出即判未验"） |
