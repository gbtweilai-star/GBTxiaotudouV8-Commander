## 0 · 定位（三件东西，一条链）

| 件 | 一句话 | 交付形态 |
|---|---|---|
| **痕迹库**（traces） | 波动过阈值时，把「谁 / 什么动作 / 什么时候 / 什么上下文」留成一条可追的痕迹 | append-only JSONL（**无删除路径**） |
| **心跳触手**（wave_probe） | 量"波动"的那根触手：只在被唤醒时读一次，**不新增常驻进程** | 挂在现成 app 心跳上（走甲） |
| **做梦技能**（dream_replay v2.0） | 白天惦记什么，夜里就重演什么：念 → 召回 → 变异 → 模拟 → 巩固 | 离线重演 + 巩固，**写路径只发生在巩固那一刻** |

三层关系：**触手量波动 → 痕迹库留痕 → 做梦技能从痕迹里长出"念"**。
没有痕迹就没有念 —— 这是 v2.0 相对 v1.0（离线回放）唯一的、也是最重要的升级。

## 2 · 痕迹库（traces）· 设计表述

**记什么（三段）**

| 段 | 含义 | 例 |
|---|---|---|
| **人** | 谁在场 / 谁触发 | 主人 · 某能力 · 某个后台任务 |
| **事** | 发生了什么动作 | 一次拒绝（denied）· 一次降级 · 一次复核退回 |
| **痕** | 时间 · 来源 · 上下文 · **证据指针** | `at` · `source` · `context` · `evidence_ref`（指向审计行/文件/哈希） |

**硬规矩**

1. **append-only、无删除路径**：痕迹只增不减；要"撤销"只能追加一条更正，不许删。
2. **无源不留痕**：没有 `evidence_ref` 的条目不许入库（同 `signal_ingest` 判据 F：缺 url 一律拒收）。
3. **过阈值才留痕，不超只记流水**：不超阈值的活动只进普通日志，不进痕迹库 ——
   痕迹库是"值得回头看的东西"，不是全量流水。
4. **写路径只发生在留痕那一刻**：读侧（看板/沙盘）永远只读；写侧要过授权门。
5. **升格常驻 = 只有你显式标记，没有第二条自动路**（2026-09-19 定案 · 本图纸以第二人称对主人说话，
   等价于"只有主人显式标记"）：重复 K 次只进 **「待升格队列」**；做梦技能里「念＋模拟双超阈值」
   也**只进同一队列**，不自动升格。
   理由：长驻层**只能追加、无法删除** —— 自动升格 ＝ 污染不可逆。

   **什么叫「显式标记」（机械形状 —— 防"声明没有执行者"）**

   | 项 | 形状 |
   |---|---|
   | 一次标记 = | **动作 ＋ 目标 id ＋ 时间**（例：「升格 `ob-2026xxxx`」） |
   | 落账字段 | `promoted_by: "owner"` · `at` · `utterance_ref`（原话指针，便于回查） |
   | **不算标记** | 没有目标 id 的笼统说法（"这个不错"）· 我替主人复述的推断（"他大概想升格"）· 计数到 K 次 · 「念＋模拟双超阈值」——后两者**只进待升格队列** |
   | 标记 ≠ 立即执行 | 落账之后，真正的写路径**仍走授权门**（标记是意愿，不是绕过门的通行证） |

### 2.1 数据模型：**五张表**（Owner 2026-09-19 原词：原有 `traces` / `trace_links` / `wave_samples` / `promotes`，新增 `obsessions`）

| 表 | 职责 | 保留 |
|---|---|---|
| `wave_samples` | **每次采样**的原始读数（at / window / count / baseline_mu / baseline_sigma / trigger_mode / triggered / coverage·blind_window） | **可滚动**（原始遥测） |
| `traces` | **过阈才留痕**的行（id / at / subject / kind / **evidence_ref** / **promoted** / resolved） | **永不删** |
| `trace_links` | 痕迹之间的关系（同一 subject 的先后、因果、配对两端）—— 配对判据（§4.8）靠它 | **永不删** |
| `promotes` | **升格事件**流水（谁、什么时候、把哪条痕迹升进长驻层、原话指针） | **永不删** |
| **`obsessions`** | **「念」表**（见 §5）——「日有所思」的落点 | **永不删**（可追加，无删除路径） |

> `traces.promoted` 是**当前状态位**，`promotes` 是**事件流水** —— 两者不是重复：
> 状态位回答"现在是不是升格过"，流水回答"谁在什么时候按了那一句"。**对账时可互相验**（不一致就是漂移）。

| 层 | 写什么 | 什么时候写 | 保留 |
|---|---|---|---|
| **`wave_samples`** | **每一次采样**的原始读数：`at` · `window`(15m) · `count` · `baseline_mu` · `baseline_sigma` · **`trigger_mode`**（3σ/floor/sigma_zero/insufficient）· `triggered`(bool) · `coverage`/`blind_window`(§3.3 落差) | **每跳都写**（app 心跳唤醒时） | **可滚动**（原始遥测：过期转冷或裁剪） |
| **`traces`** | **只有过阈的**才留痕：`id` · `at` · `subject` · `kind` · `evidence_ref` · **`promoted`** · `resolved` | **过阈才写**（§2 硬规矩 3） | **永不删**（留痕层；只能追加） |

**这两层顺手解掉了一个老矛盾**：§2 硬规矩 1 写"append-only、无删除路径"，而"痕迹保留期"意味着删 ——
现在分工写死：**保留期只作用于 `wave_samples`（原始遥测，可滚）**；
**`traces` 永不删**（它才是"证据层"）。**任何想删 `traces` 的动作，都要先过门**（坑册第 30 条同族）。

**两层靠 `evidence_ref` 串起来**：每条 trace 必须指向产生它的 `wave_sample`（有源可追，第四条硬约束）。

### 3.1 宿主：走甲 —— 挂 app（AutoClaw gateway）心跳 · 盘上实测（2026-09-19）

| 项 | 实测读数 | 出处（可复核） |
|---|---|---|
| **宿主是谁** | **app 的 gateway heartbeat 子系统** —— 不是框架自带调度器、不是 cron | `logs/gateway.log`：`[heartbeat] started` ×5，**全部对应 gateway 启动时刻**；结构化日志 `{"subsystem":"gateway/heartbeat"}` |
| **周期** | `intervalMs = 1800000`（**30 分钟**），配置 `agents.defaults.heartbeat.every = "30m"` | `~/.openclaw-autoclaw/openclaw.json` · `logs/openclaw-2026-09-19.log` |
| **定时任务表** | `{"version":1,"jobs":[]}` —— **空的**（"固定时点"这条路上目前什么都没挂） | `~/.openclaw-autoclaw/cron/jobs.json` |
| **心跳读哪份 HEARTBEAT.md** | 按 agent 工作区注入：`main` / `auto-designer` = **本仓根 `HEARTBEAT.md`**（34,698 B，纪律本）；另一个 agent `agent-gvmz-gbtv8` 注入的是 `agent-gvmz-gbtv8/HEARTBEAT.md`（**244 B 纯注释桩**，头一句原文＝"保持空可跳过心跳 API 调用"） | `agents/main/sessions/sessions.json` 的 `injectedWorkspaceFiles` |

**接线前提（动之前必读）**：`wave_probe` 的指令必须写在**心跳实际注入的那一份** `HEARTBEAT.md` 里。
今天注入 `main` 的是本仓根那份（所以写根上是对的）；**换 agent = 换注入面**，这条要跟着核。

### 3.2 图纸里要写清楚的"真话"（两条，都是诚实边界）

1. **由 app 唤醒触发，不是固定时点**：app 不在（没起 / 关了）＝ 心跳不在 ——
   **不是"慢"，是"没有"**。要固定时点（例："每天 08:30 必须量一次"）**必须单独开护照承认代价**：
   那意味着新增常驻 / 半常驻进程，与"不新增常驻进程"直接冲突；要么承认代价，要么放弃固定时点。
2. **"配置里有"不等于"观测到在跳"**：`topic_watch.timer()` 的 `scheduler_live=true` 读的是
   **配置字段**（`agents.defaults.heartbeat.every`），它只能证明"声明在"，**不能证明"跳了"**；
   而 09-18 / 09-19 没有 `HEARTBEAT_OK` **也不能反推"心跳死了"**（也许跳了、只是答的不是 HEARTBEAT_OK）——
   按《空不等于不存在律》，这里如实报**"当天没有直接实证"**，不报结论。

### 3.3 阈值口径：**相对基线 3σ**（Owner 2026-09-19 定案）

**定稿口径（Owner 2026-09-19 原文照录）**：

> 近 **15 分钟** denied / blocked / error 密度 vs 过去 7 天同时段基线，**超 3σ 触发一次波动**。

**执行细则**（不把这些定死，口径落不了地）：

| 项 | 定稿 | 来由 |
|---|---|---|
| **窗口** | **近 15 分钟**（相对每次采样时刻的滚动窗口） | 口径原文（Owner 定案） |
| **节律落差处理**（15 分钟窗口 × 30 分钟一跳） | 一跳只覆盖半段 ⇒ 另半段是盲区：读数必带 `coverage: "half"` 与 `blind_window: [起, 止]`，**盲区不许当 0 读**。可选实现（**不改变口径**）：**一跳读两格**——前半段 / 后半段各比一次同段基线，把 15 分钟窗口真正看满 | 实测 15 分钟非空桶仅 14.5%；不写这条，一半时间会被静默当 0（《空不等于不存在律》） |
| **基线样本** | 过去 **7 天**的**同一时段**（同名 **15 分钟**窗口）每天 1 个样本 ⇒ μ=均值 · σ=样本标准差(n−1) | 口径原文 |
| **触发** | `本次计数 > μ + 3σ` | 口径原文 |
| **信号白名单** | `denied` · `auth_denied` · `pipeline_blocked` · `error` · `longrun_failed` · `deploy_promote_blocked` · `health_channel_failed` · `devour_reject`（**不含 `user_error`**） | 含 user_error 时 P95 由 38 抬到 71（它占 90%），会把"波动"读成"输入量" |
| **离群日剔除** | 单日全事件数 > 覆盖期中位数的 **5 倍** ⇒ 标 `outlier_day`、从基线剔除（剔除事实进读数） | 09-11 = 256,976 事件，其余日 590–10,739；不剔就被一次性批量抬高 |
| **σ 退化兜底**（零膨胀必踩，必须有） | ① 样本 < 3 ⇒ `baseline_insufficient`（**不触发**，如实标）② σ=0 且 μ=0 ⇒ 用绝对下限 **K=3**，标 `floor_used` ③ σ=0 且 μ>0 ⇒ 退化为 `count > μ`，标 `sigma_zero` | 实测零膨胀 79–84%：7 个样本很可能全是 0（σ=0）——**σ=0 时 μ+3σ=0，任何 1 起事件都会"触发"**，等于没有阈值 |
| **空窗口 ≠ 没采** | 窗口 0 条要分两种：**真 0** 与 **心跳没跳（gap）**；gap **不进基线**，单独记 | 《空不等于不存在律》 |
| **触发留痕** | 读数必须带 `trigger_mode`（`3σ` / `floor` / `sigma_zero`） | 三种触发的含义不等价，混在一起读就是骗自己 |

**起步期行为（自动，不用另选）**：7 天样本攒够之前，每跳都会报 `baseline_insufficient` ⇒
这段时期 `wave_probe` **只记流水、不触发留痕** —— 即"先观测再定阈值"自动成为 3σ 口径的**起步阶段**。

**诚实边界（口径按主人定案走，风险摆在这儿）**：

1. **7 个样本估 σ，置信度低**；零膨胀下 σ 常为 0 ⇒ 触发会"有时按 3σ、有时按 floor"。
2. 本口径**判不出"低于基线的异常"**（例如本该有事件却归零）—— 那类异常要另立判据，别指望 3σ。

#### 取证留档（定案时已知的数据形状 · 2026-09-19 只读账本）

原稿口径：`近 15 分钟 denied/blocked/error 密度 vs 过去 7 天同时段基线，超 3σ ⇒ 触发一次波动`。

**实测**（只读 `gbt_allinone/store/audit.jsonl`：36.3 MB · 290,600 行 · 覆盖 09-11 10:34 → 09-19 12:45 = 9 个自然日）：

| 读数 | 数值 | 对口径的含义 |
|---|---|---|
| 信号类事件总量 | 21,146 条，其中 **`user_error` 占 18,977（90%）** | **"哪些事件算信号"必须先写死白名单**；含它 / 不含它，P95 差近一倍（71 vs 38） |
| 30 分钟桶 | 383 桶 · 非空 79（20.6%）· **零膨胀 79.4%** | 均值≈0、σ 被少数尖峰主导 ⇒ **3σ 不成立**（分布不是正态） |
| 分位数（含 `user_error`） | P50=0 · P90=26 · P95=71 · P99=522 · max=8,242 | 零膨胀 ＋ 重尾 ⇒ 该用**分位数**，不该用 σ |
| 分位数（不含 `user_error`） | P50=0 · P90=12 · P95=38 · P99=126 · max=189 | 剔掉 09-11 批量日后：301 桶 / 非空 54（17.9%）· P95=50 |
| 同时段样本 | 按小时切：01时=8 · 02时=9 · 09时=15 · 21时=15（其余 37–12,347） | "过去 7 天**同时段**"每格最多 9 个样本、且多数为 0 ⇒ 基线不稳 |
| 离群日 | 09-11 信号 17,871（全事件 256,976）；09-12 只有 2 条 | 基线**必须显式剔除离群日**，否则被一次性批量抬高 |

**取证结论（留档）**：这组数据形状下，3σ 会**频繁退化**（零膨胀 79–84% ＋ 同时段样本 ≤9）——
退化兜底已写进 §3.3 执行细则；**口径本身按主人定案保留为"相对基线 3σ"**。

## 4 · 做梦技能 v2.0 · 「日有所思，夜有所梦」

**核心升级（Owner 2026-09-19 口径）**：**做梦不是随机的，是被白天惦记的东西驱动的。**

**两个动作（Owner 2026-09-19 原文）**：

> **"日有所思" = 这些念被记进一张 `obsessions` 表；
> "夜有所梦" = 心跳触发时，按念的强度排序，优先重演。**

⇒ 落到系统里就是两句话：**白天往 `obsessions` 表里记念**（不新增监控，念从已有痕迹浮现）；
**夜里心跳一响，按 `intensity` 排序，从最深的念开始重演**。**顺序由强度决定，不由随机决定** ——
随机只住在变异那一格（见下）。

**红线：做梦不执行（Owner 2026-09-19）**

> **做梦不执行。** 重演只在隔离里发生 —— 不点灯、不记账到生产、不发消息、不跑命令、不碰任何设备。
> 做梦**唯一的写路径是"巩固"**（把重演结果写进 `traces` / `obsessions` / 长驻层），**且要过授权门**。

**机械判据（不靠自觉，靠扫源码 —— 同 `projection_skill` / `topic_watch` 那两条的查法）**：

1. 做梦模块源码里**不得出现**：`run_task(` · `subprocess` · `Popen` · `os.system` · 线程 / 事件循环原语 · 出网调用；
2. 读侧（面板 / 沙盘）**永远只读**：不设写入口（`do_POST` 一律没有，POST 一律 501/404）；
3. **"巩固"是唯一的写**：写之前过授权门；除此之外一切"顺手做了点什么"都算违规。

> 与第 1 步同构：**做梦 ≈ ARM（准备态，永不点亮）**；巩固 ≈ 写，但要过门。
> 一句话：**梦里什么都能演，醒来只能交一份记录。**

### 4.1 五条能力原语（v2.0 替换 v1.0 的"离线回放"五原语）

```
日间念 OBSESS  →  召回 RECALL  →  变异 MUTATE  →  模拟 SIMULATE  →  巩固 CONSOLIDATE
```

| 原语 | 干什么 | 关键约束 |
|---|---|---|
| **日间念 OBSESS** | 从已有痕迹里**自然浮现**出"念"（不新增监控） | 念必须有源：`source_trace_ids` 指向真实痕迹 |
| **召回 RECALL** | **优先召回「念」最强的那批** —— 也就是「日间未了念」：白天**反复被想到**、**没解决**、**过了阈值**、**但没升格**的痕迹（**v1.0 是「随机召回一批痕迹」，v2.0 改成按念召回**） | 只读痕迹库、不许改写原文；**四条定语缺一不可**；**按 `intensity` 排序取前 N**；结果必须能追到 `source_trace_ids` |
| **变异 MUTATE** | **围绕「念」**做**反事实推演** —— **对同一件事**做**不同**的"如果那样会怎样"（重组 / 换视角 / 补全） | ①**对象不随机**：始终围绕同一个念；②**随机只许落在「选哪条反事实分支」上**：不许随机选源（源由召回决定）· 产物**必须带源指针** · 不许无源生成 |
| **模拟 SIMULATE** | 在隔离里跑一遍"如果这样会怎样" | 模拟不产生对外副作用（同镜像维度口径） |
| **巩固 CONSOLIDATE** | **靠"念的强度"**：白天想得越多 ⇒ 夜里越容易入梦 ⇒ 越容易巩固（口径＝「念」与「模拟」**双超阈**，见 §4.5） | **唯一写路径**：写之前过授权门；过阈 ⇒ 固化 **＋** 进「待升格队列」；**未过阈 ⇒ 不固化**（不进长驻层，也别说成"有价值"） |

### 4.2 四类"念"

| 类型 | 怎么来的 |
|---|---|
| **未了念** | 白天**反复被想到**、**没解决**、**过了阈值**、**未升格**的痕迹（**四条缺一不可**，＝ §4.1 召回的目标） |

### 4.3 硬约束（**第四条是 v2.0 新增**）

1. **念从痕迹里来**：`OBSESS` 的输入只能是痕迹库，不许凭空造念。
2. **模拟必须隔离**：`SIMULATE` 阶段不产生任何对外副作用。
3. **巩固才写盘，且靠阈值**：`CONSOLIDATE` 是唯一写路径 —— **触发靠阈值**（「念」与「模拟」双超阈）、**执行过授权门**；
   即便过了阈值，也只是**固化 ＋ 进待升格队列**，**升格仍只认你的显式标记**（§2 硬规矩 5）。
4. **`obsessions.source_trace_ids` 必须指向真实痕迹；不许凭空造念，不许无源之梦。**
   （Owner 2026-09-19 原话照录；同"缺 url 不入库""没有证据的结论不采信"同族。）

   **机械判据（Owner 2026-09-19 复述：「念必须指向真痕迹」）**：

   | 项 | 判据 |
   |---|---|
   | 非空 | `source_trace_ids` 为空 ⇒ **拒收**（不是"可疑"，是不成立） |
   | 可查 | 列表里**每一个 id** 都要能在 `traces` 里查到；**有一个查不到 ⇒ 整条拒收** |
   | **何时校验** | **写入时校验**（write-time），不是"事后审计" —— 同 `signal_ingest` 判据 F（缺 url 一律拒收、控制台报错、一个字节都不写） |

### 4.6 「念」的定义（**草案** · 按盘上已有字段归纳，等主人原话替换）

**① 来历（盘上已有）**：`OBSESS` 不新增监控 —— 念**从已有痕迹里自然浮现**
（痕迹＝白名单事件写进痕迹库的那些行；见 §2）。**没有痕迹，就没有念。**

**② 机械定义**（一条"念"必须同时满足）：

| 要件 | 判据 |
|---|---|
| 对象 | `subject` 非空（同一件事／人／主题） |
| 类型 | `obsession_type` ∈ {未了念 · 反复念 · 过阈念 · 未答念} |

|---|---|

| **反复念** | 同一 `subject` 在窗口内出现 **≥ K 次**（K 待拍；K 次**只进待升格队列**） |
| **过阈念** | 单条 `intensity` **> 阈值** |

- **已升格**：进过长驻层的，**不再算"未了念"**（它已经了了）。
- **纯计数**：只是"出现了 K 次"，没有未解决/过阈的实质 ⇒ 只进**待升格队列**，不自动成为"念"。
- **自检样本**：`probe` 这类自检事件**不算真实痕迹**（R-H119 实测：自检样本会进主账本）⇒ 不能当念的源。

建议由**已有读数**合成：`出现次数 × 未解决权重 × 时间衰减(相对 half_life_s)`。
**具体权重与 K、阈值一起等你拍** —— 不给数就不落地，避免"判据自己拍自己"。

### 4.7 未了念 · 专条（**含一次失败的实测 —— 它打出了两个隐藏前提**）

**定义（四条，与 §4.1 召回目标逐字一致）**：
**反复被想到 ∧ 没解决（`resolved=false`）∧ 过阈 ∧ 未升格**。

**实测（R-H126 · 只读 `audit.jsonl` · 白名单事件）**：

```
白名单信号 = 2,161 条 · 不同 subject = 84 个
出现次数分布：1 次=9 个 · 2 次=10 个 · ≥3 次=65 个 · ≥5 次=55 个 · ≥10 次=46 个
候选"未了念" top6：
   event=auth_denied        866 次 · 未见 resolved
   kind=keylogger           111 次 · 未见 resolved
   name=bo.txt               78 次 · 未见 resolved
   name=_def_probe.txt       53 次 · 未见 resolved
   kind=audit_query          31 次 · 未见 resolved
   kind=pipeline_submit      31 次 · 未见 resolved
```

**结论（读数，不是抱怨）**：这 6 个候选**全是假念**，而且失败方式正好打出两个隐藏前提：

| 假念的来源 | 它证明了什么必须写进定义 |
|---|---|
| `event=auth_denied` **866 次** —— 我的 subject 取值兜底成"事件名"，把**所有同类事件**并成一个 subject | **subject 必须有合格口径**：什么叫"同一件事"（谁/什么/哪条痕迹），不许用事件名兜底 —— 否则会造出"866 次的超级念"，既不可解也毫无意义 |
| `keylogger` · `bo.txt` · `_def_probe.txt` —— 全是**自检/测试**产生的痕迹 | **测试痕迹不算念的源**（与 §2 硬约束 5 的 origin 闸、R-H119 那条"自检样本会进主账本"是同一件事） |

**⇒ 两条必须先定（否则"未了念"落不了地）**：

1. **subject 的合格口径**：同一件事 = ？（候选：同一 `evidence_ref` 指向的目标 ／ 同一文件 ／ 同一能力名 + 同一参数指纹）
2. **测试痕迹的排除**：测试/自检事件（`probe` · `_def_probe` · 测试文件名 · 禁用能力演练）**不进痕迹库** ⇒ 自然不成念。

**K 不许现在拍**：上面那张出现次数分布**已被假 subject 污染**（866 次那根柱子就是兜底的产物）。
按《判据不许挂在旧数据上》，**K 必须在 subject 口径定死之后重新测**，再取分位数定。

### 4.8 未了念的**合格口径 = 配对未闭合**（Owner 2026-09-19 原词：有开始没结束的痕迹）

### 4.13 模拟的去向 ·「默认闪逝」（Owner 2026-09-19 原词）

> **模拟结果不触发任何外部动作，只写内部痕迹。** · **默认闪逝。**

**一、模拟的边界（原句拆开）**

- **不触发任何外部动作**：跑命令 / 发消息 / 点灯 / 写生产 / 碰设备 —— 一律不许（§4 红线「做梦不执行」）。
- **只写内部痕迹**：模拟**允许**在**内部**留一笔（"这次模拟发生过、结果是什么"），
  写进 `traces` / `wave_samples` 这一层 —— **内部记录，不是对外动作**。

> **一处措辞要调平（我做的归位，对不对你说一声）**：前面写过"巩固是唯一写路径"，
> 这里又说"模拟结果只写内部痕迹" —— 两句不冲突，但**必须分清"内部"与"对外"**：
> **内部痕迹**（`wave_samples` / `traces`）＝做梦过程允许写的；
> **固化与升格**（`obsessions` / 长驻层）＝ 要过门的；
> **对外动作**＝**任何阶段都禁止**。

**二、「念的一生」三档去向（默认闪逝是第 1 档）**

| 档 | 触发 | 去哪 | 能删吗 |
|---|---|---|---|
| **① 闪逝（默认）** | 不满足阈值 —— **默认状态** | 内部痕迹一**笔**带过：可查、但**不升格、不进长驻层、不进对话上下文、不打扰主人** | 随 `wave_samples` 滚动 |
| ② 巩固 | **过阈**（「念」＋「模拟」双超阈，§4.5） | 固化成 `obsessions` 一行 ＋ 进「待升格队列」 | 永不删（可追加） |
| ③ 升格常驻 | **只有你显式标记**（形状见 §2 硬规矩 5） | 进长驻层 | **永不删** |

> 一句话：**默认闪逝，过阈才留下，你点头才长驻。**
> 这三档正好对应"随机只住在变异那一格"：**去向由阈值与你的标记决定，不由随机决定。**

**三、默认档的三条硬性质（Owner 2026-09-19 原词）**

> **每条梦境默认 `half_life` 短，不驻留、不放大。** · **升格要你拍。**

| 性质 | 含义（可执行解释） | 机械判据 |
|---|---|---|
| **默认 `half_life` 短** | `obsessions.half_life_s` 的**默认值**要短 —— 长期没人再碰就**自然淡掉**，不需要谁来清理 | 默认值待拍（候选：6h / 24h / 72h）；**缺少 `half_life_s` 的念不成立**（必填） |
| **不驻留** | 默认档**不进长驻层**、**不进对话上下文**、**不打扰主人** —— 它可以被查到，但不会自己浮上来 | 默认档在 `promoted=0`；进长驻层只有一条路：**你显式标记** |
| **不放大** | **重复 ≠ 放大**：出现得再多，也不会自动变得更响（不推送、不占面板、不扩采集面、不自动转常驻）；强度只按 `intensity` 口径算，**不按"被看见的次数"叠加** | 无"自动升级"路径；`intensity` 每次**重算**，不是在旧值上累加 |

> **升格要你拍**（第三次复述，写进三处）：进长驻层**永远**要你那一句标记 ——
> 阈值到了只能"巩固 ＋ 排队"（§4.5 两道闸），**没有任何自动升格路径**。

## 5 · `obsessions` 表（图纸 · 字段级）

| 字段 | 类型 | 含义 | 约束 |
|---|---|---|---|
| `id` | str | 念的编号 | 唯一 |

**Owner 给的建表原文（照录 · 2026-09-19）**：

```sql
-- 原有：traces / trace_links / wave_samples / promotes
-- 新增：
obsessions(
    id PK,
    at,
    subject,              -- 惦记的对象（哪件事/哪个痕迹）
    obsession_type,       -- 未了念 / 反复念 / 过阈念 / 未答念
    intensity REAL,       -- 念的强度（0-1，按出现频次+持续时间+波动幅度加权）
    source_trace_ids,     -- 关联的真实痕迹（不许凭空编）
    resolved INT DEFAULT 0,  -- 是否已了结
    half_life_s           -- 念也会衰减；长期没人再碰就淡了
)
```

> ⚠️ **枚举冲突（点名，不擅自改原文）**：这份 DDL 的 `obsession_type` 只列了**四类**，
> 而本图纸 §4.12 已新增第五类 **「被挡念」**（门拒绝 + 无对应通过）。
> 两条路，等你一句话：
> **(a)** 枚举补一档（五类并列）；**(b)** 「被挡念」作为「未了念」的**子类**（`obsession_type` 仍是四类，
> 用 `source_trace_ids` 指向拒绝事件来区分）。
> 不写清的话，将来实现只会落四类 —— 第五类会**静默消失**。

**表级规矩**：**可追加、无删除路径**（同痕迹库）。
「了结一条念」= 追加一次状态变更（`resolved=true`），不是删行。

**升格规矩（2026-09-19 定案）**：`obsessions` 里的一行永远只是"念"。
进**长驻层**只有一条路 —— **只有你显式标记**（形状见 §2 硬规矩 5）；重复 K 次、「念＋模拟双超阈值」
都只进 **「待升格队列」**，**不自动升格**。
注意两件事**不是一回事**：`resolved=true`（这条念了了）≠ **升格**（进只能追加、无法删除的长驻层）。
