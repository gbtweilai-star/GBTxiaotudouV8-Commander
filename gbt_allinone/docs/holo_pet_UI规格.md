## 零、一句话

四条视觉目标里，**品牌色 / 窗体 / 动效三条已经在代码里**，**只有布局没落地**：
现状是"左数字人 + 右命令台"两栏，目标是"顶栏 + 中央 + 底栏 + 右流"四段。

> **2026-09-17 追加**：风哥定下 holo_pet 最终形态为**多窗口控制台**——
> 主控台 + 三个独立子窗口（云电脑 / 克劳德 / 上帝视角）。
> 因此"布局"这一条**升格为两件事**：主控台内部的四段布局（§3.1/§3.2），
> 以及窗口与窗口之间的布局（§3.3/§3.4）。
> 框架与生命周期口径见《holo_pet多窗口架构设计.md》，本文件只管像素与尺寸。

## 二、逐条实测对照

### 2.1 品牌色 · 已落地

| 角色 | 规格值 | 实现 token | 位置 |
| --- | --- | --- | --- |
| 土豆金 | `#F5B041` | `--potato-gold: #f5b041` | `holo_pet/styles.css:8`（柔光变体 `:9`） |
| 赛博青 | `#00E5FF` | `--cyber-cyan: #00e5ff` | `holo_pet/styles.css:10`（柔光变体 `:11`） |
| 深空紫 | `#7C4DFF` | `--deep-purple: #7c4dff` | `holo_pet/styles.css:12`（柔光变体 `:13`） |
| 基底 | —— | `--bg: #050711` | `:2` |
| 语义·告警 | —— | `--alert: #ff6b72` | `:14` |
| 语义·成功 | —— | `--success: #52e4ba` | `:15` |

三个品牌色与规格值**逐位一致**（大小写差异，十六进制等价）。使用面很广：
`var(--cyber-cyan)` / `var(--potato-gold)` / `var(--deep-purple)` 在样式表里出现 60+ 处，
另有品牌渐变 `linear-gradient(90deg, var(--deep-purple), var(--cyber-cyan), var(--potato-gold))`（`:527`）。

**结论：不需要改。规格就此冻结。** 后续新增一律引用 token，不许写裸色值——
这是本次唯一新增的硬约束。

### 2.3 布局 · **未落地（本次唯一的实差）**

现状（`holo_pet/styles.css:84-98`，`.holo-shell`）是一张 **grid 两列**：

```
grid-template-columns: minmax(420px, 1fr) minmax(470px, 0.82fr);
```

- **左列** = `section.avatar-stage`（`holo_pet/index.html:22`）——数字人
- **右列** = `aside.command-deck`（`holo_pet/index.html:104`）——里面竖着叠了 **六块**：
  `header.deck-head`（`:105`，品牌与操作）→ `section.neural-core`（`:128`）→
  `section.timeline-panel`（`:208`）→ `section.notion-vault`（`:227`）→
  `section.eigenflux-network`（`:269`）→ `section.device-bus`（`:306`）→ `footer.deck-foot`（`:408`）

逐段对照：

| 目标段 | 现状 | 差距 |
| --- | --- | --- |
| 顶部品牌栏 | **不存在**跨窗口顶栏。品牌标识在右列内部（`index.html:105-126`，`h1` 当前是 `Codex 编程内核`） | **缺** |
| 中央数字人 | 数字人在**左列**（`index.html:22`） | **位置不对**（左 → 中） |
| 底部交互区 | 输入区在右列内部（`form` 结束于 `index.html:406`）；`footer.deck-foot`（`:408`）是状态条，不是交互区 | **缺独立底栏** |
| 右侧信息流 | 有，但只是右列六块之一（`timeline-panel`，`index.html:208`） | **要拆成独立列** |

**一条必须先裁的边界**：桌面壳模式下 `command-deck` 被整体隐藏（`styles.css:2441-2445`，
`body.is-desktop-shell .command-deck`）。桌面壳窗口默认 **420×780**（`main.cjs:18-19`），
最小 **420×620**（`main.cjs:71-72`）。**420px 宽塞不下"右侧信息流"**——
所以第 3 条目标在两种模式下必须给两套口径，见 §3.2。

## 三、目标规格

### 3.1 宽面板（浏览器 / ≥1280px）

```
┌────────────────────────────────────────────────────┐
│ 顶部品牌栏  44px                                    │  ← 拖拽区 + 状态灯
├──────────────────────────────────┬─────────────────┤
│ 中央数字人舞台                    │ 右侧信息流       │
│ flex: 1                          │ 320–360px       │
│ （3D canvas / 降级形象）          │ 执行轨迹 · 审批  │
├──────────────────────────────────┴─────────────────┤
│ 底部交互区  104px  输入框 + 发送 + 中断              │
└────────────────────────────────────────────────────┘
```

| 段 | 尺寸 | 内容 | 搬迁来源 |
| --- | --- | --- | --- |
| 顶部品牌栏 | 高 `44px` | 左：品牌标识（`GBT小土豆`）；右：状态灯（内核在线 / 降级可用 / 未就绪） | 现 `deck-head`（`index.html:105`）拆出身份与状态两部分 |
| 中央数字人 | `flex: 1` | 3D canvas + 星云层 + 降级形象 | 现 `avatar-stage`（`index.html:22`）平移居中 |
| 右侧信息流 | 宽 `320–360px` | 执行轨迹 + 审批卡片 + 结果 | 现 `timeline-panel`（`index.html:208`）+ 审批卡片 |
| 底部交互区 | 高 `104px` | 输入框 + 发送 + 中断 | 现 `index.html:406` 之前那块表单 + `btn-stop`（`:119`） |

其余现右列模块（`neural-core` `:128` / `notion-vault` `:227` / `eigenflux-network` `:269` /
`device-bus` `:306`）收进右列的**可折叠分组**，不再各占一段。

| 断点 | 行为 |
| --- | --- |
| `≥1280px` | 四段齐，右列 `320–360px` |
| `900–1279px` | 右列收窄至 `280px`，字号降一档 |
| `<900px` | 右列折叠为抽屉，顶栏出一个唤出按钮 |

### 3.2 桌面壳（窄窗 420×620 起）

```
┌────────────────────┐
│ 顶栏 44px           │  ← 品牌 + 拖拽 + 状态灯
├────────────────────┤
│ 中央数字人 flex: 1  │
├────────────────────┤
│ 底部交互 88px       │  ← 极简：输入 + 一个发送键
└────────────────────┘
```

右列**不进桌面壳**（宽度不允许）。信息流只在浏览器宽面板出现；
桌面壳里由**顶栏状态灯的颜色**承载体内核状态。

### 3.3 四个窗口的布局规格（2026-09-17 追加）

同一套品牌色、同一套窗体属性、同一套动效，四个窗口各自定义内容区。
**四个窗口不许各长一个样**——顶栏、圆角、描边、拖拽位必须长得是同一个家族。

| 窗口 | 默认尺寸 | 内容分区 | 默认位置 | 默认打开 |
| --- | --- | --- | --- | --- |
| **主控台** | `1440×900`（窄窗模式 `420×780`） | 顶栏 44 / 中央数字人 flex / 右流 320–360 / 底栏 104 | 屏幕右侧距边 `36px`，底边距 `18px`（沿用 `main.cjs:69-70` 的落位习惯） | **是** |
| **云电脑** | `880×620` | 顶栏 44 / 指标卡区 / 动作按钮行 / 快照列表 | 主控台左侧，横向间距 `16px` | 否 |
| **克劳德** | `720×560` | 顶栏 44 / 通道状态条 / 建议记录列表 / 两个按钮 | 主控台左侧偏上，纵向偏移 `-120px` | 否 |
| **上帝视角** | `1080×680` | 顶栏 44 / **2×2 四视图网格**（看自己 / 看任务 / 看环境 / 看账本） | 屏幕左上角距边 `24px` | 否 |

四个窗口共用的顶栏规格（与主控台顶栏同一份实现）：

| 元素 | 规格 |
| --- | --- |
| 高度 | `44px` |
| 左 | 品牌标记（土豆金圆点 + 窗口名） |
| 右 | 该窗口的状态灯（见 §3.5）+ 收起按钮 |
| 拖拽 | 整条顶栏都是拖拽区（`-webkit-app-region: drag`） |
| 吸顶 | 无 |

### 3.4 窗口之间的三件共享规格

**吸附**

| 项 | 规格 |
| --- | --- |
| 触发距离 | 与其他 GBT 窗口边缘或屏幕工作区边缘距离 `< 12px` |
| 视觉反馈 | 吸附方向画一条 `1px` 的 `--cyber-cyan` 线，透明度 `0.55` |
| 解除 | 拖离超过 `16px` 自动解除（阈值比吸附大 4px，防抖动） |

**最小化到托盘**

| 项 | 规格 |
| --- | --- |
| 图标尺寸 | `16×16`（Windows 托盘标准）+ `32×32` @2x |
| 图标构成 | 土豆金 `#F5B041` 实心圆 + 赛博青 `#00E5FF` `1px` 描边 |
| 状态点 | 右下角 `6px` 圆点，颜色用 §3.5 四态色，位置距图标边缘 `1px` |
| 右键菜单 | 四项窗口名（勾选态 = 已打开）+ 分隔线 + 全部收进托盘 + 退出 |

**多屏与越界**

| 项 | 规格 |
| --- | --- |
| 恢复校验 | 读回布局后，校验窗口矩形与任一显示器工作区**有交集**且交集面积 ≥ 窗口面积的 `20%` |
| 越界处置 | 不满足则把窗口移回主屏，保留原尺寸，不动其他窗口 |
| 缩放变化 | DPI 变化后按新工作区重新钳制（沿用 `main.cjs:186-200` 的钳制思路） |

### 3.5 状态灯口径（四个窗口共用）

## 五、验收

1. **四条目标逐条可指认**：品牌色用 token（`styles.css:8/10/12`）；窗体四属性在 `main.cjs:73/74/79/89`；布局四段在同一张截图里；动效三个 keyframes 在 CSS（`:319` / `:132`+`:324` / `:2426`）。
2. **品牌零残留**：`rg -i codex holo_pet/index.html holo_pet/app.js holo_pet/styles.css` 命中数 = 0（`archive/`、`tests/`、`node_modules/` 除外）。
3. **窄窗不塌**：`420×620` 下顶栏 / 数字人 / 底栏三段齐，无横向滚动条。
4. **宽窗四段**：`≥1280px` 下四段齐，右列实测宽度落在 `320–360px`。
5. **拖拽仍可用**：桌面壳与浏览器两种模式下都能拖动窗口，且拖拽不误触输入框。
6. **无裸色值新增**：本次改动不引入任何十六进制字面色值，全部引用既有 token。
7. **四窗同族**：四个窗口的顶栏高度、圆角、描边、拖拽位逐像素一致，看不出是四个不同来源的界面。
8. **吸附可感知**：窗口靠近另一 GBT 窗口边缘时出现青线提示并吸附；拖离超过 `16px` 自动解除，不抖。
9. **托盘四态**：托盘状态点的四种颜色与 §3.5 表格逐一对应，并能在切换时实时变化。
10. **越界不消失**：把关掉的显示器上的坐标写进布局文件，重启后该窗口回到主屏可见区域，尺寸不变。
