# 第②步策略层实证报告

> 取证日期：2026-09-16
> 取证目的：判定 `api.run_task("codex_*")` 是否会被策略层拦下，据此裁定第②步与第④/⑥步的落地顺序
> 取证方式：隔离 store 的只读探针 `.scratch/policy_probe2.py`（**未 spawn app-server、未触网、未写生产审计**）
> 配套文档：`第②步面板收口方案.md`

## 一、结论（三句话）

1. **策略层不拦。** 5 个新 `codex_*` 的 `policy.evaluate` 全部返回 `scopes=[]`、`restricted=False`。→ **第②步（面板改走 `api.run_task`）可以先于第④/⑥步落地**，不会出现「改完即被拦死」的中间态。
2. **但这不是「放行」，而是「无人认领」。** `codex_thread_new` 实际会 spawn app-server（等价 `process_execute`）、并与外部模型服务通信（等价 `external_llm`），策略层却给它 `scopes=[]` —— **5 个真正在跑的名字当前处于「零作用域保护」状态**。
3. **因此第⑥步是真加固，不是化妆。** 一旦第⑥步给它们补上作用域，非主人会话就会被要求授权。→ **第②步必须同步给面板三条路径包上 `policy.owner_session()`**，否则第⑥步落地当天，面板会被自己的策略拦死。

### 2.1 一次自我纠错（如实记录）

v1 探针的对照组用了 `process_execute` / `filesystem_write` 作为「能力名」，结果它们**没有被拦**，一度看起来像是探针失效。定性后确认：**这两个是「作用域名」，不是「能力名」**——策略层是按能力名（kind）走分支、再挂作用域；拿作用域当能力名喂进去，自然不匹配任何分支，也就不拦。

这不是产品缺陷，是**我的对照组维度用错了**。已改用真实能力名（`mcp_connect` / `mcp_call` / `desktop_commander` / `tripo` / `audit_query` / `tentacle` / `bt_control` / `vision`）重做，**9/9 PASS**。v1 与 v2 两次原始输出均已留档。

## 六、`owner_session` 传播性实证（第②步的前置依赖）

> 取证：`.scratch/ctx_probe2.py`（纯进程内：不起 HTTP 服务、不绑端口、不 spawn 子进程、不触网）
> 结果：**断言 21/21 PASS**，观察项 7 条

策略层实证只回答了「拦不拦」。但第②步还要回答「包在哪一层」——这取决于 `owner_session` 的传播性。

实现事实：`security/policy.py:21` `_TRUSTED_OWNER = contextvars.ContextVar(...)`，**不是 `threading.local`**；`is_trusted():95-98` 另有 `GBT_OWNER_SESSION` 环境变量兜底。

### 6.1 A 组 · ContextVar 裸跨线程

| # | 场景 | 实测 | 判定 |
|---|---|---|---|
| A0 | 未进入会话 | `False` | PASS |
| A1 | 已进入会话 | `True` | PASS |
| A2 | 父线程已进入会话 | `False` | PASS |
| A3 | 父线程已进入会话 | `False` | PASS |
| A4 | 会话线程内再开线程 | `False` | PASS |
| A5 | 会话已退出 | `False` | PASS |

**结论：ContextVar 不跨线程传播。** 父线程进入会话，子线程 / 线程池 worker / 孙线程一律读不到身份。→ 「谁用谁包」是唯一正确写法。

### 6.2 B 组 · `copy_context()` 显式携带

| # | 场景 | 实测 | 判定 |
|---|---|---|---|
| B0 | ctx.run 读原会话 | `True` | PASS |
| B1 | 直接 ctx.run（手动传播） | `True` | PASS |
| B2 | ctx.run 在提交后被调 | `True` | PASS |
| B3 | ctx.run 后再确认会话语义不变 | `False` | PASS |

**结论：`copy_context()` 能跨线程手动传播**，可作兜底。但观察项 `同一 Context 不可两线程同时 enter（RuntimeError）` —— 同一 `Context` 不可被两个线程同时 `enter`，面板并发多轮对话会踩 `RuntimeError`。**故方案不采用手动传播。**

### 6.3 C 组 · 环境变量兜底 `GBT_OWNER_SESSION`

| # | 场景 | 实测 | 判定 |
|---|---|---|---|
| C0 | 仅环境变量 | `True` | PASS |
| C1 | 仅环境变量 | `True` | PASS |
| C2 | 仅环境变量 | `True` | PASS |
| C3 | C3 撤掉环境变量后主线程立刻回到未受信 | `False` | PASS |

**结论：环境变量是进程级全局开关，跨线程全通。** 但它会把整个进程（含未来新增的非主人路径）一起提权，**方案明确不采用**，只用逐点包。

### 6.4 D 组 · 面板三个入口的线程拓扑与身份继承（实机结构，进程内直调）

| # | 场景 | 实测 | 判定 |
|---|---|---|---|
| D1 | _run_turn 是否继承请求线程的 owner_session | `False` | PASS |
| D2 | _run_turn 自包 owner_session 后 | `True` | PASS |
| D3 | quick.run 线程（:946 自带 owner_session） | `True` | PASS |
| D4 | 摘掉 :946 那层 owner_session 后（证明该层是承重的） | `False` | PASS |
| D5 | 调用层包 owner_session（同线程、无跨界） | `True` | PASS |
| D6 | 调用层不包 owner_session（今天真实基线） | `False` | PASS |
| D7 | 改造后 interrupt() 内部自包（任意线程可调） | `True` | PASS |

观察项（实测执行线程）：

| # | 观察 | 实测值 |
|---|---|---|
| O1 | 并发入口限制 | `同一 Context 不可两线程同时 enter（RuntimeError）` |
| O2 | P1 请求线程名（owner_session 在此层） | `Thread-1 (do_POST)` |
| O3 | P1 实际执行线程 | `gbt-holo-turn` |
| O4 | P2 实际执行线程 / kind | `gbt-holo-screen / tentacle` |
| O5 | P3 实际执行线程 / thread_id / turn_id | `Thread-5 (do_POST) / thread-from-old-process / turn-stub` |
| O6 | P3 未包时的执行线程 | `Thread-6 (do_POST)` |
| O7 | P3 改造后写法执行线程 / kind | `Thread-7 (do_POST) / codex_interrupt` |

**三个入口的线程边界结论：**

- **P1**：请求线程 → 后台线程 `gbt-holo-turn`，**跨线程**，身份不继承 → 必须包在 `_run_turn` 内部。
- **P2**：请求线程 → 后台线程 `gbt-holo-screen`，**跨线程**，但 `:946` 已自包 → 该层是**承重的**（`D4` 摘掉即掉身份），改造时不许顺手删。
- **P3**：`do_POST:1116 → interrupt():885` **同线程直调、无跨界**，所以在哪层包就在哪层生效（`D5`）；但今天**根本没人包**，真基线 `D6 = False`（未受信）→ 仍必须动刀，包在 `interrupt()` 内部（`D7` 已验证）。

### 6.5 两处自我纠错（如实记录）

1. **判据夹具错**：v1 把 `expect=None`（观察项）也计入 PASS/FAIL，报出 4 个假 FAIL。定性：**「跨线程不传播」是结论，不是失败**。已改为断言 / 观察分离，原始输出留档 `.scratch/ctx_probe2_firstrun.out`。
2. **预期写错**：我原本预期 P3 会**丢失**身份，实测 `D5 = True`。定性：**我的预期错了，不是代码错了** —— P3 没有线程边界。修正后补测真基线 `D6 = False`，得出「P3 必须包、但包在函数内部」的准确结论。

### 6.6 对第②步的确定性输入

| 输入 | 结论 |
|---|---|
| P1 包法 | `_run_turn` 函数内部包 `owner_session()`（跨线程，外层包无效） |
