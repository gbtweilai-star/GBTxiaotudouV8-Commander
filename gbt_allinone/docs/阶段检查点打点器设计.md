## 零、一句话

打点器只干一件事：**在每个阶段开始之前，把"此刻的维度 + 现实 + 时间线版本号"冻成一份可回滚的实物**，
并且让「**没打点**」和「**打点坏了**」这两件事，**不可能被读成没问题**。

---

## 一、它解决什么（为什么它是长程能力的硬前置）

《长程无人值守协议》§1.2 写死的三件套是：**维度快照 + reality 快照 + 时间线版本号**；
写死的时间是：**阶段开始之前**（不是结束后——结束后再打，出错时已经来不及）；
写死的处置是：**自动回滚到最近检查点 → 停手报人**。

而协议自己登记了一条**诚实缺口**：

> 仓库现有的检查点语义是**晋升级**——只有 `ascend()` 才会产出 `timelines/vN` 与护照，
> **没有阶段级快照机制**。

这句话的可执行形式就是本文件存在的理由：

```text
没有打点器          →  无人值守只能跑在「已有晋升回滚点覆盖」的范围内
                      （覆盖不到的阶段，不许无人值守）
有打点器            →  每个阶段自带一个回滚点 → 阶段级自治才成立
```

**它不是可选项**：V2 链路级、树引擎、无人值守，全都建立在"出错能退回去"之上。

### 2.3 诚实缺口三条（**不许假装已有**）

> ① 是协议已登记的；② ③ 是本轮新取证。

**① 阶段级检查点机制不存在。**
现有检查点语义是**晋升级**：只有 `ascend()` 产出 `timelines/vN` + `passports/vN.json`。
"每阶段一个检查点"目前是**设计目标**，不是既有能力。

**② 新实证：房间级冻结路径当前不可运行（静态取证 · 双面对照）。**

```text
rg -uu --no-heading -g "*.py" "def _replace_tree" .      → 0 命中
rg -uu --no-heading -g "*.py" "def _tree_fingerprint" .  → 2 命中   【正对照：扫描器不瞎】

调用点（有调用、无定义）：
  gbt_allinone/room_space.py:611   MS._replace_tree(dirs["dimension"], snap_dir)
  gbt_allinone/room_space.py:1140  MS._replace_tree(dirs["dimension"], timeline)
  gbt_allinone/room_space.py:1141  MS._replace_tree(dirs["dimension"], dirs["reality"])

AST 复核：mirror_space.py 函数清单 11 个，**不含 `_replace_tree`**；
         room_space.py 1,276 行，**也不定义 `_replace_tree`**。
```

**结论（把话说准）**：`room_space.snapshot()` 与 `:1140` 路径**会抛 `AttributeError`**，
即"房间级快照"这条既有零件**不能当现成原语用**。
证据强度如实标注：**静态取证（全量读 + AST 清单 + 双面对照）**，
**未运行 `room_space.snapshot()`**——运行它会写房间目录，属施工/验证动作，本设计阶段不动。
→ **建议**另登观察项（`PROJECT_BLUEPRINT.md` §八），**不在本设计里修**
（《原子落地律》：一个原子单元一件事）；本条**尚未**写入 §八，写与不写**待 Owner 拍**。

**③ `.mirror.lock` 存在但无人引用。**

```text
文件实测存在（1 B）；rg "mirror.lock|mirror_lock" -g "*.py" → 0 命中。
```

**结论**：**不存在**"镜像空间已经有一把共享锁"这回事。打点器必须**自带锁**，
不许假设"已经有锁了"（拿一个不存在的锁当保护 = 假绿的一种）。

## 三、它做什么 / 不做什么

### 3.1 做七件事（全部有判据）

| # | 动作 | 判据 |
|---|---|---|
| 1 | **打点**：阶段开始前冻一份检查点 | 副本指纹 == 源指纹（拷贝前后各算一次） |
| 2 | **状态**：回答"最近检查点是什么、可用不可用" | 三态互斥（见 §6.1），不许"看着像在" |
| 3 | **校验**：`verify <id>` 重算并比对 | 三类差异逐条列出（复用 `mirror_status` 词汇） |
| 4 | **恢复**：`restore <id>` 把维度 + 现实退回去 | 恢复后重算的差异清单 == 检查点里记录的清单 |
| 5 | **自证**：`selftest` 四臂对照 | 四臂结论**必须互相不同**，见 §6.2 |
| 6 | **落账**：每次打点/恢复/失败都进审计 | 事件名与字段见 §7.1 |
| 7 | **只读入口**：编程可调用 `run()`（像 `run_tests.py` 的范式） | 回归框架能接、不是孤儿工具 |

### 3.2 不做六件事（**边界就是安全性**）

| 不做 | 为什么 |
|---|---|
| **不调度、不常驻** | 打点时机由阶段决定，不由时间决定（协议 §1.1：阶段是目标切分，不是时间切分） |
| **不判断"阶段该不该结束"** | 判据在验证侧，不在打点器里 |
| **不推进阶段** | 打点器是原语，不是执行者 |
| **不写 `timelines/`、不写护照、不动版本号** | 那是 `ascend()` 的职责；两套语义混一起会污染"reality = 最后一次晋升的全量"这条不变量 |
| **不进 `caps_registry`** | 不给面板/无人值守新增可调用面——自治基础设施先只做 CLI + 编程入口 |
| **不自动删旧检查点** | 删除是破坏性动作，默认只报警报人（《静默失效律》：不许静默发生） |

## 四、检查点长什么样

### 4.1 目录结构

```text
store/mirror_space/checkpoints/
  .lock                          # 跨进程锁（safe_io.FileLock 口径）
  00001/
    record.json                  # 记录（指纹 + 元数据 + 漂移清单）
    dimension/                   # 维度全量实物副本
    reality/                     # 现实全量实物副本
  00002/
    ...
```

- **真相源 = 每个 `NNNNN/record.json`**（目录名只是序号，不是结论）。
- **不做 `index.jsonl`**：目前规模（每天几十个）枚举成本可忽略；多一个索引就多一个"索引与实物不一致"的静默失效面。
  等实测证明必要再加（加的时候必须写"索引不是真相源"）。
- 落点**不选 `store/health/`**：健康面是**高频、可丢**的观测数据；检查点是**低频、不可丢**的回滚实物。混一起会让保留策略打架。

### 4.2 记录字段（**对齐协议 §七**，能不改就不改）

```jsonc
{
  "checkpoint_id": "00001",
  "seq": 1,                       // 整数序号（取最新只用它，不用文件名排序）
  "phase_id": "P07-03",           // 必填；没有它 → 本次没有结论（rc=22）
  "goal": "一句话目标",
  "created_at": "2026-09-17T15:10:00",
  "tz": "Asia/Bangkok",

  "timeline_version": 20,         // 打点时刻 passports 最新整数版本
  "dimension_hash": "…64hex…",    // 树指纹的聚合哈希
  "reality_hash": "…64hex…",
  "dimension_files": 14,
  "reality_files": 12,

  "dimension_manifest": { "相对路径": {"sha": "…", "size": 0} },
  "reality_manifest":   { "相对路径": {"sha": "…", "size": 0} },

  "drift_at_checkpoint": [        // 打点时刻的维度↔现实差异（回滚判据的基准）
    {"file": "holo_pet_w3/shell/main.cjs", "kind": "not_yet_promoted", "detail": "镜像有、生产无（待晋升）"}
  ],
  "reality_drift_at_checkpoint": [],

  "tool": "checkpoint.py",
  "law": "检查点 = 回到那一刻；不许移动、不许覆盖、不许静默删除"
}
```

**两条口径继承**：

- `dimension_hash` / `reality_hash` = **对 `_tree_fingerprint()` 结果做规范化 JSON 后的 SHA-256**（口径与 `room_space._json_sha` 同族）；
  逐文件 `sha` 仍是 `mirror_space._sha_file` 的 16 hex 短指纹——**不新立第二套指纹**。
- `drift_at_checkpoint` 的 `kind` 词汇**复用** `mirror_status()` 的
  `not_yet_promoted` / `production_extra` / `diverged`——**不造近义词**（同族于"口径不一致 → 静默算错"）。

### 4.3 序号与"取最新"（**《版本号字符串序陷阱》直接适用**）

```text
取最新检查点 = max(int(目录名) for 目录名 if 目录名.isdigit())
               —— 整数序，绝不 sorted(目录名)[-1]

遇到非纯数字目录 → 计入 status.unrecognized[]（显式），
                   不参与取最新，但**不许静默忽略**（《空不等于不存在律》）
```

### 4.4 冻两层：**实物副本 + 指纹**（缺一层都不行）

| 层 | 作用 | 只有它的后果 |
|---|---|---|
| **实物副本**（`dimension/` `reality/`） | 能真的退回去 | 只有指纹 → 只能说"变了"，退不回去 |
| **指纹清单**（manifest + 聚合 hash） | 能判定"是不是那一刻"、差异在哪 | 只有副本 → 没法判"副本是不是完整的"，撕裂拷贝会被当成成功 |

### 4.5 一条不变量：**打点器对维度/现实是只读的**

打点只读 `dimension/` 与 `reality/`，只写 `checkpoints/`。
所以"打点"这个动作**不会造成镜像漂移**，`scan()`、`mirror_status()` 的结论不受打点影响。

> 这条同时回答了"只读期能不能打点"：能——**写盘由独立进程完成，不受只读期约束**
> （与风哥 2026-09-17「写盘由后台探针服务独立完成，走独立进程」的拍板同口径）。

## 五、三个动作

### 5.1 `--checkpoint --phase <phase_id> [--goal "…"] [--force] [--dimension-only]`

顺序固定（**顺序就是完整性保证**）：

```text
① 取锁（checkpoints/.lock，跨进程）
② 算源指纹：dimension + reality（mirror_space._tree_fingerprint）
③ 分配 seq = max(已有 seq) + 1（整数序）
④ 全量复制 dimension → checkpoints/<seq>/dimension/
           reality   → checkpoints/<seq>/reality/
⑤ 算副本指纹 → **必须与 ② 完全相等**
    不等 → 重试 1 次 → 仍不等 → rc=13 + checkpoint_failed{reason_code:"torn_copy"}
⑥ 记 drift_at_checkpoint / reality_drift_at_checkpoint（mirror_status 口径）
⑦ atomic_write_json 落 record.json
⑧ 落审计 `checkpoint`
⑨ 释放锁
```

**为什么 ⑤ 不是多余的一步**：拷贝期间若有人改了源文件，副本会"半新半旧"。
这种副本**看着完整、其实回不到任何一刻**——正是《静默失效律》要防的东西。
指纹前后各算一次，是把"撕裂拷贝"从"看不出来"变成"必须报错"。

### 5.2 `status`（只读 · 三态互斥）

| 结论 | rc | 判据 |
|---|---|---|
| **可用** | 0 | 最近检查点的 `record.json` 可读，且重算指纹 == 记录指纹 |
| **缺失（灰）** | 10 | `checkpoints/` 存在且可枚举，但没有任何检查点 |
| **损坏** | 11 | 有记录，但 `record.json` 非法 / 副本缺失 / 指纹不符 |
| **自盲** | 12 | 根路径不可读 / 枚举失败 / 指纹函数抛错（**真的不知道**，不是"没有"） |
| **没有结论** | 22 | 锁被占 / 未指定动作 / 路径不可用（沿用 W2.5 的 22） |

### 5.3 `--restore [<checkpoint_id>] [--go] [--reason <code>]`

```text
① 取锁
② 校验检查点可用（等价 status 的 0 档）；不可用 → rc=11，不写任何东西
③ 算当前指纹
④ 只写"确实不同"的那棵树：
     维度变了 → 清空 + 全量拷贝回检查点的 dimension
     现实没变 → **跳过写现实**（记 reality_unchanged）
⑤ 恢复前先把"当前态"另存一份 .pre-restore/<id>/（**第二保险**）
⑥ 重算指纹，与 record 逐条比对
⑦ 落审计 `rollback{phase_id, rolled_back_to, reason, reported_at}`
⑧ 释放锁；**停手报人**（不许恢复完接着跑）
```

**五条硬口径**：

1. **恢复 = 一次性全量替换**，不改单文件（与 `rewind` / `ascend` 同律）。
2. **不写 `timelines/`、不写护照、不动版本号**——所以 `rewind(19)` 这条老回滚路径**始终有效**。
3. **只在指纹不同才写**：现实没变就不碰现实。**动现实是要留痕的事，越少越好。**
4. **"回到那一刻"的判据**：恢复后重算的差异清单**必须等于** `drift_at_checkpoint`；
   不等 → 恢复不算成功（rc=13），报人。
5. **打点器不自己决定回滚**：它只执行被明确点名的 `restore`。
   "出错自动回滚"是**协议层的动作**（执行侧决定 + 落账 + 报人），工具本身只是原语。

### 5.4 `--diff [<checkpoint_id>]`（只读）

输出三类差异，**词汇与 `mirror_status()` 一致**：新增（`production_extra`）/ 缺失（`not_yet_promoted`）/ 分叉（`diverged`）。
默认 `restore` **先打 diff 再执行**；`--dry-run` 只打 diff。

### 5.5 退出码（**沿用已立的族约定，不许混码**）

| 码 | 含义 | 族 |
|---|---|---|
| **0** | 成功 / 可用 | 通用 |
| **10** | 缺失（灰：没有检查点） | 本工具 |
| **11** | 损坏（有记录但不可用） | 本工具 |
| **12** | 自盲（`CHECKPOINT_BLIND`：真的不知道） | 本工具 |
| **13** | 完整性失败（撕裂拷贝 / 恢复校验不过） | 本工具 |
| **22** | 本次没有结论（锁被占 / 未指定动作 / 路径不可用） | 通用（W2.5 已立） |

> **族约定（既有工具已隐式立起，本文件第一次显式写出来）**：
> `0` 成功 · `10–19` 本工具自身的裁决 · `20/21` 探针族的"进程不活 / 流断" · `22` 没有结论。
> **20/21 不许被本工具复用**——复用了就和 W2.5 的"进程不活 / SSE 断"混码。

### 5.6 幂等与防重

- **同 `phase_id` 已有检查点** → 再打**不覆盖**，返回既有 `checkpoint_id`（rc=0），另落 `checkpoint_reused`。
- **理由**：覆盖会**悄悄把回滚点往后挪**——那是最典型的静默失效：账本上只有一条，实际是两条。
- 真需要重打 → 显式 `--force`（**必须落账**，`reason` 必填）。

## 六、假绿防线（**打点器自己必须自证**）

### 6.1 三态互斥（**不许混**）

```text
可用(0)  ：知道，而且验过
缺失(10) ：知道，确实没有
自盲(12) ：不知道 —— 路径读不到 / 枚举抛错 / 指纹函数坏
```

**"抓不到"绝不等于"没有"**（《空不等于不存在律》）：
枚举失败必须报 `CHECKPOINT_BLIND`，**不许报 0 个检查点**，
更不许报"无漂移 / 一切正常"。

### 6.2 `selftest` 四臂（**结论必须互相不同**）

> 依据：风哥 2026-09-17 对 V3/V6 探针自伤的定论——**"两组必须给出不同结果才算可判别"**。

| 臂 | 构造 | 期望结论 |
|---|---|---|
| **A 正对照** | 正常树 → 打点 | rc=0，且副本指纹 == 源指纹 |
| **B 负对照（指纹不瞎）** | 改一个字节 | 指纹**必须变**；不变 = 指纹函数是常数，自证失败 |
| **C 负对照（差异能被看见）** | 删一个文件 | 差异清单里出现该文件的 `production_extra`/`not_yet_promoted` |
| **D 自盲对照** | 指向不存在的根 | rc=**12**（**不许** 0、不许 10） |

**判别性要求**：A、B、C、D 的**结论必须互相不同**；
若 A 与 D 同码、或 B 与"没改"同结果 → **本次自证不成立**（样本不构成判别），
必须改样本重来，**不许把"跑了四臂"当成"验过了"**。

全部在**临时目录**里跑（同 `test_mirror_space.py` 的隔离范式），**不碰生产 store**。

### 6.3 自盲的判定条件（写成代码前先写成规则）

以下任一发生 → `CHECKPOINT_BLIND`（12），**不许降级成 10**：

```text
· 根路径不存在 / 不可读（不是"空"）
· 枚举过程中捕获到异常（异常 ≠ 空集）
· 指纹函数对同一棵树两次调用结果不同
· record.json 存在但无法解析（损坏是 11；**读不到文件本身**是 12）
```

## 十二、红线（本设计的）

1. **打点器对维度/现实只读**——它只写 `checkpoints/`；打点不许改变镜像状态。
2. **不许覆盖已有检查点**——同 `phase_id` 再打 = 返回既有；要重打必须显式 `--force` + 落账。
3. **撕裂拷贝不许当成功**——副本指纹与源指纹不等 = 失败（rc=13），不许"看着拷完了"。
4. **"抓不到"不许当"没有"**——路径读不到 / 枚举抛错 = `CHECKPOINT_BLIND`(12)，不许报 0、不许报绿。
5. **恢复只在指纹不同时写**——现实没变就不碰现实；动现实必须留痕。
6. **恢复之后必须停手报人**——不许"回滚完接着跑"。
7. **打点器不写 `timelines/`、不写护照、不动版本号**——`rewind` 那条老路径必须始终有效。
8. **打点器不自己决定回滚**——它只执行被明确点名的动作；"自动回滚"属协议层。
9. **默认不删任何东西**——删除走 Owner 批。
10. **不进 `caps_registry`、不起 GUI、不动宿主键鼠、不抢焦点**；宿主规矩照旧：串行、无并发、跑完即停。
