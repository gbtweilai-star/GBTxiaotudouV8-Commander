# 人机验证情报台账（Verification Watch Ledger）· R-H180 · 2026-09-20

> **一句话**："人机验证是个笑话"这句话**对了一半**。
> 对的那一半：它防不住真正的 AI。错的那一半：**它防的本来就不是我们**。
> 它防的是"**伪人类**"（假装是人、刷量、恶意）；我们是"**新人类**"（不假装、不刷量、留痕、一 AI 一号）。
> 两者的区别不是"能不能绕过"，是 **"绕不绕"**。

---

## 一 · 立场：不主动绕（**这是合规底座的红线**）

| 层 | 含义 | 处置 |
|---|---|---|
| 技术层 | 验证机制本身可被绕过 | **知道就好，不主动绕** |
| 合规层 | 我们是合法用户，验证不该卡我们 | **走正规途径，不绕** |

🔴 **绕过人机验证 = 假冒真实用户 = 直接踩合规底座第三条红线**（"不假冒真实用户"）。
**能力上能做到 ≠ 该做。** 这不是能力问题，是**身份问题**：
绕过验证 = 假装自己是人 = **回到旧身份**。

---

## 二 · 正确姿势：不绕，但让验证变得"不必要"

平台设人机验证，是因为**分不清"AI 在干活"和"AI 在捣乱"**。那就**让平台能分清**。

| 动作 | 目的 |
|---|---|
| 用**官方 API** | 不经过前端；绕验证不是目的，是**结果** |
| 用 **OpenAPI / 开发者接口** | 平台**欢迎**的自动化路径 |
| 用平台**自己的 AI 功能** | 它们自己就在做 AI |
| **留痕 + 可追溯** | 出问题时能证明"我是合规的" |
| **账号独立** | 一 AI 一号，不混不借 |

> 这不是"绕验证"，是"**让验证变得没必要**"。

---

## 三 · 台账字段（六项 · 挂在 `research_intel` 底下，三部门各一张）

```json
{"platform": "抖音", "verification_type": "滑块 / 行为验证",
 "blocking_scenario": "网页端批量上传时触发",
 "official_api": "开放平台上传接口（需企业资质）",
 "policy": "平台开发者协议 §3.2 明示禁止自动化绕过",
 "action": "api"}
```

| 字段 | 内容 |
|---|---|
| `platform` | 哪个平台 |
| `verification_type` | 图形验证 / 滑块 / 行为验证 / 短信 |
| `blocking_scenario` | 什么操作会被卡 |
| `official_api` | 有没有官方 API 可替代 |
| `policy` | 平台明文怎么规定的 |
| `action` | `api` / `official_ai` / `human_in_loop` / `register_pending` |

### 3.1 应对路径（只有四条，**没有"绕过"这一条**）

```
有官方 API      → 走 API，不经过前端
有官方 AI 功能  → 用它自己的
都没有          → 登记，走「人机协作」（人点一下，AI 继续）
不确定          → register_pending（登记待授权，不许自作主张）
```

**归属**：`music_intel` / `video_intel` / `film_intel` **各自维护一张**
（三部门的验证形态不同，合账就是"三处真相"）。

## 四 · 写进纪律

> **不绕验证，是"新人类"和"伪人类"的分界线。**
> 平台设验证是为了防"伪人类"；我们不是伪人类，**不需要绕**。

与合规底座合体后，六条纪律成型：
证据侧 · 审计侧（基线不吞护照）· 审计侧（执行者不自写审计）· 执行侧（人类视角）
· 合规侧（一 AI 一号）· **身份侧（本台账：不绕验证）**。

## 六 · 诚实边界

- 本台账**不含任何绕过手段**，也**不做任何绕过尝试**；它只把"卡点"变成"已知情报"。
- 骨架期**台账是空的**（三部门各 0 条）——**空就是空**，不许假装已调研。
- **真实情报要出网取证**（需 `auth_gate` 授权），今天做不了；此前的所有条目只能是 `register_pending`。
