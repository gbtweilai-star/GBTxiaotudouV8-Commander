## 二 · 🔴 与原生能力**融合**的四律（本设计的关键）

主人那句「**要和原生能力完美融合，没有外部密钥也不影响能力**」——
它不是形容词，可以落成四条**可测**的规矩：

```
① 原生优先：先在原生栈里找（131 个能力位 / auto_switch / context_vault）；
            找不到才考虑引外部 ⇒ **外部只是叶**。
② 过路由：任何外部组件必须经原生路由接入（run_task / 能力位注册），
            **不许直插管道**（直插 = 换个说法绕开门禁与留痕）。
③ 零密钥自检：**没有外部密钥时，能力必须"降级但不失效"**
            —— 可测：每个能力位在无外部密钥下的自检读数（**待落判据**）。
④ 换卸不动根：装/卸/换任何外部组件，**原生栈（触手/记忆/门禁/审计）一条不动**
            （同族：能源可换、原生栈不动 · R-H226 已做成逐项闸）。
```

🔴 **第 ③ 条是这条需求的核心**：`没有外部密钥一样不影响能力` ⇒
**判据 = 零外部密钥下的能力自检**（不是"我觉得不影响"）。

## 三 · 五条红线（写死 · 沿用主人口径）

真正缺的不是"这些积木"，而是 **① 本机把模型跑起来**（CLI + 显存 + 出网拉模型）。

## 五 · 诚实边界

- 本设计**不安装任何东西、不出网、不拉模型**；
- **十个外部项目全部未取证**（盘上 0 命中 · 未出网）⇒ **待核，不许当已找到**；
- **显存读数拿不到** ⇒ 无法保证本机能带 7B-8B（你的门槛表写 8 GB 显存起步）；
- 「没有外部密钥也不影响能力」目前是**目标**，其判据（零密钥自检）**待落**；
- **层数多不等于漏得少**（同 v2.0 那句）：这五层里，我们有实现在手的四层，
  缺的那一环**恰恰是最底层**（本机把模型跑起来）。
