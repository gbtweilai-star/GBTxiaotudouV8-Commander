## 二、运行方式（怎么装、怎么起、怎么调）

### 1. 安装（卡上真实执行的脚本，已取回 `.scratch/_pod_comfy_setup.sh`）

```bash
cd /workspace
git clone --depth 1 https://github.com/comfyanonymous/ComfyUI ComfyUI
cd /workspace/ComfyUI && pip install -r requirements.txt
```

另有一条 venv 路线（`.scratch/_pod_comfy_venv.sh`）：`python -m venv /workspace/comfy_venv`
→ 装 `torch torchvision torchaudio`（cu121 源）→ 再装 ComfyUI 的 requirements。
**但实际在跑的那份不是 venv**，理由见下条读数。

### 2. 启动后的自述（`.scratch/_pod_comfy_server.log` 现读）

| 项 | 读数 |
|---|---|
| ComfyUI 版本 | **0.7.0** |
| 前端版本 | 1.35.9 |
| Python | 3.11.10 |
| torch | 2.6.0+cu124 |
| 显卡 | RTX 4090 · 总 VRAM **24091 MB** · 总 RAM **127910 MB** |

| 自定义节点 | `custom_nodes/websocket_image_save.py`（导入耗时 0.0s） |

### 3. 端口与可达性（现读，决定"怎么调"）

| 端口 | 用途 | 对外可达 |
|---|---|---|
| 8188 | ComfyUI HTTP/WS | ❌ `https://<pod>-8188.proxy.runpod.net/{system_stats,object_info,queue}` 全 **404**（未做端口映射） |
| 8888 | JupyterLab | ⚠️ 可达但要令牌：无 token GET `/api/status` → **403 Forbidden** |
| 22 | SSH | 映射到公网 `20702`（要有密钥才能用） |

**结论（这条决定所有后续设计）：ComfyUI 只能在卡内被调，外面驱动不了。**
所以触手要驱动它，只有一条正路：**在卡上跑代码**（`pod_link op=run` → 走 JupyterLab 内核通道），
由卡内代码 `POST http://127.0.0.1:8188/prompt`，产物落卷后再 `down` 取回。

### 4. 卡内调用契约（ComfyUI 标准 HTTP，运行方式即此四步）

```
POST /prompt          {"prompt": <API 格式图>, "client_id": "..."}   → {"prompt_id": "..."}
GET  /history/<id>                                                   → 取输出文件名与节点状态
GET  /view?filename=&subfolder=&type=output                          → 取回图片/视频字节
GET  /object_info                                                    → 节点全量（本文件已吸收）
POST /upload/image                                                    → 传参考图进 input/
WS   /ws?clientId=...                                                 → 执行进度与 exec 事件
```

## 五、"跑通"的判据（下一步照这个验）

### ✅ 2026-10-13 19:5x · 判据已满足（真跑通）

| 环 | 读数 |
|---|---|
| `POST /prompt` | http 200 · `prompt_id=cbdb9bb8-b799-4d1c-ad05-50080036018d` · `node_errors={}` |
| `/history/<id>` | http 200 · `status=success` · **4 秒**出图 |
| 产物 | `comfy_probe_00001_.png` · **611,121 B** · 卡上 sha16 **`f89a11fa5e5efd43`** · magic `89504e470d0a1a0a`（PNG） |
| `down` 回本机 | 611,121 B · 本机 sha16 **`f89a11fa5e5efd43`** ⇒ **两头逐字节一致** |
| 肉眼 | 黑外套 + 黄大衣、白网格背景、512×512，非空文件（`outputs/cloud/comfy_probe_f89a11fa5e5efd43.png`） |

**首跑为什么红（真因，记下来免得再踩）**：`CheckpointLoaderSimple` 报
`ERROR: Could not detect model type of: /root/ckpt/mm_sd_v15_v2.ckpt`
—— 卡上那个 `mm_sd_v15_v2.ckpt` **ComfyUI 认不出来**（不是模型缺失，是类型识别失败）。
我按字面挑了 list 里的第一个，正好是它。换成 `v1-5-pruned-emaonly-fp16.safetensors` 立刻过。

**卡上 checkpoint 现读（3 个）**：`mm_sd_v15_v2.ckpt`（**不可用**）· `svd_xt.safetensors` ·
`v1-5-pruned-emaonly-fp16.safetensors`（可用，本轮用它出的图）。

**另记一条操作教训**：`pod_link run` 的 WS 通道会因**长时间无输出**而超时（我第一版脚本 300 秒
静默轮询 ⇒ `WebSocketTimeoutException`）。卡内脚本必须**每几秒 print 一次进度**。

---

一条最小图走完整链、且**产物字节可回读对账**才算跑通：

```
卡内代码 POST /prompt（最简 sd15 图） → 轮询 /history/<id> 拿到输出名
→ GET /view 取字节 → 落 /workspace/out 并算 sha256
→ down 回本机 → 本机再算 sha256，与卡上一致 ⇒ 记为跑通
```

任一环红就是没跑通；缺授权就如实报缺哪个作用域，不绕门。
