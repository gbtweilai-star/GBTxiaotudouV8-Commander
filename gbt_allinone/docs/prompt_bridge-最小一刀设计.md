# `prompt_bridge` · 最小一刀设计（风哥拍板：先设计后动手）

> 2026-09-19 前夜 · 状态：**设计稿，未实现**。按风哥要求，交付物必须含
> **边界 / 验收判据 / 基线影响** 三样，缺一即"拖延"。

## 一、边界（做哪件、不做哪件）

**做**：

1. `gbt_allinone/prompt_bridge.py`：纯本地、零依赖的**结构化模板**转化
   （`角色 / 目标 / 约束 / 输出格式` 四段），输入大白话、输出专业提示词；
2. 两态开关：`compile` / `passthrough`，**两态都留痕**（否则"没转"会被读成"转化器不存在"）；
3. 能力层接线（同批四件）：`caps_registry` 条目 + `api.py` 分发 + `policy` 作用域 + `main.cjs` tools tab 出口清单。

**不做**（明确划出去）：

1. **不写 VS Code 插件**、不改 Codex 官方 UI（那是第二用户入口，破单入口铁律）；
2. **不建本地 HTTP 代理**（替换正式通道 = 两处真相；凭据经过自制代理 = 新信任面）；
3. **不接外部模型**（第一刀不引入 `external_llm`；转化纯本地）；
4. 不碰 `codex_bridge.py`（发车用**已有** `codex_turn_send`）。

## 二、验收判据（可跑）

| # | 判据 | 判法 |
|---|---|---|
| P1 | **结构完整** | 产出必须含 `角色 / 目标 / 约束 / 输出格式` 四段（可断言段名存在） |
| P2 | **原意保真** | 从 20 条大白话抽关键词（名词+动词），产出**必须全部保留**；丢一个即 FAIL |
| P3 | **不通电可降级** | 任何异常路径返回结构化降级（`ok:false + reason_code`），**不抛、不冒充成功** |
| P4 | **两态留痕** | `compile` 与 `passthrough` 各落一条审计（含耗时/字数/开关态），**不落原文** |
| P5 | **零新增依赖** | 跑前跑后 `regression_stamp` 的 deps 指纹一致 |

## 三、基线影响（会不会动 Ran ?）

**会动。** 必须新增契约测试（P1–P4 各至少一条），因此：

```
Ran 174  ->  Ran 178（+4）
```

**处置**（按今晚立的规矩）：要么接受基线迁移并**同批更新 A 基线式的封存记录**，
要么把测试放进**独立文件**（`gbt_allinone/tests/test_prompt_bridge.py`），使 `test_framework` 的 174 不动。

**建议后者** —— 理由：`test_framework` 的 174 是本轮刚稳住、且被用作 A 基线参照的口径；
新能力自带独立测试文件，两边互不牵连（同一晚"一个坑不踩两次"的应用）。

## 五、本刀之后，基线记录要新增哪一栏（风哥 2026-09-19 追加要求）

`prompt_bridge` 是**新能力**，它的风险不是"跑不跑得起来"，而是**它会引入新的"两处真相"面**。
先把它写出来，避免又靠门来抓：

| 面 | 会不会新增一处"声明" | 本刀的处置 |
|---|---|---|
| **policy 作用域** | 第一刀**零作用域**（纯本地模板）⇒ 不新增 scope 声明 | 但 `evaluate()` 里要加分支：**未列出动作 fail-closed**（照 `voice_orchestra` 那条），否则将来加"调外部模型"会被静默放行 |
| **注册表 ↔ api 分发** | 会：`caps_registry` 一条 + `api.py` 一条 | **必须同批**，否则 routing 自检（registered vs routed）立刻断 |
| **面板出口清单 ↔ `TOOLS_CAPS`** | 会：`tools` tab 加一行 | 同批；且**动作状态要如实**（`compile`/`passthrough` 两态 live，不写规划态） |
| **测试 ↔ `Ran N`** | 会，但**不进 174** | 测试放**独立文件** `tests/test_prompt_bridge.py` ⇒ `test_framework` 的 174 不动 |

**因此本刀对基线记录的新增栏**：

```
基线记录新增一栏：routing（registered / routed / unrouted）
  理由：新 cap 必须同批登记注册表与分发，routing 数会从 96 -> 97；
        这一栏能把"注册了但没分发"这类缺口在**每次回归**时自动暴露（不靠人眼）。
```

（这条与 O71 同源：**注册表类的断层，让门去抓**。）

## 六、与风哥贴的 v1.0 逐点对照（反复被贴的东西要有落点）

| 点 | 风哥 v1.0 | 本仓第一刀 | 取舍理由 |
|---|---|---|---|
| 编译产物 | `PromptCompiler.compile()`：字符串替换 + 固定模板 | 同思路，但**四段可断言**（`SEGMENTS` 锚点） | 没有判据的模板**无法被检验**；P1 让它可跑 |
| 保真 | 无 | **P2 原意保真**：关键词必须全保留，丢一个即 `intent_loss` | "注入角色/约束"不能把用户原意吃掉——这条是 v1.0 最容易出事的隐点 |
| 异常 | `compile()` 会因输入异常抛出 | **P3 永不抛**，结构化 `ok:false + reason_code` | 本仓口径：失败要留痕 + 原因码，不许把故障伪装成崩溃 |
| 开关 | `CodexInputBridge.toggle_state` 内存态 + `history` 内存列表 | 两态 `compile`/`passthrough`，**两态都留痕**（经能力层审计） | 内存态进程一死就丢；`print` 不算留痕 |
| 发车口 | `execute_codex()` 是 mock（print 模拟） | **不新造**：走已有 `codex_turn_send` | 已是两处真相的最小形态 |
| 落地形态 | 方案 A VS Code 插件 / 方案 B 本地代理改 Base URL | **cap op + tools tab**（不写插件、不建代理） | A 是第二用户入口；B 凭据过自制代理 = 新信任面 + 替换正式通道 |
| 元数据 | `ProjectMetadata(developer, guardian, forbid_delete)` | **不引入**：本仓已有 `signature.py` + `gbt_stamp` | 两套钢印 = 又一处"两处真相" |

**结论**：v1.0 的**设计直觉是对的**（"不打断心流"、两态开关、注入角色与边界），
但它的**四个可检验面全空**（结构/保真/异常/留痕），落地方案又都破本仓铁律。
本仓第一刀把可检验面补齐，把落地形态收回主干。

### 唯一值得从 v1.0 吸收的一条

`intercept_input()` 里**先打印开关状态再执行** —— 这个"让动作可见"的习惯与本仓"可见化出口"同源，
本仓的等价物是：**每次调用落审计（含 mode / 耗时 / 字数）**，且在 `status` 里自报 `external_model=False`。
（不吸收它的 `print`，因为打印不是留痕。）



### 更正（风哥 2026-09-19）：那条"吸收"我翻译丢了**时序**

原文写：吸收 `intercept_input()` 的"让动作可见"，等价物 = 每次调用落审计 + `status` 自报。

**这两件事的时序不同**：

| | v1.0 | 我原来的等价物 |
|---|---|---|
| 时机 | **执行前**先报当前态 | **执行后**落审计 |
| 防的是 | "**在错误的态下执行**" | "执行了没痕" |

⇒ 正确的等价物是**前置查询**：`status` 必须是**零副作用纯函数**，调用方在**发车前先问**当前 mode。
（与本仓 `preflight.before_action` 同构：先问，再动。）

**已补可验形式**：`tests/test_prompt_bridge.py::test_status_is_side_effect_free` ——
直调 `status` 前后审计流字节数不变 + 两次调用结果一致。

> 口径（风哥）：**要么给真等价物，要么明说"不吸收"**；不能译成另一个机制然后标"已吸收"。
