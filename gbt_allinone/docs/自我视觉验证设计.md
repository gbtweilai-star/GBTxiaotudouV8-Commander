# 自我视觉验证设计（Self-Vision）

> 依据：风哥 2026-09-17 拍「她**能生成对话面板，但没有『看自己』的闭环**——设计补齐」。
> 定位：本文件是**设计**，**未动任何代码**。红线：先设计，不动手。
> 配套：《holo_pet_UI规格.md》（该长什么样）·《Codex同化方案.md》§4.2 L0 判据（不该出现什么）·
>《W3上帝视角镜像方案.md》（看全局的那条通道）· `CHARTER.md` 第十四～十八章。

## 零、一句话

**零件全在，缺的不是眼睛，是「把镜头对准自己」的那一步、一张「我该长什么样」的对照表、一条「差多少算坏」的上报闭环。**
本能力叫 **自我视觉验证**（`self_vision`）；它与上帝视角互补，**不替代**上帝视角，**不替代**用户汇报。

### 1.2 铁证：**本身份看不见自己**（本轮实测）

`.scratch/_selfvision_probe.json`（只读探针，结果落文件 · 《结果通道律》）：

```json
{"capture_env": {"interactive_desktop": false,
                 "desktop": "CodexSandboxDesktop-13311955ef7f7ee2cd6cc762e90c02a1",
                 "capture_ready": false,
                 "likely_failure_roots": ["non_interactive_desktop"],
                 "backends": {"dxcam": true, "dxcam_winrt": true, "mss": true, "pyautogui": true},
                 "monitors": [{"index": 0, "width": 1536, "height": 864}]},
 "list_windows": {"count": 0, "fields": []},
 "find_holo_pet": null,
 "capture_probe": {"error": "screen grab failed"}}
```

三条硬事实：

1. **后端全在**（`dxcam / mss / pyautogui` 都能 import）——不是「没装」；
2. **本身份不在交互桌面**（`interactive_desktop=false`，桌面名是 `CodexSandboxDesktop-…`）；
3. 于是 `_enum_windows()` **返回 0 扇窗**、`_screen_capture()` **BitBlt 失败**。

### 1.3 由此得到三条**假阴样本**（本次设计必须防的坑）

| 观测 | 天真解读（错） | 真相 |
| --- | --- | --- |
| `list_windows` → `count=0` | 「面板没开」 | 我在沙箱桌面，**看不到**用户桌面的任何窗 |
| `screen grab failed` | 「屏幕坏了 / 采集栈废了」 | 后端在，是**身份**不对（同源 `GUI 身份律`） |
| `capture_ready=false` | 「能力不可用」 | 是**条件不满足**，且它自己报了原因码 `non_interactive_desktop` |

> 这就是《空不等于不存在律》在**镜子**上的形态：**镜子照不到，不等于脸上没东西。**
> 也是《GUI 身份律》的兄弟条款：那条管「GUI 进程归谁」，本能力补一条——
> **采集进程也必须真实用户身份，且必须在交互桌面上。**

### 1.4 两条仓库事实（顺带查清）

- **`vision` 能力是空壳**：`list_capabilities()` 里 `vision` 的 `handler` = **`placeholder`**（98 项能力之一），
  描述为「视觉/图像识别入口（良性子集，需外部依赖时留待接入）」。**它是占位，不是能力**——
  本设计**不挂在它上面**，要挂 `tentacle` 域的真实实现。
- **`sec_hud` 在本仓库查无此物**：带正负对照的扫描 ——
  **正对照** `snapBounds` 命中 **21** 处（证明扫描器不瞎），**负对照** `zzz_not_real_qqq` 命中 **0** 处，
  目标词 `sec_hud` 命中 **0** 处。→ 风哥表格里的 `sec_hud` 来自别处或叫法不同，**本仓库没有**。

> **取证工具判例（本轮新发现，建议入档）**：
> `rg -n "snapBounds"`（**不给路径**）→ **0 命中**；`rg -n "snapBounds" .`（**给显式路径**）→ **21 命中**。
> 同一条命令，加不加显式路径结果相反。**「rg 报 0」不是结论**——必须带**正对照**。
> 这是《扫描器自证律》在人手用命令行工具时的形态：**工具也会给你假阴。**

## 二、盲区定性（结构性，不是缺功能）

| 层 | 她能看见 | 她看不见 |
| --- | --- | --- |
| 数据层 | `/api/state` 全部字段 | ——（本就够用） |
| 代码层 | 自己写的 HTML / CSS / JS | 源码**渲染成什么样** |
| DOM 层 | DOM 结构（抓得到时） | 渲染后的**像素结果** |
| 像素层 | DXGI 能抓帧缓冲 | **认不认得出那是"我的面板"** |

**缺的是三步，不是一件**：

1. **把镜头对准自己**——现在的调用都是「抓全屏 / 抓活动窗」，没有「抓我那一扇」的入口；
2. **一份对照表**——UI 规格是**给人读的散文**，不是**给机器跑的断言**；
3. **一条上报闭环**——差异算出来了，没人拿它做判定、没人报警。

与上帝视角的关系（两条通道，互补，都要有）：

```
上帝视角      看项目在干什么（结构 + 故障矩阵 + 工作树）
自我视觉验证   看我自己长什么样（像素 + 规格对照 + 回归）
用户汇报      最终真相（用户看到的东西，是唯一裁判）
```

## 三、能力设计（对齐风哥给的五个维度）

### 3.1 采集层

**① 前置门（硬前提，写在最前面）**

```
身份门：必须是真实用户身份（非沙箱 / 非服务 / 非 Session 0）   ← CHARTER 第十七章
桌面门：必须在交互桌面（interactive_desktop == true）
两门任一不过 → 状态 = SELFVISION_BLIND（原因码 non_interactive_desktop），不许报 FAIL
```

**② 定位「我那一扇窗」——三级锚（逐级收窄）**

| 级别 | 锚 | 用什么 | 过不了怎么办 |
| --- | --- | --- | --- |
| L1 进程锚 | `pid` → 可执行路径 / 命令行含 `panel_server` / `holo_pet` | `_enum_windows()` 的 `pid` + 进程查询 | 退 L2 |
| L2 窗口锚 | `hwnd` + 标题 + `rect` | `_enum_windows()` / `_find_window()` | 退 L3 |
| L3 像素锚 | 品牌色采样点命中（土豆金 / 赛博青 / 紫） | 区域抓帧 + 取色 | 判 `NOT_RUNNING` + `identity_mismatch`（不是 FAIL），继续找 |

> L3 的必要性有先例：V3/V6 验收用的就是**三色采样点**做量化核查——像素锚在本项目已经用过，不是新发明。

**③ 抓取：窗口级，不是全屏**

- 首选 `see_window(target)` 的成熟路子：**先取 window rect，再按 region 裁剪抓帧**（`omni_vision.py:39`）；
- 不抓全屏的理由：全屏帧没有身份信息、体量大、且把无关像素拖进比对；
- 渲染进程被遮挡 / 最小化 → 走 UIA 读回兜底（`omni_domain` 的 domain_read）。

**④ 频率（四档，按代价分档 · 2026-09-17 风哥拍「加一档」）**

| 档 | 频率 | 触发 |
| --- | --- | --- |
| 常态（面板在跑） | **5 s** | 与上帝视角「节点状态 5 秒刷新」同拍 |
| **面板未起** | **30 s** | 面板没起时降频——5 s 是浪费；起窗后自动回到 5 s |
| 事件后 | **1 s**（一次性） | 窗口移动/吸附后 · 面板重启后 · 晋升后 · 品牌清洗类改动后 |
| 禁止 | **不许每帧** | 每帧 = 拿宿主资源换"实时感"，撞《宿主第一》 |

**⑤ 预算**：独立进程 **20–40 MB**（复用已批的探针预算），每小时自检内存，超 60 MB 自动降级为面板内线程。

### 3.2 识别层

**① 「这是我的面板吗」——三重证据，缺一不可**

```
进程证据：pid → 可执行路径是 Electron/node 系  +  命令行含 holo_pet / panel_server
窗口证据：标题命中 + 尺寸/位置与 windows.json 的默认值在容差内
像素证据：品牌三色采样点命中（L3）

三票全过 → IDENTIFIED
只过部分 → SUSPECT（记下过了哪几票，不猜）
一票不过 → 不是我的窗，跳过（继续找，不报错）
```

**② 四窗口区分——窗口身份表（唯一真相源）**

| 窗口 | 位置编号 | 身份键（建议） | 默认尺寸 | 默认位置 |
| --- | --- | --- | --- | --- |
| 主控台 | 窗口 1 | `main` | 1440×900 | 右 36 / 下 18 |
| 云电脑 | 窗口 2 | `cloud` | 880×620 | 主控台左，间距 16 |
| 克劳德 | 窗口 3 | `claude` | 720×560 | 主控台左偏上 −120 |
| 上帝视角 | 窗口 4 | `godsview` | 1080×680 | 左上 24 |

> 口径照《holo_pet多窗口架构设计》§术语表：**「窗口 N」讲位置，「W&lt;n&gt;」讲批次**。
> 身份键**落盘一份**（`windows.json` 已是候选宿主），**不许各窗口自己造一套**。

**③ 状态判定（两段式 · 第一段三态互斥 · 2026-09-17 风哥拍）**

**第一段：镜子先说清"自己处在哪种状态"，三态互斥，不许混。**

```
IDENTIFIED          照到了我的面板 → 才进入第二段比对
NOT_RUNNING         面板没起（不算 FAIL，也不算 PASS）
SELFVISION_BLIND    镜子自己瞎了（抓不到 / 身份门不过 / 桌面门不过 / 全部后端失败）
```

**第二段：仅当 `IDENTIFIED` 时，才出判定。**

```
PASS   规格全过
FAIL   有差异（按 §3.3③ 分级）
```

| 情形 | 第一段状态 | 原因码（诊断用，不参与判定） |
| --- | --- | --- |
| 进程在 + 窗口在 + 像素命中 | `IDENTIFIED` | —— |
| 进程在 + 窗口不在 / 进程不在 | `NOT_RUNNING` | `panel_down` |
| 身份门不过 / 桌面门不过 | `SELFVISION_BLIND` | `non_interactive_desktop` |
| 窗口被遮挡 / 最小化抓不到 | `SELFVISION_BLIND` | `occluded` |
| 三个后端全失败 | `SELFVISION_BLIND` | `backend_failed` |
| 照到了但不像我的面板（三票全否） | `NOT_RUNNING` | `identity_mismatch`（继续找，不报错） |

> **修订记录（2026-09-17 风哥拍）**：原先写的笼统 `INCONCLUSIVE` / `UNIDENTIFIED` **撤销**，
> 换成上面这套**三态 + 两段**。理由：`INCONCLUSIVE` 把「没起」「看不见」「不像我」三种完全不同的情形
> 糊成一个词，诊断时还得再拆一次；三态互斥后，**上帝视角能直接按状态上色**（IDENTIFIED 走红/绿、
> NOT_RUNNING 走灰、SELFVISION_BLIND 走**另一档灰**并带原因码）。
> 「未起」不是「坏了」；「看不见」不是「没有」——这是《空不等于不存在律》的硬要求。

### 3.3 对比层

**① 对照源：把散文变成断言**

| 规格来源 | 变成什么断言 |
| --- | --- |
| `holo_pet_UI规格.md` §3.1/3.2/3.3 | 段存在性（顶栏 44px / 中央数字人 / 右列 320–360px / 底栏 104px）+ 默认尺寸/位置 |
| §3.5 状态灯口径 | 固定点取色 vs token（四种状态色） |
| §4 品牌口径 + 上一轮《主控台品牌清洗方案》 | **文案断言**（复用那份闸门：正负对照 + 白名单） |
| `windows.json` | 多窗口尺寸/位置/身份键 |
| `CHARTER.md` 第十六章 | 「不打扰」断言：巡检期间不许抢焦点/置顶 |

**② 比对方法：三档，从便宜到贵**（先跑便宜的，够用就不上贵的）

| 档 | 方法 | 阶段 | 代价 | 能抓到什么 |
| --- | --- | --- | --- | --- |
| 1 | **结构比对**（UIA / DOM：元素在不在、文本对不对） | **P0** | 最低、最稳 | 缺段、文案回退、错窗口 |
| 2 | **颜色采样**（固定点取色 vs token） | **P0** | 低 | 状态灯错、主题漂移、品牌色丢失 |
| 3 | **像素/网格哈希**（`_ahash` + `diff_regions`） | **P1** | 中（需基准图） | 布局位移、遮挡、渲染缺失 |

> **2026-09-17 风哥拍「分步」**：P0 **只上 1+2 档**；第 3 档放 P1。
> 理由（原话）：**第 3 档需要基准图，而基准图本身需要一个「稳定的第 1+2 档」才能生成**——
> 先用结构与颜色把面板钉稳，才有资格谈"跟上一帧比"。**P0 不许偷偷上第 3 档。**

> 第 3 档必须有**基准图**才有意义；基准图的来源写死：**上一次 PASS 的帧**，且基准更新需留审计（防"越比越像自己"）。

**③ 差异分级**

| 级别 | 判据（举例） | 动作 |
| --- | --- | --- |
| **严重** | 用户可见文案里出现品牌词 · 四段缺段 · 窗口不可见 / 尺寸为 0 · 状态灯取色与规格不符 | **立即上报** + 落审计 + 上帝视角节点转红 |
| **警告** | 尺寸漂移超容差 · 位置漂移 > **20 px** · 采样色 **ΔE(CIEDE2000) ≥ 5** | 汇总上报（5 min 窗口） |
| **观察** | 措辞差异、非关键间距、非固定点像素变化 | 只落盘，不打扰 |

**颜色容差口径（2026-09-17 风哥拍）**：用 **ΔE（CIEDE2000）**，**不用通道差**。

| ΔE | 含义 | 本能力处置 |
| --- | --- | --- |
| **< 2** | 人眼不可辨 | 一律放行（不记差异） |
| **2 – 5** | 可接受 | 记为**观察**（只落盘） |
| **≥ 5** | 可感知 | 记为**警告**（汇总上报） |
| **> 10** | 明显差异 | 按**严重**处理（如状态灯色错、品牌色丢失） |

> 理由（原话）：**通道差不能反映人眼感知差异**；ΔE 有国际标准。
> 落地注意：**token 是十六进制、采样是 sRGB**，比较前统一到同一色彩空间；**采样点位置写死在断言表里**，
> 不许每次运行时现挑点（否则等于自己给自己出题）。

### 3.4 报告层

**① 主动汇报时机**

- 严重 → 立即（不看轮询周期）；
- 警告 → 合并到 5 min 窗口，一条一条列，不刷屏；
- 观察 → 只落盘；
- **改动后必报一次**（晋升后 / 改 UI 后 / 改文案后）——这正是本轮「品牌清洗」缺的那一步。

**② 落审计（独立通道）**

```
事件：self_vision_diff
字段：time / target(窗口身份键) / state(IDENTIFIED|NOT_RUNNING|SELFVISION_BLIND)
      / verdict(PASS|FAIL|n/a) / severity / frame_hash / baseline_hash
      / diff_regions[] / color_delta_e[] / reason_code / evidence_path
落点：store/health/self_vision/*.jsonl
```

**独立审计通道是硬要求（2026-09-17 风哥拍）**：`self_vision_diff` **不混进 `store/audit.jsonl`（主审计流）**。
理由（原话）：**镜子高频输出，混主审计流会污染**。
（这条与 `store/health/*.jsonl` 独立于账本同一族：**观察者的账，不许记进被观察者的账本**。）

**③ 联动上帝视角**

```
self_vision  IDENTIFIED + FAIL(严重) → 「面板异常」节点转**红** → 点击展开五要素（检测/诊断/恢复/降级/审计）
self_vision  IDENTIFIED + PASS       → 节点转**绿**
self_vision  NOT_RUNNING             → 节点转**灰**（如实报"面板没起"）
self_vision  SELFVISION_BLIND        → 节点转**另一档灰** + 原因码（照不到 ≠ 面板有问题）
```

> 三态上色分开的全部意义：**没有探针在跑的点一律灰（假绿铁律）**，但「灰」也要分得清是
> 「面板没起」还是「镜子瞎了」——否则排查方向会被带偏。

### 3.5 盲区自己的盲区（**这一节不写满就不算设计完**）

**① 三态纪律（2026-09-17 风哥拍 · 正文化）**：`IDENTIFIED` / `NOT_RUNNING` / `SELFVISION_BLIND`
**三条互斥，不许混**；`SELFVISION_BLIND` **不许**冒充 PASS，**也不许**冒充 FAIL。

**② 五种「镜子照不到自己」的情形，逐条给处置**

| # | 情形 | 会不会假阴/假绿 | 处置 |
| --- | --- | --- | --- |
| B1 | 非交互桌面 / 沙箱身份 | **假阴**（`list_windows=0`） | 前置门拦下 → `SELFVISION_BLIND` + `non_interactive_desktop` |
| B2 | 窗口最小化 / 被遮挡 | **假阴**（抓到的是遮它的人） | `SELFVISION_BLIND` + `occluded` + UIA 读回兜底 + 不算 FAIL |
| B3 | 多屏 / 高 DPI 缩放 | **假红**（坐标/尺寸对不上） | 记录 DPI 与显示器几何，容差按 DPI 折算（已实证 125% 下尺寸有 ±2px 漂移） |
| B4 | 采集后端失败 | **假阴** | 逐后端降级（DXGI → mss → 无）+ **记录实际用的哪个后端**；全程失败 → `SELFVISION_BLIND` + `backend_failed` |
| B5 | 镜子自己被观察对象托管 | **假绿**（被观察者挂了镜子也跟着挂，却显示正常） | 观察者独立进程 → 面板内线程兜底 → 兜底也挂 → 显示**「未启用」**（三层，与 §17.2.1 同构） |

**③ 镜子自己的正负对照（《扫描器自证律》· 风哥拍「写进设计正文，不是附加条款」）**

镜子自己也是扫描器，所以它报任何一个结论之前，**必须先证明自己不瞎**。三臂缺一不可：

| 臂 | 喂什么 | 必须得出 |
| --- | --- | --- |
| **正对照** | 一张**合成图**：按 UI 规格拼出来的"面板应该有"的样子 | **`IDENTIFIED`**——必须识别出「这是我的面板」 |
| **负对照** | **纯色图**（只有品牌色，没有结构） | **不是我的面板**（`identity_mismatch`）——必须识别出「这不是我的面板」 |
| **盲臂** | 抓不到 / 解码失败 / 身份门不过 | **`SELFVISION_BLIND`**——**不报 PASS，也不报 FAIL** |

> 两条判据缺一不可：只有正对照 → 可能把任何图都认成自己（**假阳**）；
> 只有负对照 → 可能把任何图都否掉（**假阴**）。**两臂结果必须不同**，对照才可判别。
>
> **判定层再加一层（P0 起生效）**：正对照图里塞一个**必然违反规格**的东西（如缺一段 / 状态灯色错）
> → 必须 **`FAIL`**；把图还原成合规 → 必须 **`PASS`**。这层验的是"**判定器**不瞎"，
> 上面三臂验的是"**识别器**不瞎"。两层都过，镜子才准开。

**④ 镜子不许抢焦点（2026-09-17 风哥拍 · 正文化）**

巡检路径**禁调**：

- `_focus_window()`（`omni_core.py:312` 一带的强激活实现）
- `SetForegroundWindow` / `ShowWindow(SW_RESTORE)` 这类前台夺取
- `win.activate()` / `win.show()` / 任何 `alwaysOnTop`

理由：《宿主不打扰律》——**巡检是背景动作，不许把主人的窗口抢过来**。
上述函数**只许在显式动作路径**（用户点了按钮、明确要求激活）里用；
**巡检路径上一律禁调**，并**加一条静态闸门**（对巡检模块做 AST 检查，命中即判红）。

### 3.6 镜子跟 W3 的关系（2026-09-17 风哥拍）

**镜子照的是「我起来的那个面板」，不是 `reality/` 里的文件。**

```
起 W3 面板  →  立刻自检一次  →  报差异（PASS / FAIL / 三态）
```

三条口径：

1. **它不是独立任务**，是**「起面板后立刻自检」**——W3 界面级验收的延伸；
2. 它**不读 `reality/` 的源文件**做判定（读文件是 `mirror_scan` 的事），
   它读的是**跑起来以后屏幕上真实渲染出来的那一片像素 + UI 树**；
3. 因此它天然接在 **W3 的 S 序列之后**：面板能起 → 镜子才可能有 `IDENTIFIED`。
   面板起不来时它必须报 `NOT_RUNNING`，**不许**替 `mirror_scan` 下"代码有问题"的结论。

## 八、红线

- **先设计，不动手**——本文件只是设计。
- **采集必须真实用户身份 + 交互桌面**；两门任一不过 → `SELFVISION_BLIND`，**不许**报 FAIL。
- **抓不到 ≠ 不存在**（《空不等于不存在律》）——`0 扇窗` / `抓帧失败` 都不是结论。
- **三态分明且互斥**：`IDENTIFIED` / `NOT_RUNNING` / `SELFVISION_BLIND`；
  `SELFVISION_BLIND` 不许冒充 PASS，也不许冒充 FAIL；`NOT_RUNNING` 就是「面板没起」，不是「坏了」。
- **镜子必须有正负对照**，报「0 差异」前先证明自己不瞎（《扫描器自证律》）。
- **观察者独立**——镜子不许挂在被观察的进程里；独立进程 → 面板内线程 → **显示「未启用」**；
  探针停 → 显示**灰**，不许绿（假绿铁律）。
- **巡检绝不抢焦点 / 置顶 / 动键鼠**（《宿主不打扰律》）——巡检路径禁调
  `_focus_window` / `SetForegroundWindow` / `win.activate()` / `win.show()` / `alwaysOnTop`，**加静态闸门**。
- **独立审计通道**——`self_vision_diff` 落 `store/health/self_vision/*.jsonl`，**不混 `store/audit.jsonl`**
  （镜子高频输出，混主审计流会污染）。
- **S7 单独批**——`ascend()` 不许和别的改动混刀。
- **不替代**上帝视角（看全局）· **不替代**用户汇报（最终真相）。
- **结果落文件**，GUI stdout 不当结果通道（《结果通道律》）。
- 复用既有零件（`vision_bus` / `visual_memory` / `brain_verify` / `capture_environment`），**不重复造轮子**；
  **不挂在 `vision` 空壳上**。

## 九、落地（2026-09-18 · R-H3 · 风哥拍「追踪根源修复」）

本文档 §一 把 `capture_environment.status()` 定性为「**前置门的数据源**，它只是体检，不做判定」。
该定性在 2026-09-18 之前**只落在文档与体检里**，采集路径（`omni_core._screen_capture`）没有接这道门，
于是非交互桌面上照旧每帧试三个后端、每帧喷一行「吞错」—— 现象复发。

现在**判定真落地在采集路径上**（行为层，不再只是表达层）：

- `capture_environment.capacity()`：轻量身份读数（只查窗口站/桌面），与 `status()` **同源**；
- `omni_core._screen_capture()` 入口先过身份门（2 秒缓存）：`interactive_desktop=false`
  ⇒ 抛 `CaptureUnavailable("non_interactive_desktop")`，**不试后端、不喷噪音**，同一原因码只播一次；
- 后端全灭 ⇒ 抛 `CaptureUnavailable("screen_grab_unavailable")`（带各后端首条错因）；
- 守护测试：`tests/test_framework.py :: TestFramework.test_screen_capture_identity_gate`。

实测（沙箱身份）：`desktop=CodexSandboxDesktop-7637d56e…` · `interactive_desktop=false` ·
第一次抓帧一行提示 + 原因码，第二次 stderr 为空；`tentacle see` 返
`{"ok": false, "error": "CaptureUnavailable: non_interactive_desktop: …"}`。
