# 蚂蚁啃大象 · 视频流水线（R-H464 立项 · **图纸已落**）

> 主人给的六步与红线**逐字登记**；取证读数与边界另列。
> 一句话：**不追求一次生成整片，追求每小段都稳。**

---

## 一 · 为什么是「蚂蚁啃大象」（逐字）

```
7G 显存跑不动整片 → 但跑得动 3 秒片段。
100G 飞书存不下所有中间产物？ → 只存成品 + 关键片段 + 元数据。

万能插调度，触手分片，飞书存储，本地留源。

——模型可以换，能源可以换，
   但每一步都要落盘、留痕、可回滚。
```

**这不是降低标准，是把大目标拆成能一口一口吃下的小目标。**

## 二 · 六步（逐字）

| 步骤 | 动作 | 说明 |
|---|---|---|
| 1. 拆 | 把剧本拆成分镜，再把分镜拆成 2–5 秒片段 | 每个片段 = 一个独立生成任务 |
| 2. 锚 | 每个片段带角色圣经 + 场景圣经 + 首尾帧 | 防止跨片段「变脸 / 串味」 |
| 3. 啃 | 逐片段生成，本地优先，跑不动走云端 | 7G 显存一次只啃一小口 |
| 4. 检 | 每段生成后独立校验（一致性 / 画质 / 时长） | 不过关就重做，不往下传 |
| 5. 拼 | FFmpeg 拼接 + 转场 + 调色 + 音频 + 品牌片尾 | 最后合成完整成片 |
| 6. 存 | 成片 + 片段 + 元数据上传飞书 | 本地留源，飞书做副本 |

> **核心**：不追求一次生成整片，追求**每小段都稳**。

## 三 · 红线（写死）（逐字）

| 红线 | 说明 |
|---|---|
| 本地是源，飞书是副本 | 不许反向覆盖本地 |
| 密钥只存 DPAPI | 飞书凭据、云端能源密钥，全部走密钥池 |
| 每次操作留痕 | 写 `trace_store`，`source_kind="feishu_storage"` 或 `"video_segment"` |
| 不可逆动作二次确认 | 删除、覆盖、发布，必须确认 |
| 上传前校验 | 每个片段带 checksum，防止传坏 |
| 失败如实报 | 本地跑不动就标 `needs_cloud_energy`，不硬撑 |
