## 一 · 一句话蒸馏

**LibTV CLI 不是"又一个命令行"，是把 AI 从「创意建议者」推进到「创作协作者」的那道门** ——
装上它，Agent 不再只会"给你一段建议 / 让你复制一段 prompt"，而是能**直接**在 LibTV 里
建项目、搭画布、上传素材、建节点、连工作流、调模型出图出片。

---

## 二 · 命令面（Agent 要会调的那几个）

| 命令 | 作用 | 关键口径 |
|---|---|---|
| `libtv login` | 登录 | **会在浏览器里打开登录页**，登录态回传给 Agent |
| `libtv logout` | 取消登录 + 解除绑定与授权 | 本机凭据被清除、目录绑定被解除 |
| `libtv project list` | 查项目列表 | `-w/--workspace` 指定空间；也会读**当前目录绑定**的项目 |
| `libtv project create` | 建项目 | `-w/--workspace` 指定落点空间 |
| `libtv project use / unuse` | 绑定 / 解绑「当前目录 ↔ 项目」 | 多项目并行时靠它切上下文 |
| `libtv node --run` | 跑节点 | 官方明说：**避免调用方无意义轮循**（省的是调用方 token） |
| `libtv node / state query` | 查节点与任务状态 | 长任务**先查状态，别重复提交** |

## 五 · 失败诊断分类学（六类）

| key | 判据（官方给的常见原因） |
|---|---|
| `prompt_unclear` | prompt 没写清生成目标 / 参考图用途 / 视频节点要求 |
| `asset_missing` | 素材缺失：空节点、没有结果 URL、参考图没上传 |
| `ref_order` | 引用顺序错：连线变了、参考顺序漂移、引用失效 |
| `model_limit` | 模型能力不足：复杂多图 / 多角色 / 多步骤理解不了 |
| `safety_review` | 安全审核拦截（Seedance 类自动合规检测） |
| `transient` | 网络波动 / 临时服务不稳定 / 模型异常（可重试类） |

🔴 **归不进六类就如实报 `unknown`，不许硬塞一个原因**（红线⑥）。

> 诚实边界：这是**关键词归类**，作用是**逼出一次诊断**；它不替代人判断。

## 六 · 交付契约（七件，缺一件就不算完整交付）

1. 项目链接　2. 最终视频链接　3. Unit 列表　4. 主要视觉资产清单
5. 失败节点与修复记录　6. 剧本 / 脚本摘要　7. 下一步可继续编辑的建议

> 为什么较真：**只回一个视频链接 ⇒ 后续很难修改、追踪、复用**（官方原话的痛点）。

## 七 · 口径三条（官方明说，不是我们猜的）

| 项 | 口径 |
|---|---|
| **积分** | 通过 CLI / Skill 发起的调用，消耗的是**所登录账户的积分**，与画布中生成对应节点相同；**失败是否返还以平台当前规则为准** ⇒ **不许把「失败一定不消耗」当承诺** |
| **空间** | CLI 的登录态与可访问项目**取决于登录时浏览器里的账号与空间** ⇒ 要切就**先在浏览器切、再重新登录**，并把期望的个人 ID / 团队 ID 交给 Agent 核对 |
| **登录** | 登录要在浏览器里点 ⇒ **Agent 不代签**（人类视角执行律） |

## 一 · 交互方式（**人的位置**）

| 项 | 是什么 | 谁 |
|---|---|---|

## 二 · 要求面四条（每条**带判据**）

| # | 要求 | 判据（机械形态） |
|---|---|---|
| ① | 上传参考图 / 视频 | 素材必须**带用途**（谁当角色 / 谁当场景 / 谁当道具）；只上传、不写用途 ⇒ 拒 |
| ② | 轮询生成进展（**增量**） | 轮询必须**带游标**；不带游标 / 全量重拉 ⇒ `poller_without_cursor`；**「这一轮没有变化」不算失败** |
| ③ | 批量下载结果到本地 | **每一项都要有本地落点**；只留 OSS 链接 ⇒ `oss_link_only`；空清单 ⇒ 拒 |
| ④ | 切换当前绑定的项目 | 切换后必须**显式绑定**；没绑定就操作 ⇒ `no_project_bound`（不许靠「我记得是那个项目」） |

## 三 · 三条带牙用例（**判据 → 怎么咬**）

### ① 返回值不许带明文 `LIBTV_ACCESS_KEY`

```
判据：形状扫描（sk-/ak-/lt-…）+ **命名字段扫描**（key/token/secret 的值为长 token 形状）
咬法：{"LIBTV_ACCESS_KEY": "lt-live-xxxxxxxxxxxxxxxx"}      => 拒 plaintext_key_in_return
      {"key_id": "ai-video-1", "key_masked": "****"}        => 放行（标识/掩码不是密钥）
⚠️ 收窄纪律：`key_id` / `key_masked` / `key_ref` **不算密钥** ——
   把它们当明文抓就是「判据扩大化」（会天天误报，最后被绕过）。本刀实测踩过一次。
```

### ② 生成结果必须下载到本地，不许只留 OSS 链接

```
判据：结果必须带 local_path（落盘证据）
咬法：{"oss_url": "https://oss…/a.mp4"}                      => 拒 oss_link_only
      {"oss_url": "…", "local_path": "store\\libtv\\a.mp4"}  => 放行
理由：链接**会失效** ⇒ 只留链接 = 交了等于没交（且 trace 里也追不到产物）
```

### ③ 必须走 libtv-skill 脚本，不许自己拼 API 请求

```
判据：调用必须显式声明 via="libtv-skill …"；且参数里不许出现 http(s):// / /open-apis/ 拼出来的地址
咬法：{"via": "libtv-skill run", "url": "https://api…/v1/gen"} => 拒 handmade_api_request
      {"via": "自己写的 requests 调用"}                         => 拒 not_via_skill_script
      {"via": "libtv-skill node --run"}                        => 放行
理由：自己拼请求 = **绕开技能包的参数校验与留痕** ⇒ 出问题查不到、复现不了
      —— 它把「可追踪」降级成「猜」。这条与"不给安全面造第二套路径"同族。
```

# 附二：平台面 · 安装面 · **密钥口径撞车点的收口**（R-H208 · 2026-09-20）

## 一 · 它到底是什么（官方口径）

**LibTV = LiblibAI 推出的 AI 视频创作平台**，核心是**双入口**：

| 入口 | 给谁 | 是什么 |
|---|---|---|
| **无限画布** | 人 | 搭剧本 / 分镜 / 镜头 / 剪辑流程 |
| **Skill 接口** | AI Agent | 理解任务 → 调用模型 → 编排工作流 → 自动完成创作 |

**能力覆盖**：文生图/视频 · 图生图/视频 · 视频续写 · 风格迁移 · 局部编辑 ·
短剧 / MV / TVC · 角色三视图 · 分镜设计 · 首尾帧视频 · 音频生视频。

**底层模型**：Seedance 2.0 · Kling 3.0 / O3 · Wan 2.6 · NanoBanana · Midjourney · Seedream 5.0。

## 二 · 安装面（官方给的两种方式）

```bash
# 方式一：npx 一键装
npx skills add libtv-labs/libtv-skills --skill libtv-skill

# 方式二：手动克隆
git clone https://github.com/libtv-labs/libtv-skills.git
# 解压到 ~/.openclaw/skills/
```

**落点**：`~/.openclaw/skills/`（OpenClaw 技能规范）
**依赖**：**无需额外依赖 —— 仅用 Python 标准库**

**R-H208 取证**：`npx` / `git` / `node` **都在 PATH**；三个技能目录（`~/.openclaw/skills` ·
`~/.openclaw-autoclaw/skills` · `~/.agents/skills`）**全部存在**，但**都没有 libtv** ⇒ **未安装**。
🔴 装技能 = 往家目录写东西 + 要出网 ⇒ **本骨架不装，要主人点头**。

## 三 · 🔴 口径撞车点，以及怎么收（本刀最重要的东西）

```
官方配置口径 ：环境变量 LIBTV_ACCESS_KEY（从 LibTV 网站的项目设置里取）
我们的红线   ：密钥只走 DPAPI / 密钥池，不许明文落盘
⇒ 两条直接冲突
```

**解法：把「取」和「放」分开。**

| 环节 | 规矩 |
|---|---|
| **取**（来源） | **只从** `model_key_pool` / DPAPI 保险箱取 |
| **放**（去向） | **只在该次子进程的环境里注入**，进程结束即弃 |

```
✅ 正确形状：{"source": "model_key_pool", "inject_to_child_env": true}   => 放行
❌ 从 env / .env / 配置文件取                                            => key_source_not_pool
❌ 写进 .env / 配置文件 / 脚本（= 明文落盘）                              => key_persisted_to_file
❌ 只说"从池里取"却不说怎么给技能包                                       => injection_channel_unspecified
```

**为什么这样收才不破例**：技能包的接口是**既定的**（它只认 env），
但**密钥从哪来是我们能决定的** —— 来源归池、注入归进程、用完即弃。
既没绕开官方接入方式，也没把密钥明文落盘。

> **注入 ≠ 落盘**：注入是运行时内存，落盘才是明文。

## 四 · 本刀照报：旧用例的判据又扩大化了一次

本模块的 `KEY_INJECTION["forbidden"]` 里**写着**"不许 `os.environ`"，
于是 R-H204 那条裸字符串扫描的用例**当场变红** ——
它把**文档里的禁令**当成了**代码里的违规**。

**修法**：静态扫描先 `tokenize` **剥掉注释与字符串字面量**再查（只查代码）。
这与今天的「**注释提过 ≠ 真接线**」同族：**判据要卡在真问题上，别扩大化。**

# 附三：技能包的 **5 个脚本**（R-H209 · 2026-09-20）

官方口径：技能包的核心是 **Agent-IM 会话技能**，包含 **5 个脚本**。

| # | 脚本 | 作用 | 实证度 |
|---|---|---|---|
| 1 | `create_session.py` | **创建会话 / 发送生成指令**（如"生一个动漫视频"）—— 会话入口 | ✅ 主人原话 |
| 2 | `query_session.py` | 查询会话进展（**增量轮询**） | ⚠️ 推定 |
| 3 | `change_project.py` | 切换当前绑定的项目 | ⚠️ 推定 |
| 4 | `upload_file.py` | **上传图片 / 视频到 OSS** | ✅ 主人原话 |
| 5 | `download_results.py` | 批量下载结果到本地 | ⚠️ 推定 |

**实证统计：2/5 有主人原话（#1 · #4）· 3/5 为推定（#2 · #3 · #5）。**

## 🔴 采集纪律（写死）

```
① 只抄不猜：名字没给的，不许编；
② 名字有、作用没说的 ⇒ 标 evidenced=False（推定），**不许当已证**；
③ 推定项出现在契约里时**必须自曝**（check_script 会给 hint）。
```

## 两条契约的相互印证（#4 是钥匙）

`upload_file.py` = **上传到 OSS** ⇒ 素材在 OSS、**结果也在 OSS** ⇒
这正是**「不许只留 OSS 链接」**那条红线的由来：**地址会失效，所以必须下载到本地**。

```
① 会话链路：create_session（建会话/发指令）
              → query_session（增量轮询，别全量重拉）
              → download_results（落本地）
② 上下文链：change_project（切项目，切完必须显式绑定）
③ 素材链：  upload_file（进 OSS）→ 结果也在 OSS ⇒ must_localize_oss 才有牙
```

## 脚本白名单闸

```
✅ create_session.py / C:\…\libtv\upload_file.py   => 放行（取 basename）
❌ my_own_uploader.py                              => unknown_script
   （自己造脚本名 = 自己拼链路 ⇒ 与「不许自己拼 API 请求」同族）
❌ 空                                                => missing_script
```

# 附四：调用形态 + 会话契约（R-H210 · 2026-09-20）

## 一 · 实测调用形态（主人给的原话）

```bash
# 创建会话并发送指令
python3 scripts/create_session.py "生一个动漫视频"

# 增量查询进展（适合轮询）
python3 scripts/query_session.py <SESSION_ID> --after-seq 5
```

## 二 · 由此钉死的四件事

| # | 钉死的事实 | 证据 |
|---|---|---|
| 1 | 脚本在技能包的 **`scripts/`** 目录，调用形态是 `python3 scripts/<脚本> …` | 上面两行原话 |
| 2 | **增量轮询的游标 = `--after-seq <N>`** | `query_session.py <SESSION_ID> --after-seq 5` |
| 3 | 返回 **`projectUuid` + `sessionId`**，用于**后续查询和下载** | 原话 |
| 4 | **所有创作通过发送自然语言消息完成**，Agent 自主编排工作流 | 原话 |

🔴 **第 2 条把「增量」从一个形容词变成了一个必填参数**：
`--after-seq` 不带 ⇒ `poller_without_cursor`（= 全量重拉 = 烧调用方 token）。

🔴 **第 3 条是"钥匙"**：`projectUuid` + `sessionId` 丢了，就只剩**重建会话**一条路
—— 而重建意味着**前面的钱白花**。所以下载/查询前必须带齐两个。

## 三 · 实证度更新

```
#1 create_session.py  ✅ 原话（含调用形态）
#2 query_session.py   ✅ **本轮从推定升为实证**（--after-seq 就是游标）
#3 change_project.py  ⚠️ 推定
```
