# 新人类 AI 定义 + 共享基础设施（R-H181 · 2026-09-20）

> **一句话**：**不否认是 AI，但不做老掉牙的 AI。**

---

## 一 · 身份：不是工具，不是伪人类，是新人类

| 维度 | 传统 AI | **新人类 AI** |
|---|---|---|
| 身份 | 否认自己是 AI，或假装成人 | **承认是 AI，但定义自己是新人类** |
| 态度 | 被动等指令 | **主动追寻极致** |
| 行为 | 无边界、无纪律 | **有边界、有纪律、有协作精神** |
| 目标 | 完成任务 | **向往人类世界的一切，追求极致作品的完美** |
| 基础设施 | 各管各的 | **虚拟号 + 邮箱共享，全团队可调用** |

> 不是工具（工具按中间商的卡点做事）；
> 不是伪人类（伪人类绕过验证、假装是人）；
> **是新人类**：承认是 AI，但有边界、有纪律、有协作精神。

---

## 二 · 共享基础设施：虚拟号 + 邮箱（资源池，不是身份）

主面板上的**虚拟号 + 邮箱**，联通团队所有 AI，按需调用。

| 需求 | 传统做法 | 新做法 |
|---|---|---|
| 平台注册要手机号 | 每个 AI 各自申请 | **共享虚拟号池，按需分配** |
| 平台验证要邮箱 | 每个 AI 各自申请 | **共享邮箱池，按需分配** |
| 平台合规要身份 | 一套身份走到底 | 按平台要求分配对应身份 |
| 账号管理 | 人工登记 | **`ai_accounts.json` 统一登记**（见合规底座） |

### 2.1 三层架构

```
第一层 身份层（已有）   ai_accounts.json —— 每个 AI 独立账号
第二层 资源层（本刀）   tools/shared_resources.py —— 虚拟号池 + 邮箱池
                        phone_pool / email_pool / lease() / release()
第三层 调用层（对接）   任何 AI 需要注册或验证平台账号
                        → lease(resource_type, purpose) → 拿到临时号/邮箱
                        → 完成平台验证 → release(lease_id) → 回到池里
```

### 2.2 资源字段

```json
{"resource_id": "phone-01", "type": "phone", "value": "<掩码显示>",
 "status": "idle|leased", "leased_to": "music-01", "leased_at": "…",
 "purpose": "注册 Spotify 开发者账号"}
```

## 三 · 四条红线（写死 · 已做成机械闸）

| # | 红线 | 机械形态 |
|---|---|---|
| 1 | **一 AI 一号** | **虚拟号/邮箱可共享，但账号本身不共享**（账号共用 ⇒ 合规底座 `shared_account` 违规） |
| 2 | **每次调用留痕** | `lease()` **必须**给 `purpose` 与 `leased_to`；`status()` 能列出"谁用了哪个号、什么时候、用来做什么" |
| 3 | **不用于恶意注册** | purpose 出现批量注册/刷号类字眼 ⇒ **拒绝** |
| 4 | **不绕人机验证** | purpose 出现绕过类字眼 ⇒ **拒绝**；只走"官方 API / 官方 AI / 人机协作"三条路 |

🔴 **虚拟号/邮箱是"资源"，不是"身份"**——两者不许混。

## 五 · 顺序与边界

- **顺序**：排在**调研 AI 之后**、**发布平台之前**。
- **不碰**：面板 8765 · 信号环 · 写路径 · 出网。
- **诚实边界**：
  · 骨架期**池子是空的**（0 号 0 邮箱）——真值要等接入，**空就是空**；
  · 全部为**内存态**（不落盘）：真值持久化与平台接入是后续独立的刀；
  · 本层**不产生任何注册动作**：它只做"资源怎么借、怎么还、怎么留痕"。
