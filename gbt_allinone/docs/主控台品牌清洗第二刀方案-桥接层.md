## 〇、为什么要改桥接层（本刀的结构性理由 · 风哥指定置于正文头部）

`app.js` 有 **7 条 `result.error` 直渲染路径**（`:181-192` `compactResult()` 取
`detail → error → note → message → status` 的优先文案 · `:873` 蓝牙 · `:955` Notion ·
`:1032` 读取 · `:1150` / `:1208` / `:1239` EigenFlux），
而 R36 的白名单过滤**只挂在 `last_error` 一路**
（`panel_server.safe_last_error` → `app.js:227/230/247/250`）。

**上游异常原文从别的路径出来，过滤器一次都拦不住**——所以**改源头文案是唯一通用防线**，
`app.js` 过滤只是 `last_error` 那一路的第二道保险。

这条是"为什么要改桥接层"的最强理由：**不是品牌美化，是过滤器覆盖不到所有出屏路径。**

## 二、取证与扫描器自证（先证明不瞎，再报数）

两个扫描脚本，都带正负对照（《扫描器自证律》），失败即报 `SCANNER_BLIND` 并 `exit 12`：

| 脚本 | 判据 | 正对照 | 负对照 | 结果 |
|---|---|---|---|---|
| `.scratch/_r40_bridge_scan.py` → `_r40_bridge_scan.json/.txt` | **AST 按父链定性**（A 异常文案 / B RPC 错误 / C 日志行 / D 协议标识 / E 文档串） | 合成 `raise CodexAppServerError("…codex…")` → 判成 **A** ✓ | `class CodexAppServerError(RuntimeError)` + `server.codex_path` → **0 条 A/B** ✓ | `codex_bridge.py` 51 处品牌命中：**A 8 · B 3 · C 4 · D 24 · E 12** |

**编码口径**：两个脚本都用 `encoding="utf-8-sig"` 读源码——上一轮 24 个 BOM 文件整份没进 AST、
「扫 0 行报 0 命中」的教训（《扫描器自证律》实证②）在这里做了防御。

**人审补正（必须写明做了这一步）**：扫描器认不出"入屏参数长什么样"。逐条人审后**改了 3 处判定**：

2. `codex_bridge.py:1211`（注入给模型的提示词）被落到 D——**不是**文案位，但也不是标识符；
