## 0 · 总纲

一句话：**把五类原生能力从「按需启用」改成「默认常驻」——动的是默认值和启动顺序，不是能力本身。**

范围（不含已落地的）：

| # | 能力 | 一句话目标 |
|---|---|---|
| 1 | 原生视觉总线 | 默认开 —— 不是"需要时抓帧" |
| 2 | 亿万触手意图库 | 默认监听 —— 不是"需要时匹配" |
| 3 | 生命档案 | 默认挂载上下文 —— 不是"需要时查" |
| 4 | 脑部宪法域 | 默认生效 —— 不是"决策时调用" |
| 5 | 大脑执行层 | 触手默认就绪 —— 不是"调度时拉起" |

三条原则：

1. **不是新建能力，是改默认值。**
2. **不是重写逻辑，是改启动顺序。**
3. **不许把"设为默认"当成新增常驻进程** —— 用现成能力清单 + 现成启动钩子。

红线（Owner 原话）：

- S7 单独批。
- 判据取当时实测。
- 不许把"默认"当成"新增"。

### 0.1 口径正名（Owner · 2026-09-18 · 修正上一轮表述）

- **不是「她需不需要这些能力」，而是「不存在『我能不能干』这个判断环节」。**
  技能与域**本来就是她的基座，不是选项** —— 所以根本不该产生"干不干得了"的念头。
- 据此，"默认化"的正确定义 = **去掉那个判断环节**，不是"把选项勾上"。
- 基座规模（**2026-09-18 本机实测**）：`gbt_allinone/caps_registry.py` ——
  **94 条 benign（21 个域）＋ 11 条 disabled（dangerous）＝ 105 cap**。
  ⚠️ **既有文档里的「18 域 / 98 cap」已过期**（口径出自 2026-09-16：
  `gbt_allinone/docs/克劳德集成设计.md:33` · `gbt_allinone/docs/全项目思维导图架构.md:46` ·
  `memory/2026-09-16.md:1418`）—— **以本次实测为准**。
- 本稿 §2 的五条**不是基座的全部**，而是基座里"**还缺默认接线**"的那几条；
  其余已登记域按现有入口即可调用。

### 0.2 器官化判据（Owner · 2026-09-18）

**外挂 vs 器官**（Owner 原话）：

| | 路径 | 代价 |
|---|---|---|
| **外挂** | 遇到问题 → 想"我该用哪个能力" → **选择** → 调用 → 验证 | 每个环节都在等"决定"——这就是卡顿、"没接上"、"忘了我还有这个能力"的根源 |
| **器官** | 遇到问题 → **本能反应** → 直接就做了 | 没有选择延迟 |

**由此得到本稿采用的一条可判定标准**：

> **器官化判据**：从"意图出现"到"能力被命中"的路径上，**要求调用方显式指名 / 选择的步骤数 = 0**。

- 这条是**可数**的：数一次调用链里有几个人工选择点，**0 才叫器官**。
- 按此重判 §1 矩阵：
  - 视觉总线 —— 要人先"想到要抓帧" → **仍是外挂**（选择点 1）
  - 亿万触手 —— 要人先给出 `action` → **仍是外挂**（选择点 1）
  - 生命档案 —— 只有文字提醒，要人先"想到去查" → **仍是外挂**（选择点 1）
  - 大脑执行层 —— 要显式调 `brain_unify` 才走全链 → **仍是外挂**（选择点 1）
- 本稿 §2 五条改动的**共同目标 = 把选择点数从 1 压到 0**，不是"多挂一个工具"。
- 与 §0.1 的关系：§0.1 说"不该有『我能不能干』的念头"，§0.2 说"不该有『我该用哪个』的动作"——**同一条总纲的两面**。

### 0.3 器官能力四条（Owner · 2026-09-18 · 本方案最高总纲，全部改动按此落地）

| # | 原则 | 含义 |
|---|---|---|

**功能 vs 器官（Owner 原话补全 · 2026-09-18）**：

**检验标准（Owner · 2026-09-18 · 器官 vs 功能的判据）**

四条：**本能反应** · **不产生这个判断** · **一直在用** · **可观测行为**。

**可观测行为四条（判据只许落在这层）**：

1. **启动后默认就绪，不查清单**；
2. **行为发生时不产生调用指令**；
3. **上下文里没有「该用哪个」的推理**；
4. **不依赖「用户提了这个需求」**。

**三组改写（不可观测 → 可观测）**：

| 不写（不可观测） | 写（可观测） |

| 「她记住了」 | **任务中不需要查清单就能命中** |
| 「她听懂了」 | **行为发生了，但没产生调用指令** |

**四条判据的可观测验证方式（Owner · 2026-09-18 · 落到代码级可查）**

## 2 · 五条逐项设计

### 2.1 原生视觉总线 —— 默认开

**现状实测**

- `gbt_allinone/tentacle/vision_bus.py`（12,407 字节）对外只有 5 个动作：`snapshot()`:101 · `diff_regions()`:189 · `diff_with_previous()`:217 · `stream_record()`:243 · `stream_replay()`:278。
  **没有 `start()/stop()`，没有后台循环，没有常驻线程。**
- 眼睛本体由 `gbt_allinone/tentacle/bridge.py:39 get_eye()` **惰性**获取；`:55 eye_ready()` / `:60 eye_error()` 只做探测。
- `bridge.py:176 _DummyEye` —— 眼睛起不来时返回**假眼**（能调、不干活、`__bool__` 为 False）。
- 缓存：`snapshot(eye, region=None, ttl=60)`，指纹命中即复用，不重复截屏。

**判定**：现状是「懒惰 + 缓存」，不是「眼睛常开」；且失败被假眼吞掉。

**改动（改默认值，不重写）**

- 在 `bridge.py` 增 `warm_up()`：装配时先取眼 + 抓一帧就位；失败**如实落审计**并保留 `eye_error()`，不静默。
- 由「装配锚点」（§3-A）调用一次。
- **零新增进程、零常驻轮询**：只是把"首次调用"从"用户开口时"提前到"装配时"。

**判据**：装配后 `eye_ready() == True`；失败时 `eye_error()` 非空且审计可见。
