# 一 · 示范书目：《计算机程序的构造和解释》(SICP)

## 1.1 吞 —— 核心思想（摘要级，非原文）

- 程序是**描述过程的语言**：先有"要什么"，再谈"怎么算"。
- 复杂系统靠**抽象壁垒**控制：每层只对外承诺一层语义，层与层之间不许穿透。
- **数据与过程同权**：过程可以作为数据被传递、组合、返回。
- **环境模型**：状态存在于环境的绑定中；改变状态的代价是引入时间与顺序。
- 抽象的价值在于**可替换**：换掉下层实现，上层不该察觉。

## 1.2 消 —— 抽象原则（剥离语言与例子）

1. 层界是承诺边界，不是文件夹边界。
2. 状态一旦引入，就会把"求值"变成"过程"，必须在层内被封闭。
3. 抽象合格与否，用"能否被单独替换并验证"判定。
4. 能声明"要什么"的地方，不要写"怎么做"。

## 1.3 衍 —— GBT 原生条款

### 条款 C1 · 层界即契约

- **来源书**：《计算机程序的构造和解释》(SICP)
- **核心原则**：每个抽象层只对外承诺一层语义。跨层直达下层内部结构 = 把两层压成一层，此后任一层改动都会同时伤到两边。
- **应用行为**：**架构设计** —— 新功能只能经本层公开面抵达下层。出现「绕过某一层直接改存储 / 直连外部」时，必须在同批里补出那一层，**不许就地开洞**。
- **验证方式**：替换或删除下层实现，上层是否**零改动**即可通过测试；跨层直连点在重构中只允许单调下降。
- **应用记录**：
  - **2026-09-18（追溯适用 · 本会话）**：`gbt_allinone/safe_io.py` 已按此层界运作 —— 所有写盘只经该层入口，调用方不接触临时文件、fsync 与换行对齐；M3 / M4 / M5 / M8 / M9 五刀全部经该层落盘，**未出现一处就地 `open()` 直写**。
  - **待首次适用**：下一刀若触及 `store` 结构，须先补层再改。

### 条款 C2 · 状态必须在层内封闭

- **来源书**：《计算机程序的构造和解释》(SICP)
- **核心原则**：引入可变状态就把"求值"变成了"过程"，从此**顺序与次数**都成为语义的一部分。状态只允许存在于最内层，且只通过受控入口变更。
- **应用行为**：**架构设计 + 代码生成** —— 共享可变状态不得跨层暴露；跨进程读改写必须持锁并原子落盘，禁止"读—改—写"三段裸奔。
- **验证方式**：能否指出该状态的**全部**写入点，且每个写入点都在同一层、都经过锁或原子替换；若写入点分散在多处，条款即被违反。
- **应用记录**：
  - **2026-09-18（追溯适用 · 本会话）**：AutoClaw 两个配置文件的改动，走的是「备份 → 语义 diff 单一基线 → 原子写 → 写后复核」；55 秒后复查未被应用回写，写入点唯一。
  - **待首次适用**：后续任何 `store` 写入，必须复用同一形态。

### 条款 C3 · 抽象必须可单独验证

- **来源书**：《计算机程序的构造和解释》(SICP)
- **核心原则**：抽象合格与否，用「能否脱离上层被单独替换并验证」判定。抽不出独立判据的抽象不是抽象，只是搬家。
- **应用行为**：**判据设计** —— 每引入一层，必须同时给出只针对该层的判据；判据必须能独立运行，不依赖上层装配。
- **验证方式**：该层的判据能否在上层完全缺席时跑绿；跑不绿，说明层界没切干净。
- **应用记录**：
  - **2026-09-18（追溯适用 · 本会话）**：技能额度调查中，「只读 description 还是读全文」被做成**独立 A/B 探针**（正文 44,930 字节 vs 描述 1,826 字符），脱离主线单独验证，结论 = 正文占 **102 字符**、正文零进入。这正是"可单独验证"的形态。
  - **待首次适用**：`store` 相关判据需补一个"上层缺席也能跑"的独立用例。

### 条款 C4 · 声明式优先于命令式

- **来源书**：《计算机程序的构造和解释》(SICP)
- **核心原则**：能声明「要什么」的地方，不要写「怎么做」。过程细节一旦前置，就锁死了实现，后续无法替换策略。
- **应用行为**：**代码生成 + 决策记录** —— 配置与意图用声明式表达（清单、契约、判据），执行细节下沉；决策记录只记「要什么 + 判据」，不记操作流水。
- **验证方式**：同一意图换一种实现路径时，声明层是否需要改动；需要改，说明声明层里混进了过程细节。
- **应用记录**：
  - **2026-09-18（追溯适用 · 本会话）**：技能额度的调查写成了「判据先行」的声明（不触发警告 ⇔ 描述总量 ≤ 7,688 字符 / 均 122 字符），而不是一串操作步骤；因此后来换档位时无需重写判据。
  - **待首次适用**：下一份方案文档沿用此形态。
