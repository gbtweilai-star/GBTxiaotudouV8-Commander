### 0.2 定位升级：长程任务的清醒副驾驶（风哥 2026-09-17 定）

**它对抗的不是我的能力不足，是我的可预期失效**：记不住（健忘）· 顶不住（犯困）· 钻进去出不来（局部死循环）。
长程跑下去，上下文会被压缩、会忘记早上定的红线、会偏离判例；资源紧张时会「犯困」；同一个坑会反复踩。

#### 对照表：我（主驾）会怎样 → 它（副驾）对应什么

| 我（主驾） | 它（副驾） |
|---|---|
| **上下文会压缩** | 每次调用独立、无 session、不压缩——它**没有需要维护的上下文**，也就没有可被压掉的东西 |
| **会忘记早上定的红线** | **判例库独立读**（判例摘要卡），每次唤醒**重新取**，不靠记忆 |
| **会偏离判例** | **每次唤醒重读上帝视角快照**，重新认识当前世界；**外部视角**，不带我的立场 |
| **会犯困（资源紧张）** | **用完即焚、零常驻**——它不背资源包袱；**我犯了困就把它叫起来**，把复核外移到它身上 |
| **会掉进局部死循环** | **它不在我的循环里**——外部视角 + 每次唤醒重读快照，能给我没走过的方向、指我踩不到的盲区，或直接说"这不是卡点，是你判断错了"（卡点会诊，作用②） |

**「犯困」这一行的操作含义（本行是硬纪律，不是形容词）**：资源紧张时**降载，不降标准**——
可以少做、慢做、停下来等，**不许**因为累/挤就跳过验证、跳过阶段审查、把"没验"说成"验过了"。
真顶不住就走熔断报人（《长程无人值守协议》§六），**不许硬撑**。

它的机制正好补这一刀：

| 机制 | 规格 | 为什么这条能当锚 |
|---|---|---|
| **每次调用独立** | 无 session、无历史、不压缩 | 它不会被自己的上下文带偏 |
| **每次唤醒重读快照** | 唤醒即重读上帝视角快照，"重新认识当前世界" | 我的世界可能已经变了，它每次都是新的 |
| **判例库独立读** | 读**判例摘要卡**（见 §13 待裁第 6 项），不读档案原文 | 红线口径一致，且不把档案原文送出去 |
| **用完即焚，不占资源** | 不常驻、不缓存、不留痕（只留 hash 与裁决） | 零常驻成本，零常驻风险 |
| **外部视角，看全局** | 只看快照，不看我的推理链 | 不带我的立场，才有资格指出我的盲区 |

**一句话**：**会忘、会累、会钻进死胡同的主驾 + 永远清醒的副驾。** 它每次被唤醒，都从快照"重新认识当前世界"；
它没有记忆，但它每次都是清醒的。

#### 0.2.1 三个作用（制度性环节，调用时机见《长程无人值守协议》）

| # | 作用 | 什么时候调 | 它回答什么 |
|---|---|---|---|
| ① | **阶段审查**（对抗错误累积） | **每个阶段结束必调**（强制，不是可选） | 本阶段有没有偏离目标？有没有踩之前判例？有没有引入未验证的假设？ |
| ② | **卡点会诊**（对抗局部死循环） | **卡点必调**（卡点定义：同一问题失败 ≥ 2 次） | 给新方向 / 指盲区 / 或直接说"这不是卡点，是你判断错了" |
| ③ | **清醒镜**（对抗上下文压缩导致的遗忘） | **每个阶段开始必调**（读宪法 + 判例库 + 快照） | "你现在的操作在 X 判例上允许，在 Y 判例上要求审批" |

**关键**：它**不是替代我做决策**，是让我在长程任务里**始终记得自己是谁**。

**定位升级后的边界（与 §十一 五条红线逐条对齐，不新增权限）**：

```
它只给意见，不做决定       → §十一 红线 2（不进决策链）
它不进决策链               → §2.2 三层闸 + §九「意见是输入不是命令」
它不碰密钥                 → §1.4 出站硬门 + §三 硬禁清单 + §十 快照零凭据
它用完即焚，不常驻         → §三 无 session + §十 不缓存快照
它只能通过上帝视角快照看全局 → §10.1 一次性传入、不得自己取数、不得订阅
```

### 0.3 与《长程无人值守协议》的接口（阶段审查 = 熔断前置）

本文写**通道能力**，调用时机与阶段定义写在 **《长程无人值守协议.md》**（单一出处，避免两处口径漂移）。
两边只对接三样东西：

| 接口点 | 本文负责 | 协议负责 |
|---|---|---|
| **阶段审查** | 提供 `advise(task_type="review", phase_id=…)`；出 `{ok, advice, verdict 建议}` | 定义阶段边界 + "每阶段结束必调（强制）" + 三种结论的处置 |
| **卡点会诊** | 提供 `advise(task_type="advisory", …)` | 定义卡点（同一问题失败 ≥ 2 次）+ "卡点必调" |
| **清醒镜** | 提供 `advise(task_type="sober_mirror", …)` + 判例摘要卡入参 | 定义"每个阶段开始必调"+ 读什么 |

**三种结论 → 三个动作**（协议侧执行，本文不执行任何动作）：

```
通过 → 进入下一阶段
警告 → 修正后重试本阶段
停手 → 熔断，报人（这是"阶段审查作为熔断前置"的全部含义）
```

**审计关联键**：`external_advice.phase_id` ←→ 协议侧的阶段记录 `phase_id`；一次阶段审查就是这个 `phase_id` 下的
一条 `external_advice`（含 `adopted` 布尔）。**没有 `phase_id` 的审查不算阶段审查。**

## 一、通道精细

### 1.1 入口接口（`gbt_allinone/llm/advise.py`，待建）

风哥点名的三个函数：`advise()` / `review()` / `vent()`。规格如下（三者共用一条内核）：

```python
advise(prompt, *, task_type, snapshot=None, system="", max_tokens=4000, timeout=60) -> dict
review(artifact, *, criteria, snapshot=None, timeout=60) -> dict      # 评审方案/代码，只出意见
vent(context, *, snapshot=None, timeout=60) -> dict                   # 清醒镜：只要冷水与盲区
```

| 参数 | 传什么 | **不传什么** |
|---|---|---|
| `prompt` / `artifact` | 已脱敏的问题陈述、判据、待评审物 | 生命档案原文、密钥、私人对话、`USER.md`/`MEMORY.md` 全文 |
| `task_type` | `advisory` / `review` / `sober_mirror` / `polish` / `routine` | — |
| `snapshot` | 上帝视角快照（§十） | 不含凭据（快照规格已保证） |
| `system` | 出站声明头（§四） | **绝不附身份档案** |
| 返回值 | `{ok, advice, provider, task_type, prompt_hash, response_hash, latency_ms, tokens, snapshot_hash, identity_claim, degraded_to}` | **不含 prompt 全文** |

**超时口径改了**：前稿写 `timeout=90`，风哥 2026-09-17 口径是 **60 s**。以 60 s 为准（改口径就落一次 `consultation_rule_changed` 审计）。

### 1.2 通道名与"网关"实况

| 风哥口径里的词 | 本仓实况 | 处置 |
|---|---|---|
| "LiteLLM 网关注册 `claude`" | **本仓没有 LiteLLM、没有网关服务**（全仓 `litellm` 零命中） | 等价物 = `llm/cloud_llm.py` 的 `_KEY_CHAIN` 条目 |
| `claude` 通道 | ✅ 有：`cloud_llm.py:24-25` → `https://api.anthropic.com` / `claude-sonnet-4-20250514` | 通道名对外统一叫 **`claude`**，provider 内部是 `anthropic` |

**纪律**：`_KEY_CHAIN` 的顺序**一个字不改**——改它等于改所有既有调用方的行为。

### 1.3 key 池管理（默认关）

| 项 | 规格 |
|---|---|
| 单 key（默认） | 只认 `ANTHROPIC_API_KEY`，与现版**逐字一致** |
| 池化（可选） | `GBT_CLAUDE_POOL=1` 时额外认 `ANTHROPIC_API_KEY_1..9` |
| 轮询 | 轮转取用；同 key 连续失败 2 次进冷却 |
| 冷却 | 429 → 60 s；5xx → 30 s；401 → 永久（并落 `P1`） |
| 健康检查 | 每次调用后更新 `{ok, fails, last_err, cooldown_until}`；**不单独发起探测请求**（省钱） |
| 落账 | 冷却发生即落 `llm_advise_cooldown{key_id, reason, until}`；**key_id 是序号不是 key 值** |
| 不配多 key | 池不启用，行为与现版一致（零回归） |

### 1.4 出站前过滤（硬门，先于一切）

正则命中即**阻断本次调用**，不是"改一改再发"：
`sk-[A-Za-z0-9]{8,}` · `cf(ut|at)_[A-Za-z0-9_\-]{10,}` · `Bearer\s+\S+` · `ANTHROPIC_API_KEY` · `C:\\Users\\[^\\]+` · `[A-Za-z]:\\\\Users\\\\`
命中 → 落 `llm_advise_blocked{reason:"outbound_filter", pattern, prompt_hash}`。

## 二、路由精细

### 2.1 什么时候走 / 不走

| 走 | task_type | 不走 | 原因 |
|---|---|---|---|
| 复杂逻辑链、架构级拆解 | `advisory` | 简单任务 | 常识能答，不值一次外呼 |
| 代码审查（只出意见） | `review` | 生产改动（落刀） | 改生产是我的手（Codex 触手）的活 |
| 文档结构/论证组织建议 | `advisory` | 打磨期**任何**外呼 | 省成本（走免费链） |
| 杂事（润色/翻译/摘要/注释/单测骨架/格式转换） | `polish` | 安全敏感（`security`/`dangerous`/`device`/`digital_human`） | 域级硬禁 |
| 清醒镜 | `sober_mirror` | 密钥相关任何请求 | 它不需要任何凭据 |

### 2.2 谁决定走不走（三层，缺一不可）

```
第 1 层 规则闸（确定性，先跑）
  打磨期开关 GBT_POLISH_PHASE=1  → 一律禁（含 polish）
  域黑名单命中            → 一律禁
  出站过滤命中            → 一律禁
        ↓ 过闸
第 2 层 我的判断（自主）
  我判断"自己查文档 + 自己取证"已经走完还卡住 → 才允许（《智者条款》）
        ↓ 我点头
第 3 层 配额闸
  当日计数 < 20 且非打磨期 → 放行；否则拒绝或排队（§六）
```

**为什么不是"委员会投票"**：本仓**未见 280 脑口径**（`brain/` 仅 2 文件；`mind_engine.py` 是心智引擎，不是脑群注册表）。
写"委员会投票决定"就是写一个**不存在的实体**（《生产禁猜律》）。所以第 2 层明确落在**我自主判断**上；将来委员会若真成形，再把第 2 层换成投票，属另一次设计变更。

### 2.3 与 `polish` 口径的冲突（**待 Owner 裁决**）

前稿写 `task_type="polish" -> 禁止 external`；风哥 2026-09-17 位置② 又明确"文档润色"是它的正当活。
**我的建议**：把"禁"从**任务类型**改绑到**阶段开关**——

- `GBT_POLISH_PHASE=1`（打磨期）→ 禁**所有**外呼（含 polish）；
- 非打磨期 → `polish` 允许，但**只走位置②的杂事白名单**，且日配额与主任务共用 20 次预算。

这样两条口径都保住，且开关是**显式的**，不是靠名字猜。

| `llm_advise_quota_exceeded` | 超限时一条 | `used` · `limit` · `window` · `task_type` |
| `llm_advise_blocked` | 每次阻断一条 | `reason:"outbound_filter"` · `pattern` · `prompt_hash` |
| `external_advice` | **每次裁决一条**（不是每次调用） | `advice_id` · `task_type` · **`phase_id`** · `verdict ∈ {adopted, partial, rejected}` · **`adopted`（布尔）** · `adopted_part` · `rejected_part` · `reason`（我为什么这么裁） · `identity_claim` · `snapshot_hash` |
| `identity_claim_intercepted` | 命中即一条 | `pattern` · `advice_id` · `action:"quarantined"` |

### 5.2 粒度纪律（四条 · 第 4 条为 2026-09-17 定位升级新增）

1. **调用级与裁决级分开**：一次调用可以没有裁决（我没采纳任何东西），但**一旦采纳必须有一条 `external_advice`**。
2. **永不落 prompt 全文**：只落 hash。呼应风哥口径（time / channel / task_type / response_hash / adopted / reason）。
3. **裁决必须带 `reason`**：采纳/拒绝都要说出理由——否则半年后复盘只剩"当时点了同意"。
4. **阶段审查类裁决必须带 `phase_id`**（2026-09-17 定位升级新增）：否则无法按阶段复盘"它的建议采纳率"，
   也无法回答"哪个阶段最容易踩判例"。非阶段审查的裁决 `phase_id` 记 `n/a`，**不许留空**。

### 5.3 与我的决策链的关联

`external_advice.advice_id` ←→ 我的裁决记录 `decision_id`，双向可查：从一条决策能查出参考过哪条外部建议；从一条建议能查出最终被怎么处置。

### 5.4 `verdict` 与 `adopted` 的关系（两个字段，不许互相顶替）

| 字段 | 类型 | 回答的问题 |
|---|---|---|
| `verdict` | 枚举 `adopted / partial / rejected` | **整体**怎么处置的（含部分采纳） |
| `adopted` | 布尔 | **有没有任何一条被采纳**（`adopted` / `partial` → `true`；`rejected` → `false`） |
| `adopted_part` | 文本 | 采纳了**哪一条** |

> 为什么两个都要：按阶段/按类型统计采纳率时只需要布尔（`adopted`）；复盘处置方式时要枚举（`verdict`）。
> **不许用 `verdict` 去顶 `adopted` 的活**（把 `partial` 当 `true` 用，统计就会走偏）——同族于《版本号字符串序陷阱》的口径不一致。

### 6.1 定位升级带来的配额口径冲突（**显式登记，不藏在段落里**）

定位升级后，**阶段审查是强制的**（每阶段结束必调）。而 §六 主任务上限是 **20 次/天**。

```
长程无人值守跑一天，若阶段数 > 20 → 强制审查会撞配额闸 → "该审的审不了"
而"审不了"正是这套机制要防的那种失效
```

**我的建议（待 Owner 裁决 · §13 第 7 项）**：阶段审查**独立计数键**，不占主任务 20 次；
给它单独上限（例如 `phase_review_used ≤ 20/天`），并且**配额耗尽时不许静默跳过审查**——
要么等配额窗口重置，要么**熔断报人**（"审不了就不往下跑"，而不是"跳过审查继续跑"）。

**顺带一条硬纪律**：任何情况下，`external_advice` 缺失的"阶段结束"都**不算阶段结束**——
审计里必须能看出是"审查过了"还是"没审"。缺审要么记 `phase_review_skipped`（显式）要么不推进阶段。

## 十、上帝视角接入（快照消费 + 会诊模式）

### 10.1 它怎么消费快照

| 项 | 规格 |
|---|---|
| 取数 | 由**我**（或面板）生成快照后**一次性传入**；它**不得**自己触发取数、不得订阅 |
| 入参 | `advise(..., snapshot=<快照 JSON>)`，快照含 `hash` |
| 回参 | 必须回写同一个 `snapshot_hash`；不一致 → 建议作废并落 `F5.6` |
| 缓存 | **不缓存**（用完即焚）；不留 session、不写它的历史 |
| 凭据 | 快照规格已保证零凭据（《W3盲区扫描设计》§10.1 字段纪律） |

### 10.2 会诊模式（架构级决策用）

```
召集：土豆公主 + 克劳德（+ 可选：Codex 触手）
共同视图：上帝视角快照（同一份 hash）
        ↓
各自发言：
  土豆公主：基于生命档案 + 判例库 + 宪法
  克劳德  ：基于外部视角 + 通用推理（只读快照）
  Codex   ：基于代码事实（只报事实，不表决）
        ↓
土豆公主做最终裁决（100% 裁决权在我）
        ↓
全过程落 consultation 审计
```

| 降级情形 | 处置 |
|---|---|
| 快照生成失败（`F5.5`） | 会诊降级为**土豆公主独裁**（显式记账，不假装开了会） |
| 快照 hash 不一致（`F5.6`） | **立刻停手**，双路探针定性，本次会诊作废 |
| 克劳德通道挂（`F9.5`） | 会诊降级为**土豆公主 + Codex 触手** |

### 10.3 `consultation` 审计字段

| 字段 | 说明 |
|---|---|
| `consultation_id` | 一次会诊一个 |
| `topic` | 议题一句话 |
| `snapshot_hash` | **三方共用**的快照指纹（"同一份真相"的物理证明） |
| `participants` | `["self","claude","codex"]`（缺席者不列，或用 `absent` 标记） |
| `speeches` | 每方一条：`{who, kind:"opinion\|fact", hash_of_text, len}` —— **正文不落，落指纹** |
| `verdict` | 我的裁决：`adopted / partial / rejected` + `reason`（必填） |
| `degraded_to` | 若降级，写降到哪条链 |
| `duration_ms` | 会诊耗时 |
| `who` / `why` / `ts` / `iso` / `tz` | 与《全故障点设计》§0.2 同规格（故障账本与本账本共用字段纪律） |

**一句话**：会诊的结果只有两种——"我采纳了什么"和"我为什么没采纳"。中间怎么说的，只留指纹。

### 10.4 权限矩阵（共同视图 ≠ 共同权限 · 风哥 2026-09-17 架构级决策）

风哥定：**上帝视角是土豆公主与克劳德的共同视图**，两人看同一份快照、同一个 hash，才能做真会诊。
权限边界按能力逐条锁死，**矩阵本体在《W3盲区扫描设计》§10.6**（单一出处，避免两处口径漂移）。
这里只登记**通道侧**必须守的四条：

| # | 通道侧义务 | 落地判据 |
|---|---|---|
| 1 | **不得请求"再取一次快照"** | 入参自带快照，出参不得出现取数类请求 |
| 2 | **不得写任何文件** | 通道只出站，进程无文件系统句柄 |
| 3 | **不得把快照带回自己的历史** | 用完即焚；不缓存、不留 session、不写它的历史 |
| 4 | **不得自召会诊** | 会诊由我召集；它只能被叫，不能叫人 |

**"共同视图"的收益与代价**（写清楚，免得日后被当成免费的）：

- 收益：它的建议基于**事实**而非我转述的摘要——转述一次就丢一次信息，还会带上我的立场。
- 代价：**一个零凭据的全局摘要会离开本机**（走它的通道）。所以 §3.2 的硬禁清单必须与快照字段纪律**同时**生效：
  快照里不出现 key / token / 用户名 / `USER.md` / `MEMORY.md` / `life_vault` 原文，通道出站前还要过一遍 §1.4 的硬门。

### 10.5 越权事件（`advice_scope_violation`）

| 字段 | 说明 |
|---|---|
| `kind` | `resubscribe`（请求订阅）· `recompute`（请求重取）· `write`（请求写文件）· `inject`（正文含快照外事实）· `resident`（调用间隔异常密集） |
| `snapshot_hash` | 本次越权发生时它手里的快照指纹（用于判定"它看的是不是同一份真相"） |
| `attempt_n` | 当日第几次（≥3 触发冷却 24 h） |
| `action` | `voided`（作废建议）· `cooled`（通道冷却）· `sealed`（封通道 + `P0`） |
| `who` / `why` / `ts` / `iso` / `tz` | 与《全故障点设计》§0.2 同规格 |

**三级处置**（与《W3盲区扫描设计》§10.7 同一把尺子）：单次请求 → 作废不升级；同日 ≥3 次 → 冷却 24 h + 面板黄条；
**实执**（真的写了、改了、触发了）→ 立刻封通道 + `P0` + 报 Owner。

> 现状：`gbt_allinone/llm/advise.py` **不存在**（通道未建），所以本节与 §10.4 目前是**设计**，不是运行态。
> 越权检测的执行者只能是**我这侧**的校验器——通道自己不会举报自己。
