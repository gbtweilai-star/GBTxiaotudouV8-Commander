## §0 一句话口径

**卡点不是"做不到"的同义词，是"还没查完"的同义词。**

遇到卡点，先查三处（本机既有实现 / 上游参照项目 / 官方文档与本机 API 清单），
再回答"能不能做"（先照四张镜子 + 本机现状），最后按**三档口径**说人话：
① 能力位里有 ⇒ **有**，给调用法；② 没有但有本机工具 ⇒ **可建**，给建法；③ 都没有 ⇒ **没有**，写清缺什么、谁有权给。
🔴 **没有三查出处的「做不到」，不许写进任何交付物或回报** —— 这条由机械闸（§5）当门。

## §1 R1 · 卡点三查（开口前必须查完三次）

任何"**做不到 / 不支持 / 没有 / 无法 / 只能靠主人**"的结论之前，必须先完成三查并留痕：

| # | 查什么 | 怎么查（缺一不可） | 例（出处） |
|---|---|---|---|
| **查①** | **本机既有实现** | 同族能力位 / 触手方法名册 / 既有脚本，用 `grep` 找关键词 | `py -3.14 -m gbt_allinone list`（现读 240 位）· `run tentacle_manifest`（触手总纲）· `state/surfaces/*.json`（面键表）· 全仓 grep 关键词 |
| **查②** | **上游 / 参照项目** | **主人点过名的那个开源项目里，同类功能怎么做** —— `gh api .../contents/<path>` **现读原文**，带**文件与行** | BaiLongma（白龙马）的 `electron/main.cjs` 第 779-787 行给 media 放行（详见 §3） |
| **查③** | **官方文档 / 本机 API 清单** | `--help`、官方 README、系统 API 能力与设备现状（设备端点状态 / GPU / 已装工具） | Electron 官方 `session` 页原文「**media - Request access to media devices such as camera, microphone and speakers.**」· `powershell Get-CimInstance Win32_VideoController` |

**留痕格式（写死，逐字照抄）**：

```
查①…(出处) · 查②…(出处) · 查③…(出处) → 结论：<做不到|能做到，怎么做>
```

写在**正文段落**里（别塞进代码块 —— 机械闸不认代码块里的留痕，理由见 §5「口径边界」）。
🔴 **没有三查出处的"做不到"，不许写进任何交付物或回报。**

**出处写法（踩过才有的，两条硬规矩）**：
- **仓内**文件用 `文件:行`（例：`holo_pet_w3/shell/main.cjs:1193`）—— `audit-line-refs.py` 会去现读那一行验锚。
- **仓外**（别人的仓、上游）文件**别写 `文件:N`**，写「**第 N-M 行**」+ `gh api` 命令/URL。
  实测（2026-10-08）：仓里**没有** `voice-core.js`（现读 `find . -name voice-core.js` = 0 个），
  写成 `src/ui/brain-ui/voice-core.js:731` 会被锚审计判 `BROKEN_MISSING` —— **凭空造一条红给别的任务**。
- `electron/main.cjs:779` 这种写法在本仓会**先按仓根解析**，再按「唯一 basename」兜底解析到
  **我们自己的** `holo_pet_w3/shell/main.cjs`（该文件真有 779 行，是一句注释）⇒ **指向了完全不相干的行**。
  ⇒ 仓外文件一律「第 N-M 行」写法。

## §3 案例复盘：今天栽的这个跟头（麦克风）

### 3.1 现场：读了什么、下了什么结论

2026-10-08 本会话，探到三条读数：

1. 浏览器 `navigator.mediaDevices.enumerateDevices()` ⇒ **0 个 `audioinput`**；
2. `getUserMedia({audio:true})` ⇒ 抛 **`NotFoundError`**；
3. WASAPI ⇒ **活动录音端点 0**。

当场的结论原话（**这就是反例**：三查没做、结论先出）：

```
「这台机器没有可用的麦 / 只有主人能启用设备」—— 然后停了。
```

主人一句话打回：

```
白龙马开源项目的麦克风这么部署的你不看的吗
```

### 3.2 三查查出来什么（现读原文，2026-10-08）

**查① 本机既有实现**（`run tentacle_manifest` 回执 + 本仓 grep 现跑）—— 回执原文：

```
❌ **麦克风** —— 准确口径（按 WASAPI 状态掩码实测）：**活动录音端点 = 0**，
在册 5 个（DISABLED 1 / NOTPRESENT 3 / UNPLUGGED 1）。
⚠️ **不是「没有麦克风硬件」，也不是「有麦克风」** —— 这两种说法我都说过，**都不准**。
```

⇒ **在册 5 个、其中 1 个是 DISABLED** —— 这是"**启不启用**"的问题，**不是"没有硬件"**。
⇒ 同一轮现跑取证：`holo_pet_w3/shell/*.cjs` 全文件 grep `setPermissionRequestHandler|setPermissionCheckHandler|media` = **0 命中**
—— **我们的壳从来没给 `media` 放行过**。这两件事（"壳有没有放行" vs "机器有没有麦"）当时**被混成了一件**。

**查② 上游参照项目**（白龙马 BaiLongma，`gh api .../contents/electron/main.cjs` 现读原文）：

```js

window.webContents.session.setPermissionRequestHandler((webContents, permission, callback) => {
  if (permission === 'media') return callback(true)
  callback(false)
})
window.webContents.session.setPermissionCheckHandler((webContents, permission) => {
  if (permission === 'media') return true
  return false
})
```

⇒ 上面是 **第 779-787 行**；而且**三个窗都放行**：主窗 **779-787** · `focusBannerWindow` **974-981** ·
`wakeProbeWindow` **1463-1467**（后者检查处理器一行 `permission === 'media'`）；**第 771 行**还给
`autoplayPolicy: 'no-user-gesture-required'`（无手势也能起音频）。
⇒ 采集端能用的**前提**是壳先放行 —— 白龙马把它当**必备布线**，不是可选项。

**查② 续**：`src/ui/brain-ui/voice-core.js`（1016 行，现读）里的采集工程：

```js

// 第 779-815 行：双路径 —— 首选 AudioWorklet（独立音频线程，"UI 渲染再卡也不丢音频帧"），

```

⇒ 另有 **第 89-90 行** `PCM_CHUNK_SAMPLES = 2048`（@16k ≈ 128 ms/块）；**第 676-681 行**关掉分析用
`AudioContext` —— 注释原文：不关会累积，**触顶浏览器约 6 个的硬上限后麦克风彻底失灵**。
⇒ 设备清单侧（`src/ui/brain-ui/settings.js` **第 1200-1260 行**）：`enumerateDevices()` 过滤 `audioinput`；
**先 `getUserMedia` 要一次权限**（否则拿不到标签），再把失效的 `deviceId` 从 localStorage 里清掉。
⇒ 白龙马的口径是「**枚举为空 ⇒ 回退默认设备**」，不是「枚举为空 ⇒ 没有麦」。

**查③ 官方文档 / 本机 API 清单**（Electron 官方 `session` 页 · `py -3.14 -m gbt_allinone list` 回执）：

```
Electron 官方文档 session 页原文：media - Request access to media devices such as
camera, microphone and speakers. （并写明：两个 handler 都要实现 —— 多数 Web API 先查后请）
```

⇒ 壳**不装**这两个 handler 时，`media` 授权**没有"没人管就默认放行"这回事** —— 我们的壳是空白，等于没布这道线。
⇒ `py -3.14 -m gbt_allinone list` 回执：本机 **240 位**里**没有**"音频采集"位（只有 audio 播放 / 环回 / 设备读数那些）。
⇒ 这一格按 §2 三档口径属**②**：能力位没有，但本机有工具与系统 API ⇒ **可建**。

### 3.3 正确的留痕应该长什么样（照 §1 格式，逐字）

**今天麦克风这条腿（补完三查的原话）**：

查①（本机既有实现）`run tentacle_manifest` 回执原文「活动录音端点 = 0，在册 5 个（DISABLED 1 / NOTPRESENT 3 / UNPLUGGED 1）」· `state/surfaces/netsh.json` 43 把键（面键表现读）· 本仓 `holo_pet_w3/shell/*.cjs` 全文件 grep `setPermissionRequestHandler|setPermissionCheckHandler|media` = 0 命中（现跑）；查②（上游参照项目）BaiLongma `electron/main.cjs` 第 779-787 行给 media 放行（`gh api repos/xiaoyuanda666-ship-it/BaiLongma/contents/electron/main.cjs` 现读原文）· 同仓 `src/ui/brain-ui/voice-core.js` 第 623-630 行约束 / 第 646-668 行 deviceId 回退链 / 第 731-734 行显式采样率 / 第 779-815 行 Worklet→ScriptProcessor 双路径；查③（官方文档与本机 API 清单）Electron 官方 `session` 页原文「media - Request access to media devices such as camera, microphone and speakers.」· `py -3.14 -m gbt_allinone list` 回执 240 位（无采集位）→ **结论：能做到**，怎么做：给壳两处 handler 都加 `media` 放行（照抄白龙马第 779-787 行），采集端照抄 deviceId 回退链 + 显式采样率 + Worklet 首选双路径；**没做完的一件**：放行之后这台机器**还有没有麦**要**加完放行再实测**（现读仍是"活动录音端点 0"，那不是"没有麦"，是"没启用/没放行"两件事还没分开验）。

### 3.4 三条教训（按"真因排序"，不是按"最好听"排序）

1. **真因第一是"我们壳没放媒体权限"**（本仓 grep 0 命中 + 白龙马三处放行）—— 不是"这台机器没有麦"。
   当时的结论把**两件事混成一件**：`enumerateDevices` 空既可能是"没设备"，也可能是"没放行/没启用"。
2. **本机自己的总纲早就写清楚了**（在册 5 个、DISABLED 1）—— **查①只要读一次，就不会说错**。
3. **上游有现成布线，而且主人点过名**—— 白龙马把 media 放行当必备件；**查②是主人明说的义务**。

> **口径纠偏（顺带钉一条纪律）**：主人材料里记的是白龙马"显式 **48k**"；**现读原文是 16000**
> （`voice-core.js` **第 731 行** `const targetSR = 16000;`），48k 只出现在 `src/voice/whisper/audio.py` 的
> **注释**里（"480000 samples"）。**三查的用处之一就是纠正转述**——按现读原文写，不按转述写。

## §4 正例 / 反例（机械闸照着判的两个样）

**✅ 正例（绿：结论 + 三查齐全，同段）** —— 就是 §3.3 那段。要点：结论句与三查在**同一段**（或结论句后 15 行内），
三个标记都**带得出处**。

**🔴 反例（红：只有结论、没有三查）**：

```
本机麦克风这条腿本机是真没有，做不到语音采集，只能靠主人去系统设置里启用设备。
```

**🔴 反例（红：骑墙结论，且没查）**：

```
麦克风大概是没有的，可能做不到，也许要主人才能开。
```

**🟡 不是红（授权态，别硬套三查）**：

```
这一格缺授权，要主人发作用域；缺票的能力位调用会如实报缺什么。
```

⇒ 「缺授权 / 缺票 / 缺作用域」是**授权态**（口径第三档，接法明确：主人发作用域），**不算"做不到"结论**；
但把它写成强词（"做不到/只能靠主人/不支持"）的句子，闸**照样抓**。

## §5 机械闸：`tools/codex-scripts/blocker-research-check.py`（新建）

**它干什么（很窄）**：扫文档里"做不到/没有/无法/只能靠主人"式的**结论句**，看它**旁边有没有三查留痕**；
没有 ⇒ 报红。**它不判结论对不对**（那要人查资料），只判"**你查没查、留没留痕**"。

**用法**：

```powershell
cd C:\Users\ADMIN\Desktop\GBT小土豆V8
py -3.14 tools\codex-scripts\blocker-research-check.py                     # 默认扫 docs/*.md + AGENTS.md
py -3.14 tools\codex-scripts\blocker-research-check.py --json              # 机器版读数（退出码同）
py -3.14 tools\codex-scripts\blocker-research-check.py --files docs\能力接线总表.md AGENTS.md
py -3.14 tools\codex-scripts\blocker-research-check.py --selftest          # 正负对照（临时目录现造样例）
```

**退出码（可复跑）**：`0` = 全绿 · `1` = 有红（缺三查 / 骑墙 / 标记缺出处）· `2` = 用法或 IO 错（**fail-closed**）。

**判据 11 条**（写死在脚本 docstring，`--selftest` 逐条验）：

| # | 判据 | 算坏的形态 |
|---|---|---|
| C1 | 结论句识别（强词） | 整句出现 `做不到 / 办不到 / 不支持 / 只能靠主人 / 无法实现 / 无法做到 / 不可能做到 / 无此能力 / 没有能力 / 没有可用的 / 没有这个能力 / 不能做 / 没法做` ⇒ 须有三查 |
| C2 | 结论句识别（弱词**相邻式**） | `没有 / 无法 / 不能 / 未支持 / 缺 / 缺了 / 未接 / 未装` **必须与能力语素相邻**才算（中间只许夹一个动词）；或「能力语素 + 不可用」倒装 |
| C3 | 授权态豁免 | `缺授权 / 缺票 / 缺权限 / 缺作用域`**不计**（写成强词仍会抓） |
| C4 | 代码块与引号不算 | (a) 代码围栏内不算结论、也**不算留痕**；(b) **引号里只由词表词组成的片段**、或**带元话语标记的行里的引号片段** = "在讨论这些词"，不算断言 |
| C5 | 三查覆盖 | 结论句所在**段落**内或其**后 15 行**内，须**同时**有 `查①` `查②` `查③` 三种标记（也认 `查1/2/3`） |
| C6 | 出处可解析 | 每个标记**同一从句**里须带出处形态（括号内容 / 路径 token / `--flag` / URL / `文件:行`）——"我查过了"不算出处 |
| C7 | 含糊不算数 | 带 `可能 / 也许 / 大概 / 未必 / 不确定 / 说不好` 而三查不满三条 ⇒ 红 |
| C8 | 文件级 fail-closed | 读不了 / 一个文件都没匹配上 / **代码围栏不成对** ⇒ 红 + 退出码 2 |
| C9 | 读数必须自报 | 输出带：扫描文件数 · 命中结论句数 · 绿 · 红 · 每条红的 `文件:行` + **原文** |
| C10 | 退出码语义 | 0/1/2 三态写死 |
| C11 | 负对照（自证） | `--selftest` 在**临时目录**现造 5 例：正例绿 · 只结论红 · 骑墙红 · 授权态不红 · 围栏坏 ⇒ 红且 rc=2 |
