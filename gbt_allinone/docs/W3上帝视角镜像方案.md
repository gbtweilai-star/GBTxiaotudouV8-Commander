## 零、一句话

W3 先在镜像维度里长出**五样东西**（窗口页面 / 窗口样式 / 数据绑定 / 主进程骨架 / 账本常驻化），
由**三支探针**验证，`scan()` **5/5 全绿**且探针全过才允许晋升。
**晋升 ≠ 上线**——晋升只落到 `store/mirror_space/reality/`，离生产树还有单独一步（见 §六）。

### 2.1 四视图 × 数据源（风哥 2026-09-17 指定 · 逐条取证）

| 视图 | 权威数据源 | 取证 | 怎么进窗口 |
| --- | --- | --- | --- |
| **看自己** | `GET /api/state` → `bridge.state()`（`holo_pet/panel_server.py:1232` → `:348`）；其中 `mind` 来自 `_mind_pulse()`，宿主资源 `cpu_percent` / `memory_percent` 来自 **`psutil`**（`gbt_allinone/mind_engine.py:1349-1351`） | 端点返回 `codex / mind / life / bluetooth / sensory / notion / eigenflux / xingyun` 八段（`:350-362`） | 渲染进程 `fetch('/api/state')` + 订阅 `GET /api/events`（SSE，`:1235`），**只读** |
| **看任务** | `gbt_allinone/store/tasks.json` —— `{"next_id":55,"tasks":[…]}`，每条含 `task_id / kind / priority / status / attempts / depends_on / acceptance / last_error / escalation / created_at` | 本轮实测读取：46,768 B、mtime 9-15 13:12，旁边有 `tasks.json.lock`（写者是别人，W3 只读） | **它不在 `/api/state` 里** → 由窗口主进程（`shell/main.cjs`）直接 `fs` 读，经 IPC / `contextBridge` 交给渲染进程 |
| **看环境** | `gbt_allinone/services.py:inspect()`（`:79-122`，线程池探活登记服务，含 `optional` 与 `optional_down` 语义） | 读源码取证；`DEFAULT_SERVICES` 14 项在 `:18-33` | 主进程起一个子进程 `py -3.10 -c "from gbt_allinone import services; …"`；**必须 `quiet=True`** —— 否则会落 `svc_down` 审计（`:118-119`），直接破 V6 |
| **看账本** | `gbt_allinone/store/audit.jsonl`（35.8 MB，行形如 `{"ts":…,"iso":…,"event":…,"meta":{…}}`）+ 四路账本（扶正后 `store/ledger/*.jsonl`，见 §三） | 本轮实测首行 `2026-09-11T10:34:27 event=call`、末行 `2026-09-17T11:31:51 event=signature_guard` | **必须 tail 读**（按字节从文件尾回溯取 N 行），**禁全量载入** |

三条纪律：

1. **只读**：四路都不得产生写操作（V6）。`audit.jsonl` 只 tail、`tasks.json` 只 read、`services` 只 `quiet=True`。
2. **不假数据**：取不到就显示"取不到 + 原因"，不许拿默认值顶替（《反空壳律》）。
3. **观察项（本轮实测，不在 W3 修）**：`store/services.json` 现在是 `{}`（3 字节），而 `services.py:36-42`
   只在文件**不存在**时才回落到 14 项 `DEFAULT_SERVICES` → 当前 `inspect()` 返回 `total=0`。
   视图必须**如实**显示"未登记服务"，不得拿默认表冒充。要不要补登记表，等风哥单独拍。

### 2.2 窗口生命周期 · 吸附 · 托盘（W3 定口径）

- **生命周期**：`shell/main.cjs` 是唯一宿主进程，`app.requestSingleInstanceLock()`（重复启动只唤起既有窗口）；
  每扇窗口一个独立 `BrowserWindow` + 独立 `webContents`——**关一扇不影响其他**（V4）。
  W3 阶段 shell **只登记"上帝视角"一扇**（`windows.json`）；主控台（W1）仍在生产树 `holo_pet/` 里，本方案不动它，
  接管 W1 是 §六 的晋升步骤。主控台关闭 = 应用退出（子窗口一并关）；子窗口全关 ≠ 退出；
  最小化 → 托盘常驻，不占桌面。
- **吸附**：无边框窗口用 `-webkit-app-region: drag` 拖拽；释放时距**屏幕边缘**或**其他 GBT 窗口边缘** ≤ 12 px 即吸附对齐；
  吸附只在主进程 `moved` 事件里算，**不写页面、不落盘**。
- **布局持久化**：`app.getPath('userData')/window-layout.json`，每窗 `{x, y, w, h, visible}`；
  恢复时做**越界校验**——坐标落在可见屏幕之外就回落主屏（V5）；托盘菜单提供"重置布局"。
- **托盘**：图标用 `window.css` 的品牌 token（土豆金 + 赛博青描边）；菜单 = 显示/隐藏各已注册窗口 · 重载当前窗口 · 重置布局 · 退出。

### 3.1 四路账本

沿用既有四层语义（`docs/探针无网络影响确认报告.md:112-115` 已定义、已验证），只是从探针态扶正为常驻：

| 层 | 文件 | 记什么 |
| --- | --- | --- |
| `panel.send` | `store/ledger/panel.send.jsonl` | 面板/窗口发出的意图帧（含"意图 3 行 / 真实出网 4 行"的区分） |
| `bridge.emit` + `bridge.recv` | `store/ledger/bridge.jsonl` | 桥的出网帧与入站帧，`direction` 字段区分 |
| `route.recv` | `store/ledger/route.recv.jsonl` | 路由收到并转发前后的帧 |
| `mock.recv` | `store/ledger/mock.recv.jsonl` | 终点接收帧 |

### 3.2 一行账本的形状

以现有探针账本的真实行形为准（`.scratch/codex_v2_bridge_ledger.jsonl` 第 1 行，本轮实测）：

```
{ "event": "bridge.emit", "layer": "bridge", "frame_direction": "out",
  "route_from": "bridge", "route_to": "codex app-server(stdio)",
  "received": false, "method": "initialize", "req_id": 1,
  "frame_bytes": 174, "frame_bytes_hash": "e0839b1dc1b1ceb4",
  "params_keys": ["capabilities", "clientInfo"],
  "schema_verdict": "warn", "timestamp": "2026-09-16T10:51:37" }
```

纪律三条：**append-only**（不许改写历史行）、**不记 payload 全文**（只记指纹与字节数，
与《凭据不离屏律》同源）、**四路同一帧的 `frame_bytes_hash` 必须一致**。

> **勘误（2026-09-17）**：本文件先前两稿把指纹字段写作 `frame_sha256_16`（§3.2 与 V2），
> 那是**笔误**。仓内权威字段名是 **`frame_bytes_hash`**：探针 `entry_refactor_probe.py:69`
> 写的就是它，判据脚本 `.scratch/verify_panel_ledger.py:24-29` 也是拿它做跨层比对的。
> 常驻化沿用 `frame_bytes_hash`，不新造字段名。

### 3.3 与既有判据对齐

`docs/第②步面板收口方案.md:70` 早已定下判据："四层账本逐帧 SHA256 前 16 位一致"。

## 五、晋升条件与回滚

### 5.1 晋升条件（三条同时成立）

1. `scan()` 5/5 全绿；
2. V1–V6 六条判据全过；
3. 三支探针全 PASS，且 PASS 是**跑出来的**，不是推断的。

任一条不过 → 停在维度里改，**不许晋升**。`ascend()` 自己也会拦（`mirror_space.py:150-154`：
验证未全绿直接返回 `blocked`），这是双保险。

### 5.2 回滚路径

| 情形 | 动作 |
| --- | --- |
| 维度里改坏了 | 直接覆盖重写（`shape()` 幂等），**不用回滚** |
| 晋升后发现不对 | `rewind(<上一个版本号>)`——当前现实是 v19，所以回升 W3 后若出问题，回 `rewind(19)` 即可回到 Backbone 演示状态 |
| 想找回被清掉的旧演示 | 同上，`timelines/v19` 有完整快照 |

## 六、一条必须显式说清的边界：晋升 ≠ 上线

`ascend()` 的落点是 **`store/mirror_space/reality/`**（`mirror_space.py:167-169`），
**不是 `holo_pet/`，也不是 `potato_pet/`**。

所以 W3 镜像全绿只证明一件事：**产物是对的、范式是通的**。
要真正让上帝视角窗口在桌面上出现，还差一步：

> 照护照（`passports/vN.json` 的逐文件指纹）把 reality 的产物落到生产树 `holo_pet/`，
> 并把 `holo_pet/desktop/main.cjs` 从单窗口改造成窗口管理器。

**这一步才是真正动生产代码，必须单独授权**。本方案不覆盖它，也不预设它的做法。

### 10.5 与 V6「只读」的关系（风哥 2026-09-17 已拍，口径定死）

V6（§2.1 纪律 1）要求 W3 四路数据源**不得产生写操作**。故障矩阵的「自检」按钮与此**不冲突**——
拍板口径是：**允许点，但不写盘**。

```text
只读期：点「自检」──> 探针在内存里跑一遍 ──> 结果只喂窗口 4 的 UI（窗口关了就没了）
                        └─ 不落任何文件

写盘期（后台探针服务上线后）：
        窗口「自检」按钮 ──POST /api/health/selfcheck──> 后台独立进程 ──> 写 store/health/*.jsonl
        窗口本体          <──只读 tail store/health/────────────────── 探针服务
```

| 主体 | 权限 | 说明 |
|---|---|---|
| 窗口 4（只读期） | 可点自检 · **不写盘** | 结果只在 UI 内存里活着；立即返回"只读态：自检结果仅 UI 显示，不落盘" |
| 窗口 4（任何时期） | **不得写** | 历史状态一律 tail 读 `store/health/` |
| 后台探针服务 | **可写** | 独立进程，**不受只读期约束**（见《GBT全故障点设计.md》§17.2.1） |

- 这是 V6 的**延伸**：窗口这一侧**没有任何写口**，V6 判据（探针扫窗口的写行为）照旧成立。
- 只读期自检与写盘自检**判据不同**，UI 上必须标清当前是哪一个态——
  **不许让"内存里的绿"冒充"落盘的绿"**。

### 12.5 施工期四条新发现（如实报）

1. **维度是文本沙箱，`import` 会落 `__pycache__`。**
   T2 探针用 `importlib` 加载 `holo_pet_w25/main.py` 验产物，结果在维度里生成了
   `holo_pet_w25/__pycache__/main.cpython-310.pyc`，当场把 `scan()` 的 `discipline` 关打红（12 → 13 文件）。
   **处置**：清掉该目录（已确认在仓库内才删），并给探针加 `sys.dont_write_bytecode = True`。
   **教训入账**：凡是要 import 维度内文件的探针，必须禁字节码，否则“验证动作自己破坏被测对象”。
2. **本机 `time.monotonic()` 分辨率 ≈ 15.6 ms。**
   `time.sleep(0.001)` 实测读回 `0.0 / 16.0`，相邻变化量恒为 15–16 ms
   （CPython 在 Windows 上走 `GetTickCount64`）。
   所以 W2.5 探针的 `latency_ms` 是**量化值**，不是真实耗时——判据本身不依赖它，
   但以后任何拿 `latency_ms` 做阈值的逻辑，都得先扣掉这个 15.6 ms 的量程。
3. **CORS 决定了 SSE 订阅者的位置。**
   `panel_server.py:1220-1227 _send_json` 不发 `Access-Control-Allow-Origin`，
   渲染进程从 `file://` 直接 `fetch('/api/state')` 会被浏览器拦死；
   给它加头就是动生产代码（§八 红线）。所以订阅者前移到**主进程**，
   推送通道仍是同一条 `/api/events`——**不新增第二套推送**。

4. **沙箱内的进程/端口枚举会静默返回空——空 ≠ 不存在。**
   收尾判活时我用 `Get-NetTCPConnection -LocalPort 8765` 与 `Get-CimInstance Win32_Process` 取证，两条都返回**空**，
   于是写下“面板已随会话退出、8765 已释放”并写进回执——**这是错的**。
   改用端点探测（`GET /api/state` → **200 / 7,048 B**）当场证伪：面板 `pid=13500` 当时**还活着**。
   **处置**：用护栏命令停掉该进程（先校验 `ProcessName=python` 且 `StartTime > 13:59:00`），停后端点确认 down。
   **判例入账**：凡判“进程/端口是否活着”，必须用**端点探测（HTTP/TCP 连接）或提权查询**；
   沙箱内 `Get-NetTCPConnection` / `Get-CimInstance` / `Get-WmiObject` 会返回空或 `Access denied`，
   拿它下结论等于**拿静默当证据**——《静默失效律》在探针侧的样子。

### 12.6 与方案的实现差异（三处，如实报）

1. **产物 4 拆成三个文件**：`shell/main.cjs`（壳）+ `shell/layout.cjs`（布局纯逻辑，**不 require electron**）+ `shell/preload.cjs`（只读 IPC 桥）。
