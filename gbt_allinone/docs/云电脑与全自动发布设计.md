## 一、云电脑独立窗口（`tools/cloud_pc.py`）

### 形态：卡片 + 触手，**不是 iframe**

| 项 | 定法 |
|---|---|
| 形态 | 面板上加一个**独立窗口**（与其他卡同级） |
| 为什么不是 iframe | 跨域 + 登录态会撞；而且嵌网页会把「呈现」和「动手」混在一起 |
| 卡片只做 | 呈现云主机状态 / 安装进度读数 / 最近可回滚点 |
| 动手走 | `run_task("cloud_pc", {...})` → **过 auth_gate** → 触手 |
| 给谁用 | **给她（数字人）装一台云电脑** |

### 五原语（逐个标「花钱 / 不可逆」）

| 原语 | 做什么 | 花钱 | 可逆 | 要过门 |
|---|---|---|---|---|
| `PROVISION` 开通安装 | 开主机 + 装底座 | ✅ | ❌ | ✅ |
| `CONNECT` 连上 | 连上去干活 | ❌ | ✅ | ❌ |
| `STATUS` 读数 | 配置 / 用量 / 账单 | ❌ | ✅ | ❌ |
| `SNAPSHOT` 快照 | 留可回滚点 | ✅ | ✅ | ❌（花钱但可回滚，仍留痕） |
| `RELEASE` 释放 | 退掉 | ❌ | ❌ | ✅ |

**「谁花钱、谁不可逆，必须逐个标出来」** —— 不标就会被当成「都一样」。

### 五条红线（都做成了机械闸）

```
① 密钥只存 DPAPI：云端凭据走密钥池，不许明文落盘、不许进返回值
② 先算账再花钱：开通 / 释放前必须先给**资源与预算读数**（预算 + 账单，缺一不可）
③ 每次操作留痕：写 trace_store，source_kind=cloud_pc
④ 不绕官方入口：走云厂商官方 CLI / SDK，不许自己拼请求
⑤ 身份内核不变：**她住在云上，身份源仍在本地** —— 云端不许改写身份内核
```

### 现状（先取证，再说话）

```
凭据    本地没有（也不许有明文）⇒ 一律 not_implemented + requires_external_key
厂商    主人**未给** ⇒ 本骨架**不编**（未取证不引外部）
本机    本机可用 ≠ 云上可用 ⇒ **两处读数不许互相顶**
```

## 二、社交推广 / 发布作品 / 收益 · 全自动执行（`tools/auto_publish.py`）

### 🔴 核心口径：**「全自动」的边界写在纸上**

```
全自动 = 除「发布 / 提现 / 改价」那几下之外，全自动。
```

那几下**不可逆 + 出网 + 涉及钱** ⇒ 必须过门；其余全自动跑，不用问。

| 动作 | 归哪边 | 为什么 |
|---|---|---|
| `plan` 排期 | **全自动** | 纯本地，可反复改 |
| `compose` 成稿 | **全自动** | 纯本地，可反复改 |
| `track` 追踪 | **全自动** | 只读 |
| `settle_read` 收益汇总 | **全自动** | 只读（**只汇总，不代提**） |
| `publish` 发布 | **过门** | **不可逆 + 出网**：发出去收不回来 |
| `settle_withdraw` 提现 | **过门** | 涉及**钱** |
| `price_change` 改价 | **过门** | 影响钱与承诺 |

把「全自动」说成「连发布也不问」，就是把**不可逆**当成**可逆** —— 这是最贵的一种错。

### 过门的两种方式（任选其一）

```
① 逐条确认：这一次主人点了头 ⇒ 放行这一次
② 有 TTL 的批量令牌：token 非空 **且** ttl_seconds 是正数 ⇒ 放行
   （缺 TTL 的令牌**不算**——那是长期万能钥匙）
默认：**0 张令牌** ⇒ 发布一律走逐条确认
```

### 六条红线（都做成了机械闸）

```
① 发布必须过门（不可逆 + 出网）
② 密钥只存 DPAPI：平台凭据走密钥池，不许明文落盘、不许进返回值
③ 每次发布留痕：写 trace_store，source_kind=publish
④ 一人一号：接合规底座 account_registry —— 不许共用账号、不许抢别人的号
⑤ 收益只汇总不代提：提现 / 改价单独授权
⑥ 不刷量、不做假数据、不绕验证：**数据可以难看，但不能是假的**
```

## 三、与既有架构怎么接（不另立口径）

| 接哪 | 怎么接 |
|---|---|
| 授权门 | 云电脑的开通/释放、发布的每一发，全走 `run_task` → `auth_gate` |
| 密钥池 | 云凭据与平台凭据都只走密钥池（DPAPI 只存路径），**不进返回值** |
| 痕迹库 | `source_kind=cloud_pc` / `source_kind=publish` |
| 合规底座 | 发布账号接 `account_registry`（一人一号） |
| 编排内核 | 两个能力位**落地即接线**（真 import + 派发表），审计器孤儿数为 0 |
| 身份内核 | 云电脑是**副本的住处**，身份源永远在本地 |

## 七、🔴 同刀抓到一处真缺陷：**能力位要接三处，不是两处**

本刀第一版只登记了两处：

```
① caps_registry.BENIGN_CAPS      ← 在册
② orchestration_kernel 派发表    ← 编排内核认识它
```

结果**出口拿得到 ok、拿不到载荷**：

```json
{"ok": true, "kind": "auto_publish", "result": {"status": "ok", "kind": "auto_publish",
                                                "result": null}}
```

病根：`api.py` 里**每个能力位还要有一个 kind 分支**（真正的调用点）。
补上第三处之后，出口才给得出载荷。

```
③ api.py 的 kind 分支            ← **真调用点**（缺了它就只是「在册」）
```

> 这正是「**挂号 ≠ 接线**」的又一现场：**三处在册才算接上**。
> 本刀把它记在这里，下次新能力位照着三处一次接齐。
