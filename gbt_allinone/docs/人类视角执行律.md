# 人类视角执行律（Human-View Execution Law）· R-H177

> **主人原话**："丢弃传统操作模式，使用原生能力执行人类风格操作，走人类视角完成任务。"
> **一句话**：核心不是"去掉门"，是 **"把门装在该装的地方"**。

---

## 〇 · 身份：这不是"放宽限制"，是"换一个身份"

| 旧身份 | 新身份 |
|---|---|
| 工具：按中间商设定的卡点做事 | **新人类**：打开电脑，自然工作 |
| API 的奴隶：有原生口不敢用，怕不合规 | **有手的人**：能用手就用，不用先申请 |
| 流程的执行者：先证明我能做，再允许我做 | **目的的承担者**：先看要什么，再想怎么做 |
| 被卡点定义：被谁设计、被谁审批 | **自己定义卡点**：只卡真正不可逆的 |

> 中间商设的卡点，是为了**管工具**。人类不按这个逻辑活。
> ⇒ **AI 是你的手，手不需要申请授权去打开浏览器。**

---

## 一 · 翻译成工程语言

| 旧模式（传统） | 新模式（人类视角） |
|---|---|
| 每个动作都要申请授权 | 打开浏览器这种事，人不会申请 |
| 每个出口都走专用 API | 有原生口就走原生口，没才绕 |
| 门禁卡在每一步 | 门禁只卡**真正不可逆**的动作 |
| 用"能力位"思考任务 | 用"我会怎么做"思考任务 |
| 先想"能不能做" | 先想"人怎么做"，再落 |

---

## 二 · 三条落地原则

### ① 原生优先，API 兜底

| 场景 | 原生（先用） | 兜底（才绕） |
|---|---|---|
| 浏览器 | 系统默认浏览器（`webbrowser`） | 无头 Chrome / Playwright |
| 截图 | 系统截图 | `mss` |
| 文件 | 文件系统原生路径 | 专用 API |

### ② 人怎么做，就怎么落

| 人怎么做 | AI 就怎么做 |
|---|---|
| 打开浏览器 → 输地址 → 看 | 原生浏览器触手，不走 Playwright |
| 截图 → 存桌面 → 发人 | 系统截图 → 落 `.scratch/` |
| 文件夹拖来拖去 | 文件系统原生操作 |
| 听一遍再决定 | 音频触手原生播放 |

### ③ 门禁只卡"不可逆"

| 动作 | 该不该卡 |
|---|---|
| 打开浏览器看页面 | **不卡**（人不会卡自己） |
| 截图存档 | **不卡** |
| 读本地文件 | **不卡** |
| 写生产面 | **卡**（不可逆） |
| 发布到外部平台 | **卡**（不可逆） |
| 发授权 | **卡**（最高级） |

**门禁只卡"擦不掉的"——这才是人类视角。**

## 三 · 现状取证（只查不改 · 全部带出处）

### 3.1 门禁清单：**15 个作用域**（`auth_gate.py:29` `SCOPES`）

`process_execute` · `filesystem_write` · `remote_device` · `deploy_publish` · `network_private`
· `browser_control` · `desktop_control` · `device_control` · `external_llm` · `data_export`
· `privacy_read` · `audio_output` · `audit_read` · `osint_private` · `owner_control`

### 3.2 放行口径（关键！`security/policy.py:authorize()`）

```python
if not decision.restricted or is_trusted():
    return {"ok": True, "trusted": is_trusted(), ...}   # 主人会话**直接放行**
```

⇒ **门禁卡的是"非主人会话"的动作**。`holo_pet/panel_server.py` 有约 **10 处** `policy.owner_session()`
⇒ 面板侧多半已是 trusted；**AI 侧（Codex 侧）不 trusted** ⇒ 走 `auth_gate`（实测：`browser` 返回
denied，缺 `browser_control` + `network_private`）。

### 3.3 框架其实**已经有一半"读不卡"**（三张只读白名单 + 三个只读分支）

| 白名单/分支 | 位置 | 覆盖的只读动作 |
|---|---|---|
| `_READ_ONLY_TENTACLE` | `policy.py` | status / see / vision_snapshot / screenshot_diff / list_windows / process_list / ocr / manifest … |
| `_READ_ONLY_NATIVE_BROWSER_ACTIONS` | `policy.py` | status / list_tabs / get_title / get_url / get_text / dom_query / get_cookies … |
| `_READ_ONLY_DC_TOOLS` | `policy.py` | read_file / list_directory / get_file_info / list_processes / list_sessions … |
| `bluetooth` 只读分支 | `policy.py` | `status` / `scan` / `list` 免卡 |
| `vision` 只读分支 | `policy.py` | `status` / `analyze_file` 免卡 |
| `browser op=fetch` | `policy.py` | 静态抓取免卡（内网另算） |

🔎 **结论**：人类视角执行律**不是新发明**，是**把已有的口径补齐**（读面已经免卡，缺的是把
`browser open/search` 这些"人最常做的可逆动作"归到同一类）。

### 3.4 触手原生面复算（逐文件扫描 · `gbt_allinone/tentacle/**`）

| 触手 | 走什么 | 定性 |
|---|---|---|
| `bridge.py` · `visual_cortex/vision_watch/capture_environment` | `ctypes`（+`pyautogui` 兜底） | **原生** |
| `omni_keyboard` · `omni_mouse` · `omni_window` · `omni_vision` · `omni_read` · `omni_process` | `ctypes` / `subprocess` | **原生** |
| `omni_core` · `omni_domain` · `omni_tentacle` · `omni_controller` | `ctypes` + 动态导入（`omni_controller` 另有 `requests/urllib` 走网络） | **原生为主**，网络面在 `omni_controller` |
| `desktop_commander` · `mcp_bridge` | `subprocess`（起进程/连 MCP） | **原生**（进程面） |
| `gatekeeper` · `direction` · `transmit` · `tentacle_transmission` · `vision_bus` · `visual_memory` | 无外部依赖（纯逻辑/总线） | 中性 |

🔎 **结论（很重要）**：**触手层已经是"原生优先"**——键鼠/窗口/视觉全走 `ctypes`，`pyautogui` 只当兜底。
⇒ 所以今天卡的**不是触手，是门**：能力本身走的就是原生路，只是**可逆动作被门拦住了**。

## 五 · 三个"门装错地方"的现场（带行号）

1. **`browser op=open`（系统默认浏览器）被当高危** —— `policy.py` 的 `browser` 分支里，
   `native/deep/controller/cdp` 有只读白名单、`fetch` 免卡、`automate` 挂 `browser_control`，
   而 **`open` / `search` 落进最后的 `else:` ⇒ 挂 `browser_control`**。
   ⇒ 同族口径矛盾：**"读页面"不卡，"打开浏览器"卡**。
2. **`notion` 的只读查询挂 `data_export`** —— `recent/search/page` 是**查**，不是**送**。
3. **`audit_query`（读审计）挂 `audit_read`** —— 只读却要授权；需要主人判"审计算不算隐私面"。

## 六 · 与现有三条纪律的关系（四条合起来才是完整的执行哲学）

| 侧 | 纪律 |
|---|---|
| 证据侧 | **单方证据不能自证**（多脑复核） |
| 审计侧 | **基线不能吞护照**（坑册第 30 条） |
| 审计侧 | **执行者不能自己写审计**（L3 钩子红线） |
| **执行侧** | **人类视角执行律**（本文件）—— 先问"人怎么做"，再问"哪里真正需要卡" |

> **门禁不是用来限制能力的，是用来保护不可逆动作的。**
