# GBT小土豆 · 飞书镶嵌窗口

> **不是"再建一个系统"，是面板上多一张卡**（卡⑥「飞书」）——
> **走浏览器触手操作，不走 API。**

---

## 一 · 为什么走浏览器触手（**不是选择，是被读数逼出来的**）

```
① 凭据：configured=false · **credential_source: unreadable**
        ⇒ 沙箱身份读不出 DPAPI（**不是缺凭据，是身份不同**）
② 出网：受限 ⇒ 连不上 open.larksuite.com
⇒ **走「飞书 API」这条路，在沙箱里跑不通。**
```

| 触手 | 能不能用 | 原因 |
|---|---|---|
| **API 触手** | ❌ 卡死 | 凭据读不出 + 出网受限 |
| **浏览器触手（原生）** | ✅ **正解** | 用系统浏览器打开飞书网页版，**你已登录** ⇒ 不需要 DPAPI、不需要新密钥 |
| 桌面触手 | ✅ 备选 | 操作飞书桌面客户端（如已安装） |

🔴 这正是**原生优先律**的现场应用：能用原生，就不绕 API。

## 二 · 镶嵌窗口的形态

```
APP 面板 8765
  ├── 卡①投影 / 卡②穿透网 / 卡③净化 / 卡④音乐
  ├── 卡⑤工作区
  ├── 上帝视角（全局总览）
  └── ★ 卡⑥ 飞书（镶嵌窗口）
        ├── 只读呈现区：飞书知识库目录 / 最近文档 / 待办
        ├── 操作按钮：走浏览器触手打开对应页面
        └── 触手链：open_feishu(page) → 浏览器触手 → 原生浏览器
```

🔴 **它不是 iframe 嵌网页**（会撞跨域 + 登录态），是「**卡片 + 触手打开**」。

## 三 · 四条红线（写死 · 已做成机械闸）

| # | 红线 | 机械形态 |
|---|---|---|
| 1 | **飞书是副本，本地是源** | `check_copy_not_source` → `feishu_as_source` |
| 2 | **凭据不许明文** | `check_no_plaintext_key` → `plaintext_key`（本方案**不需要新凭据**） |
| 3 | **不绕验证**（不模拟登录、不抓 Cookie） | `check_no_bypass` → `bypass_login` |
| 4 | **每次操作写 `trace_store`** | `must_trace` → `call_not_traced` / `bad_source_kind`（`source_kind="feishu"`） |

🔴 第 1 条的理由（**今天刚立的账**）：本地已有**三处知识库口径未收口**
（`devoured/` · `pipeline/records/` · `brain_vault`）——
飞书再进来就是**第四处**。⇒ **本地为真相源，飞书做镜像/外发。**

## 六 · 顺序与诚实边界

- **顺序**：排在**当前队列之后，不抢**。
- **本刀不改面板**（面板 8765 正跑实例**不碰**）⇒ 卡⑥ 的实际接线是**后续一刀**。
- **不碰**：面板 8765 正在跑的实例 · 信号环 · 写路径 · 出网。
- **诚实边界**：
  · 本骨架**不打开浏览器、不出网、不落盘、不发密钥**；
  · **API 级自动化做不到**（凭据 + 出网双限）——这是**读数**，不是取舍；
  · 三处 host **盘上未验证**；
  · 「走浏览器触手」的前提是**你已登录**——**登录这一步永远是人做的**（Agent 不代签）。
