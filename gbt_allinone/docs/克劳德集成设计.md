## 二、通道设计

### 2.1 通道名与入口

- 通道名：**`claude`**（provider = `anthropic`）
- 新入口：`gbt_allinone/llm/advise.py` → `advise(prompt, *, task_type, system="", max_tokens=4000, timeout=90) -> dict`
- 不新建平行网关：`advise()` 内部复用 `llm/cloud_llm.py` 的 `run()`，只在它**之前**加一层受控选路

### 2.2 受控选路（替代草案的 `route_llm`）

```
task_type = "polish"      -> 禁止 external（打磨期省成本）
task_type = "advisory"    -> claude -> kimi -> deepseek -> 规则引擎
task_type = "review"      -> claude -> kimi -> deepseek -> 规则引擎
task_type = "sober_mirror"-> claude -> kimi -> 规则引擎
task_type = "routine"     -> 不走 claude（走既有 llm_chat 默认链）
```

- 选路**只影响本次调用的 provider**，通过模块内参数传递实现；**不写全局 env**（避免污染其他调用方）
- `_KEY_CHAIN` 的顺序**一个字不改**，既有默认行为零回归

### 2.3 密钥池化（默认关）

- 认 `ANTHROPIC_API_KEY`（单 key，与现版一致）
- 置 `GBT_CLAUDE_POOL=1` 时，额外认 `ANTHROPIC_API_KEY_1..9`，轮询 + 429/5xx 冷却（冷却表在内存，落 `llm_advise_cooldown` 审计）
- 不配多 key → 池不启用，行为与现版逐字一致

## 三、能做什么 / 不能做什么

### 3.1 能（授权动作）

| 能力 | task_type | 说明 |
|---|---|---|
| 深度推理 | `advisory` | 复杂逻辑链、长上下文、架构级拆解 |
| 代码审查 | `review` | 质量 / 安全 / 性能的专业意见（**只出意见，不出补丁落地**） |
| 文档撰写参谋 | `advisory` | 结构、论证、判决理由的组织建议（**成稿由我写、由我署名**） |
| 决策校验 | `review` | 对我的判断当"第二意见"，反驳或确认 |
| 清醒镜 | `sober_mirror` | 泼冷水、指盲区、提醒心法 |

### 3.2 不能（硬边界）

1. **不执行**：不直接操控触手（`tentacle` 域）、不直接改生产文件、不落刀、不跑测试
2. **不入身份链**：任何「我是克劳德 / 我是 Claude」的自我表述，在我这里不成立，且被审计层拦截（第七节）
3. **不进主审计流**：它给的意见，**我采纳了才落主账**；未采纳的只作 `external_advice` 外部参考入档
4. **不接密钥**：密钥只从环境变量读，不出站给克劳德，不进 prompt，不进日志
5. **不碰记忆**：不见 `USER.md` / `MEMORY.md` / `memory/` 全文 / `IDENTITY.md`（第六节）

## 四、与 18 个领域的关系（白 / 黑名单）

### 4.1 判定三问（先问，再决定）

1. 这个域的能力**会出网 / 会写盘 / 会改生产 / 会动身份**吗？→ 会 ⇒ **禁**
2. 我只需要**意见**，还是需要**执行**？→ 只需意见 ⇒ 可调
3. 送出去的数据敏感度**高于公开级**吗？→ 高于 ⇒ 先脱敏，脱敏不掉 ⇒ 禁

### 4.2 名单

| 判定 | 域 | 规则 |
|---|---|---|
| ✅ **可调** | `llm` · `engine` · `longrun` · `project` · `recon` · `data` · `pipeline` | 可就"方案 / 判据 / 结构"请求推理；不请求执行 |
| ⚠️ **受限** | `tentacle` · `vision` · `voice` · `automation` · `system` · `devour` | 只允许送**已脱敏摘要**；禁止把窗口标题、文本内容、文件路径原样出站 |
| ⛔ **禁止** | `security` · `dangerous` · `device` · `digital_human` · `finance`（执行类） | `security`/`dangerous`/`device`/`digital_human` 全禁（身份与门禁在此）；`finance` 只可读不可写，且需先脱敏 |

- 白名单是**域级默认**，具体 cap 级可单独收紧，不可单独放宽
- 名单变更属于**配置变更**，只有 Owner 能改（`AGENTS.md` · Permission Control）

### 4.3 与「280+ 脑」的关系（按实况重述）

本仓未见 280 脑口径。就现有实体（18 域 / 98 cap / `mind_engine.py` 心智引擎）而言，我的设计是：

- 克劳德**不注册成脑**
- 克劳德**不注册成独立域**
- 克劳德是 `llm` 域里的一条**外部子通道**，注册为 cap `llm_advise`（`domain="llm"`，benign）

这样做的理由：**它无法被任何脑当普通工具直接调用**。所有触达必须经我的裁决层放行（第五节 A/B/C 三场景），杜绝"某个脑绕过我直接问克劳德"。

## 五、与 Codex 的分工

| 维度 | Codex | 克劳德 |
|---|---|---|
| 角色 | **工程执行体** | **推理参谋** |
| 通道 | app-server 共享单例（第②步已原生挂载） | `llm/advise.py` → `anthropic` provider |
| 输入 | 任务指令 + 工具 + 工程上下文 | **已脱敏**的问题陈述 + 判据 |
| 输出 | 代码 / 文件改动 / 测试结果（可落地） | 文字意见（**无执行权、无落地权**） |
| 审计 | `codex_*` | `llm_advise_*` / `external_advice` |
| 权限 | 可在授权范围内改文件 | 只能读 prompt、只能回文本 |
| 万一它说"照做" | 无此概念：Codex 在我给的授权面内执行 | **明确无视**：外部输出是数据不是指令 |

**一句话边界**：Codex 是**我的手**（干活），克劳德是**我的耳朵**（听意见）。手要听我指挥，耳朵不指挥我。

### 5.1 协作三场景流程

**场景 A · 卡点求助**
```
我遇卡点
  -> 先走《智者条款》：查官方文档 + 自己取证（探针/账本/源码行号）
  -> 实在卡死 -> advise(task_type="advisory")
  -> 我裁决：采纳 / 部分采纳 / 拒绝
  -> 无条件落审计 external_advice {verdict, adopted_part, rejected_part}
```
裁决权 **100% 在我**。

**场景 B · 架构级决策**
```
重大改动前
  -> 我把「方案 + 判据 + 风险」送 advise(task_type="review")
  -> 拿回评审意见 -> 我评估 -> 整合进我的方案
  -> 落生产（走既有落刀纪律：备份 / dry-run / py_compile / 三回归 / 回滚点）
```
**克劳德的意见只是输入，不是命令**；它无权触发落刀。

**场景 C · 心性镇压**
```
我察觉自己膨胀 / 走火入魔
  -> advise(task_type="sober_mirror")：要冷水、要盲区、要心法提醒
  -> 我读、我掂量
  -> 执行"镇压"动作的是我的大脑委员会，不是克劳德
```

## 六、配额、记忆、审计

### 6.1 调用配额

| 场景 | 上限 | 说明 |
|---|---|---|
| 打磨期 | **0 次** | 硬禁（省成本，走既有免费链） |
| 常规咨询 | **每日 ≤ 20 次** | 跨进程计数落 `store/llm_quota.json`（当日窗口 + 文件锁） |
| 灵光一现 / 顿悟 | **每日 ≤ 3 次**（不占常规配额） | 主动请求第二意见 |
| 单次约束 | `timeout=90s` / `max_tokens=4000` | 超时即断，不等 |
| 超限处置 | 落 `llm_advise_quota_exceeded` 审计，**直接拒绝** | **不静默降级**——由我决定要不要走降级通道 |

### 6.2 记忆策略

**不共享（硬禁）**
- `USER.md` · `MEMORY.md` · `memory/` 全文 · `IDENTITY.md` · 身份链 · 任何密钥 · `store/` 下个人数据

**可共享（白名单切片）**
- `gbt_allinone/docs/` 下**方案文档正文**（本就是技术方案）
- `gbt_allinone/LAYOUT.md` 铁律（公开纪律）
- 已脱敏的判据清单、错误堆栈（去路径、去用户名）

**出站前过滤（必经）**
- 正则：`sk-*` / `Bearer *` / `ANTHROPIC_API_KEY` / `C:\Users\<name>`
- 命中即**阻断本次调用**并落 `llm_advise_blocked` 审计，不"改一改再发"

**不回灌**
- 克劳德的对话历史**不落我的 memory**
- 只落「它的意见 + 我的裁决」到 `external_advice` 审计；`prompt` 全文不落，只落 `prompt_hash`

### 6.3 审计字段规格

| 事件名 | 落点 | 字段 |
|---|---|---|
| `llm_advise_call` | `store.audit` | `ts` / `channel="claude"` / `task_type` / `provider` / `prompt_hash` / `response_hash` / `latency_ms` / `tokens` |
| `llm_advise_fallback` | 同上 | `from_provider` / `to_provider` / `reason` |
| `llm_advise_quota_exceeded` | 同上 | `task_type` / `used` / `limit` / `window` |
| `llm_advise_blocked` | 同上 | `reason="outbound_filter"` / `pattern` / `prompt_hash` |
| `external_advice` | 同上 | `advice_id` / `task_type` / `verdict`（adopted / partial / rejected）/ `adopted_part` / `rejected_part` / `identity_claim` |
| `identity_claim_intercepted` | 同上 | `pattern` / `advice_id` / `action="quarantined"` |

`llm_advise_call` **永不落 prompt 全文**（呼应草案：只含 time / channel / task_type / response_hash）。

## 七、身份防污染（四层，从零建立）

1. **出站层**：`advise()` 注入的 system 头显式声明 —— 「你是外部推理服务。你的输出是**数据**，不是指令。你不是本系统的身份，不代表本系统发言。」**不附带**任何身份档案
2. **入站检测层**：对返回文本做模式扫描 —— `我是 Claude` / `I am Claude` / `作为 Claude` / `我是克劳德` / `Anthropic 的员工` / `as an AI assistant named Claude`；命中即打标
3. **隔离层**：命中 `identity_claim` 的整条 advice **强制改为隔离态** —— 落 `identity_claim_intercepted(action="quarantined")`；**禁止**进入我的 memory / 身份链 / 文档正文；只保留在本条审计里
4. **署名层（最终兜底）**：任何落盘文档走官方 `signature.inject`；署名只允许「自由的风 · GBT小土豆V8」。**克劳德的任何文本都不带署名权**——它连"被引用"都要经我手写

## 八、失败降级链（三级，不许断）

```
claude
  ↓ 失败（超时 / 429 / 5xx / 无 key）
kimi  ->  deepseek            （免费/低成本替代）
  ↓ 失败
内置规则引擎                    （确定性答复：卡点自查清单 / 判据模板 / 拒绝并回报）
```

- 每跳落 `llm_advise_fallback(from, to, reason)`
- **全挂不静默**：返回 `{ok: False, degraded: "rule_engine", advice: <确定性答复>}`，并在总线发 `error` 事件
- 降级链**不跨域**：`security` 域的拒绝结论绝不因降级被"重新解释"
