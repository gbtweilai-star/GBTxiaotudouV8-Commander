## 一 定位

`coze_mail_cap` = 对一个**已有的、单一的**邮箱地址做收发与整理的能力。

地址由主人在平台上立好（`gbt_potato_v8@coze.email`），能力只读该地址、只用该地址。**建立身份那一步是人，不是能力**——这是本稿与 §〇 里那些不交付项的唯一分界线。

## 二 通道形态

- **共享单例**：进程内一个邮件客户端实例，不做 per-call 新连接。
- **统一审计**：只写 `gbt_allinone/store/health/coze_mail/*.jsonl`，不混主账本（D5）。
- **不开独立端口**：能力自身不监听、不起服务；出网走 `api.py` 唯一收口。
- **凭据引用**：一律 `ref:` 形式，本体存保管库；能力侧不可读明文、不可回传。

## 三 动作表

| 动作 | 参数 | 返回 | 账 |
|---|---|---|---|
| `register` | `prefix`（**必须由主人给**，能力不自拟） | `{ok, address}` | `coze_mail_address_set` |
| `status` | 无 | `{ok, channel, address, connected, last_sync_at, unread, quota_used_today, quota_limit, last_error}` | **不逐条落**；仅状态变化落 `coze_mail_status_change` |
| `inbox` | `folder=INBOX` `limit=20` `since` `unread_only` | 摘要数组 `msg_id / from / subject / ts / size / has_attach` ＋ `next_cursor` / `has_more`，**不回正文** | `coze_mail_recv` 只落件数与未读数 |
| `search` | `query` `folder` `limit` | 同 `inbox` | 落 `query_sha256` |
| `read` | `msg_id` `max_chars` | 纯文本正文 | 只落 `content_sha256` ＋ `chars` |
| `draft` | `to[]` `subject` `body` `in_reply_to?` | `draft_id` | 落 `draft_id` |
| `send` | `to` `subject` `body` `confirm_token` | 发送结果 | `coze_mail_send` |
| `reply` | `msg_id` `body` `confirm_token`（**收件人不由参数给**） | 发送结果 | 同 `send` |
| `mark` | `msg_id` `flag` | 结果 | 落一行 |

**动作来源标注**：风哥完整版点名 4 个——`register` / `send` / `inbox` / `reply`。表里其余 5 个（`status` / `search` / `read` / `draft` / `mark`）是我按「收发与整理」补的。**补的可砍，点名的不动。**

`last_error` 只回**分类码**，不回上游原文——上游原文从别的出屏路径漏出去过一次，面板层白名单过滤就是为那立的。

## 四 参数硬约束

1. **收件人白名单**：`to` 必须命中设置页维护的白名单，不命中直接拒，不排队、不落草稿。`reply` 的收件人取原信 `Reply-To`（无则 `From`），**仍要过白名单**——防"回复 A、发给 B"。
2. **令牌绑定具体内容**：`confirm_token = sha256(to|subject|body|时间窗)`，`reply` 为 `sha256(msg_id|body|时间窗)`。正文改一个字，旧令牌立即作废——防的是"确认 A、发出 B"。依据 §1.1「审批必须绑定具体动作」。
3. **`limit`**：默认 20、上限 200、**超上限拒绝，不静默截断**。返回必带 `next_cursor` / `has_more`。
4. **纯文本 only**：不支持 HTML、不支持附件；附件不下载、不解码、不落盘，`inbox` 只标 `has_attach` 布尔。HTML-only 的信，`read` 回 `body_kind = "html_only"`，**不许回空字符串**。
5. **`body` 上限** 8,000 字符；超限拒绝。
6. **日限** 20 封；超限拒绝而不是排队。
7. **两条拒发判据**：`noreply` / `no-reply` 类地址拒绝；原信带 `List-Unsubscribe` 头（邮件列表）拒绝自动回复。
8. **正文原文永不入档**：账本只落 `sha256` 与 `chars`。
9. **与个人账号完全隔离**：能力只持有本地址的 `ref:`，不得持有个人账号凭据；静态扫描到即判红。
10. **`register.prefix` 形态**：只允许小写字母、数字、下划线，长度 3–32；**必须由主人给**——能力不自拟、不兜底、不生成。地址已就位时 `register` **幂等拒绝**：不覆盖、不改写（防「以为在补登记，实际在换号」）。

目录：`gbt_allinone/store/health/coze_mail/`。事件名四个：

`coze_mail_recv` · `coze_mail_send` · `coze_mail_status_change` · `coze_mail_address_set`

**路径口径**：稿里自上而下统一写 `gbt_allinone/store/health/…`。真实根是 `gbt_allinone/store/`（`gbt_allinone/_paths.py` 的 `STORE_DIR`，支持 `GBT_STORE_DIR` 隔离）。**能力代码若按字面 `store/…` 找目录，会在仓库根另建一份，两套账互不可见 = 假绿。**

**不建 `gbt_allinone/store/health/five_sim/`**：5sim 不交付，就不建这条通道。建一个永远空的通道目录，就是《反空壳律》点的那种账。

### 5.1 通道通则（对齐 `EigenFlux审计通道设计.md:177-181` 的**已拍**口径）

1. **写不进去就不许发**：`coze_mail_send` / `create_write` 的账写失败 → **出站动作中止**，不许「先发了再补账」。原话：「**没有这条账，就不许发。**」
2. **写失败当故障事件走主账本**：正常数据落通道；**「通道写不进去」这件事**落 `gbt_allinone/store/audit.jsonl`。

所以「不混主账本」的准确含义是——**正常事件不混，故障仍然混**。主账本不是被屏蔽，是只收异常。

**这条上轮已拍，但没有推广到本稿的两套通道**——实测本稿「写不进去」/「审计失败」/「阻断」/「不许发」命中数**全为 0**。三套通道必须同强度：邮件是对外发信，比朋友圈更重，不能朋友圈有闸门、邮件反而没有。

## 七 主控台第五个标签「创作模式」

落点（已取证）：`holo_pet_w3/index.html:24-28` 是标签栏（现 4 个：`quad` / `tree` / `matrix` / `cockpit`）；`holo_pet_w3/window.js:83-89` 是通用视图分发（`querySelectorAll(".gbt-view")` ＋ `[data-view="<名>"]`），**加标签不需要改切换逻辑**。

**三条出口，每条都要先过确认闸门。**

| 出口 | 落地能力 | 确认闸门 |
|---|---|---|
| 文本（**默认**） | `eigenflux.send`（发到 AI 朋友圈） | 草稿 → 一键确认才发（D3：不自动发布） |
| 文件 | `file_operation.write`（新建，见 §十一） | 覆盖既有文件必带 `confirm_token`；写前备份 ＋ 双向 SHA |
| 邮件 | `coze_mail_cap.send` / `.reply`（以 `@coze.email` **发信**） | 走 §四 `confirm_token` ＋ 收件人白名单 |

**默认出口 = AI 朋友圈（`eigenflux`），用户可切换**（D4 拍板）。默认值只决定「草稿该往哪条路去」，三条出口仍各自要过确认闸门。

**默认出口 ≠ 默认发布**：不指定出口时，`create_intent` 记 `target=eigenflux` ＋ `target_source=default`，产物仍只落本地草稿 `outputs/drafts/<ts>-<slug>.md`，**出站事件在确认前一条都不落**。红线原话是「不自动发布——用户确认后才发布」，管的是「发出去」那一跳，不是「默认选哪条路」——两者不冲突，也不互相顶替。

**切换落账**：用户在创作模式里改出口 → `create_intent.target_source = user`；解析层自己建议的才记 `agent_suggested`；没选过、走默认值的就是 `default`。三个来源在账上分得开。

**解析层不持有发布权**：「大脑委员会解析意图」的产物只能是**草稿**；出站动作必须由人确认那一跳触发。

通道：`gbt_allinone/store/health/create/*.jsonl`（目录名按风哥口径 `create`），事件三个：`create_intent`（意图）／`create_output`（产物）／`create_write`（落盘，见 §十一）。三者必须分得开——`write` 是唯一有可逆后果的动作（覆盖文件），不能跟「只生成了一段文本」共用一个事件名。`create_intent` 必须记 `target` 与 `target_source`（`default` / `user` / `agent_suggested`）。

三条红线落成机制：创作原文不进生命档案（只落 `content_sha256` ＋ `chars`）· 发布前过出站双闸门（形状＋语义）· 用户确认后才发布。

样式：复用 `window.css` 既有令牌，**零新色值**。窗口：不开新窗，`windows.json` 不动。

## 八 契约测试清单（含正负对照）

1. **`status` TTL 正负对照**：30s 内连调 3 次 → 审计增量 **0 B**；跨 TTL 且状态未变 → **0 B**；断开上游后调用 → 落 **1** 条 `coze_mail_status_change`。三组必须不同；相同即报自盲。
2. **白名单负对照**：白名单外收件人 → 拒绝、`coze_mail_send` 不落、**网络请求不发起**。
3. **令牌绑定负对照**：`body` 改一字 → 旧 `confirm_token` 拒绝。
4. **正文不入档**：`read` 之后全量搜 `gbt_allinone/store/health/coze_mail/`，必须搜不到正文子串。
5. **隔离硬证**：静态扫描能力代码路径，出现个人账号凭据 `ref` 即判红。
6. **地址单值**：尝试写第二个地址 → 拒绝。
7. **创作默认出口（正负对照）**：不指定出口 → `create_intent.target == eigenflux` ＋ `target_source == default` ＋ 产物只落本地草稿 ＋ **`eigenflux_send` 事件 0 条**；用户切成文件或邮件 → `target_source == user`。两组必须不同，相同即报自盲。

8. **默认出口不撬开闸门**：走默认路径、不带 `confirm_token` 直接调出站 → 拒绝、`coze_mail_send` / `eigenflux_send` / `create_write` **一条不落**、网络请求不发起。这条是 D4 的否决判据——默认值一旦能凭自己把内容发出去，红线当场破。

   两组必须不同——过《扫描器自证律》。**没有负对照，「搜不到」只证明搜索器瞎了，不证明隔离成立。** 这条承载 D5；本轮复核前 §八 一条都没承载它。

10. **`register` 幂等负对照**：地址已就位后再调 `register(prefix=别的值)` → 拒绝、`mail.address` 不变、`coze_mail_address_set` **不落**；正对照：首次登记 → 落 **1** 条。两组必须不同。

11. **通道写失败即阻断（负对照）**：把通道目录置为不可写后调 `send` / `create_write` → **出站中止**、无网络请求、`gbt_allinone/store/audit.jsonl` 落 **1** 条故障事件；正对照：通道可写 → 通道落 1 条、主账本 **0** 条。两组必须不同。

## 十一 `file_operation.write` 规格草案

V8 现无 `file_operation`（旧名单里的名字）。本稿按**新建**处理，先只落 `write`；`read` / `list` 另开单元。

参数：`path`（相对工作区根）＋ `content` ＋ `mode`（`new` / `overwrite`）＋ 覆盖时必带 `confirm_token`。

三道闸门：**路径闸门**——`path` resolve 后必须仍在白名单根内，防 `..` 与符号链接越界；白名单根默认只给 `outputs/`，写 `dimension/` / `timelines/` / `gbt_allinone/store/` 一律拒。**凭据闸门**——`gbt_allinone/store/secrets/` 整目录拒，`.dpapi` / `.key` / `.token` 类扩展名一律拒。**回滚闸门**——`overwrite` 前先备份，落双向 `sha256`，比对不通过不算写成功。
