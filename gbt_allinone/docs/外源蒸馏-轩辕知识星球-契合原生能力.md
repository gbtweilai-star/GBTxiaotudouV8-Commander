## 二、公开问答里**可迁移的方法论**（3 条，都是"怎么做"，不是"答案是什么"）

1. **不要为了学而学开源项目，要为了用它而学**：先设计自己的架构与各模块输入输出，
   再回头了解 Yara / ClamAV 这类件怎么装、怎么调、输出怎么用 ⇒ 先使用层，再整体架构，再核心模块源码。
2. **看源码要把核心函数调用链梳理成图**（他公开提到自己分享过 Cuckoo / Nginx 的调用关系全景图）：
   一是看图不迷路，二是复习时能快速捡起来。
3. **求职/转行的通用规律**：通用岗位（前端/测试/Java 后端）拼学历与标准化；**有特殊技术需求的岗位**
   供给少 ⇒ 只要你有那个具体的、不好招的技术点（例：熟 suricata 的 C++ 安全研发），学历劣势可被压过。
   —— 一句话：**先回答"企业为什么非要招你"**。

## 四、由这份对齐得出的**四条可执行缺口**（按价值排序，不夹带）

1. **媒体链缺"生成步"**：三方向目前是"人写输入 → 实现器合成"，**没有**"配音/生图/视觉检查"这三个生成类步。
   这正是他们 Day4 的内容，也是我们**唯一一条结构性的缺**。
2. **没有视频预览**：他们有 Day6 的预览；我们的 `media-console` 只有音频试听台。
   而视频是嵌不了的（宿主 12 MB 单文件上限，见 `host.js`）⇒ 只能做**引用式预览**
   （播放器指向 `projects/**` 的成品，或抽帧留影）。
3. **没有"视频制作 Agent"专用 preset**：机制齐（preset + 技能根 + 工具位），缺一支**组装好的**。
4. **调用链全景图**（他们第 2 条方法论）我们**已经有**：`brain.html` 三维排布 + 连接网络
   （结构从 `brain_exec.py` 的 AST 现算，源码里查不到的边不画）。⇒ 这条**不用补**。
