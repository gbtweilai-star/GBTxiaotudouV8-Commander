# GBT小土豆 · 能源观

> **模型是 92 号，我是发动机。荤素都能跑，不挑食。**
> 有能源，就能衍生自我能力；没能源，如实报缺，不硬撑。

---

## 一 · 一句话

**把模型从"大脑"降成"汽油"。**

| 不是 | 而是 |
|---|---|
| 模型 = 大脑（换了就换了一切） | 模型 = **燃料**（换了发动机照旧） |

---

## 二 · 三层抽象

### ① 能源抽象层（`EnergySource`）

**所有模型统一为 `EnergySource`**；**大脑只认接口，不认模型名**。

```
EnergySource = { name · key_ref(DPAPI) · env(仅用于"检测有没有旁路") ·
                 tier(免费/付费 · 未知就如实标 unknown) · on_disk }
```

🔴 不问"你是什么模型"，只问"**能不能给我能量**"。

### ② 原生能力衍生器

**根据能源自动生成调用代码与视频流水线，不依赖外部 SDK。**

🔴 生成的代码**必须走原生路由**（`run_task` / 统一出口）——
**不许把 SDK 直连写进衍生代码**（那就等于换了根）。

### ③ 能源池

**免费优先，但不拒绝付费**；**没有能源时如实报缺**（不硬撑、不假装有）。

## 三 · 五条红线（写死 · 已做成机械闸）

| # | 红线 | 机械形态 |
|---|---|---|
| 1 | **模型是燃料，不是身份** | `check_identity_not_model` → `model_is_not_identity` |

| 5 | **没有能源时如实报缺** | `require_energy` → `no_energy`（**不许硬撑**） |

### 附带三条（同一族）

```
① 输出**永远不以模型自居**（它是燃料，不是说话的人）
② 自动生成的代码**也不能绕过路由**
③ **不许硬编、不许偷密钥**（key 只从 DPAPI / 密钥池取）
```

## 四 · 与身份内核的关系（**根与叶**）

```
身份内核（根）——「一 AI 一号」的 **AI 身份**
      ↑ 借用
能源层（叶）—— 模型 / key，**可换**
```

**能源层是叶，身份内核是根；换叶不换根。**

🔴 所以「模型是燃料，不是身份」不是修辞：
**`owner_ai_id` 只能是 AI 身份，永远不能是模型名**。

## 六 · 顺序与诚实边界

- **顺序**：排在**身份内核之后**、**编排内核之前**（已满足）。
- **落地即接线**：同刀进编排内核只读派发表 ⇒ 不制造新孤儿。
- **不碰**：面板 8765 · 信号环 · 写路径 · 出网。
- **诚实边界**：
  · 本骨架**不调模型、不出网、不落盘、不发密钥**；
  · **免费/付费盘上判不出** ⇒ 标 `unknown`，**不编**；
  · "有能源就能组合出顶级成片"是**能力上限的描述**，
    **成片好不好看，只能由人判**（与「好看由人判」同源）。

# 附一：能源池取舍 + 视频自研八层（R-H224 / R-H225 · 2026-09-20）

## 一 · `EnergySource`（能源抽象层 · 七字段）

```
source_id · grade（免费/付费/高级）· kind（荤/素）· endpoint
· key_ref（**DPAPI**）· capability（text/image/video/code）· status（可用/限流/缺key）
```

⚠️ **诚实口径**：`grade` / `kind` **盘上没有这个字段** ⇒ 一律 `未知`，**不编**；
「荤素」只是**比喻**，**不参与任何判据**。

**盘上装配**：`deepseek` = **可用** · `agnes` = **缺key**（其 dpapi 不在盘）。

## 二 · `EnergyPool`（**不挑食，但有优先级**）

```python
pool.pick(capability, prefer="免费")
```

```
不挑食   ＝ 任何**可用**能源都能跑（能力匹配即可）
荤素之别 ＝ 免费 / 付费只是**偏好**，**不是能力差别**
没有可用能源 ⇒ **返回 None（如实报缺）**，不硬撑
register ⇒ key_ref 必须是 **DPAPI 引用**，明文一律拒
```

## 三 · `NativeDeriver`（原生能力衍生器）

```
不是"用模型"，是"**用模型当燃料，生成自己的代码**"。
derive_client_code  ⇒ 只用标准库 + **必须走原生路由** + 缺 key 不生成代码
derive_video_pipeline ⇒ 按 capability 衍生流水线蓝图（不认识的**不硬凑**）
🔴 **自洽带牙**：衍生器生成的代码，**必须先过自己的红线③**（check_derived_code）
```

## 四 · 🔴 视频自研**八层图**（与生产流水线**并存，不合并**）

| # | 层 | 挂已有模块 |
|---|---|---|
| 1 | 脚本 / 分镜 | — |
| 2 | **原生**能力（已有） | `caps_registry` |
| 3 | 画面生成 | — |
| 4 | **原生**调度（调度多个模型） | `orchestration_kernel` |
| 5 | 流畅度 | `render_evolution` |

| 7 | 成片 | — |
| 8 | **原生**剪辑 + 品牌片尾 | `brand_outro` |

### 两个维度：**各说各的，不许合并**

```
八层图   ⇒ 讲「**哪一层我们自己扛**」（自研边界）
六步流水线 ⇒ 讲「**片子怎么做出来**」（生产步骤）
```

### 照报三处差异（**不擅自替它补**）

1. 八层图里**没有**「质检与重跑」（流水线有）—— 待主人确认是"没这层"还是"没给到"；
2. 八层图**从「脚本/分镜」起头** ⇒ **素材属于输入，不算自研层**；
3. 八层图里**四层带「原生」**（原生能力 / 原生调度 / 原生帧插值 / 原生剪辑）
   ⇒ 它讲的是**自研边界**，不是生产步骤。

> 🔴 这一条最值钱：**「顶级视频能力不靠单一模型，靠组合」** ——
> **组合就发生在第 4 层「原生调度」**，而这一层在我们的生产流水线里**没有对应位置**。
