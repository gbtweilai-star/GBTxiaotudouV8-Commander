## 二、三条链的源码级触网判定

### 1. `_run_fallback`（panel_server.py:699-719）——结构上不可达

- `:700` `_ensure_fallback()` → `:163` `if self._chat is None and ChatClient is not None:` —— 探针把 `PS.ChatClient` 置 `None`，`_chat` 恒为 `None`。
- `:701-704` `if self._chat is None:` → 播报"Codex 与外部 LLM 均不可用"后 `return`，**提前返回**。
- `:716` `self._chat.send(text, ...)` 是唯一外发点，被 `:701` 挡死。
- **实证**：事件总线原文 `{"type": "activity", "text": "Codex 与外部 LLM 均不可用"}` —— 降级链确实走到了封死分支，且没有外发。

### 2. `quick` / 路由出口（panel_server.py:898-958）——出口哑化

- `:947` `result = api.run_task(kind, request)` 是 `quick` 唯一的执行出口。
- 探针把 `PS.api.run_task` 换成 `_dummy_run_task`：只写账本、返回 `{"probe": true, "not_executed": true}`，**不执行任何真实能力**。
- **实证**：C 层 1 行（`kind="mind"`，`route_to="api.run_task"`）。

### 3. `interrupt`（panel_server.py:877-888）——走 stdio 管道，不经网络

- `:885` `server.interrupt(thread_id, turn_id)` → 桥 `_write`(`codex_bridge.py:285`) → 自建实例的 Popen stdin。
- 该 Popen 的 argv 被探针强制为 `[sys.executable, mock_v2_server.py]`，是**本地 stdio 子进程**，非网络对端。

### 4. HTTP 服务（panel_server.py:1128-1160）——从未构造

- `:1131` `ThreadingHTTPServer((host, int(port)), _Handler)` 只被 `:1137 main()` 调用；`main()` 只在 `:1160 if __name__ == "__main__":` 下触发。
- 探针以 `spec_from_file_location` + `exec_module` 装载面板模块，**未调用 `main()` / `run()`**。
- 层1 卫兵把 `ThreadingHTTPServer` 也换成了会抛异常的守卫：若真被构造会当场暴露 —— 实测构造 0 次。

**判定：三条链 + HTTP 服务，全部不触网。**

## 六、如实报告：两个小插曲

1. **`panel_probe.py` 语法错**：`except Exception:` 悬空 —— 写文件时 `try:` 整行丢失，且 `ledger(...)`
   首行缩进未比 `try:` 深。已补 `try:` 并把该行缩进 +4；括号内续行不受缩进约束。`PARSE_OK` 复验通过。
2. **第一次 netguard 运行缺后置账本**：根因是 `panel_probe.py:334 sys.exit(0 if allok else 1)`
   —— 探针**自带退出码**，`runpy` 把 `SystemExit` 传播出来，跳过了 netguard 的打印段。
   已加 `except BaseException` 兜住。**`exit=0` 本身即 PASS 的第二个独立凭证。**
   另：`Start-Process -FilePath "py"` 撞上 PowerShell 的 `Path`/`PATH` 环境字典冲突 bug，
   改为 `cmd /c` 直跑；由此产生的空转 shell（PID 20884）已 `Stop-Process` 清除，宿主复检干净。
