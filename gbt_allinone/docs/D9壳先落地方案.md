## §0 一句话结论 + 三条待拍

**结论：「壳先落地」今天卡在一个真空上——没有任何一条通道把维度产物送到工作区根。**

现有镜像四件套 `shape` / `scan` / `ascend` / `rewind` **只写 `mirror_space/` 内部**。
`ascend()` 的实测动作是 `shutil.rmtree(_REALITY)` + `shutil.copytree(_DIM, _REALITY)`
（`gbt_allinone/mirror_space.py:167-169`）——**它不碰工作区根**。
所以 **D9 不是"再跑一次 ascend"，而是"定义并使用一条新通道"**。这一步不说清，落地就会变成"以为跑过 ascend 了"的假绿。

出稿时我把「维度树」与「壳」说成了一个数。逐项拆开后的准确事实：

| 对象 | 文件 | 字节 | 备注 |
|---|---|---|---|
| 整棵 `mirror_space/dimension/` | **14** | **88,008** | 出稿时我写的"14 文件 / 88,008 B"指的是**这个** |

`reality/` 侧逐项同构（整树 14 / 88,008 · 壳 11 / 74,336 · w25 3 / 13,672）。
**「14」是维度树，「11」是壳**——数字本身都真，是我出稿时把两者混成了一个数。

**另一条口径说明**：本稿前一份报告写的维度指纹 `2d45b70bcf0e4cd7` 与本轮脚本算出的

**两个数字不可直接比较**。可比的是：文件数 **14**、总字节 **88,008**、`dimension == reality` = `True`——
三项与出稿时逐条一致，**说明期间零漂移**。

## §2 "落地"的准确定义（和"晋升"不是一回事）

| 动作 | 通道 | 写哪里 | 本刀要不要 |
|---|---|---|---|
| 晋升 `ascend()` | **既有** | `mirror_space/reality/` + `timelines/vN` + `passports/vN.json` | 只在**维度内容变更时**用（见 §5 待拍 ③） |
| **落地**（本稿新定义） | **新立** | **工作区根 `holo_pet_w3/`** | **本刀核心动作** |

**落地四条硬判据（缺一不可）**：

1. **源** = `mirror_space/dimension/holo_pet_w3/`（**权威源**，见 §4）；
2. **目标非空即拒绝** —— 不许覆盖已有目录（覆盖 = 无法回退的破坏，且会把"部分成功"藏起来）；
3. **逐文件 SHA256 对照** —— 落地后 11 个文件的 `{路径, sha256, size}` 与源清单**逐条相等**；
   不等即判失败，且**不删目标**（留现场给人看，不许自动回滚掩盖）；
4. **留证据** —— 清单落 `.scratch/`，并向**主账本**写一条落地审计（这是生产写动作，属"账"不属"数据"）。

## §4 落地后的三副本与漂移（待拍 ② · 这是 O23 同型风险）

落地之后 `holo_pet_w3/` 会有**三份**：`dimension/` · `reality/` · **工作区根**。
**今天 O23 刚抓过"两份副本开始漂移"**（`llm/cloud_llm.py` 对 `gbt_allinone/llm/cloud_llm.py`）——
社交域窗口不许重演同一个坑。

**口径提案**：

- **权威源 = `mirror_space/dimension/`**：唯一允许写入的口；
- **落地副本（工作区根）= 只读**：只许由落地动作**整棵替换**，**不许手改**；
- **改内容一律走链**：改维度 → `scan()` 全绿 → `ascend()` → 落地；**不许直接改工作区根那一份**；
- **漂移判据**：工作区根 `holo_pet_w3/` 逐文件 SHA 对照维度清单，不等即报"漂移"；
- **漂移检测落哪**：甲 = 进 `mirror_status()`（现成函数）；乙 = `.scratch/` 探针 + `PROJECT_BLUEPRINT.md` 观察项。
  **倾向乙**——`mirror_status()` 属生产核心，本轮不扩它的语义。

## §5 起动命令口径（含 README 实测错误 · 待拍 ③）

**实测可用形态**（从工作区根跑一条命令）：

```powershell
holo_pet\node_modules\electron\dist\electron.exe holo_pet_w3\shell\main.cjs
```

理由（§1 条 10）：壳只 `require("electron")` 与 node 内置模块 → **不需要 `holo_pet_w3/node_modules`**；

W3 README 现写的 `node_modules/electron/dist/electron.exe holo_pet_w3/shell/main.cjs` 是**错命令**（两个路径今天都不存在）。
修它 = **改维度内容** → 要走 `shape()` + `scan()` + `ascend()`。
**这是本刀唯一一处"改内容"的动作，请单独拍**（不拍就只落地、不改 README，落地后我如实报"文档命令仍是错的"）。
