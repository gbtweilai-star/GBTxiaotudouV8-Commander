## 零、一句话

**长程无人值守不是"让它自己跑"，是"每一段都有人复核，只是复核的不是人，是清醒副驾"。**

它**只对抗一件事**：**我跑长线会因上下文压缩而健忘、偏离、出错**。这一件事有三个表现——

| 同一根因的表现 | 长什么样 | 谁防它 |
|---|---|---|
| **错误累积** | 每一步都只偏一点点，十步后偏出目标 | 阶段审查（每阶段结束强制） |
| **局部死循环** | 同一个坑反复踩，越试越深 | 卡点会诊（同一问题失败 ≥ 2 次必调） |
| **上下文压缩导致的遗忘** | 早上定的红线，下午就"想不起来" | 清醒镜（每阶段开始必调） |

三个表现对应三个作用、三道闸，**根因只有一个**——这是为什么这套机制必须三件一起上，缺一件就漏一种偏离。

**另有一个触发源：犯困（资源紧张）。** 它不改变偏离的形态，但会让我**想走捷径**（少验一次、跳过一轮审查、
把"没验"写成"验过了"）——所以本协议单列一条降载纪律（§6.2）。

## 一、阶段与检查点

### 1.1 阶段：**不是时间切分，是目标切分**

| 项 | 规格 |
|---|---|
| **阶段** | 一个**可独立验收**的工作单元——有明确的输入、产物、验收判据 |
| **切分依据** | **目标**（不是工时，也不是"跑满 N 分钟"）——一个阶段 = **一个明确、可验证的目标** |
| `phase_id` | 形如 `P<任务号>-<序号>`（例 `P07-03`）；**贯穿本阶段所有审计事件** |
| 阶段边界 | 由**我**划；**不许由克劳德划**（它只审、不划） |
| 阶段记录 | `phase_id` · `goal` · `started_at` · `ended_at` · `artifacts[]` · **`checkpoint`** · `verdict` |

**阶段结束 = 三件事同时成立（缺一个就不算结束）**：

```
① 目标达成   —— 不是"差不多达成了"
② 验证通过   —— 我这侧的判据 + 证据（含反假绿对照），不是"看着像对"
③ 快照落盘   —— 上帝视角快照 + 本阶段检查点（见 1.2）
```

> **为什么强调"目标切分"**：按时间切分会让"到点了"变成推进的理由——
> 时间到了、目标没到，却照样换阶段，把"没验"当"验过了"。**这正是假绿的温床。**
> 一根轴是**目标**，时间只是**上限**（见 §6.3 限时）。

**划阶段的原则**：一个阶段**只解决一件事**，且"做完了没有"能用判据回答（不是"差不多做完了"）。

### 1.2 检查点与回滚（**每阶段一个**）

| 项 | 规格 |
|---|---|
| **打点时机** | 每个阶段**开始之前**打一个检查点（**不是结束后**——结束后再打，出错时已经来不及） |
| **检查点内容** | ① **维度快照**（`store/mirror_space/dimension/`）② **reality 快照**（`store/mirror_space/reality/`）③ **时间线版本号**（`timelines/v<N>` + `passports/v<N>.json`） |
| **出错处置** | **自动回滚到最近检查点 → 停手报人**（不许"先修修看再说"） |
| **回滚原语（现成）** | `mirror_space.rewind(version)` 全量回滚（`mirror_space.py:250`）；`ascend()` 晋升时自动留 `timelines/vN` + `passports/vN.json`（`:167-188`） |

> **诚实缺口（不许假装已有）**：仓库现有的检查点语义是**晋升级**——只有 `ascend()` 才会产出
> `timelines/vN` 与护照，**没有阶段级快照机制**。所以本节"每阶段一个检查点"目前是**设计目标**，
> 落地属施工项（见 §十 待裁）。在阶段级机制建好之前：
> **无人值守只能跑在"已有回滚点覆盖"的范围内；覆盖不到的阶段，不许无人值守。**

## 二、每个阶段必做四件事（顺序固定）

```text
① 阶段开始 → 调清醒镜（读宪法 + 判例摘要卡 + 快照）→ 拿到"本阶段红线提示"
        ↓
② 干活（串行、无并发、跑完即停）
        ↓
③ 我这侧验证 + 落快照 + 报状态（验证通不过 → 不许进第 ④ 步）
        ↓
④ 调克劳德做阶段审查（强制）→ 通过 / 警告 / 停手
        ↓
   通过 → 下一阶段｜警告 → 修正后重试本阶段｜停手 → 熔断，报人
```

**纪律**：③ 的"验证"是**我这侧的**（判据 + 证据 + 反假绿对照），**不许拿克劳德的意见当验证**。
它的结论是**输入**，不是**判据**（《克劳德精细设计》§十一 红线 2）。

## 三、阶段审查（**强制，不是可选**）

### 3.1 送什么

| 送 | 不送 |
|---|---|
| 本阶段 `goal`（一句话目标） | 生命档案原文 · `USER.md` / `MEMORY.md` |
| 本阶段产物清单 + 验证结论（判据与证据摘要） | 密钥 / 令牌 / 完整路径里的用户名 |
| **上帝视角快照**（同一份 `hash`，零凭据） | 我的完整推理链与内心戏 |
| **判例摘要卡**（见 §五.2） | 判例原文 |

### 3.2 审查什么（它必须回答的三问）

1. 这个阶段**有没有偏离目标**？
2. 有没有**踩之前的判例**？
3. 有没有**引入未验证的假设**？

### 3.3 三种结论 → 三个动作（**结论必须落到这三个之一，不许"还行吧"**）

| 结论 | 动作 | 审计 |
|---|---|---|
| **通过** | 进入下一阶段 | `external_advice{phase_id, verdict, adopted, reason, snapshot_hash}` |
| **警告** | **修正后重试本阶段**（不推进） | 同上（`verdict="partial"`/`rejected`，`adopted` 按实际，**`reason` 必填**） |
| **停手** | **熔断，报人**（这是"阶段审查作为熔断前置"的全部含义） | 同上 + 熔断事件（§6.1） |

**审计字段口径（风哥 2026-09-17 给定）**：阶段审查的结论一律写 `external_advice`，**必带 `phase_id` + `verdict` + `adopted`**；
字段定义与"`verdict` 与 `adopted` 不许互相顶替"见《克劳德精细设计》§5.1 / §5.4。

### 3.4 缺审怎么办（**不许假绿**）

```
没审 ≠ 审过了
配额耗尽 / 通道挂 / 快照挂 → 记 phase_review_skipped（显式、带原因码）
                          → 阶段**不推进**：要么等（通道恢复/配额窗口重置），要么熔断报人
```

**绝不允许**："审查没做成，那就先往下跑"——这等于把这套机制的核心环节静默摘掉。

## 四、卡点会诊（**卡点必调**）

### 4.1 卡点的定义（可判定的，不靠感觉）

```
同一问题失败 ≥ 2 次 → 判定为卡点 → 必调会诊
（"同一问题"以现象指纹判定：同一判据、同一报错族、同一模块）
```

### 4.2 它输出什么

| 输出 | 含义 |
|---|---|
| **给新方向** | 换一条它认为可行的路径（只给方向，**不落刀**） |
| **指盲区** | 指出我反复失败的原因是我没看到的东西 |
| **直接说"这不是卡点，是你判断错了"** | 最值钱的一种——把"死循环"定性成"方向错" |

### 4.3 纪律

- 会诊**不打断**当前串行流程：卡点定住后**停手**再去问，不许边跑边问。
- 会诊结论落**两条**审计：`external_advice`（`task_type="advisory"`，`phase_id` 照填）+ **`consultation`**
  （一次会诊一条，含共用 `snapshot_hash`、`participants`、`degraded_to`；字段规格见《克劳德精细设计》§10.3）。
- **它给的方案不许直接执行**——落刀仍走我这侧的验证链（镜像 → 探针 → 报 Owner）。

## 五、清醒镜（**每个阶段开始必调**）

### 5.1 它回答的问题

> "你现在的操作在 **X 判例**上允许，但 **Y 判例**要求审批。"

**输出格式固定为三问（风哥 2026-09-17 给定）**：

| # | 输出 | 内容 |
|---|---|---|
| ① | **当前阶段允许做什么** | 白名单：本阶段可以自主推进的动作 |
| ② | **需要审批什么** | 灰名单：要 Owner 点头的动作（**逐条列出**，不许含糊成"敏感操作要审批"） |
| ③ | **禁止什么** | 黑名单：本阶段一律不做（域黑名单 + 禁止自动化清单 + 当前判例的硬禁） |

它不替我决策，**让我在长程任务里始终记得自己是谁**。
**定位**：这是**对抗"上下文压缩导致忘红线"的前置机制**——阶段一开始就把红线摆出来，而不是踩到了才回头查。

### 5.2 判例摘要卡（**独立读，不读原文**）

| 字段 | 说明 |
|---|---|
| `case_name` | 判例名（如《空不等于不存在律》/《版本号字符串序陷阱》） |
| `one_line` | 一句话结论 |
| `scope` | 适用范围（什么时候适用 / 什么时候不适用） |
| `requires_approval` | **是否要求 Owner 审批**（布尔） |
| `source_ref` | 内部指向（**只放标识，不放档案正文**） |

**冲突登记**：风哥 2026-09-17 指名清醒镜读「宪法 + 判例库」，
而《克劳德精细设计》§3.2 硬禁 `CHARTER.md` **全文**与 `memory/` **全文**出站。
**我的建议（待 Owner 裁决）**：**不送全文，送判例摘要卡**——红线口径一致，档案原文不出本机。

## 六、熔断、限时与报人

### 6.1 异常熔断（触发条件 · 九条）

| # | 触发族 | 具体条件 | 处置 |
|---|---|---|---|
| 1 | **探针报红** | 探针在巡检周期内**上报了，且报错** | 自动停 |
| 2 | **资源超阈值** | 内存 **> 90%** 或 磁盘 **< 1 GB** | 自动停 |
| 3 | **外部依赖失败** | Agnes / DeepSeek / Cloudflare / 飞书 不可用 | 自动停 |
| 4 | **阶段审查报"停手"** | 克劳德审查结论 = 停手 | 自动停（阶段审查 = 熔断前置） |
| 5 | 卡点会诊后仍失败 ≥ 2 次 | 会诊给出方向但仍走不通 | 熔断报人（不许"再试一次看看"） |
| 6 | 配额耗尽且审查无法完成 | 阶段审查做不了 | **停手报人**（不是跳过审查） |
| 7 | 命中禁止自动化清单 | `PROJECT_BLUEPRINT.md` §1.3：支付 / 实名 / 绑卡 / 注销 / 提权 / 破坏性删除 | **无条件熔断** |
| 8 | 越权迹象实执级 | `advice_scope_violation` 的 `sealed` 档 | 封通道 + `P0` + 报人（《克劳德精细设计》§10.5） |
| **9** | **探针报灰**（风哥 2026-09-17 补录 · 第九条） | 任何探针在巡检周期内**未上报**（不是报错，是**没报**）→ 视为灰 | 自动停 |

**统一处置**：**自动停 + 报警 + 等人工确认**。**不许硬撑。**

> **第 9 条单独成条的理由**（风哥原话）：无人值守下，**"没消息"和"坏消息"在"能不能继续"这个问题上答案相同**。
> 第 1 条管的是"报了，且是坏的"；第 9 条管的是"压根没报"——**两条的判据不同，所以不许合并成一条**。
> 这也是《假绿铁律》在无人值守里的形态：灰 = **不确定** = **不能继续**。

> **一处不对称，显式说明**：克劳德是**审查者**，它自己挂掉**不属于第 3 条**——
> 它挂了不立刻熔断报警，而是**阶段不推进 + 落 `external_advice_unavailable` 审计 + 降级为 Owner 报批**（§九）；
> **但 Owner 在 N 分钟内未响应 → 升级为熔断报警**（风哥 2026-09-17 加的一层）：
> **主驾可以短暂单飞，不能无限期单飞。**

**报人格式**（升级包）：`phase_id` + 卡在哪 + **试过什么** + 判据与证据 + 待 Owner 拍的具体选项（2~3 个，带代价）。

### 6.2 犯困纪律（资源紧张 · 降载不降标准）

| 允许 | 不许 |
|---|---|
| **少做**——砍阶段数量、拉长阶段间隔、把大阶段拆小 | 跳过验证 |
| **慢做**——等配额窗口重置、等通道恢复 | 跳过阶段审查 |
| **停下来**——直接熔断报人，说清"顶不住了" | 把"没验"说成"验过了"（假绿） |
| **把复核外移**——多调清醒镜/会诊，把判断负担挪给副驾 | 因为赶进度而降低判据标准 |

**一句话**：**资源紧张时降的是产出速度，不是判据高度。** 判据一旦降下来，前面所有阶段的账就都作废了。

### 6.3 限时与汇报（无人值守的两个时间闸 · 风哥 2026-09-17 给定）

| 项 | 规格 |
|---|---|
| **限时** | 无人值守**默认 2 小时**（可配）；**到点自动停**——不管阶段跑完没跑完 |
| **限时的性质** | 它是**上限**，不是进度条：到点停 = 收工报人，**不是**"赶紧把没验的验成验过" |
| **心跳汇报** | **每 N 分钟**往**指定通道**汇报一次，内容三样：**我还活着** + **当前阶段**（`phase_id` + 目标） + **异常**（有就写，没有也写"无"） |
| **断报即异常** | 超过 `2N` 分钟没收到汇报 = 视为**失联**→ 按 §6.1 处置（自动停 + 报警 + 等人工确认） |

**为什么要有心跳**：无人值守时，"它还在跑"和"它已经死了"在外部看起来是一样的——
**没有心跳，就没法区分这两者**（同族于《空不等于不存在律》：读不到 ≠ 没事）。

**已拍口径（风哥 2026-09-17）**：`N` = **10 分钟**（`2N` = **20 分钟**未报即判失联）；
**主通道 = 本地审计文件**（零外部依赖）；**飞书 / 手机推送是"可选二次通知"，不是必需通道**——
外部依赖挂了不能影响协议本体。

| `external_advice` | `phase_id` · `verdict` · **`adopted`（布尔）** · `reason` · `snapshot_hash`（定义见《克劳德精细设计》§5.1） |
| `phase_review_skipped` | `phase_id` · `reason_code`（`quota_exhausted` / `channel_down` / `snapshot_down`） |
| 卡点事件 | `phase_id` · `problem_fingerprint` · `fail_count` · `consultation_id` |
| 熔断事件（§6.1） | `phase_id` · **`trigger_family`**（`probe` / `resource` / `dependency` / `review_stop` / `loop` / `quota` / `forbidden` / `scope`） · `trigger` · `evidence_path` · `reported_at` |
| **心跳汇报**（§6.3） | `phase_id` · `channel` · `alive`（布尔） · `abnormal`（无则写 `none`，**不许留空**） · `sent_at` |

**四条粒度纪律**：① 没有 `phase_id` 的审查不算阶段审查；② `adopted` 与 `verdict` 不许互相顶替（《克劳德精细设计》§5.4）；
③ **缺审必须显式记账**，不许留空、不许"默认通过"。**第四条**：心跳汇报里的 `abnormal` 一栏**无异常也要写 `none`**——
留空会被读成"没报"，那是《空不等于不存在律》要防的假阴。

## 十二、红线

- **无人值守 ≠ 无边界自治**（风哥 2026-09-17 · 第一条）：能在无人看管下跑的，**只有**已被授权、且回滚点覆盖的动作；
  边界之外一律停手报人，**"没人看着"不是扩权的理由**。
- **不许跳过检查点**（风哥 2026-09-17 · 第二条）：每阶段一个检查点，出错回滚到最近检查点再报人；
  **没打点的阶段退回上一检查点**——不许"继续往前跑，出事再说"。
- **不许在探针灰 / 红时继续**（风哥 2026-09-17 · 第三条）：探针报红停，报**灰也停**——
  "没人看着"与"看着它坏了"在能不能继续跑这个问题上答案相同。
- **克劳德只给意见，不做决定**；它不进决策链。
- **不许假绿**：缺审记 `phase_review_skipped`，**不许默认通过**；通道挂显示灰，不许显示绿。
- **不许把它的方案直接落刀**——落刀走我这侧验证链（镜像 → 探针 → 报 Owner）。
- **它只通过上帝视角快照看全局**（《克劳德精细设计》§十一 新增第五条）。
- **它不碰密钥**；判例摘要卡零凭据、零档案原文。
- **命中禁止自动化清单 → 无条件熔断报人**。
- **无人值守期间不许动宿主键鼠 / 不许抢焦点**。
- **串行、无并发、跑完即停**。
