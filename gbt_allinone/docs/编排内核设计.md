## 一、三源蒸馏：每个框架贡献一个原语

**榜单与口径（Owner 2026-09-19 口述 · 出处记在这里）**：

| 排名 | 框架 | Stars | Pulse Score | 归入编排类的理由 |
|---|---|---|---|---|
| 1 | **BrowserUse** | **114k**（口述） | **90.0** | 浏览器自动化 + Agent 循环，核心是"状态空间 + 动作空间" |
| 2 | **CrewAI** | **58.3k**（口述） | **81.7** | 多角色协作 + 流程状态机 |
| 3 | **Mastra** | **27.9k**（口述） | **78.8** | TS 原生 + 可持久化声明式工作流 |

> **Stars 列按"有数才填"（现已三家齐）**：BrowserUse **114k** · CrewAI **58.3k** · Mastra **27.9k**
> —— **全部为口述（`owner-claim-20260919` · 未联网核实）**，不是抓来的读数。
> **一条不许混读**：**Stars 是"多少人收藏"，Pulse 是"综合健康度"，两者都不等于"同类"、更不等于"适配我们"**
> （OpenClaw 386k+ 却不算编排框架，就是这条的现场反例）。

> **Pulse Score** 是 `ai-agent-pulse` 的实时综合分（**星速 + 提交活跃度 + 社区健康度**等）。
> **一条归类的判断**：**OpenClaw 星数更高（386k+），但定位是"个人 AI 助理"而非"编排框架"，故未归入编排类。**
> ⇒ 口径差异要在出处里写明：**"热度高" ≠ "同类"**（同 §3 三条口径的精神：每一栏都别替下一栏背书）。

| 框架 | 核心哲学 | 贡献的原语 |
|---|---|---|
| **BrowserUse** | **不抽象，最大化动作空间**（创始人原话：发过几千行元素提取器/DOM 索引器/点击包装器，后来全删了——**封装越多，LLM 能发挥的空间越小**） | **状态空间**（看到什么，DOM→可交互元素有序列表）+ **动作空间**（click/type/scroll/extract_text） |
| **CrewAI** | **角色扮演 + 流程优先**（独立跑 Crew 是原型，**封装进 Flow 才是生产**） | **角色工作组**（Role / Goal / Backstory）+ **流程状态机**（Flow：条件分支 / 循环 / 状态持久化） |
| **Mastra** | **TypeScript 原生 + 可持久化声明式工作流** | **可存储图**（`toStorableGraph()` / `rehydrateWorkflow()`）+ **挂起恢复**（任意步骤挂起，从挂起点精确继续） |

**Mastra 那条最值得记**：**工作流本身就是数据**——可被 UI 或 LLM 动态生成，然后被引擎执行。
⇒ 它**可以被讨论**，而不只是被编码。

## 三、落刀要点（Owner 定）

1. **优先接入顺序（核实后修正：三件 → 两件 + 一格半）**：
   **① 步骤级挂起/恢复**（不是从零做：把已有的 `engine.resume_run()` **从 run 级扩到节点级**——

   ~~可存储图~~ ⇒ ✅ **已有**（`store/workflows.json` + `wf_runs/`），**不新建**。

3. **工作流是数据**：图要能序列化成 JSON（可被讨论、可被动态生成），但**执行仍由引擎 + 门禁决定**。
