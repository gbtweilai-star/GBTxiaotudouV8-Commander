# 代码画画艺术内核（Code Art Kernel）· R-H188 · 2026-09-20

> **五源蒸馏**：`awesome-creative-coding` + `algorithmic-art` + `p5.js` + `tldraw` + `HashLips`
> ⇒ **一条创作链**：`找工具 → 定种子 → 设画布 → 加图层 → 导出`，元数据回流（可复现、可追溯）。
> 灵魂仍是那一句：**作品不是为情绪做的，是为场景做的。**

---

## 一 · 五原语（缺一即开环）

| 项目 | 原语 | 一句话 |
|---|---|---|
| awesome-creative-coding | **INDEX**（索引） | 找什么——资源总目录 |
| algorithmic-art | **SEED**（种子） | 怎么复现——种子可控 |
| p5.js | **CANVAS**（画布） | 画在哪——创意编程母语 |
| tldraw | **LAYER**（图层） | 怎么拼——无限画布/交互 |
| HashLips | **EXPORT**（导出） | 给谁——批量产出带元数据 |

---

## 二 · 三层架构

| 层 | 原语 | 问什么 |
|---|---|---|
| **表达层** | INDEX + CANVAS | **看到什么**？（用什么工具 / 渲染在哪） |
| **生成层** | SEED + LAYER | **怎么画**？（同输入同输出 / 图层可组合可回退） |
| **交付层** | EXPORT | **给谁**？（单件 = 作品 · 批量 = 系列；每次导出带元数据） |

---

## 三 · 四条红线（写死 · 已做成机械闸）

| # | 红线 | 机械形态 |
|---|---|---|
| 1 | **无种子不许导出** | `export()` 检查 `work.seed`，无则 `reason="seed_missing"`（不可复现的作品等于不存在） |
| 2 | **图层只追加、不覆盖** | `add_layer()` 只 `append`；要改走 `rollback_layer()`（可逆） |
| 3 | **索引只读** | `index()` 只返回结构，**不写盘**；不许把索引当成第二份数据源 |
| 4 | **批量导出必带元数据** | `export(batch=True, meta=False)` ⇒ **拒绝**（谁生成的、什么参数、什么种子） |

## 五 · 顺序、边界与诚实边界

- **顺序**：排在**编排内核之后**。
- **不碰**：面板 8765 · 信号环 · 写路径 · 出网。
- **诚实边界（原样保留）**：

> 内核能保证"**可复现、可回退、可追元数据**"；
> 但它保证不了"**画得好不好看**"——**好看只有人看了才知道**。
> 这条和情感投射同族：**机器保证结构，人保证共鸣**。
