# 原生能力优先律（Native-First Law）· R-H199 · 2026-09-20

> **唯一固定不变的公理**：**模型可以换，原生能力不能换。**
> 换成 Agnes / GPT / Claude / DeepSeek —— 不管换谁，**默认执行路径永远是原生能力**。

---

## 一 · 根与叶

| 层 | 是否固定 | 说明 |
|---|---|---|
| **大脑（主机）** | ✅ **固定** | 纪律、门禁、审计、决策 —— 框架自己的 |
| **原生能力栈** | ✅ **固定** | 触手、路由、记忆、认知包 —— 与生俱来的 |
| **外部模型** | ❌ 可换 | **补认知**（推理 / 生成 / 判断），**不补执行** |
| **执行路径** | ✅ **固定** | **默认走原生**；外部模型只做"参谋" |

> **模型是"外脑"，原生能力是"神经系统"。外脑可以换，神经不能换。**
> **根不动，叶可换。根有短板，登记台账，循环打磨。叶换了，短板不会跑。**

---

## 二 · 为什么这条公理是命门

| 不钉死这条 | 钉死这条 |
|---|---|
| 换模型 = 换**整个执行路径** | 换模型 = 换一个"参谋"，**执行照旧** |
| 每个模型自带一套习惯 | **原生能力是唯一习惯** |
| 短板跟着模型变 | 短板跟着**原生能力**走，可追踪 |
| 进化分散在各模型里 | 进化**集中在原生能力**上 |

---

## 三 · 五条红线（写死 · 已做成机械闸）

| # | 红线 | 机械形态 |
|---|---|---|
| 1 | **默认走原生** | `route(task)` 第一站必是 `native`；外部模型角色恒为 `advisor`（除非任务显式 `cognition_only=True`） |
| 2 | **模型可换，栈不变** | `assert_stack_unchanged(before, after)`：切模型时触手 / 记忆 / 门禁 / 审计的**指纹必须逐项相同** |
| 3 | **外部模型只补认知** | `external_model_may(action)`：`execute` / `write_store` / `bypass_route` ⇒ **一律拒** |
| 4 | **原生能力必须持续打磨** | 短板必须**登记进台账**并绑定打磨任务；`gaps_ledger()` 不给空话只给条目 |
| 5 | **短板跟着原生能力走，不跟着模型走** | 台账条目的宿主字段是 `native_surface`，**没有 `model` 字段**；带 model ⇒ 拒 |

## 四 · 先取证（R-H199 实测 · 四条）

| # | 取证项 | 读数 |
|---|---|---|
| 1 | 盘上有没有"外部模型直接执行"的路径？ | **直接 `import llm` 层共 11 处**：`api.py`×2（**那是路由本身，合法**）；**另 9 处不经 `run_task`**：`autopilot` · `devour` · `drama` · `pipeline` · `semantic_route`×2 · `think_loop` · `vision_cap` |
| 2 | 这 9 处是"补认知"还是"替执行"？ | **待逐条判**（诚实标"未核"）——名字上最可疑的是 `pipeline` / `autopilot` / `think_loop`（像编排执行） |
| 3 | 原生栈有没有被模型名绑住？ | **基本没有**：`caps_registry` 1 处（只是 `llm_chat` 的描述文字）· `tentacle/` 2 处（1 注释、1 识别文本的正则）——**都不是真依赖** |
| 4 | 密钥池里现在有几个模型？ | **池里 0 个**（`keys_total 0`）；可支持的 profile **2 个**：`agnes` · `deepseek` |

🔴 **口径边界**：第 1 条的 9 处是**按 import 关系取出来的清单**，还没有逐条读语义 ⇒ **第 2 条标"待逐条判"**，不假装已清干净。

## 五 · 进化循环（机械 · 不靠"记住"）

| 步 | 动作 | 落点 |
|---|---|---|
| 1 | 扫描原生能力栈，列出短板 | `tools/coverage_auditor.py` |
| 2 | 短板登记进台账（挂**原生面**） | `gaps_ledger`（本刀新落） |
| 3 | 每个短板绑定一个"待打磨"任务 | `docs/待落刀登记.md` |
| 4 | 每次打磨完成，更新覆盖率读数 | 覆盖审计器 `audit()` |
| 5 | 新增场景 ⇒ 自动触发覆盖审计 | 心跳触发（**未接**） |

> **短板台账不挂在模型上，挂在原生能力上。**
> **不许"一次搭好就完事"** —— 这条同样适用于**我们自己的大脑**：大脑的短板也要登记、也要循环打磨。

## 六 · 与已有架构对接

```
大脑（唯一固定：纪律 / 门禁 / 审计 / 决策）→ 一切任务默认走原生能力
        ↓
万能插（唯一固定：caps_registry / run_task / 编排）→ 外部模型是"参谋"，不是"执行者"
        ↓
触手（唯一固定：全息能力 + 认知包）→ 借的是"认知"，不是"执行"
        ↓
密钥池（可换：Agnes / GPT / Claude / DeepSeek…）→ 换谁，触手照旧全息；触手换谁，路由照旧原生
```

**解耦**：密钥池（可换）↔ 原生能力栈（固定）—— 两边**不许互相绑**。

## 七 · 顺序与诚实边界

- **顺序**：排在**密钥池之后**、**编排内核之前**（编排内核已落，故本刀紧随）。

  · **大脑自己的短板同样入册**，不许只查别人。
