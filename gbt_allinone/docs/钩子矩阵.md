# 钩子矩阵（50 个 · 六大类 · 三层部署）· 图纸（**未落地**）

> 落点：`gbt_allinone/tools/hook_registry.py`（只读骨架，与穿透网骨架并列）
> 状态：**未落地**（盘上 0 命中）· 排队：**排在编排内核之后**
> 一句话：**钩子不是功能，是秩序。** 50 个钩子 = 50 个传感器与阀门；它们不产生内容，
> 但决定**内容能不能安全、有序、高质量地产出**。
> 设计基准：Agent 编排 / 触手网络 / 证据链 / 内容创作流水线；参照 Claude Code · CrewAI · Cloudflare 的钩子模式。

## 三层部署位置（**红线所在**）

| 层 | 钩子类型 | 部署位置 | 关键纪律 |
|---|---|---|---|
| **L1 · 框架级** | 通用钩子（限流 / 重试 / 超时） | **触手基类**，所有触手共用 | 统一实现，不重复编写 |
| **L2 · 业务级** | 业务钩子（参数校验 / 格式检查） | **每根触手内部** | 每根触手自己声明，契约不同 |
| **L3 · 审计级** | 审计钩子（证据 / 护照 / 异常） | **触手外部，装饰器包裹** | 🔴 **执行者不能自己写审计** |

> 🔴 **L3 是红线**：`pre_audit_log` · `on_evidence_submitted` · `on_passport_close` 等
> **绝对不能挂在触手内部** —— 必须包在**触手外面**，由框架统一执行。
> 否则触手就会变成"**自己给自己打分**"的执行者（=「证据链不能自指」的底线）。

## 命名空间规则

```
hook.general.*    （L1）
hook.business.*   （L2）
hook.audit.*      （L3）    —— 不许同名混用
```

## 三条红线（写死）

1. **审计钩子必须挂在触手外部** —— 执行者不能自己写审计；
2. **钩子自身的失败必须隔离**（`on_hook_failed`）—— 不许拖垮主流程；
3. **钩子链必须可中断**（`on_hook_chain_timeout`）—— 不许无限等待。
