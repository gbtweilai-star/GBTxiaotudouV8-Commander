# ai-bot 技能升级 · 「穿透网」设计（图纸 · 未落地）

> 状态：**图纸，未落地**（Owner 2026-09-19 口述；盘上尚无对应模块）

> 前置：第 1 步（投影只读卡片）**已收口**；第 2 步（痕迹库 + 心跳触手）**在飞**（第一/二小刀已收口）。

## 0 · 一句话

**不是导航，是穿透。**

```
旧：你 → 打开网站 → 搜索 → 点卡片 → 跳到工具网页 → 手动操作
新：你（或触手）→ 说一句话 → 路由命中能力位 → penetrate() → 触手直达工具核心 → 结果回传
```

**网站消失了。只剩下一张能力网和一群触手。**

> 蒸馏到极限的样子，不是"把网站抄下来"，是**把网站拆成能力位，把触手接到能力位的真实入口上**。
> 从"打开网页点卡片"，到"说一句话直接调用"。

## 1 · 五层模型

| 层 | 职责 | 本图纸的落地顺序 |
|---|---|---|
| **索引层** | 有哪些能力位（名字 / 类目 / 来源 / 链接） | **先做（只读）** |
| **入口层** | 每个能力位的真实入口在哪（网页 / API / CLI） | **先做（只读）** |
| **契约层** | 怎么调（参数 / 返回 / 约束） | 第二步：**只对开放 API** 做 |
| **调用层** | 真调（含授权） | 等前两层收口再谈 |
| **反馈层** | 结果回传与留痕 | 等前两层收口再谈 |

## 2 · 落点与接口（图纸 · 待实现）

```
gbt_allinone/tools/ai_capability_net.py
    CapabilityNode           能力位（索引层 + 入口层的载体）
    PenetrationProtocol      穿透协议（"怎么算穿透成功"的判据）
    penetrate(node, params)  统一调用接口 —— 触手不需要知道背后是网页、API 还是 CLI
    SwitchRouter.route(intent, dimension)   切换＝路由（按类目/场景/热度/教程/来源/授权类型）
```

**`CapabilityNode` 必须带的诚实字段**（缺一个都不许标"可用"）：

| 字段 | 含义 |
|---|---|
| `indexed` | 进了索引（**只是知道它存在**） |
| `entry_known` | 入口找得到（网页/API/CLI 任一） |
| `contract_known` | 参数与返回写清了 |
| `penetrate_ready` | **真跑过**、跑通了 |
| `verified` | 跑通这件事**被独立复核过** |
| `authorized` | 这一步的调用**在授权范围内** |

**默认值全部为 `False`**：`indexed=False, entry_known=False, contract_known=False,`
**`penetrate_ready=False`**, `verified=False, authorized=False` —— **没跑过的就标 `penetrate_ready=False`**。

## 3 · 三条诚实口径（Owner 原文照录 · 关键红线）

> **"在索引里" ≠ "能穿透"**
> **"能穿透" ≠ "已核实能穿透"**
> **"已核实" ≠ "已授权"**

**不许**把"在索引里"写成"能穿透"，**不许**把"能穿透"写成"已核实"。

机械判据（防"四个字段互相顶包"）：

1. `penetrate_ready=True` **只在真跑过之后**才许写（要带 `evidence_ref` 指向那次的读数）；
2. `verified=True` **只在独立复核之后**才许写（复核 checker 标签不许与执行方同标签 —— 同框架自改门那一条）；
3. `authorized=True` **只由授权门给**（AI 不许自授，与 `auth_gate` 同口径）；
4. **任何一层为 False 时，展示面必须显示 False**（不许用"通常都行"之类的话糊过去）。

## 4 · 落地顺序（Owner 定案 · 不变）

1. **先做只读层**：索引层 + 入口层（抓网站，**标未核实**）；
2. **再做契约层**：**只对开放 API 的工具**做；
3. **调用层和反馈层**等前两层收口后再谈 —— 它们涉及**授权与写路径**。

**红线**：不碰面板 8765 · 不碰信号环；走今天的规矩（开护照 → 改 → 用例 → 独立复核 → 关账）。

## 5 · ⚠️ 本刀实测：沙箱**出不了网**，"抓网站"这一步现在做不了

```
DNS mapmapteam.github.io => 185.199.110.153   （能解析）
DNS github.com           => 20.205.243.166    （能解析）
TCP  github.com:443      => **被拒：PermissionError [WinError 10013]**（不允许的套接字访问）
TCP  127.0.0.1:8765      => 通（本机面板）
```

**读数 ⇒ 结论（不是推断）**：**DNS 能解、TCP 出网被挡**。所以：

- 索引层的**"抓网站"在本沙箱身份下做不了** —— 不许用"我抓到了"之类的话糊过去；
- 索引节点允许 `indexed=True, fetched=False`：**知道它存在**，但**内容没抓过**（这正好落在第一条口径上）；
- 真要抓，三条路（等主人一句话）：**(a)** 主人在**本机**抓，把结果交给框架；**(b)** 走浏览器触手（本机身份）；**(c)** 只做"结构 + 路由 + 口径"，把**抓取做成可注入的入口**（有网时再灌数据）。

## 7 · Owner 原文照录：五层穿透模型 v2.0（2026-09-19）

```python
# -*- coding: utf-8 -*-
"""
万能插 · AI能力穿透网 (AI Capability Penetration Net) v2.0
蒸馏自：ai-bot.cn（1000+工具 · 9类目）
极限版：从导航 → 能力位 → 穿透触手
开发者：自由的风
守护者：公主土豆
禁止删除
"""

from dataclasses import dataclass, field
from enum import Enum
from typing import Dict, List, Optional, Callable, Any


class PenetrationLayer(Enum):
    INDEX      = "索引层"     # 网站上的卡片：名称 + 描述 + 链接
    ENTRY      = "入口层"     # 真实入口：URL / API endpoint / CLI
    CONTRACT   = "契约层"     # 入参契约：需要什么参数、返回什么
    INVOKE     = "调用层"     # 触手穿透：直接调用，不经过网页
    FEEDBACK   = "反馈层"     # 调用结果回传：成功/失败/产物


@dataclass
class CapabilityNode:
    name: str
    category: str
    desc: str
    web_url: Optional[str] = None
    api_endpoint: Optional[str] = None
    cli_command: Optional[str] = None
    requires_params: List[str] = field(default_factory=list)
    returns: List[str] = field(default_factory=list)
    auth_type: Optional[str] = None     # 免费 / API Key / OAuth / 需授权
    invoke_mode: str = "unknown"        # web / api / cli / manual
    penetrate_ready: bool = False       # 是否已核实可穿透
    last_invoked: Optional[str] = None
    last_result: Optional[str] = None


class PenetrationProtocol:
    def penetrate(self, node, params):
        missing = [p for p in node.requires_params if p not in params]
        if missing:
            return {"ok": False, "reason": "missing_params", "missing": missing}
        if node.invoke_mode == "api":
            return self._via_api(node, params)
        elif node.invoke_mode == "cli":
            return self._via_cli(node, params)
        elif node.invoke_mode == "web":
            return self._via_web(node, params)
        else:
            return {"ok": False, "reason": "not_penetrable", "node": node.name}


class SwitchRouter:
    """'可随意切换'的本质：路由选择（不是导航）。"""
    def route(self, intent: str, dimension: str = "category") -> list:
        ...


HONEST_BOUNDARY = (
    "穿透网只保证『能力位可路由』，"
    "不保证『每个能力位都可穿透』。"
    "没有 API/CLI 的工具，只能走 web 自动化；"
    "需要授权的工具，必须过授权门。"
    "『在索引里』不等于『能穿透』，"
    "『能穿透』不等于『已核实能穿透』。"
)
```

> ⚠️ **一处必须点名的空壳（Owner 原文里的问题，不照抄）**：原文 `_via_api` / `_via_cli` / `_via_web`
> 三个方法**直接 `return {"ok": True, ...}`，中间什么都没做** —— 那是**空壳假执行**
> （与《反空壳与反假执行律》正面冲突，也与本图纸 §3 第一条口径冲突：没跑过却报 ok）。
> **落刀时的写法**：三个分支一律返回
> `{"ok": False, "reason": "not_implemented", "note": "等契约层收口"}`，
> **直到真有一条能跑的路径**才允许出现 `ok=True` —— 而且那时必须带 `evidence_ref`。

## 8 · 五层穿透的诚实读数（按当前盘上事实逐层给）

| 层 | 现在能做吗 | 依据（读数） |
|---|---|---|
| **INDEX 索引层** | ⚠️ **半做**：结构可落，**抓取做不了** | 沙箱 `TCP github.com:443 => PermissionError [WinError 10013]`；DNS 可解但 socket 被拒 |
| **ENTRY 入口层** | ⚠️ 同上层（入口 URL 本身就来自抓取） | 同上 |
| **CONTRACT 契约层** | ✅ 只对**开放 API**、且**本地已有记录**的能力位可写；其余待补 | §4 落地顺序第 2 条 |
| **INVOKE 调用层** | ❌ **不开工**（涉及授权 + 出网） | §4 落地顺序第 3 条；且出网在本沙箱被挡 |
| **FEEDBACK 反馈层** | ❌ **不开工** | 同上 |

**一句话读数**：**五层里现在真正能落的是"结构 + 路由 + 契约（限开放 API）"三块；
索引层缺"抓"、调用/反馈层缺"授权与出网"。** 这不是保守，是盘上事实。

**所以开局的最小可验证切片 = 只落"结构 + 路由 + 口径"**：

`penetrate()` 对未实现分支一律 `not_implemented`（**绝不返回 ok=True**）· 用例锁死这三条。
抓取做成**可注入入口**（有网/有本机抓取结果时再灌），节点允许 `indexed=True, fetched=False`。

**索引层的字段（照 Owner 原文，加两个诚实位）**：

name / category / desc                      # 索引层三件套

fetched=false                               # **内容抓过没有**（抓不到就必须是 false）
penetrate_ready=false                       # **真跑过没有**（默认永远 false）

**四个分母，四个百分比（别合并 —— 合并就是把口径踩平）**：

| 栏 | 分子/分母 | 现在 | 能不能报 100% |
|---|---|---|---|
| **`indexed`（进了索引）** | 130/130 | **100%** | ✅ **能——而且现在就成立**（种子全灌进来即达） |
| `entry_known`（知道入口在哪） | 115/130 | 88.5% | 要 100% ⇒ 得把 15 条无出处的外部项**逐条找到入口**（现在找不到） |
| `penetrate_ready`（真跑过） | 0/130 | 0% | 要 100% ⇒ 得**逐条实打**，每条带 `evidence_ref` |
| `verified`（独立复核过） | 0/130 | 0% | 要 100% ⇒ 每条再经一个**不同 checker** |
| `authorized`（在授权范围内） | 0/130 | 0% | 只由授权门给（AI 不许自授） |

> 谁要说"穿透网覆盖率 100%"，必须先说清是**哪一栏**的 100% ——
> 把"索引 100%"读成"能穿透 100%"，就是那三条口径里第一条的**现场违例**。
> 目标可以是 `penetrate_ready → 100%`，但到达路径**只有一条**：逐条实打 + 留证，没有捷径。

## 11 · 入口层切片（**三态分开** · 2026-09-19 实测）

入口层**不是一个布尔**，是三态 —— 混成一个，就会重演"在索引里＝能穿透"那种错：

| 状态 | 问的是 | 怎么得到 |
|---|---|---|
| `entry_known` | 入口**在哪**（URL / endpoint / CLI / 模块） | 看清单与盘上文件即可 |
| `reachable` | **连得上吗**（打一枪的通断） | 必须真连一次（本地可当场验；外部要出网 ⇒ 今天 `unknown`） |
| `penetrate_ready` | **真跑通了吗** | 真跑 + `evidence_ref`（§3 口径） |

**本地种子实测（111 条）**：

```
能力位 111 · handler=blocked（策略禁用）11
其余 handler 去重 100 个：
    入口在盘上（同名 gbt_allinone/<handler>.py）  = 19   ← entry_known 直接成立
    入口不在盘上（需走映射表：api/engine/服务层） = 81   ← 入口存在，但**不在同名文件里**
```

**⇒ 这一刀的读数**：本地 111 条的 `entry_known` **不是 111**，而是
**19 条一眼可见 + 81 条要靠映射 + 11 条被策略禁用**；我**没有把它们凑成 100%**
——因为"入口不在同名文件里"只是**我还没找到**，不等于**没有入口**（《空不等于不存在律》）。

**外部那 19 条**：`entry_known=4`（有 repo），另 15 条**连入口都不知道**；
而 `reachable` 对外部**今天一律 `unknown`**（出网被挡 ⇒ 连不通与连得上都无法判定，
**不许**因为"连不上"就把 `reachable` 写成 `false` —— 那是把"测不了"读成"不行"）。

**落地切片（入口层）**：

1. 先建**映射表**（handler → 真实入口：模块 / `api.run_task` 能力名 / CLI），把 81 条补齐；
2. 本地 `reachable` **当场可打**（import 一次 / 调一次只读口）⇒ 一格格点亮，带 `evidence_ref`；
3. 外部 `reachable` 保持 `unknown` 直到出网通道打开 —— **`unknown` 是一个诚实值，不是失败**。
