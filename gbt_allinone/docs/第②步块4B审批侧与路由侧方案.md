## 一、取证四结论（先读，未动刀）

### 1.1 审批侧是纯单槽：缺的不是「改挂载方式」，而是通道本身不存在

| 机制 | 位置 | 语义 |
|---|---|---|
| 单槽 `on_approval` | `codex_bridge.py:160`（构造参数） | 赋值即**覆盖** |
| 审批派发 | `codex_bridge.py:443-451` | 只问 `self.on_approval`；为 `None` → `_default_denial` 安全拒绝 |
| 事件侧多订阅 | `codex_bridge.py:407-416` + `:394-405` | 追加式 + 返回 `remove()` 句柄 + 广播；**审批侧无对应物** |

结论：需**新增** `_approval_listeners` + `add_approval_listener()` + 链式派发。

### 1.2 路由侧从不挂载任何钩子（全仓扫描）

- `api.py` 的 `codex_*` 分支（`:505-523`）全部是**请求-回执同步调用**：`status()` / `dynamic_tool_specs()` / `start_thread()` / `start_turn()` / `interrupt()`
- 全仓 `get_shared_server` 调用点仅 `api.py:517/521/523` —— **均不带任何钩子 kwarg，也不调 `add_listener`**
- 其余 `on_event=` / `on_approval=` 出现处：`holo_pet/panel_server.py:251-252`（面板，4-A/4-B 处理）、`potato_pet/codex_client.py:104-105`（**自建私有实例**，非共享单例，另案挂账）、`gbt_allinone/codex_bridge.py:1283`（`run_once` 私有实例）
- `doctor(live=True)` 的 `server.on_event = on_event`（`:1451`）作用在 **`doctor` 自建的私有实例**（`:1410`）上，与共享单例无关

### 1.3 `codex_bridge.py:1283` 的 `on_approval=` 归属

- 位于 `run_once(...)`（`:1224` 定义）内部，为它自己 `new` 的**私有实例**传参（`:1280-1286`），默认 `approval_handler=None`
- `run_once` 的调用方**只有测试**（`test_codex_bridge.py:326/340`）；生产无调用方

**定性**：

- 事件类：桥已写 `codex_error_event`；其余事件流**刻意不入审计**（高频噪声）。路由若挂空壳「只记账」＝把高频事件流塞进审计，**反模式**，且与桥层、框架层**三重重复**
- 审批类：**真缺口**，但审批决策产生在**桥的派发点**（`:443-451`）；路由既不在审批链上、也没有审批钩子可用 → **路由挂事件钩子补不了这个缺口**（挂在了与缺口无关的位置）

## 二、路线裁决：A —— 路由侧不挂事件钩子

三条实测理由：

1. **无需求**：路由侧没有任何事件消费行为（1.2），挂上即空壳
2. **三重重复**：错误类已有 `codex_error_event`，调用类已有框架层 `call`/`ok`；事件流本身刻意不入审计（1.4）
3. **补不到缺口**：唯一真缺口（审批决策留痕）必须在**审批链路**上补，路由挂事件钩子与其无关（1.4）

→ **4-B 聚焦审批侧；路由侧明确标注「无事件消费需求，不挂事件钩子」，`api.py` 改动 0 行。**

## 三、4-B-1 桥侧：审批订阅通道（`gbt_allinone/codex_bridge.py`）

| tag | 锚点 | 内容 |
|---|---|---|
| T0 | `:172-173` 之后 | `self._approval_listeners: list = []` + `self._approval_listeners_lock = threading.Lock()` |
| T1 | `:407-416`（`add_listener` 之后） | 新增 `add_approval_listener(listener)`：追加式注册 + 返回 `remove()` 句柄 |
| T2 | `:443-451` | 链式派发：`on_approval`（旧槽，优先级最高）→ `_approval_listeners`（注册顺序）→ `_default_denial`；**非 None 短路**；逐 handler `try/except` 隔离 |

派发语义（与 `_emit_event:394-405` 同型）：

- 先取句柄**快照**再逐个调用（避免迭代中 `remove()` 触发 `RuntimeError: list changed size`）
- 单个 handler 异常**不打断**后续 handler，只记 `logger.warning`
- 全部返回 `None` → `_default_denial(method)`（安全拒绝语义逐条不变）

镜像验证（B1-B6 见第六节）：单槽短路、链式顺序、首非 None 即停、全部 None 回落、异常隔离、句柄幂等。

落生产验收标尺：`test_codex_bridge.py` 审批用例（`test_command_approval_roundtrip`、`test_default_denial_when_no_handler`）**零回归**；红 1 维持不增。
