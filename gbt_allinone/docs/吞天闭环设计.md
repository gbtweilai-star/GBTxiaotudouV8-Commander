# 吞天闭环设计（R-H258 · 2026-09-20 · 只读骨架）

> 主人口径：**「吞天能力里面加入蒸馏提炼吸收自动跑通闭环，避免留下垃圾导致吞噬失败」**
> 机器面：`gbt_allinone/tools/absorb_loop.py`（能力位 `absorb_loop` · `domain=brain`）

---

## 一 · 三阶段 + 一回灌（吞天闭环）

```
DISTILL 蒸馏   原始料 → 要点（去重 / 去噪 / 去掉不相关；**不压缩掉出处**）
REFINE  提炼   要点   → 结构（可复用条目 / 模板 / 口径；**不替原话下结论**）
ABSORB  吸收   结构   → 落地（能力位 / 文档 / 口径）+ 登记
   ↺ FED_BACK 回灌：吸收的结论回喂蒸馏过滤器 ⇒ **下次别再吞同类垃圾**
```

**闭环的「闭」就在回灌这一步**：不回灌 = 直线 —— 吞进来的东西落完就完，
下次照样把同类垃圾再吞一遍。

## 二 🔴 为什么要防垃圾（**取证，盘上有标本**）

```
· gbt_allinone/devour.py 的 _v8_deploy 每次覆盖都会留下一个 .deploy_bak，
  而全模块 grep 找不到任何清理逻辑（清理|cleanup|清场 = 0 命中）；
· 实测：gbt_allinone/store/devoured/（**吞噬自己的产物目录**）26 个条目里，
  已经躺着 1 个 gap_deploy/knowledge.json.deploy_bak。
⇒ 「留下垃圾导致吞噬失败」不是假想：**产物目录自己就在攒垃圾**。
```

## 三 · 四条机械闸（都带牙）

| # | 闸 | 报的规则名 | 咬什么 |
|---|---|---|---|
| ① | `check_stage_clean` | `stage_dirty` | 阶段收尾没清场，把 `.tmp` / `.deploy_bak` / `.partial` 带进下一阶段 |
| ② | `check_loop_closed` | `loop_not_closed` | 三阶段缺一段，或三段跑完**没回灌**（直线不是闭环） |
| ③ | `check_scan_junk` | `junk_left_silently` | 盘上有垃圾，既没清、也没**显式登记理由** |
| ④ | `check_resumable` | `not_resumable` / `bad_resume_point` | 中断了却没留续跑点 ⇒ 下次只能从头吞，半成品还可能挡路 |

另有一条红线闸：`check_source_evidenced`（`source_not_evidenced`）——
**没出处的料拒收**（与「未取证不引外部」同族）。

## 四 · 五条红线（写死）

```
① 吞完必须清场：阶段收尾扫垃圾，有则清、或写明理由（不许带进下一阶段）
② 闭环必须可续：中断留续跑点，不留半成品卡住下一次
③ 每阶段留痕：写 trace_store，source_kind=absorb
④ 不许吞未取证来源：没出处的料拒收
⑤ 垃圾不许静默留：要么清、要么显式登记理由（与坑册 §57 同族）
```

## 五 · 与已有体系的接法

| 关系 | 说明 |
|---|---|
| **吞噬引擎**（`devour.py` / `DevourTentacle`） | 本骨架是它的**纪律面**：吞之前问来源、吞完扫垃圾、断了留续跑点 |
| 自改门（R-H249 后的可见范围） | `.tmp` / `.deploy_bak` **不在**门的监视后缀里 ⇒ 门不会为它报警 ⇒ 更要自己扫 |
| 坑册 §57（有理由的空） | 第 ③ 条闸是它的复用：**垃圾要么清、要么登记**，不许默认沉默 |
| 痕迹库 / 做梦技能 | 每阶段留痕（`source_kind=absorb`）走同一套 trace 口径 |
