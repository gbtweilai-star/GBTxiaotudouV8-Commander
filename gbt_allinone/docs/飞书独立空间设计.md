### 1.3 凭据容器：**有、已落盘**；但**当前身份解不开**（关键分叉）

```
gbt_allinone/store/secrets/  ← 与 cloudflare / deepseek / notion / xingyun 同一容器
  feishu_app.dpapi    378 B   ← 飞书这套在
  cloudflare_api.dpapi 338 B · deepseek_api.dpapi 318 B · notion_api.dpapi 330 B · xingyun_app.dpapi 364 B
环境变量：GBT_FEISHU_APP_ID / _APP_SECRET / _BRAND / _SECRET_FILE  **全部未设置**（凭据走 DPAPI，不靠 env）
```

`feishu_bridge.status()` 实数：

```
configured False · credential_source "unreadable" · credential_protected False · token_cached False
base_url https://open.larksuite.com · brand lark
```

**判别实验（决定性）**：

| 实验 | 读数 | 说明 |
|---|---|---|
| DPAPI 往返（内存内加密再解） | **ok=True**（282 B blob） | 当前身份 DPAPI **本身可用** |
| 同容器**五个** `.dpapi` 文件逐个解 | **全部 decryptable=False** | ⇒ **不是飞书那一份的问题** |

⇒ 结论：**原因是"身份不同"** —— 这些 blob 是**主人交互会话**创建的，沙箱进程的令牌解不开
（与 AGENTS.md 已记的"沙箱身份 ≠ 真实用户"同族）。
🔴 **因此"飞书配没配"不能在沙箱里判**：我看到的是"**解不开**"，不是"**没配**"。
要判，必须在主人会话里跑：`py -3.10 -m gbt_allinone.feishu_bridge status`。

### 1.4 额外发现（两条，都会影响设计）

1. **技能层已装 28 个 `lark-*` 技能**（lark-doc / lark-drive / lark-wiki / lark-base / lark-im /
   lark-sheets / lark-task / lark-calendar / lark-approval / lark-mail …），走 **lark-cli**；
   另有 `~/.lark-cli/hermes/`（`config.json` 219 B + `update-state.json` 51 B）
   ⇒ **这是第二套凭据体系**。两套并存 = "**两处真相**"的种子 ⇒ 设计必须写死"谁是主"。
2. **出网被挡**（本环境 `TCP:443 => PermissionError`）⇒ 飞书是云端 API，
   **任何"能不能连通"的结论今天都不许下**（在 ≠ 能用）。

### 1.5 一条自我纠错（照报）

第一版读数把 `~/.lark-cli/**hermes**/config.json` 读成了 `~/.lark-cli/config.json`
——错在**只打印裸文件名、不打印相对路径**，于是把子目录里的文件当成了根下的。
**纪律**：列文件必须打印**相对路径**；裸名字 = 归属误判的温床。

## 二 · 三条红线（写死在设计里）

| # | 红线 | 含义 |
|---|---|---|
| 1 | **飞书是外存，不是主库** | 盘上永远是唯一真相；**不许反向覆盖盘上**。反向同步（飞书 → 盘）必须单独授权 |
| 2 | **只读镜像优先** | 先做"**盘上 → 飞书**"的单向同步；反向同步另立一刀 + 人工授权 |
| 3 | **凭据进 DPAPI** | App Secret **不许明文落盘**（沿用现有 DPAPI 容器与 `GBTxiaotudouV8:feishu:v1` 熵）；日志与状态接口一律掩码 |

## 三 · 文件夹结构（飞书侧"独立空间"）

```
飞书独立空间/
├── 00_inbox/        收件箱 —— 未分类的原始素材
├── 01_training/     训练   —— 模型训练数据、语料、样本
├── 02_rehearsal/    排练   —— 试跑、彩排、中间调试
├── 03_drafts/       半成品 —— 未完成但有价值的产出
├── 04_finished/     成品   —— 已验收的交付物
├── 05_archive/      归档   —— 过期但需保留
└── _index/          索引（知识库入口）
    ├── manifest.json   所有文件的元数据 + 状态
    ├── taxonomy.md     分类规则（什么进哪个文件夹）
    └── tag_rules.md    标签规则
```

### 3.1 索引三件套的字段（`manifest.json` 一行一文件）

```json
{"path": "03_drafts/xxx.md", "sha256": "…", "bytes": 0,
 "source": "盘上相对路径", "created_at": "2026-09-20T…", "updated_at": "…",
 "status": "draft", "evidence_ref": "护照/用例/读数出处",
 "promoted_from": null, "promoted_at": null, "promoted_by": null, "promote_reason": ""}
```

`status` 四态：**training / rehearsal / draft / finished**（`05_archive` 用 `archived`）。

## 四 · 四条纪律

| # | 纪律 | 机械保证 |
|---|---|---|
| 1 | **不覆盖** | 同名文件加时间戳后缀；写入前先查 `manifest.json` 的 `sha256` |
| 2 | **带出处** | 每个条目必须有 `source` / `created_at` / `status` / `evidence_ref`，缺项判非法 |
| 3 | **状态可查** | 四态进 `_index/manifest.json`；"什么在什么状态"必须能一眼查到 |
| 4 | **不静默迁移** | `drafts/ → finished/` 必须留痕：谁升的（`promoted_by`）、什么时候、**为什么**（`promote_reason`） |

## 八 · 落刀前必须拍板的两件事（R-H174 加 · 附取证）

### 8.1 凭据"谁是主"——两套并存，**不先定主就会出两处真相**

| 体系 | 落在哪 | 谁在用 | 本次读数 |
|---|---|---|---|
| **框架 DPAPI** | `gbt_allinone/store/secrets/feishu_app.dpapi`（378 B） | `feishu_bridge.py`（熵 `GBTxiaotudouV8:feishu:v1`） | 沙箱身份下 `credential_source = "unreadable"`（**身份边界，非缺失**） |
| **lark-cli** | `~/.lark-cli/hermes/`（`config.json` 219 B · `update-state.json` 51 B） | **28 个 `lark-*` 技能**（`lark-cli config init` 产物） | 未读（内容含凭据，按纪律不打印值） |

**建议（待主人拍板）**：**主 = 框架 DPAPI · 副 = lark-cli**。理由三条：

1. **所有权**：盘上是唯一真相；框架侧的写动作要走护照与审计，凭据在框架容器里才追得回来；
2. **可审计**：lark-cli 的配置**不进框架账本**（它的 `--as user/bot` 身份模型与 exit 10 高风险确认门，
   本来就是为"人在环中"设计的）；
3. **单向写**：同一份内容**只允许一个方向写**（盘上 → 飞书）；两边都写 = 两处真相。

### 8.2 28 个 `lark-*` 技能 与 `feishu_bridge` 的关系（互补 / 替代 / 并存）

**建议（待主人拍板）**：**互补，但分工写死**——

| 面 | 谁 | 干什么 | 为什么是它 |
|---|---|---|---|
| **前台 / 操作面** | 28 个 `lark-*` 技能（走 lark-cli） | 主人问"发消息 / 建文档 / 查日程"时走它 | 有身份模型（`--as user/bot`）· `--dry-run` · exit 10 高风险确认门 |
| **后台 / 触手面** | `feishu_bridge.py` | 只做"框架自己"的事：痕迹库 / 图纸 / 产出的**只读镜像** | 框架内可登记、可审计、进护照账 |

🔴 **不许同一件事两边做**（同族纪律：两处真相）。
🔴 **`feishu_bridge.py` 必须接进 `caps_registry`** —— 让它从"**孤儿模块**"变成"**能力**"（坑册第 37 条）。

### 8.3 开工前必须先拿到的那一个读数（主人会话里跑）

```bash
py -3.10 -m gbt_allinone.feishu_bridge status
```

- `configured True` ⇒ 设计可继续（下一步：单向镜像骨架）；
- `configured False` ⇒ 本文件补一条"**需先配凭据**"，且**落刀排在配凭据之后**。
- 为什么必须在这一步：**它是所有同步方案的基石**；而沙箱身份**判不了**（今日实测 `unreadable`）。
