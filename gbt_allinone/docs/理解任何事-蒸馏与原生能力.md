## 二、蒸成原生能力：`know_map`（第 309 位）

| op | 作用域 | 干什么 |
|---|---|---|
| `scan` | 零票 | 走盘 + 分类 + 找入口（空目标不算成功） |
| `build` | 写（`state/know_map/<slug>.json`） | 三层建图：结构 / 知识 + 逻辑边（导入·提及） |
| `layers` | 零票 | 分层视图（每层按度排前几） |
| `tour` | 零票 | **引导导览**：入口 → 它引入谁 → 文档怎么说 → 分层 |
| `ask` | 零票 | **词面**检索（节点+边+证据行）+ 顺手查 `context_vault` |
| `impact` | 零票 | **变更影响**：改了哪些路径 → 图里哪些连接被牵动 |

## 三、铁律（写死，判据里有）

1. **每条边必须带 evidence**（`path` 或 `path:line`）—— 判据 `test_every_edge_carries_evidence` 逐条验。
2. **空目标不算成功**（`empty_target`）；目标不在就 `target_not_found`。
3. **截断必须可见**：撞 `max_files` 上限 ⇒ 图里 `partial: true`，不当全图读。
4. **自带库不刷屏**：`.pylibs`/`vendor`/`site-packages` … 不进图（它不是我们的代码）。
5. **`ask` 是词面不是语义**：返回里写死，不冒充语义搜索。
6. **解不开的导入不建边**（实测踩过：旧版把 `from . import x` 全指向 `__init__.py`）。

## 五、诚实边界

- “BUSINESS LOGIC” 层在本位只到**导入/提及**这一层，没有语义理解（不装）；
- `ask` 不是语义检索（没有 embedding）；
- `know_map.build` 会写盘，但 `security/policy.py` **目前没有本位分支** ⇒ 门算出零票（**漂移，已如实上报**）。
