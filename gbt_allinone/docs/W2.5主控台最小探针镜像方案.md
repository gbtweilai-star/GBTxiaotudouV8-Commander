## 三、探针规格（只做两件事，不做第三件）

### 3.1 两件事

| # | 检查项 | 怎么做 | 判据 |
|---|---|---|---|
| 1 | **进程活着** | TCP 连 `127.0.0.1:8765` + `GET /api/state`，看 `ok == true`。原语是**现成的**：`holo_pet/launch_panel.py:18-30 _panel_ready()` | 拿到 `ok:true` → PASS；连接失败 / 超时 / 非 JSON / `ok` 非真 → FAIL |
| 2 | **SSE 可连** | `GET /api/events`，读到**任意一字节**即 PASS：优先命中的是历史回放（`panel_server.py:1252-1255` 会把 `bus.snapshot()[-40:]` 先发一遍），无历史时等 `: heartbeat`（15 s 一次，`:1258`） | 超时内读到任意字节 → PASS；否则 FAIL |

**两个都要过才算健康。** 任一不过 = 不健康——**不许"差不多健康"**。

### 3.2 频率与形态

| 项 | 口径 |
|---|---|
| 频率 | **计划任务每分钟 `--once`**，与中继看门狗（`codex_relay_watchdog.py`，计划任务 `CodexRelayWatchdog`）同款 |
| 形态说明 | 《GBT全故障点设计.md》§17.2 写的"探针 30 s"**要等常驻服务**；计划任务最小粒度 1 min，W2.5 先按 1 min 跑通，30 s 留给 W3 之后的常驻采集器 |
| 依赖 | **纯标准库**（`socket` / `urllib` / `json` / `time`），不引 `flask` / `requests` / `psutil`——与 §17.2.1 的"依赖只加载必需项"对齐 |
| 互斥 | 文件锁，避免计划任务重入（抄中继看门狗 `--once` 的互斥做法） |

### 3.3 产物与字段

写 **`store/health/main_console.jsonl`**（append-only，一行一验；目录为新建）：

| 字段 | 含义 |
|---|---|
| `ts` | 本次检查时间（ISO） |
| `probe` | 探针标识，固定 `main_console` |
| `target` | `127.0.0.1:8765` |
| `result` | `ok` / `fail` |
| `detail` | 失败原因原文（**不许 `except: pass` 吞掉**） |
| `latency_ms` | 两项检查各自的耗时 |
| **`ttl_s`** | 本条记录的**有效期**（建议 **180**） |

### 3.4 假绿防线：`ttl_s` 是判据，不是装饰

**窗口读到的最后一条记录，若 `now - ts > ttl_s` → 显示灰（未启用），不许显示绿。**

这就是"没有探针在跑就必须灰"的可执行形式：探针停了、计划任务被禁用、文件写不进去——
真值都是"没人看着"，而**没人看着不等于健康**。

（对应《GBT全故障点设计.md》§17.2.1 的第三重保险：独立进程 → 面板内线程 → **假绿防线**。）

### 3.5 退出码（抄中继看门狗范式，退出码即结论）

| 码 | 含义 |
|---|---|
| `0` | 健康（无需动作） |
| `20` | 进程不活（端口 / `/api/state` 探不到） |
| `21` | 进程活着，但 **SSE 连不上**（能问话，流断了） |
| `22` | **本次没有结论**——互斥锁被占用 / 未指定动作 / 配置或 health 路径不可用 / **记录超期判灰** |

`20` 与 `21` **必须分开**——"进程在不在"与"流通不通"是两件事，混成一个码就没法诊断。

`--status` 复用同一套码：新鲜且健康 → `0`；新鲜但不健康 → `20` / `21`（按记录里 `detail` 的前缀还原是哪一项挂的）；**记录超期 → `22`（灰）**。判灰走“没有结论”，不走“故障”——因为“没人看着”和“看着它坏了”是两回事。

## 五、晋升与回滚（一条硬约束：不能单独晋升）

### 5.1 关键约束：`ascend()` 是全量替换

事实 4 写着：`ascend()` **先清空后拷贝**。于是：

```text
W2.5 与 W3 若各自 ascend 一次
  → 后一次会把前一次的产物整份删掉（全量替换，不是增量）
```

**结论：两部合并为一次晋升。** 维度里 `holo_pet_w25/` 与 `holo_pet_w3/` **并列存在**，
`scan()` 全绿后**一次性 `ascend()`**。这与 W3 文档说"维度里不能同时住两个项目"是同一条道理，
区别在于：`holo_pet_w25/` 与 `holo_pet_w3/` 是**同一个项目（GBT）的两批产物**，本来就该一起晋升。

### 5.2 晋升条件（三条同时成立）

1. `scan()` **5/5 全绿**（含 `holo_pet_w25/main.py` 与 `holo_pet_w3/index.html` 两个入口）；
2. §四 三支探针全过；
3. `store/health/main_console.jsonl` 里 `ts` / `ttl_s` / `result` **字段齐全**（W3 的窗口 4 要靠它判灰）。

### 5.3 `S7 ascend()` 单独批

全量替换现实这一步，**到 S7 之前停下来报风哥，单独点头**（沿用 W3 口径，不许一步冲到底）。

### 5.4 回滚

`rewind(19)` → 回到现在的 Backbone 演示快照；每次晋升自动留 `timelines/v20` + `passports/v20.json`。

## 六、红线

1. **只探不救**——W2.5 不含自动重启。恢复动作归 W3 之后的后台恢复器（《GBT全故障点设计.md》§17.3）。
2. **不许假绿**——探针不跑 = 灰；超 `ttl_s` = 灰。这一条优先于"界面好看"。
3. **两件事就是两件事**——不许顺手加第三项检查；要加，先报风哥改口径。
4. **不碰账本**——探针产物只落 `store/health/`；`store/audit.jsonl` 与 `store/ledger/` 是账本常驻化（W3）的地盘。
5. **不单独晋升**——见 §5.1。
6. **S7 单独批**。
