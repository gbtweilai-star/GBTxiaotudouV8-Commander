> 依据：风哥 2026-09-17 定下的 holo_pet 最终形态（唯一用户入口 + 多窗口控制台）。
> 本文**只出设计，不动代码**。每一条现状都带 `file:line` 或命令出处，可复算。
> 配套文档：《holo_pet_UI规格.md》（像素口径）·《Codex同化施工方案.md》（内核口径）。

## 零、一句话结论

框架**选 Electron 43**（已在跑、进程隔离天然成立、托盘内置、透明无边框已实测通过）。
四个窗口里，**主控台今天就能做**；**上帝视角能亮一半**；**云电脑窗口没有实例可连**；
**克劳德窗口的后端一行代码都还没写**。后两者需要先建后端，窗口才有东西显示。

## 一、现状取证（动手前必须先看清的三件事）

### 1.1 现在的桌面壳是单窗口

`holo_pet/desktop/main.cjs:13` 只从 electron 取了 `app, BrowserWindow, globalShortcut, ipcMain, screen`；
`:66` 建了一个 `BrowserWindow`；全仓 `rg -e 'Tray' -e 'BrowserView' -e 'WebContentsView'` 在 `desktop/` 下**零命中**。
也就是说：**托盘没有、多窗口没有、布局保存没有**，全部从零加。

### 1.2 四个窗口的后端，成熟度差得很远

| 窗口 | 后端现状 | 判定 |
| --- | --- | --- |
| 主控台 | 完全就绪：`panel_server.py:348-362 state()` 已暴露 `codex / codex_ready / mind / life / bluetooth / sensory / notion / eigenflux / xingyun`；`/api/events` SSE 已通；3D 形象已通 | **今天就能做** |
| 云电脑 | `cloudflared.exe` **已装在** `C:\Program Files (x86)\cloudflared\`；隧道鉴权门 `gbt_allinone/deploy/panel_gate.py` **已写好**（401 拦截 + Cookie 换发 + SSE 支持）。**但：没有虚机、没有指标采集端、没有快照/回滚/迁移的任何实现。** 选型**已定**（风哥 2026-09-17：不租第三方，自建虚机），`免费云电脑服务器对比.html`（GCP / Azure 接力）**整份作废**；本机虚拟化层可用性见 §3.2 | **无实例可连，需先建** |
| 克劳德 | 设计文档 `gbt_allinone/docs/克劳德集成设计.md` 已完备（通道名 `claude`、入口 `llm/advise.py`、审计字段、配额 20+3）。**但 `gbt_allinone/llm/advise.py` 不存在**（实测 `Test-Path → False`），`llm/` 目录下只有 `bridge.py` / `cloud_llm.py` / `__init__.py`。审计事件 `external_advice` **从未生产过一条** | **后端未落地，需先建** |
| 上帝视角 | 已就绪：`psutil` 读数在 `mind_engine.py:1347-1351`（cpu / memory / disk）；服务探活 `services.py`；任务队列 `store/tasks.json`（46KB）+ `store/pipeline/`；审计流 `store/audit.jsonl`（35.8MB）。**缺口**："四层账本"目前是**探针产物**（`.scratch/codex_v2_*_ledger.jsonl`，见 `docs/探针无网络影响确认报告.md:112-115`），**不是常驻账本** | **能亮一半，账本需常驻化** |

> 这一节是全文最重要的一节。四个窗口听起来对等，实际是"一个能做、一个半成品、两个没后端"。
> 设计必须按这个真实落差排期，不能四个一起开工然后三个空转。

### 1.3 一件好事：入口已经是一个网页

`holo_pet/index.html` 本身就是整块面板，`panel_server.py:1230-1329` 是它的 HTTP 面。
所以"加窗口"在实现上不是"重写四个应用"，而是**同一台本地服务上的四个视图**——
这是本设计能收敛的关键前提。

## 二、框架选型

### 2.1 候选与实测

| 方案 | 前置条件（本机实测） | 多窗口/进程隔离 | 托盘 | 透明无边框置顶 | 判定 |
| --- | --- | --- | --- | --- | --- |
| **Electron 43** | Node `v24.15.0` ✅、`holo_pet/node_modules/electron` **已装（43.0.0）** ✅ | 每个 `BrowserWindow` = **一个独立渲染进程**，主进程共享 | `Tray` **内置** | **已实测通过**（`main.cjs:73/74/79/89`） | **推荐** |
| Tauri 2 | Rust 工具链 ✅（`cargo.exe` / `rustc.exe` 在 `C:\Users\ADMIN\.cargo\bin`） | 多 `WebviewWindow`，共用系统 **WebView2**，内存更省 | `tray-icon` 插件 | 支持，但 Windows 透明窗口有已知坑，需单独调 | **可行备选**：代价是重换整条栈 + 引入 Rust 构建链 |
| 纯 WebView2 直驱 | Windows 自带 | 每个 `WebView2` 实例独立 | 需自己写 | 需自己写 | **不推荐**：等于自研一个 Electron，收益不明 |
| 浏览器多标签页 | 无 | **同进程多标签，不满足"关一个不影响其他"** | 无 | 无 | **不满足需求** |

### 2.2 选 Electron 的四条理由

1. **已经在跑**。`desktop/main.cjs` 是现成的壳，改动是"加窗口"，不是"换地基"。
2. **进程隔离天然成立**。需求里的"每个窗口独立进程、关一个不影响其他"，Electron 的 `BrowserWindow` 默认就是这个模型，不需要额外设计。
3. **托盘内置**。需求里的"最小化到托盘"，`Tray` 是 Electron 一等公民；Tauri 要装插件，WebView2 要自己写。
4. **透明无边框置顶已实测**。`main.cjs:73/74/79/89` 四属性在这台机器上跑通过，换框架等于把已验证的东西重新赌一次。

### 2.3 一句不推荐 Tauri 的实话

Tauri 在内存占用上确实更优（共用 WebView2，而不是各带一个 Chromium）。
但本设计的瓶颈不是内存，是**"两个窗口的后端还没写"**。
在这个阶段换框架，等于把唯一已经验证过的地基拆掉，去换一个还没验证的——**不是工程选择，是折腾**。

## 四、窗口间通信机制

### 4.1 三层，各管各的

```
┌─────────────────────────────────────────────────────────────┐
│ 主进程（窗口管理器 · 唯一常驻）                                │
│   · 窗口注册表 / 位置尺寸持久化 / 托盘 / 吸附                  │
│   · ipcMain：跨窗口广播（如"账本刷新"）                        │
└───────┬─────────────────────────────────────────────────────┘
        │ ① Electron IPC（主进程 ↔ 各渲染进程）
        │    用途：窗口控制（开关/吸附/移动/置顶），不传业务数据
   ┌────┴────┬─────────┬─────────┐
   ▼         ▼         ▼         ▼
 主控台    云电脑     克劳德    上帝视角      ← 每个 = 一个 BrowserWindow
   └─────────┴─────────┴─────────┘
        │ ② 共享的本地 HTTP + SSE（127.0.0.1:8765）
        │    用途：业务数据。四个窗口是同一台服务的四个视图
   ┌────┴─────────────────────────┐
   ▼                              ▼
panel_server.py               （未来）云电脑采集端点
   │ ③ 进程内直连（同一 Python 进程）
   ▼
gbt_allinone/api.run_task  → 共享单例 / 能力库 / 审计
```

| 层 | 机制 | 传什么 | 为什么这么选 |
| --- | --- | --- | --- |
| ① | Electron IPC（`ipcMain` / `ipcRenderer`） | 窗口控制指令 | 跨窗口广播是主进程的活；业务数据走 IPC 会绕开已有的审计与策略层 |
| ② | 本地 HTTP + SSE | 业务数据（状态、事件、指标） | **面板已经在用**（`state()` + `/api/events`）。复用意味着零新增机制，且天然带审计 |
| ③ | 进程内 Python 调用 | 能力调度 | 所有窗口最终都落到同一个 `api.run_task`，**不绕路**（与《Codex同化施工方案》P2a 同一口径） |

### 4.2 一条纪律

**窗口之间不许直连业务数据。** 云电脑窗口要读账本，走 ②；克劳德窗口要写审计，走 ②。
没有"窗口 A 直接读窗口 B 的变量"这条路——那是把进程隔离的好处自己拆掉。

## 五、窗口生命周期

| 窗口 | 谁创建 | 常驻？ | 关闭语义 | 备注 |
| --- | --- | --- | --- | --- |
| **主进程** | Electron 自身 | **是**（唯一常驻） | 只有托盘"退出"才结束 | 它同时是窗口管理器 |
| 主控台 | 主进程，启动即建 | **是** | 关 = 收进托盘（`win.hide()`），**不 `app.quit()`** | 唯一自动打开的窗口 |
| 云电脑 | 主进程按需建（首次点开才建，之后保留） | 否 | 关 = 真销毁（`win.destroy()`） | 无实例时为**空态窗口** |
| 克劳德 | 同上 | 否 | 同上 | 同上 |
| 上帝视角 | 同上 | 否 | 同上 | 同上 |

三条规则：

1. **主进程是唯一常驻体**。任何一个窗口被关掉，进程不死、其他窗口不受影响——这是需求"关一个不影响其他"的实现方式。
2. **主控台关闭 ≠ 退出**。关它只收托盘；要真退出走托盘菜单。否则用户关掉主控台会连带杀掉全部子窗口，与需求矛盾。
3. **子窗口懒创建、即销毁**。没打开过的窗口不占进程；关掉就释放，下次打开重建。

| 项 | 设计 |
| --- | --- |

## 九、验收

1. **入口唯一**：全机只有一个 holo_pet 进程组对外；重复双击启动只唤回已开实例。
2. **关一个不影响其他**：关掉云电脑窗口，主控台与上帝视角继续刷新，进程数只减该窗口的渲染进程。
3. **主控台关闭不退出**：关主控台后托盘图标仍在，右键可唤回。
4. **布局记得住**：调好四个窗口位置 → 退出 → 重开，位置尺寸逐个还原；把窗口拖到已拔掉的第二屏坐标，重启后回落主屏不消失。
5. **托盘状态点与面板一致**：托盘点的颜色与主控台状态灯在四种状态下逐一对应。
6. **零明文密钥**：自建云电脑**不再有任何云厂商凭据**；克劳德五条红线里明确**不碰密钥**；Cloudflare Token 仍只以 `.dpapi` 形式存在于 `store/secrets/`，全仓 `rg` 扫不到明文。
7. **空态不撒谎**：云电脑与克劳德两个窗口在后端未就绪时显示"未绑定 / 未启用"，不显示任何假指标。

### 11.3 状态灯色彩规范（四窗口共用，一处定义）

| 灯 | 色值 | 含义 | 判据 |
|---|---|---|---|
| 绿 | `#22C55E` | 健康 | 主模态 `✓`，且最近一次检测在本周期内 |
| 黄 | `#F5B041`（土豆金同族） | 告警 / 降级中 | 触发降级链，或检测超期 |

| 窗口 | 后台服务（能力层） | UI（显示层） | 用户操作（控制层） |
|---|---|---|---|
| 窗口 1 主控台 | **W2.5 最小探针先插**（探主控台进程活着 + 主控台 SSE 可连）+ 窗口位置快照（`userData/window-layout.json` 比对，5 min 一趟，偏移 > **20 px** → 纠正 + 落审计 `window_drift_corrected`） | 顶部灯 + 健康徽章 | 展开自检详情 |

两处不一致时**以总控为准**。

### 11.6 干预动作的权限（与门禁对齐）

- **看**故障：只读，不落账。
- **触发自检**：只读期灰；加装后走 `POST /api/health/selfcheck`，**串行执行**，落 `health_selfcheck`。
- **干预**（重启 / 回滚 / 降级）：
  - 一律走既有审批范式 `POST /api/approval`（`holo_pet/panel_server.py:1277`），**Owner 二次确认**；
  - 破坏性动作（重启 / 回滚）按 AGENTS.md《Runtime Safety》口径**必须 Owner 确认**，面板不许自作主张；
  - 每次干预落 `health_action{who, when, why, fault_id, action, result}`。
- **手动切换降级链 = 直接切 + 审批卡片**（风哥 2026-09-17 拍板）：
  点「切换」→ 弹审批卡片（复用 `/api/approval` 范式）→ 确认 → 后台执行 →
  落 `degrade_chain_switched{from, to, fault_id, who, when}`。
  **不许静默切换**——降级链是安全关键，必须留痕。
