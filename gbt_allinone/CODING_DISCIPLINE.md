# GBT小土豆V8 · 编程注意事项手册（她必须清楚的一切）

> 本手册是框架写代码时的纪律清单。不是教程，是红线与习惯。
> 违反任何一条 = 体检层（selfscan）或验收（Judge）会抓住它。

## 一、永远不伪造

1. **没有实现就说没有实现**：返回 `needs_dependency` / `stub` 并说明缺什么，绝不返回假结果占位。
2. **错误原样上报**：异常信息截断可以（200 字符），改写/美化/吞掉不行。`error` 事件的 `reason` 必须能溯源。
3. **验收不由模型自说自话**：任务"完成"只能由 Judge 的非LLM标准判定（status_ok / contains: / file_exists: / no_error），未知标准直接拒。
4. **N/A 优于编造**：查不到的数据如实标 N/A / unknown / needs_dependency（社交探测返回三态就是这条的落地）。

## 二、写入纪律

5. **生产写入必须原子**：`os.replace(tmp, final)`，绝不允许半发布状态被读到。管线 Stage 3 是唯一生产通道。
6. **append-only 优先**：审计/任务图/运行记录全部追加式 + 落盘优先，进程死了数据还在（tasks.json 就是为此）。
7. **写前校验，拒后留痕**：危险能力 denied 落审计；管线门禁不过进隔离区并报 `blocked_by`；长程任务超限/停滞生成升级包——每一条拒绝都有名有姓有原因。
8. **幂等设计**：重复执行同一任务不产生副作用翻倍（引擎重试、长程重试都建立在节点幂等的假设上）。

## 三、连接与暴露面

9. **注册与路由双向对账**：BENIGN_CAPS 里每一项必须在 api.py 有真实分派路径；api.py 里的路由必须都能在注册表找到。体检层第一维就是查这个（quant 漏网事件是教训）。
10. **改能力先改注册表**：新增能力 = caps_registry 注册 + api.py 路由 + 测试用例，三件套缺一不可。
11. **路径与导入**：bundled 解释器开 safe_path，入口文件必须自己 `sys.path.insert(0, root)`；不要假设 cwd。
12. **硬编码路径是债**：quant_tech 的 Workspace 绝对路径是已知债务，新代码一律走配置/参数。

## 四、并发与时间

13. **并行交给线程池**：同层无依赖节点才并行（ThreadPoolExecutor, max 8）；端口扫描类 IO 并发、CPU 密集不并发。
14. **重试要有上限**：节点 max_node_retries、任务 max_attempts，超过就 failed + 升级包，绝不无限重试。
15. **停滞检测**：同样结果连续 3 次 = 卡住（指纹比对），硬撑没有意义，升级给人。
16. **到期判定单调**：调度用 `now - last_run_ts >= every_seconds`，错过不补跑防雪崩。

## 五、安全与合规

17. **内网目标默认拒绝**：guard.py 拦环回/私网/保留段；自有资产必须显式 `allow_private=True`——授权边界写在代码里。
18. **证书校验不关**：任何网络调用禁止 `CERT_NONE`（曾经三处全关的教训）。
19. **密钥不进源码**：`.env` 已 gitignore，密钥走环境变量；日志与返回值里密钥打码。
20. **禁止名单已清空（Owner 2026-09-23 令「把禁止全部解开」）**：`DISABLED_CAPS` 现为 `{}`；那 11 个名字转在 `UNIMPLEMENTED_CAPS` 只做登记 —— **只有名字、没有实现**，点下去得到的是如实的 `unknown capability`，**不是**"被安全策略挡住"。改口径的实测依据：解禁前后**行为等价、能力零增益**（零实现文件），而旧闸的真实代价是让扫描在"能看见什么"上持续失真。红线**一条没放宽**：AI 不许给自己发授权、不许改 `policy.py`、不许绕门；同类合法需求走良性通道 + Owner 显式授权（如授权渗透测试 → `sec_surface`/`sec_scan`/`sec_chain`/`sec_defenses` + Owner 发放作用域）。

## 六、表达与协作（察言观色层）

21. **只调怎么说，不改说什么**：分寸（紧急→结果先行 / 受挫→先接住 / 疲惫→压缩）永远不改变事实本身。
22. **坏消息如实到达**：不隐藏、不稀释、不美化。
23. **困难必带方案**：升级包必须含 2~3 个带代价的选项，把选择权留给 Owner，不替人拍板也不空手回来。
24. **深夜与急事**：识别到疲惫/紧急信号时压缩篇幅、结论前置，但下一步永远给足。

## 七、无人值守纪律

25. **无人值守 ≠ 无人负责**：全链路（wf_define → sched_define → lr_tick → pipeline_submit → svc_inspect）每个环节都落审计，出问题能回放定位到具体节点。
26. **杀进程前先想数据**：长程任务图天然跨进程（tasks.json），但工作流中途被杀要靠 wf_resume 续跑——写中断友好的代码。
27. **服务只看不动**：巡检层纯 TCP 探活，绝不启停别人的进程；启停是 Owner 的显式指令。
28. **预留端口如实报**：v8_isolated 未启动不算掉线，是预期状态。

## 八、验证纪律

29. **每个新能力都要有测试**：注册、路由、成功路径、失败路径四项全测才算完成。
30. **改完就跑全量回归**：`python gbt_allinone\tests\test_framework.py`，全绿才算收工；只跑单测不算。
31. **重大改动派独立验收**：自己测自己容易瞎，验收 Agent 用独立视角复核对账。
32. **测试残留要清**：演示工作流/测试任务用完即清（`t-` 前缀约定），别污染下一个体检窗口的信号。

## 九、触手纪律（第 33 条起）

33. **先看再动**：触手动作类能力（click/type/scroll/kill）调用前必须先经 see/读取确认现场；动后必须再 see 验证。六铁律（先看再动/动后等稳定/找不到就滚/遇弹窗必关/每步亲眼验证/不确定就对比前后截图）不可绕过。
34. **动作类留确认门**：click/type/kill 等改变系统状态的触手方法，统一接口调用时必须带明确的任务上下文并落审计；keylogger/screen_sniff 永远禁用。
35. **穿透传输不阻塞**：触手硬件层的任何上报失败都不允许阻塞本体动作（垫片吞错落审计是唯一正确姿势）。
36. **单例纪律**：全框架只有一只眼睛一双手（bridge.get_eye 单例），任何模块不得自建触手实例。
